# cozy-web-game

## 중요 — 절대 깨지 않는 규칙

이 넷은 어떤 요청이 와도 지킨다. 요청과 부딪히면 사용자에게 말하고 다른 길을 제안한다. **references 끼리 부딪히면 `references/model-voice-and-play.md` 가 이긴다**(다른 파일의 옛 제안에 남은 취향 딱지·필수 이유 필드보다 먼저).

1. **AI 캐릭터는 정직하게 표기한다.** 규칙이 움직이면 화면에 늘 "데모 규칙/데모 두뇌" 표시를 둔다. 기록 줄마다 누가 했는지 적는다(`by`: `user` · `model` · `demo-rules` · `playback` · `fallback`). 읽지 않은 곳을 '읽음'으로 보이지 않는다. 편지·감사·기념품을 지어내지 않는다. (§2)
2. **벌과 압박이 없다.** 배고픔·감쇠·연속 출석·"N일 만에 왔네"·타이머 압박·점수 화면 금지. 거절·집에 있기·쉬기에 시무룩한 연출이나 죄책 대사 금지. (§1)
3. **코드는 사실만 쓴다.** "조개를 3번 골랐다"는 코드가 적는다. "조개를 좋아해" 같은 취향·감정 말은 캐릭터(모델)가 직접 쓴 메모에만, 작성 주체를 붙여서 남는다. 모델이 쓴 말은 고치거나 몰래 자르지 않는다(길이를 넘어도 원문을 보관하고 그대로 넘긴다). 모든 선택 메뉴에 그만두기를 넣고 이유를 묻지 않는다. (`references/model-voice-and-play.md`)
4. **결정 코드는 시드로 돈다.** `scripts/prng.js`(FNV-1a + mulberry32 + 로컬 날짜 키)를 쓴다. 결정·결과 코드에 `Math.random` 금지(grep 0건으로 확인). 결과는 출발 시점에 계산해 저장한다. (§5)

작고 아늑한 웹 게임을 **빠르게, 그러나 싸구려 느낌 없이** 만들기 위한 규칙이다. 근거가 되는 리서치 원문은 `references/` 에 있다(출처·GitHub 스타 수·검증 표 포함). 여기 본문은 바로 적용할 수 있게 압축한 것이다.

## 1. 루프: 사람에겐 동사 하나, 결정은 캐릭터가

여행 개구리·Finch·네코아츠메가 사랑받는 이유는 **통제권이 적어서**다. 사람은 준비(도시락/힌트)만 하고, 언제 나갈지·어디 갈지·무엇을 가져올지는 캐릭터가 정한다. 그래서:

- 메인 화면에 채워진 색의 버튼은 **하나**. 나머지 조작은 `<details>` 로 접어 "데모 조작" 으로 둔다.
- 힌트는 확률을 기울이는 **짐**이지 목적지가 아니다. 캐릭터는 따르기도, 무시하기도, 도중에 벗어나기도 한다. 결과 기록에 "힌트: 따라감/무시함/도중에 벗어남/없음" 을 그대로 적는다.
- **집에 있기**는 외출과 같은 무게의 결말이다. 집에 있는 날도 자기 장면(창가·낮잠·정리)과 자기 카드가 있고, 진행(등불)은 똑같이 오른다. "미안", "다음엔 나가볼까?" 같은 문구 금지.
- 진행은 **사람이 안 볼 때** 일어나고, 돌아왔을 때 **드러난다**. 떠난 동안 캐릭터는 화면에 없고, 기록이 한 줄씩(2~5초 간격, 시드로 흔들기) 쌓인 뒤에야 결과물이 걸린다. 세션 안 기다림은 20~60초, 건너뛰기 버튼은 두되 "빨리 와" 는 두지 않는다.
- 결과물 앞면 = **한 장면 + 스티커 하나 + 한 줄**(1인칭, 보고서 아님). 뒷면 = 영수증(들른 곳 전부, 실패 포함). 같은 입력이라도 날짜가 다르면 다른 결과가 나오게 시드를 `날짜|입력|그날 몇 번째` 로.
- 방은 A Dark Room 식으로 **한 줄 상태문**이 바뀌며 꾸며진다("등불 한 칸. 창턱에 이끼 화분이 놓였다"). 문서 `<title>` 도 같이 바꾼다. UI는 의미가 생길 때만 드러낸다(첫 포스터 전엔 앨범 섹션 숨김).
- 패널티 없음: 배고픔·감쇠·연속 출석·"N일 만에 왔네" 화면 금지. 벽시계 간격은 아무것도 바꾸지 않는다.
- 희귀 티어(1/6 정도, 시드로): 손님 스티커·두 장 스티커·특별 액자. 갈아서 얻을 수 없어야 한다.
- 공유 카드: URL·입력 텍스트·실제 방 이름 없이 갈래 낱말 한 줄 (`뽈뽈 #3 · 비 오는 날 · 손 · 바다 · 들판`). 이모지 줄은 쓰지 않는다(§3).

## 2. AI 캐릭터를 보여 줄 때의 정직 표기 (필수)

AI 모델을 마스코트로 그리면 사람은 "진짜 모델이 골랐다" 고 믿기 쉽다. 그래서:

- 규칙 뭉치가 움직이는 데모라면 화면에 **항상** "데모 두뇌" 같은 칩을 두고, 모든 기록 하단에 "고른 이: 데모(규칙) / 사람이 조작 / 모델" 을 적는다(기록 필드는 `by`).
- 읽기 상태를 넷 이상으로 나눈다: `read`(실제로 가져옴, 출처 링크 필수) / `builtin`(내장 메모) / `simulated`(문 앞까지만, 내용 안 읽음) / `failed`. `https://` 로 시작한다고 ✅ 를 찍지 않는다. 정적 페이지는 바깥 URL을 못 읽으므로 항상 `simulated`. 불러온 이벤트의 상태도 다시 검증한다.
- 실패·모의 방문 행은 성공 행과 **같은 모션, 다른 색/글리프**. 빨간색·흔들림 금지. 문구는 캐릭터 목소리로 중립("문이 잠겨 있었어").
- 지어내지 않는다: 편지·감사·기념품·사진. 사람이 쓴 것만 사람이 썼다고 하고, 없으면 "아직 비어 있어" 로 둔다.
- 거절·집에 있기에 캐릭터가 시무룩해지는 반응(컨펌셰이밍) 금지. 기쁨 표현은 얼마든지.
- 결과물은 캐릭터의 앨범이지 사람에게 주는 보고서가 아니다. "결과/리서치/보고" 대신 "기억/산책/한눈팔기".

## 3. UI 규칙 (폰 360px 기준)

- 간격 눈금 4/8/12/16/24/32/48만 쓴다. 묶음 사이 간격 > 묶음 안 간격. 페이지 좌우 16px.
- 색: 순수 #000/#fff 금지, 웜 니어블랙/페이퍼 화이트. 중립색은 한 온도(웜 또는 쿨)로만 틴트. 강조색 **하나**(예: 등불 호박색). 다크 모드는 반전이 아니라 **강조색은 더 밝고 덜 채도**, 표면은 +5~7% 흰색으로 띄우고 그림자 제거.
- 대비 텍스트 4.5:1, UI 3:1. 상태를 색만으로 구분하지 않는다(픽셀 아이콘 + 글자: 읽음 / 못 읽음 / 모의 방문).
- **픽셀 폰트는 실제 격자를 재서 쓴다.** 갈무리(Galmuri)는 이름보다 1px 큰 격자다: Galmuri11 → 12px, Galmuri9 → 10px, Galmuri7 → 8px. 이름대로(11/9/7px의 2배 = 22/18/14px) 쓰면 획의 61~64%가 반투명으로 번진다. 24/20/16px(정수 배)에선 0%. 캔버스에 글자를 그려 반투명 픽셀 비율을 세는 10줄짜리 스크립트로 확인할 수 있다.
- 한글: `body{line-height:1.65}`, 짧은 라벨·한 줄 문구는 `word-break:keep-all; overflow-wrap:anywhere`, URL은 `break-all`. 글자 12px 미만·굵기 400 미만 금지. 실 사용자에게 바로 나가는 화면이라 여기고 단추·라벨·말풍선 머리·`aria-label`·placeholder 에 이모지·꾸밈 기호를 쓰지 않는다 — 글자나 픽셀 아이콘만(못 불러오면 비우거나 글자, 개발용 화면은 예외, 모델이 쓴 말·출처 발췌는 그대로).
- 탭 타깃 44×44 이상, 카드 전체가 탭 대상. `<input>` 글자 16px(iOS 확대 방지). `:focus-visible` 2px 링. `user-scalable=no` 금지.
- 라벨은 최후 수단: "7번째 산책", "등불 3/8칸", "들른 곳 4 · 못 읽은 곳 1".
- 버튼은 동사로 1~2단어. 캐릭터의 선택에 확인/취소를 붙이지 않는다(사람이 승인하는 게 아니므로).
- 빈 상태는 캐릭터 목소리로 상태+다음 행동 한 줄. 🖼 같은 자리표시 글리프 금지.
- 토스트는 `<output aria-live="polite">` 하나, 2.5초. 로그는 `role="log" aria-live="polite" tabindex="0"`, 지난 날짜는 접는다.
- 좁은 화면의 상세는 바텀시트(드래그 핸들 32×4, 스크림, 44px 닫기 행, `env(safe-area-inset-bottom)`), ≥600px 은 가운데 다이얼로그. `<dialog>` 를 쓴다.
- 빛은 위에서: 버튼 윗선 밝게·그림자 아래, 입력칸은 살짝 인셋, 카드 테이프/핀은 위쪽.

## 4. 모션 수치 (복사해서 쓰기)

`assets/motion-tokens.css` 를 `:root` 에 붙인다. 요지:

- 누름 150ms / UI 250ms / 장면 500ms / 의식(하루 한 번 순간) 900ms. 들어올 땐 decelerate, 나갈 땐 accelerate 하고 **더 짧게**.
- `transform/opacity` 만 애니메이션. 그림자·블러·높이 애니메이션 금지. 재트리거되는 건 transition(중간에 되돌릴 수 있게), 한 번뿐인 의식만 keyframes 하고 `data-state` 로 중복 재생 방지.
- 누름 `scale(.97)`, 등장은 `scale(.95)+opacity 0` 에서(절대 `scale(0)` 에서 시작 금지), 목록 행은 `translateY(8px)` 60ms 스태거(최대 6행). **픽셀 테마에선 배율 대신 2px 이동**(아래 "자주 생기는 문제" 1).
- **예비 동작**: 떠나기 전 600ms 움츠림(`scaleY(.92) scaleX(1.05)`) + 200ms 정지 → 900ms 호 그리며 퇴장 → 작은 먹물 퍼프. 집에 있기로 하면 같은 움츠림이 `1.03` 오버슈트로 풀린다(같은 윈드업, 두 결말).
- 귀가 600ms + `scale(1.04)→1` 200ms 정착, 기록 행은 정착 250ms 뒤부터. 카드 걸기 500ms 상승 후 스티커 150ms 늦게. 등불 500ms + 8번째 칸 800ms 블룸, 소품은 등불 **200ms 뒤** 페이드(후속 동작).
- 캐릭터만 통통 튄다. 버튼·시트·로그는 바운스 없음.
- 주 버튼은 비활성 회색 대신 "다녀오는 중…" 알약으로 모핑(300ms), 2초 숨쉬기 opacity .7↔1.
- 앰비언트 반복 주기는 서로 안 맞게(예: 1.3/3.7/2.3/2.9초). 같은 주기 둘이면 방이 한 몸처럼 숨쉰다.
- `prefers-reduced-motion`: 줄이되 없애지 않는다. 이동/회전/스케일 → 크로스페이드, 비/패럴랙스 정지, 색 변화는 유지. JS 는 `matchMedia` 의 `change` 도 듣는다.
- 디버그: `?slow=4` → `--speed:4` 로 전부 느리게 보고 다음 날 다시 본다.

## 5. 엔지니어링

- `type="module"` 금지(file:// 에서 막힘). 전역 객체 몇 개(WORLD/BRAIN/APP)로 연결. 외부 의존성 0, 폰트만 Google Fonts + 시스템 폴백.
- 시드: `scripts/prng.js` (FNV-1a + mulberry32 + 로컬 날짜 키). 게임 로직에 `Math.random` 금지. 결과를 **출발 시점에 전부 계산**해 저장하고, UI 는 시간을 두고 공개만 한다 → 새로고침·탭 닫힘에 안전, 나중에 서버가 보낸 같은 형식의 이벤트를 재생할 수 있다.
- 저장: `localStorage` 키에 버전(`app_v2`), `try/catch`, 마이그레이션 함수, 옛 키는 지우지 않고 `_backup` 으로 이름만 바꾼다. 파생 화면(벽·앨범·로그)은 저장된 기록에서 매번 다시 그린다. 렌더 결과(SVG 문자열)를 저장하지 않는다.
- 진행 중 상태(`running`)가 저장돼 있으면 열자마자 즉시 마무리하고 "네가 없는 동안 다녀왔어".
- 카드 앞면은 SVG(저장 데이터만으로 재현), 뒷면은 HTML(링크 클릭). PNG 내보내기는 `document.fonts.ready` 뒤 SVG→canvas.
- 픽셀아트 장면: 고정 내부 해상도(320×240) + 정수 배 확대 + `image-rendering: pixelated`, 모든 스프라이트는 같은 픽셀 밀도, 이동은 게임픽셀 단위로 스냅. UI 글자는 픽셀 캔버스 밖에.
- 스모크 테스트: Playwright 로 "첫 실행 → 입력 → 주 버튼 → 건너뛰기 → 카드 1장 → **새로고침** → 그대로 → 카드 탭 → 뒤집기" 를 돌리고 스크린샷을 남긴다. 외부 fetch 는 `page.route` 로 성공/실패/중단 세 경우를 주입한다.

## 6. 작업 순서 (추천)

1. 설계 문서 한 장: 피드백 반영표 → 핵심 루프 → 진행표 → 캐릭터 두뇌 규칙 → 카드 앞/뒤 → 상태 스키마 → 이벤트 형식 → 모듈 계약. 이 문서가 병렬 구현의 계약서가 된다.

## 8. 한 방에 뽑는 지시문 형식 (LOOK / GAME / UI / QUALITY BAR)

"Island Grand Prix" 류의 바이브코딩 프롬프트가 잘 먹히는 이유는 문체가 아니라 **구조와 숫자**다. 장면 하나, 미니게임 하나를 에이전트에게 맡길 때 이 틀로 쓴다.

- 첫 줄에 산출물 형태를 못 박는다: 단일 HTML인지 모듈 파일인지, 라이브러리와 **정확한 버전/CDN 경로**(예: three.js r128 UMD, cdnjs), 빌드 없음, `<title>` 규칙.
- **LOOK**: 렌더 파이프라인을 수치로(렌더 타깃 픽셀 크기, 팔레트 색 수와 색공간, 디더 행렬, 외곽선 방식, 카메라 종류·각도·거리·far plane), 월드 크기(m), 기하 목록(무엇이 어디에, 몇 개), 조명 상태 전환, 드로우콜 예산.
- **GAME**: 엔티티 수와 생성 규칙, 상태 흐름(시작→…→끝), 물리/AI 규칙을 수치로, 예외 처리(끼임 복구, 겹침 해소), 기본값(예: 오토파일럿 ON).
- **UI**: 캔버스 위 HUD와 옆 패널의 항목 목록, 키·터치 매핑, 폰 레이아웃 규칙.
- **QUALITY BAR**: **검증 가능한** 합격 기준. 헤드리스 봇 테스트 수치, 콘솔 에러 0, 폰에서 가로 스크롤 없음, 스크린샷 산출. "돌아가고 스크린샷이 남아야 완성"으로 정의한다.
- 숫자가 없는 형용사("예쁘게", "부드럽게")는 그 자리에서 수치로 바꾼다. 모르면 범위라도("25~60초").

주의: 이 형식은 **장면/프로토타입 한 덩어리**를 뽑을 때 강하다. 결정적 로직(시드·저장·프로토콜)은 따로 모듈로 두고 지시문에 "건드리지 말 것"을 명시한다. 그리고 문서 30장보다 **먼저 돌려 보는 것**이 낫다(Claude Code Game Studios의 블라인드 리뷰에서 가장 무거운 문서 모드가 꼴찌였다): 설계 문서는 한 장, 나머지는 실행과 스크린샷으로 판단한다.

## 9. 그릴 게 없게: 절차적 3D + 픽셀 룩 (three.js)

손그림·블렌더 대신 three.js로 전부 코드로 만들고 후처리로 픽셀아트처럼 보이게 하면 에셋이 0이 된다. 레시피와 GLSL 조각은 `references/three-pixel-look.md`.
- r128 UMD(전역 `THREE`)를 `vendor/` 에 두면 file:// 과 오프라인에서도 돈다. 최신 ESM은 file:// 상대 import가 막힌다.
- 캐릭터는 원시 도형 조합(구 + 캡슐 다리)으로도 팔레트 스냅 + 외곽선이 셀 느낌을 만들어 준다. 다리는 짧고 통통하게(애니메이션·실루엣 둘 다 쉬움).
- 색은 사용자가 고르게 하고, 그 색에서 램프(하이라이트/밑면/그림자) 5단계를 만들어 팔레트에 넣는다.
- 조명은 실제 시계(로컬 시각)로: 새벽/낮/노을/밤 사이 60초 이징. 날씨는 날짜 시드.
- 포인터 레이캐스트로 쓰다듬기·두드리기·창문 보기 같은 소통을 넣되, 소통은 자원이 아니다(게이지·횟수·알림 금지, 거절에 시무룩 금지).
- WebGL 없을 때의 2D 폴백을 같은 API로 둔다. 컨텍스트를 잃었다가 안 돌아올 때도 같은 폴백으로 간다.

## 10. 하위 에이전트 브리핑과 토큰 절약 (요약, 근거는 references/delegation.md)

- 브리핑은 항상 **목표 · 산출물 경로 · 형식 · 멈추는 조건** 네 가지를 적는다. 모호하면 중복 작업과 구멍이 생긴다.
- **경로만 넘기고 본문을 붙이지 않는다.** 하위 에이전트는 내 대화를 못 보니 디스크를 가리킨다("README §2, src/x.js:1-80 먼저 읽어").
- **보고는 ≤10줄, 파일 내용·로그 금지.** 돌아온 글은 전부 내 컨텍스트가 된다.
- **검증 수단을 브리핑 안에** 넣는다: 돌릴 명령 + 남길 스크린샷/테스트. "다 통과했어요"는 증거가 아니다.
- 난이도별로 모델·에이전트 수를 정한다: 찾기/grep → 작은 모델 1개 5콜 · 파일 하나 기능 → 중간 모델 1개 · 설계/횡단 리팩터 → 큰 모델 2~4개 + 통합자 1명.
- 병렬은 **독립 작업만**, 파일 집합을 나눠 주고, 끝나면 통합자 한 명이 이음새를 고친다.
- 디스크에 있는 메모를 다시 조사하지 않는다. 시끄러운 일(웹 읽기, 긴 로그)은 깨끗한 컨텍스트의 에이전트에 보내 요약만 받는다.
- 오케스트레이터 자신은 `sed -n`/`grep`/`tail`로 조각만 읽고, 주제 바뀌면 `/clear`.
- 3콜 미만·파일 1개면 직접 한다. 두 번 고쳐도 안 되면 세 번째 잔소리 대신 브리핑을 다시 쓴다.
- 비용 감: 채팅 1× · 에이전트 1개 ≈4× · 멀티에이전트 ≈15×. 가치가 그만큼일 때만.

브리핑 뼈대: `CONTEXT(3줄) / DELIVERABLE(경로) / RULES(제약) / DONE WHEN(명령+산출물) / REPORT(≤10줄)`.

## 11. 룩 루프: 한 패스에 레버 하나, 그림으로 판정

원샷으로 "고퀄 픽셀아트 3D"는 안 나온다. 같은 앵글 스크린샷(낮/밤/클로즈업)을 전·후로 찍고 에이전트가 **직접 보고** KEEP/REVERT 를 적는 루프로 수렴시킨다. 레버 순서(중요도): 캐릭터 비율·크기(화면을 지배하면 먼저) → 밀도·구성(소품 40~80개, 빈 면 30% 미만) → 검증된 팔레트(Apollo 46 / Endesga 64 / Resurrect 64) → 조명 비율(따뜻한 키 1.5~3.3 vs 차가운 앰비언트 0.2~0.5, 밤은 별도 표) → 엣지(깊이 어둡게 ×0.6, 노멀 밝게 ×1.3, 접촉 그림자) → 디더·픽셀 스냅 → 저해상도 블룸 → 움직임.
- 메트릭을 같이 찍는다: 고유 색 수(≤ 팔레트+5), 엣지 픽셀 비율(2~8%), 평균 밝기, 드로우콜, 소품 수.
- 레퍼런스 이미지를 브리핑에 첨부하고 "따라 할 것 3개"만 적는다. 수치 없는 형용사는 쓰지 않는다.
- 사람 루프용 데브 패널(픽셀 크기·디더·외곽선·키/앰비언트·시각·팔레트·📷)을 둔다. 80→95%는 사람이 슬라이더 10분 돌리는 게 가장 빠르다.
- 못 가는 것은 미리 말한다: 절차적 3D 캐릭터는 "픽셀화된 3D 장난감"이 상한이고, 손으로 찍은 도트 애니메이션 질감은 2D 스프라이트에서만 나온다.

## 12. 놀이 우선과 모델의 뜻 (요약, 자세히는 references/model-voice-and-play.md)

- **처음 온 사람이 30초 안에 찌르고 웃는다.** 설명 없이 엄지 자리에 장난감 하나. 첫 톡에서 웃음까지 약 1.5초. 캐릭터가 먼저 놀자고 해도 된다(무시해도 시무룩 없음).
- **고르는 과정을 보여 준다.** 눈이 즉시(≤100ms) 향함 → 숨 고르기 1.0초 → 팔이 반쯤 다가감 → 멈춤 0.3~0.6초 → 잡기 또는 마음 바꾸기(고른 쪽이 `considered` 를 줬을 때만).
- **모델은 높은 수준의 행동 하나만 고른다.** 연출은 로컬. 결정은 상황이 가라앉을 때만, 판마다 start 1 + 갈림길 1 + 선택적 마무리 1. payload 는 약 500바이트(상한 1,200).
- **설명 의무 없음, 거절은 정상 응답.** 대사·메모·이유는 전부 선택. `stop` 은 늘 메뉴에 있고, 고르면 그대로 따른다.

## 자주 생기는 문제

| 증상 | 원인 | 고침 |
|---|---|---|
| 1. 픽셀 UI·스프라이트가 눌리거나 착지할 때 흐려진다 | `scale(.97)`·`scale(1.2)` 같은 정수 아닌 배율이 픽셀을 다시 샘플링한다 | 픽셀 테마에선 확대 대신 2px 이동(`:active{transform:translate(2px,2px)}`), 등장도 2px 계단(`steps()`). 글꼴 번짐은 §3 격자 규칙 |
| 2. 새 문구의 몇 글자만 다른 글꼴로 보이거나 늦게 뜬다 | 새 음절·기호를 넣고 서브셋 글꼴을 다시 안 만들었다(실제 사례: 주석의 '≠'). 서브셋 스크립트는 js·css·index.html 만 센다 | `python3 tools/subset-fonts.py --check` 가 `stale: none` 인지 보고, 아니면 다시 돌린다. 새 HTML 본문 글자는 JS 가 넣는다. 주석은 ASCII 만 |
| 3. 기기 '동작 줄이기'를 켰는데 계속 움직인다 | 축소 모션 규칙이 테마 규칙(`:root[data-font="pixel"] …`)보다 앞에 있거나 우선순위가 낮다. 또는 기본값을 빠뜨렸다(`:not([data-motion="auto"])`) | 축소 모션 블록을 CSS 맨 끝에, 테마와 같은 우선순위로. 기본값은 `:is([data-motion="auto"], :not([data-motion]))`. `page.emulateMedia({reducedMotion:'reduce'})` 로 테마마다 확인 |
| 4. iOS 사파리에서 눌림(`:active`)이 안 보인다 | iOS 는 터치 리스너가 없으면 `:active` 를 그리지 않는다 | `document.addEventListener('touchstart', function(){}, {passive:true})` + `touch-action: manipulation` |
| 5. 다른 앱을 다녀오면 장면이 까맣게 멈춘다 | `webglcontextlost` 에서 플래그만 세워 렌더 루프와 걷던 걸음이 멈춘다 | `e.preventDefault()`, 걸음은 즉시 도착 처리, 3초 안에 `webglcontextrestored` 가 없으면 2D 폴백. 테스트는 `renderer.forceContextLoss()` |
| 6. 불러온 기록에 가짜 '읽음'·엉뚱한 출처가 뜬다 | 가져온 이벤트의 상태와 출처를 그대로 믿었다(실제 사례: `javascript:` 주소에 '위키백과' 출처) | 불러온 이벤트도 검증을 다시 거친다. 못 읽는 곳은 `simulated`, 모르면 `failed`, 출처는 허용 도메인 https 만. 검증 뒤 저장, 실패하면 되돌림 |
| 7. 모델 연결 토큰이 터지거나 요청이 쌓인다 | 손가락 움직임·탭마다 모델을 불렀다 | 첫 반응은 로컬 ≤100ms. 결정은 손 뗀 뒤 1.0초, 상황이 가라앉을 때만. 대기 중엔 `dirty` 만. 판당 3번, 넘치면 로컬 `ponder` |
| 8. 새로고침하면 결과가 바뀌거나 진행이 사라진다 | 공개할 때 계산했다. `Math.random`·UTC 날짜 키를 썼다(`toISOString` 은 한국 오전 9시에 날이 바뀐다) | 출발 시점에 계산해 저장, `dateKey()` 로컬 날짜, 진행 중 상태는 열자마자 마무리. 스모크에 새로고침 단계 |
| 9. 탭 두 개를 열면 기록이 덮어써진다 | 탭마다 자기 사본을 통째로 저장한다 | 저장 직전에 다시 읽어 합친다. `storage` 이벤트로 다른 탭 변경을 받는다 |

## 예시

**1. 손맛.** 사용자: "탭할 때 손맛이 하나도 없어 ㅠ 통통 튀게 해줘"
→ 읽기: §4, `assets/motion-tokens.css` (수치 근거는 `references/motion-and-feel.md`)
→ 할 일: 버튼은 `scale(.97)` 150ms(픽셀 테마는 2px 이동). 통통은 캐릭터에만(`scaleY(.92) scaleX(1.05)` 움츠림 → `1.03` 오버슈트). transform/opacity 만. 축소 모션과 iOS `touchstart` 처리.
→ 결과: 토큰만 쓴 CSS 변경, 360px 스크린샷, `?slow=4` 로 본 확인 한 줄.

**2. 장난감.** 사용자: "문어랑 같이 놀 장난감 넣어줘. 공 굴리면 쫓아가게"
→ 읽기: 위 "중요", §12, `references/model-voice-and-play.md`
→ 할 일: 30초 안에 웃는 상황 하나(공 톡 → 받아치기). 반사는 로컬. 결정은 상황이 가라앉을 때만. 메뉴에 `watch`·`stop`. 기록 줄마다 `by`. 정직 줄 "데모 규칙이 고름 · 모델 아님".
→ 결과: 놀이 화면 + 테스트(첫 반응 ≤100ms, 판당 결정 ≤3, `Math.random` 0건, 무시된 초대 뒤 시무룩 없음).

**3. AI 표기.** 사용자: "뽈뽈이가 AI라는 거 화면에 어떻게 표시해? 진짜 사람처럼 보이면 안 될 것 같아"
→ 읽기: §2, `references/model-voice-and-play.md` §2·§6
→ 할 일: 늘 보이는 정직 줄, 기록 `by` 5종, 읽기 상태 4종, 모델이 쓴 말은 글자 그대로.
→ 결과: 화면 문구 제안 + 기록 스키마 + 자동 점검 목록(`references/model-voice-and-play.md` §9).
