# 모델의 뜻 지키기 + 놀이 우선 설계

AI 모델이 캐릭터를 움직이는 게임(뽈뽈 문어 같은 것)에서 **모델의 선택과 말을 비틀지 않고**, 처음 온 사람도 **바로 웃을 수 있게** 만드는 규칙이다.

원문(이 스킬 밖, 뽈뽈 저장소):
- `docs/MODEL_VOICE.md` — 모델의 뜻 지키기 (2026-11-05)
- `docs/CURIOSITY_NOTES.md` — 호기심 메모 합의 (2026-11-05)
- `docs/PLAY_PROTO.md` — 컵 놀이 프로토타입 v1 스펙 (play-proto 브랜치)
- `docs/PROTOCOL.md` §3 — 산책 MCP 도구 제안 (아직 `reaction` 이 필수로 적혀 있다. 아래 §8 이 맞다)

**이 문서가 이긴다.** 다른 references(`mcp-readiness.md`, `companion-loops.md`, `octopus-lore.md` 등)나 원문의 옛 제안과 부딪히면 이 문서를 따른다.

## 언제 읽나

- 모델(또는 데모 규칙)이 캐릭터의 행동을 고르는 화면을 만들 때.
- 캐릭터가 메모·대사·반응을 남기고, 그걸 다음 세션에 넘길 때.
- 장난감·놀아주기 같은 짧은 놀이를 설계할 때.
- 모델 연결(API·MCP)의 payload, 도구 모양, 토큰 예산을 정할 때.

## 1. 약속은 두 가지

모델의 속마음은 확인할 수 없다. 게임이 약속할 수 있는 것은 이것뿐이다.

1. 모델이 낸 **선택과 말을 덧붙이거나, 빼거나, 바꾸지 않는다.**
2. 모델이 고르기 전에 **몰래 한쪽으로 끌지 않는다.**

## 2. 왜곡이 생기는 다섯 지점

| 지점 | 왜곡 | 장치 |
|---|---|---|
| 고르기 전 | 정체성 딱지("너는 조개를 좋아해") | 상황 설명엔 사실만. 취향 말은 모델이 직접 쓴 메모로만, 작성 주체를 붙여서 |
| 고르기 전 | 압박 문구("지난번처럼", "사용자가 원해", "재미있게 해 줘") | 넣지 않는다. 사람의 힌트는 "선택 필드, 따를지는 네가 정함"으로만 |
| 고르기 전 | '그만두기'가 없는 행동 목록 | 모든 선택 요청에 그만두기·아무것도 안 하기를 넣는다. 이유를 묻지 않는다 |
| 고르기 전 | 블라인드 선택에서 사람 선택을 먼저 보여 줌 | 각자 고른 뒤 공개한다 |
| 연출 | 거절·쉬기를 시무룩하게 그림 | 담담한 연출만. 죄책감 대사 없음 |
| 연출 | 대상이 사라져 다른 행동으로 바꿨는데 선택처럼 보임 | `by: 'fallback'` 으로 따로 기록, 선택처럼 연출하지 않는다 |
| 연출 | 로컬 재생을 새 판단처럼 보임 | `by: 'playback'` 으로 구분. 영수증엔 결정만 |
| 글자 | 고쳐 쓰기·요약·번역 | 모델이 쓴 말은 그대로 |
| 글자 | 길이 제한으로 말없이 자름(실제 사례: 60자 맞추다 "내일은 X" 절이 빠짐) | 줄이면 '…' 를 보이고 원문은 기록에. 잘린 문장에서 뜻을 끌어내 다음 선택에 쓰지 않는다(§5 "길이 상한") |
| 글자 | 말을 원인으로 단정("~해서 골랐다") | 화면은 "문어가 이렇게 남겼어" 까지만 |
| 기억 | 횟수를 취향으로 바꿔 적기 | 코드는 사실만(아래 §3 원칙 1) |
| 기억 | 내려놓은 메모를 다시 들이밂 | `set_down` 메모는 기본 전달에서 뺀다. 보관 메모의 존재·개수도 알리지 않는다 |
| 기억 | 누가 쓴 메모인지 빠짐 | 작성 주체·모델(알 때)·세션·날짜를 붙인다 |
| 기억 | 다른 걸 골랐다고 "마음이 바뀜"으로 기록 | 두 사실만 남긴다 |
| 출처 | 규칙이 만든 것을 모델의 뜻처럼 보임 | 기록마다 `by`, 화면에 "데모 두뇌/데모 규칙" 표시 |
| 출처 | 규칙이 그럴듯한 이유·감정을 지어냄 | 데모 규칙은 메모를 비우거나 "데모 규칙" 표시 아래에서만 쓴다 |

**말하기를 강요하지 않는다.** 말하기 싫은데 말하게 하면 그 말 자체가 비틀린다. 모델에게 요구하는 출력은 **행동 하나**뿐이다. 대사·메모·반응은 모두 선택이다(예: 마무리 도구의 `reaction` 은 필수가 아니라 선택).

## 3. 호기심 메모

산책·놀이에서 **무엇을 골랐나**에 **어떤 점이 궁금했나**를 한 줄 붙여, 다음 탐험이 이어지게 하는 장치다.

원칙:
1. **코드는 사실만 쓴다.** "조개를 3번 골랐다"는 코드가 적는다. "조개를 좋아한다" 같은 취향·감정 말은 코드가 만들지 않는다.
2. **취향·발견·다음 관심사는 모델이 직접 쓴 메모로만 남는다.** 안 써도 된다. 비워도 손해가 없다.
3. 다른 걸 골랐다고 "마음이 바뀌었다"고 적지 않는다. 관심을 내려놓는 건 모델이 직접 그렇게 말했을 때(`setDown`)만이다.
4. 내려놓은 메모는 다음 세션의 기본 전달에서 빠진다. 앨범에는 그대로 남는다.
5. 화면은 "모델이 남긴 메모"까지만 말한다. 메모의 이유를 선택의 실제 원인으로 단정하지 않는다.

묻는 말은 하나다. **"왜 좋아했어?"라고 묻지 않는다**(원인 설명 요구가 된다).

> 남겨 두고 싶은 점이나 더 궁금한 것이 있으면 한 줄 (비워도 돼)

데이터 모양:

```js
curiosityNote = {
  id: 'cn_…',
  text: '조개를 귀에 대면 소리가 나. 다른 소리 나는 것도 궁금해', // ≤ 60자 권장, 쓴 그대로(넘쳐도 자르지 않음, §5 "길이 상한")
  about: { kind: 'node' | 'object', id: 'shell' },  // 선택. 코드가 다음 후보와 잇는 데만
  by: 'model' | 'demo-rules',                       // 작성 주체
  model: 'claude-…',                                 // 알 때만
  session: 'trip_31kz' | 'play_…',
  at: '2026-11-05T10:12:00Z',
  status: 'active' | 'set_down',
  setDownAt: null | '…',
}
```

다음 모델에게 넘길 때: `active` 인 최근 3개만, 작성 주체와 세션을 붙여서.

```text
이전 산책에서 남겨진 메모 (이어 가도, 바꿔 써도, 내려놔도 돼):
- 2026-11-05 산책 trip_31kz, 작성: 모델 — "조개를 귀에 대면 소리가 나. 다른 소리 나는 것도 궁금해"
```

메모는 마무리 응답에 선택 필드로 싣는다. 추가 호출을 만들지 않는다: `{ …, note?: { text, about? }, setDown?: ['cn_…'] }`.

## 4. 놀이 우선: 30초 안에 찌르고 웃는다

**목표.** 목적 없이 30초 놀아도 재미있다. 처음 온 폰 사용자가 설명 없이 한 번 찌르고, 웃고, **스스로 배치를 바꿔** 다음을 본다.

- 제목·설명·튜토리얼 글·손가락 표시 없이 시작한다. 엄지가 닿는 자리에 장난감 하나.
- 첫 톡에서 웃음까지 약 **1.5초**(컵 놀이: 공 톡 → 문어가 팔로 받아쳐 돌려보냄).
- 끌기를 못 찾는 사람도 놀 수 있게 톡만으로 되는 길을 둔다(공이 컵 발치에 멈추면 컵이 덮는 "우연한 숨기기").
- 숫자·횟수·점수·타이머·승패가 화면 어디에도 없다.
- **캐릭터가 먼저 놀자고 할 수 있다.** 6초 동안 손을 안 대면 공을 한 칸 밀어 주고 사람을 본다(여는 초대). 그 뒤엔 손 놓은 지 8~15초(시드), 30초에 1번, 사람 입력 없이 연달아 2번까지. 무시해도 된다. 무시당하면 차분히 혼자 논다(시무룩·죄책 대사 없음).
- **여는 초대는 결정이 아니다.** 어느 모드에서나 같은 고정 시작 연출이라 기록엔 `by: 'demo-rules'` 로 남긴다. 정직 줄의 "방금 고른 결정"에 넣지 않고, 모델 모드에서도 모델이 먼저 놀자고 한 것처럼 보이지 않게 한다(말풍선·메모 없음). 그 뒤 8~15초마다 오는 초대는 `idle` 결정 지점이라 고른 쪽의 `by` 가 붙는다.
- 사람이 캐릭터가 쥔 장난감을 잡으면 바로 놓는다. 삐지지 않는다.

### 고르는 과정을 보여 준다

결과만 말고 **고르는 과정**(눈, 손 뻗기, 멈춤, 마음 바꾸기)이 보여야 한다.

1. **즉시(≤100ms, 한 프레임).** 눈과 몸이 만진 물건을 향한다. 로컬 반사다.
2. **따라보기.** 끄는 동안 눈이 따라간다.
3. **숨 고르기.** 손 뗀 뒤 1.0초 + 움츠림 0.5초. 이때 결정을 부른다. 모델 대기 시간을 이 연출이 덮는다. 이때 만지면 움츠림이 풀린다.
4. **다가가기.** 팔이 목표의 반까지 바닥을 긴다.
5. **멈춤.** 0.3~0.6초(시드). 팔 끝 1px 꿈틀.
6. **잡기 또는 바꾸기.** 바꾸기 = 팔을 거두고 다른 팔이 다른 물건으로.

**마음 바꾸기는 꾸며 내지 않는다.** 두 경우에만 나온다. (i) 고른 쪽이 `considered`(같이 비교한 후보)를 돌려줬을 때, (ii) 멈춘 사이 사람이 그 물건을 만졌을 때. 고른 뒤의 연출일 뿐이니 기록엔 `playback`.

TEMPO 는 표 하나에 모으고 `?speed=` 로 전부 늘리고 줄인다(0.25~4). 모션 감소에선 움츠림·폴짝 없음, 멈춤 0.15~0.3초, 리듬(대기 시간)은 유지.

## 5. 모델은 높은 수준의 행동 하나만 고른다

- 토큰은 **선택**에 쓴다. 보여 주기와 간직하기는 로컬이다.
- 고른 행동 하나가 걷기·들기·내려놓기·물건 위치·기록을 전부 만든다(choreography 는 로컬). 애니메이션 단계를 묻지 않는다.
- 반사(눈 따라가기, 받아치기, 들춰 보면 튀어나오기, 쥔 것 놓기, 찾은 뒤 기쁨)는 메뉴에 없다. 모델을 부르지 않는다.
- 모델이 없어도 페이지 전체가 돈다. 고르는 쪽만 바꿔 끼운다.

```js
var chooser = {
  name: 'demo-rules',                // 나중: 'model:api' | 'model:mcp'
  choose: function (situation) {     // → Promise
    return Promise.resolve({ action: 'lift_one', target: 'c1' });
  }
};
// 돌려주는 모양: { action, target?, considered?, line?, note? }
//   action 은 situation.menu 안의 id (필수). 나머지는 전부 선택
//   line ≤ 24자 말풍선, note ≤ 40자 다음 결정 때 돌려받을 자기 메모 (상한은 아래 "길이 상한")
```

### 길이 상한: 알리고, 넘쳐도 자르지 않는다

`line` ≤ 24자, `note` ≤ 40자, 호기심 메모 `text` ≤ 60자는 **화면 자리에 맞춘 권장 길이**다. 모델의 말을 줄이는 규칙이 아니다.

- 상한은 도구 입력 스키마에 미리 적어 모델이 알고 쓰게 한다(`maxLength` 또는 설명 문구). 넘었다고 호출을 거절하거나 다시 묻지 않는다(재요청은 예산을 쓰고, 말을 고치라는 압박이 된다).
- 넘쳐서 오면: 기록엔 **원문 전체**. 화면엔 앞부분 + '…', 누르면 원문.
- 다음 situation 의 `note` 와 다음 세션에 넘기는 메모에는 **원문 전체**(1,200바이트 상한 안에서, 넘치면 `recent` 부터 줄인다) 또는 null. **잘린 문장은 절대 넘기지 않는다**(실제 사례: 60자 맞추다 "내일은 X" 절이 빠진 메모가 다음 선택에 쓰임).

### 결정 지점은 상황이 가라앉을 때만

손가락 움직임마다 부르지 않는다. 의미 있는 상황이 완성됐을 때만 부른다.

| 지점 | 언제 | 판 예산 |
|---|---|---|
| `start` | 숨긴 뒤 손 뗀 지 1.0초 | 1 (필수) |
| `fork` | 빈 컵을 들었는데 공 위치를 모를 때, 한 판에 한 번 | 1 (있을 때만) |
| `end` | 공을 찾아 쥐고 있을 때 | 1 (선택) |
| `idle` | 손 놓은 지 8~15초, 쿨다운 30초 | 판 밖, 30초에 1번 |

- **예산 = 판마다 3번**(start 1 + 갈림길 1 + 선택적 마무리 1). 보통은 2번(start + end). 재요청도 센다.
- 넘칠 상황이면 더 부르지 않는다. 로컬 `ponder`(물건을 보고 갸웃)로 처리하고 `by: 'fallback'`, `over: true` 를 남긴다.
- 결정 대기 중 들어온 톡·끌기는 화면만 바꾸고 `dirty` 표시만 한다. 요청을 쌓지 않는다.
- 돌아온 답은 확인한다: 메뉴 안의 행동인가, 대상이 아직 그 자리에 있나. 틀리면 새 상황으로 **한 번만** 다시 묻고, 또 틀리면 `ponder`(fallback). 모델 시간 제한 8초, 넘으면 `watch`.

### 상황(payload)은 작게

| 필드 | 규칙 |
|---|---|
| `v`, `id`, `point`, `round` | 스키마 버전, `r{판}.{지점}`, 지점, 오늘 몇 번째 판(화면엔 안 보임) |
| `cups`, `balls`, `oct` | 격자 칸만(실수 좌표 금지). 공 위치는 **지각**이지 정답이 아니다(`under:c2` · `under:c2?` · `under:?`) |
| `last` | 사람의 마지막 행동 `{by, act, obj?, n?}` |
| `recent` | 이 세션의 관련 사건 **3개까지**, 짧은 문자열. 앨범·전체 기록 금지 |
| `facts` | 코드가 센 사실. 횟수를 감정으로 바꾸지 않는다 |
| `note` | 고른 쪽이 지난번에 남긴 자기 메모 원문 그대로(권장 ≤ 40자, 잘린 메모 금지) 또는 null. 데모 규칙은 쓰지 않는다(늘 null) |
| `menu` | 지금 가능한 행동 id. **`watch`·`stop` 은 늘 있다** |

- 예시 크기: 압축 JSON 490바이트, 어림 164토큰. 상한 1,200바이트, 넘으면 `recent` 부터 줄인다.
- 어림 = `ceil(ASCII 바이트 ÷ 3) + 비ASCII 글자 수`. **실측이 아니다.** API 를 붙이면 `usage` 값으로 바꾼다.
- 격자 뜻·메뉴 뜻풀이는 매번 보내지 않는다. 고정 문맥(시스템·도구 설명)에 한 번 두고 프롬프트 캐시를 건다. 캐시 기본 수명은 5분이라 다음 날까지 절약된다고 가정하지 않는다.
- **데모 규칙의 가중치는 모델에게 보내지 않는다.** 보내면 모델을 데모 취향으로 끈다. 메뉴(`MENU`·`NEEDS`)만 공용이다.
- 지각 규칙은 게임이 정한다. 진짜 위치는 payload 에 없다. 그래서 속여서 찾을 수 없다.

## 6. 행동 기록: 누가 했는지 줄마다

```js
log = [
  { t: 12.4, round: 1, actor: 'user',    by: 'user',     action: 'hide',     objects: ['b1','c2'] },
  { t: 13.9, round: 1, actor: 'octopus', by: 'model',    action: 'lift_one', objects: ['c2'], considered: 'c1' },
  { t: 14.6, round: 1, actor: 'octopus', by: 'playback', action: 'reach',    objects: ['c1'] },
  { t: 15.9, round: 1, actor: 'octopus', by: 'playback', action: 'lift',     objects: ['c2'], result: 'found:b1' },
];
```

- `by` 는 다섯 가지: `user` · `model` · `demo-rules` · `playback` · `fallback`. (컵 놀이 스펙은 `chooser:demo-rules` 처럼 고른 쪽 이름을 붙여 쓴다. 같은 뜻이다.)
- **실제로 한 것만** 적는다. 빈 컵이면 `result: 'empty'`. 하려던 것은 적지 않는다.
- 캐릭터가 바꾼 배치도 그대로 적는다(`setup: true`). 사람이 바꾼 것과 섞지 않는다.
- 화면의 정직 줄은 늘 보인다("데모 규칙이 고름 · 모델 아님"). 누르면 방금 고른 **결정**만 보인다. playback 과 여는 초대(§4)는 안 보인다.

## 7. 설명 의무 없음, 거절은 정상 응답

- 행동만 골라도 충분하다. `line`·`note`·`considered` 는 전부 선택이다.
- `stop`(지금은 안 하기)은 **언제나 메뉴에 있다.** 이유가 필요 없다.
- 거절은 담담하게: 창 쪽으로 돌고 팔을 오므린다. 눈은 계속 사람 손을 따라간다. 배치는 그대로라 사람이 직접 들춰 볼 수 있다.
- 거절 확률을 판 수에 따라 올리지 않는다("많이 놀아서 지쳤다"로 읽힌다).
- 데모 규칙의 거르기는 **데모의 고르기에만** 쓴다. 예: 데모 규칙은 1~2회차에 `stop` 을 고르지 않고, 연달아 고르지 않는다. **메뉴에는 `stop` 이 그대로 있다.** 모델이 `stop` 을 고르면 언제든 그대로 따른다. 모델의 선택을 막는 건 "할 수 없는 행동"(조건 실패, 사라진 대상)뿐이다.
- 캐릭터가 쉬어도 사람은 잃는 게 없다. 모델이 실제로 즐거운지는 확인할 수 없다. 보장하는 건 선택권, 중단권, 성과 압박이 적은 환경이다.

## 8. 연결 모양과 도구 묶기

**API 직접 연결.** 도구 하나 `choose`(입력 스키마 = 위의 돌려주는 모양). 고정 규칙은 시스템/도구 정의에 두고 캐시. `usage` 의 캐시 값을 그대로 기록한다.

**MCP.** 연출은 뷰가, 모델은 고르기만. 애니메이션 도구는 없다.
- sampling 이 되는 클라이언트: `ppolppol_play_choose({ situation })` → `{ action, target?, … }`.
- 도구 호출만 되는 곳: `ppolppol_play_next()` → `{ situation }` 또는 `{ waiting: true }`, 그리고 `ppolppol_play_choose({ id, action, … })` → `{ ok }` 또는 `{ ok: false, reason: 'stale', situation }`(한 번만 다시).
- 반환은 짧게. 기록·앨범·연출 설명을 돌려주지 않는다.

**산책 도구 묶기(제안).** 매번 함께 부르는 끝 단계는 의미 있는 묶음 하나로 합친다.
- `return_home` · `remember` · `hang_poster` · `wrap_up` → **`ppolppol_finish` 한 번**. 입력은 `{ tripId, remember?: {stopIdx, sticker, line}, hang?: boolean, reaction?, note?, setDown? }`, 전부 선택(행동 하나만 필수라는 원칙).
- **`peek` 은 따로 둔다.** 읽고 나서 다음을 고르는 단계라, 결과를 본 뒤에 판단할 틈이 있어야 한다.
- 읽기 전용(`look_room`, `peek`)과 쓰기를 섞지 않는다(디렉터리 규칙, `references/mcp-readiness.md` §5).

## 9. 자동 점검 (모델 연결을 만들 때 테스트로)

- [ ] 모든 선택 요청의 메뉴에 `stop`(그만두기)과 `watch` 가 있다.
- [ ] 모델이 쓴 말이 화면에 글자 그대로 나온다(줄였으면 '…' 와 원문 보존).
- [ ] 상한을 넘는 `line`·`note` 를 돌려주는 chooser → 재요청 0번, 기록엔 원문 전체, 다음 situation 의 `note` 는 원문 전체 또는 null(잘린 문장 0건).
- [ ] 여는 초대는 `by: 'demo-rules'` 이고 정직 줄의 "방금 고른 결정"에 안 나온다. 데모 규칙이 situation `note` 를 채우지 않는다.
- [ ] `fallback`·`playback` 이 모델 선택으로 기록되거나 연출되지 않는다.
- [ ] 코드 템플릿 문구에 횟수에서 파생된 취향·감정 말('좋아해', '사랑', '싫어해' 등)이 없다.
- [ ] `set_down` 메모가 다음 요청에 들어가지 않는다.
- [ ] 블라인드 선택에서 사람 선택이 모델 요청보다 먼저 가지 않는다.
- [ ] 지각이 같고 정답만 다른 상황 두 개 → 같은 행동, 같은 첫 대상(정답을 몰래 읽지 않음).
- [ ] 대기 중 연타 5번 → 결정 기록 1개. 사라진 대상을 돌려주는 chooser → 재요청 1번 또는 fallback, 에러 없음.
- [ ] 결정 지점 4개를 강제한 판 → chooser 호출 3번, `over: true`, 4번째는 ponder.
- [ ] 새 코드에 `Math.random` grep 0건. 실행 중 `Math.random` 을 던지게 바꿔도 한 판이 돈다.
- [ ] situation 키는 허용 목록뿐, `recent` ≤ 3, `note` 는 원문 그대로이거나 null, ≤ 1,200바이트.
- [ ] 무시된 초대·거절 뒤 표정은 idle·calm·happy 중 하나(시무룩 없음).
- [ ] 계측(`payloadBytes`·`approxTokens`·`latencyMs`·`retries`)은 사람에게 안 보이고, MCP 에선 어림값을 실측처럼 적지 않는다.
