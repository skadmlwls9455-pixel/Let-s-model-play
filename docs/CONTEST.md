# 주말 콘테스트 (11-21, 7차 F 갈래)

주인: "주말마다 콘테스트가 열려서 캐릭터 옷 도감 입고 패션 콘테스트 나가면 주제랑 요소에 맞게 점수 받아서 우승하면 조개 받는 식."

규칙은 `js/contest.js` (전역 `CONTEST`, DOM · 시계 · 난수 없음), 화면은 `js/app.js` 의 `[7-F]` 자리 (`#contest-sheet`), 검사는 `tools/test-contest.js` · `tools/test-contest-live.js`.

## 꾸미기 심사 놀이들이 점수를 매기는 방식 (원리만)

옷 입히기 놀이와 꾸미기 심사가 있는 게임들, 공개된 옷 입히기 코드들을 훑어 보면 채점은 거의 같은 뼈대다.

- **주제가 먼저 나온다.** 회마다 주제 하나 (계절 · 장소 · 분위기) 가 걸리고, 그 주제가 바라는 속성 두세 개가 정해져 있다. 주제를 그림과 짧은 제목으로 먼저 보여 주면 점수를 받고 나서야 기준을 아는 일이 없다.
- **옷마다 속성 꼬리표가 붙는다.** '귀여운 · 멋진 · 단정한' 같은 느낌과 색 계열. 입은 것 하나하나에서 주제와 맞는 꼬리표를 세어 더한다 (칸마다 상한을 두어 한 벌이 다 하지 않게).
- **한 벌로 맞춘 덤.** 입은 것들이 같은 느낌으로 모이면 덤을 준다. 주제와 달라도 준다 — 제 취향대로 맞춰 입은 것도 값이 있다.
- **색.** 주제 색 계열을 따로 센다. 물들이기처럼 손이 간 것은 작은 덤.
- **심사와 경쟁자.** 심사 몇이 칸 하나씩을 맡아 그림 카드로 보여 주고, 같은 규칙으로 채점된 경쟁자 몇과 등수를 가른다. 경쟁자는 그 회의 주제를 어느 정도 맞춰 입고 나온다 (센 · 중간 · 가벼운).
- **지지 않는 쇼.** 아늑한 쪽 게임들은 꼴찌에도 참가 보상을 주고, 감점 · 탈락 · 한정 보상을 두지 않는다.

이 게임에 옮기면서 뺀 것: 뽑기 옷 · 등급 · 기간 한정 주제 · 남은 시간 · 연속 참가 덤 · 순위표 (COMMON 4번 선). 다른 게임의 이름 · 그림 · 배치 · 주제 이름은 가져오지 않았다.

## 주와 주제

- 주 = 월요일 날짜 키 (`CONTEST.week(dateKey)` → `{ key, open, theme }`). 기기 달력으로 토 · 일에만 `open`.
- 주제 열둘. 네 개씩 세 묶음을 묶음 안에서만 시드로 섞는다 (12주에 한 바퀴) → 같은 주제는 적어도 9주 뒤에 다시 나온다. 주제는 돌아오므로 놓쳐서 영영 못 하는 것이 없다.
- 평일에는 주제 · 내 차림 · 옷 갈아입기만 보이고 '주말에 열려.' 한 줄 (날짜 · 남은 시간 없음).

## 채점 (`CONTEST.score(worn, theme, seed)` → 0..100)

더하기만 있다. 무엇을 더 입거나 물들여도 점수가 내려가지 않는다 (`tools/test-contest.js` 3 — 2000 번).

| 칸 | 점수 | 상한 |
|---|---|---|
| 무대 (나가기만 해도) | 8 | 8 |
| 주제: 입은 것마다 맞는 꼬리표 하나에 8 (한 벌에 16까지) | | 56 |
| 색: 주제 색인 것 (또는 주제 색으로 물들인 것) 마다 6 | | 18 |
| 어울림: 같은 느낌 꼬리표가 둘이면 6, 셋 이상이면 12 | | 12 |
| 물들임: 주제 색으로 물들인 것이 하나라도 있으면 | 6 | 6 |

같은 주 · 같은 차림은 늘 같은 점수다 (시드는 동점 순서에만 쓴다). 심사 카드 셋 (주제 · 색 · 어울림) 은 칸 점수를 별 1 ~ 3 으로 바꿔 든다 — 가장 낮아도 별 하나.

## 경쟁자 · 등수 · 조개

- 경쟁자 셋은 그 주의 시드로 옷 목록 (`APP.wardrobe()`, 그냥 있는 옷과 가게 옷 모두) 에서 칸마다 하나씩 뽑는다. 주제에 맞는 것을 고를 확률이 0.8 · 0.55 · 0.3 이다. 같은 `score` 로 채점한다. 한 주 내내 같은 셋.
- 등수 = 나보다 높은 경쟁자 수 + 1 (동점은 내가 앞). 조개 12 · 8 · 5 · 3 — 누구나 받는다.
- 열린 날마다 한 번 (토 · 일 따로). 그날 다시 열면 적힌 결과 그대로 (다시 뽑지 않는다, 옷을 바꿔도).
- 조개는 나가는 순간 한 번 (`paid`). 쇼를 넘기거나 닫아도 같다.

## 정직

- 채점은 규칙이다: 결과 줄에 '채점 규칙' 꼬리표. 심사 문어 (가게 문어 셋 — `NPC` 명단이 있으면 이름과 색) 는 그림 카드만 든다. 말 · 마음 · 평가 글이 없다.
- 경쟁자는 이름 없는 마을 문어 그림자다. 다락 문어는 나오지 않는다.
- `APP.npcSay` 가 있으면 열린 날 처음 열 때 `('clothes', 'contest.open', { theme })`, 결과가 보일 때 `('clothes', 'contest.result', { rank, shells })` 를 한 번씩 부른다 ('대본' 표시는 N 갈래의 말상자가 한다). 없으면 아무것도 띄우지 않는다.

## 저장 (`S.user.contest`)

```
{ v: 1, weeks: { '<월요일 키>': { theme, days: { '<날짜 키>': { v, at, theme, total, parts, rank, shells, paid, look, rivals } } } } }
```

- `CONTEST.normalize(user)`: 없거나 깨진 칸만 기본값, 모르는 값은 그대로. `CONTEST.merge(a, b)`: 두 탭 — 주 · 날을 합치고, 같은 날이 둘이면 조개를 준 쪽 (둘 다면 먼저 나간 쪽).
- 두 탭: 나가기 직전에 저장소를 다시 읽어 다른 탭이 이미 나갔으면 그 결과를 보여 준다 (조개는 한 번). 다른 탭의 옛 저장이 이 탭의 기록을 덮으면 기록과 그때 받은 조개를 함께 다시 얹는다.
- 그날 기록 칸 (오늘 · 앨범 일기) 에 '콘테스트 N등 · 조개 M' 한 줄 (`dayRows` 가 `ctDayRows` 를 부른다).

## 다른 갈래와 닿는 곳

- P (옷 목록): 입은 것은 `APP.wearing()` 에 `APP.wardrobe()` 의 본디 꼬리표를 합쳐 읽는다 (물들여서 잃는 것이 없게; `wearing` 이 없으면 `worn` 표시). 경쟁자 옷 그림은 `APP.itemThumb(cat, id, 32)`. 꼬리표 달린 옷 목록이 없으면 무대 단추와 `APP.openContest()` 는 아무것도 하지 않는다.
- V (무대 단추): `#btn-plaza-stage` 누름. 없으면 넘어간다. 2D 장면에서는 열리지 않는다.
- N (명단 · 대본): `NPC.roster` 의 `clothes` · `goods` · `cafe` 이름 · 색, `APP.npcSay`.
- 조개: 기존 놀이 보상 함수는 판마다 2 ~ 8개로 고정이고 달리기 과제를 표시하므로 쓰지 않았다. 주간 선물과 같은 방식 (`userState()` → 더하기 → `save()` → `renderBagChip()`) 으로 준다.
