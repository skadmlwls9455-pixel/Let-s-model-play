# 포스터 픽셀 그림 (POSTER_ART)

> 11-10. 포스터 앞면에 붙던 위키 사진이 픽셀 장면과 따로 놀았다 (주인 11-10). 사진 자리에 **그 방(세부 주제)의 픽셀 그림**을 붙인다.
> 방 66장 + 주제 9장 (+ 쪽지 8장 · 배경 9장). 32×32, Apollo 팔레트. 지금 그림은 넷째 판 (형태 음영 렌더러) 이다.

## 무엇이 바뀌나

- 포스터 앞면 (`js/app.js` `posterSVG`): `POSTER_ART.svg(trip, …)` 가 그림을 주면 그것을 사진 칸 가운데에 **정수 배**로 놓는다 (300px 포스터 = ×4 · 600px 저장본 = ×8). 그러면 사진과 '사진: 위키미디어 공용' 줄은 앞면에서 빠진다.
- 읽은 글 · 출처 링크 · 사진 출처는 **일기(뒷면)에 그대로** 남는다. 저장 데이터(`poster.thumb`)도 안 건드린다.
- `js/poster-art.js` 가 없거나 못 읽으면 예전처럼 사진을 붙인다 (설정 › 화면 › 포스터 썸네일은 그때만 쓰인다).
- 작은 포스터(벽 · 앨범 카드 · 날아가는 포스터)는 예전에도 사진이 없었고 지금도 그림을 안 붙인다 (32px 보다 작아서 뭉개진다).

## 포스터가 비어 보이던 것 채우기 (11-10 둘째 판)

앞면은 장면(위 56%) + 한 줄 글 + 맨 밑 날짜뿐이라 글과 날짜 사이가 통째로 빈 종이였고, 장면 배경은 임시 벡터 그림이었다. 셋을 더했다:

| 무엇 | 어디 | 어떻게 |
|---|---|---|
| **주제 배경 9장** | 장면 칸 전체 | 66×56 픽셀 배경 (`sceneSvg`). 장면 칸이 300px 포스터에서 264×224 라 정확히 ×4. 임시 벡터 장면(`assets/scenes/*.svg`)과 흐린 도형 대신. 작은 포스터(mini: 벽·날아가는 포스터)는 예전 그대로 색 띠 |
| **들른 곳 줄** | 한 줄 글과 날짜 사이 | 그날 들른 정류장의 그림을 **들른 순서대로** 놓고 점 둘로 잇는다 (`trailSvg`). 기억한 곳 밑에 빨간 작은 표시, 못 읽은 곳(문 앞까지만 · 못 읽음 · 앉아만 있음)은 흐리게. 글이 한 줄이고 다 들어가면 64px, 아니면 32px. 넘치면 앞에서부터 + 점 셋 (기억한 곳은 꼭 보인다). 정류장이 한 곳뿐이면 안 그린다 (큰 그림과 같아서) |
| **쪽지 그림 8장** | 집에 있던 날 쪽지의 장면 가운데 | 그날 집 활동(`receipt.activity.id`)을 하는 문어: 빗방울 세기 · 낮잠 · 창밖 보기 · 이끼 화분 · 포스터 다시 읽기 · 포스터 자리 바꾸기 · 흥얼거리기 · … (아무것도 안 함). 모르는 활동이면 안 붙인다 |

들른 곳 줄은 일기(뒷면)의 정류장 목록과 같은 데이터다 — 새로 지어내는 것이 없다. 읽기 상태의 정확한 말(읽음 · 책장 메모 · 모의 방문 · 못 읽음 · 앉아만 있었음)은 여전히 일기가 말하고, 앞면은 '읽었다 / 못 읽었다' 만 흐림으로 가른다.

미리보기: `tests/evidence/poster-art/scenes.png` (배경 9장) · `posters.png` (여러 경우) · `real-poster.png` · `album.png` (진짜 산책으로 만든 포스터).

## 넷째 판 (11-10): 그리는 법을 바꿈 — 형태 음영 렌더러

첫 판 그림(붓으로 도형에 색칠)은 음영이 대각선 하나로 갈려 평평했고 외곽선 무게가 색마다 달랐다 (주인: "좀 구리다").
두 가지를 해 봤다:

1. **자동 마감** (실루엣 가장자리를 한 단계 밝게/어둡게 + 진한 외곽선) — 버렸다. 덩어리 큰 그림은 조금 볼록해졌지만 열쇠·벌집처럼 얇은 그림은 오히려 지저분해졌다.
2. **형태 음영 렌더러** (`tools/ui-art/sculpt.js`) — 채택. 그림을 '부품'으로 짓는다. 부품마다 형태가 칸마다 면의 방향을 주고, 렌더러가 빛(위·왼쪽·앞)과의 각도로 그 재질 램프의 다섯 단계 중 하나를 고른다.

기존과 새 그림을 번호·이름표와 함께 나란히 보고 (`tests/evidence/poster-art/compare/` — 그때의 기록) 주인이 골랐다: **새 방식 · 같은 크기(32px)** 로 83장 전부. 두 배 촘촘한 64px 판도 만들어 봤지만 쓰지 않는다 (큼직한 픽셀이 더 귀엽다).

| 렌더러가 하는 일 | |
|---|---|
| 형태 → 음영 | 공(`ball`)은 초승달 그늘, 관·고리(`solid` + 거리 함수, bevel = 반지름)는 긴 하이라이트, 판(`solid`, bevel 1 안팎)은 모서리만, 돌림체(`lathe`: 병·종·컵·탑)는 가로로 도는 음영 |
| 반짝이는 재질 | 빛이 튀는 자리에 작은 흰 점 (`spec`) |
| 겹침 | 위 부품이 아래 부품에 1px 그림자 (오른쪽·아래) |
| 외곽선 | 닿은 재질의 가장 어두운 색 (`MAT.*.ol`) — 무게가 일정하다. 단색 무늬는 밑 덩어리의 외곽선을 따른다 |
| 단색·한 칸짜리 | `flat`(무늬·눈) · `stroke`(선, 1px 이상) · `grid`(글씨처럼 칸을 직접 찍기) · `spark`(칸에 맞춘 십자 반짝) |
| 진짜 곡면 | `lib.surface` — 매개변수 곡면을 깊이 버퍼에 찍는다 (매듭 이론의 세잎 매듭 관 · 뫼비우스 띠) |

32px 에서 배운 것 (그림을 더할 때 지킬 것):

- 반짝은 `spark` 로 (비스듬한 마름모는 찌그러진다). 작은 물방울은 덩어리 말고 `lib.dot` (덩어리로 그리면 검은 점이 된다).
- 글씨·규칙적인 점(한글 '한' · 점자)은 돌리지 말고 `grid`·정수 좌표로 (돌리면 칸이 흐트러진다).
- 칸 무늬(소수의 타일)는 칸 가운데에 맞춘다: 가운데 x.5 + 반 너비 2.4 = 5칸 타일 + 1칸 틈.
- 한 그림에 큰 덩어리 하나 + 작은 것 하나까지. 빽빽하면 (주판 대 다섯 → 넷) 줄인다.
- 문어는 `lib.oct` (레퍼런스 그림: 둥근 머리 · 흰 테 눈 · 주황 빨판). 작게 놓을 땐 다리 끝이 31칸을 넘지 않게 `y` 를 잡는다.

## 셋째 판 (11-10): 일기 줄 · 주제 스티커 · 작은 포스터

- **일기(뒷면) · 열람의 들른 곳 줄**: 정류장마다 주제 아이콘 대신 그 방 그림 (32px 그대로, `stopIcoH`). 방 그림이 없는 정류장(주소 문 · 도서관 밖 글)은 예전 아이콘.
- **주제 스티커**: 방 그림이 붙은 포스터에서는 오른쪽 가장자리 세로 띠에만, 반 크기 정수 배 (300px = 32px), 기울기 0. 높이는 저장된 `stickerPos.y` 그대로.
- **작은 포스터** (mini: 3D 벽 텍스처 · 2D 벽 · 들고 오는 포스터 · 앨범으로 날아가는 포스터): 주제 배경 + 방 그림을 장면 칸 가운데에 (`miniSvg`, 부드럽게 줄임 — 칸이 정수 배가 안 된다). 그림이 있으면 주제 스티커는 뺀다. 벽에서는 8px 쯤이라 색 점으로 보인다.

## 고르는 순서

1. 기억한 방의 그림 — `poster.sticker` (방 id), 없으면 기억한 정류장의 id
2. 그 방·정류장의 **주제 그림** — 도서관 밖 글(모델이 고른 위키 글 등)을 기억했을 때
3. 포스터 장면(`poster.scene`)의 주제 그림 → 그것도 없으면 들판

집에 있던 날 쪽지는 집 활동 그림, 복원된 옛 포스터에는 붙이지 않는다. 기억한 정류장은 일기에 저장된 `nodeId` 로 찾는다.
그림은 '그 방이 무엇인지' 보여 주는 삽화다. 문어가 무엇을 봤다·읽었다는 기록이 아니다 — 읽기 상태는 일기가 말한다.

## 파일

| 경로 | 역할 |
|---|---|
| `tools/ui-art/sculpt.js` | 형태 음영 렌더러 (넷째 판) — 장면 · 형태 · 거리 함수 · 재질 표 |
| `tools/ui-art/poster/lib.js` | 그림들이 같이 쓰는 부품 (구름 · 별 · 음표 · 물방울 · 문어 · 조각보 · 들꽃 · 매개변수 곡면) |
| `tools/ui-art/poster/kit.js` | 첫 판의 붓 — 지금은 배지 · 큰 기념품 그림만 쓴다 |
| `tools/ui-art/poster/<주제>.js` | 방 그림 (방 id → `[이름, 그리는 함수]`) |
| `tools/ui-art/poster/corners.js` | 주제 그림 |
| `tools/ui-art/poster/stay.js` | 쪽지(집 활동) 그림 |
| `tools/ui-art/poster/scenes.js` | 주제 배경 (66×56, 칸마다 색을 돌려주는 함수) |
| `tools/make-poster-art.js` | `assets/poster/*.png` + `js/poster-art-data.js` + 미리보기 |
| `js/poster-art-data.js` | **만든 파일.** 그림을 base64 로 (약 43 KB). 손으로 고치지 않는다 |
| `js/poster-art.js` | 전역 `POSTER_ART` — `forTrip` · `forStop` · `svg` · `sceneSvg` · `trail` · `trailSvg` |
| `tools/test-poster-art.js` | 검사 (`npm test`) |

그림을 data URI 로 싣는 까닭: 포스터 SVG 는 그림으로 굽힐 때(3D 벽 텍스처 · PNG 저장) 밖의 파일을 못 읽는다. 주소 대신 그림 자체를 넣으면 `file://` · 번들 · 저장본이 모두 같은 길로 간다. manifest 에는 넣지 않는다 (번들이 같은 그림을 두 번 담지 않게).

## 방을 더하거나 그림을 고칠 때

1. `js/world.js` 에 방이 생기면 `tools/ui-art/poster/<주제>.js` 에 같은 id 로 `[이름, function (S) { … }]` 한 장을 더한다 (S = 렌더러 장면. `S.ball` · `S.solid` · `S.lathe` · `S.flat` · `S.stroke` · `S.grid` · `S.spark`. 검사가 빠진 방을 알려 준다).
2. `node tools/make-poster-art.js` → `node tools/test-poster-art.js`.
3. `tests/evidence/poster-art/sheet.png` 를 눈으로 본다 (종이 바탕 · 밤 바탕 둘 다).

## 본 게임에 넣은 줄 (app.js 묶음)

- `index.html`: `js/app.js` 앞에 `js/poster-art-data.js` · `js/poster-art.js` 두 줄
- `js/app.js` `posterSVG`: 사진을 붙이던 `if` 앞에 `var art = … POSTER_ART.svg(…)` 와 `if (art) s += art; else`, 사진 출처 줄 조건에 `!art &&` · 장면을 그리는 줄 앞에 `var bg = … POSTER_ART.sceneSvg(…)` (있으면 벡터 장면을 건너뜀) · 날짜 줄 앞에 `POSTER_ART.trailSvg(…)` — 모두 12줄쯤
