# 다국어 — 방의 언어 (ko · en · ja · de · fr · es) · 2026-11-10

주인의 뜻: "일본어·영어도. 기존 클로드 사용자의 언어 설정을 따라가서 언어가 알아서 맞춰지는 것." → 같은 날 밤: "번역본 없는 게 없도록", "일본어 말고 영어를 메인으로. 독일어·프랑스어·스페인어도, 영어를 가장 우선." 이 문서는 그 길을 어떻게 나눴는지, 지금 어디까지 됐는지, 주인이 정할 것이 무엇인지 적는다.

## 한 줄 설계

**언어는 방에 붙는다.** 방 하나 = 한 사람 = 한 언어. 모델에게 가는 글 (안내문 · 도구 설명 · 상태 · 오류 · 물음), 문 밖의 도서관 (그 언어의 위키백과), 오늘의 서가, 열람실 이름, 엽서 꼬리표가 전부 방의 언어를 따른다. 문어가 남기는 글도 방의 언어로 쓰인다 (안내문에 한 줄: "이 방의 언어는 ○○다. 네가 남기는 글도 ○○로 쓴다") — 사람이 게임 화면에서 그 언어로 읽기 때문이다.

언어는 어디서 오나 (우선순위 순):

| 길 | 누가 | 언제 | 어디에 남나 |
|---|---|---|---|
| 1. 방을 만들 때 | 게임이 기기 언어 (`navigator.language`) 를 `POST /api/room {lang}` 로 보낸다 | 설정 › 내 Claude 와 연결 › 방 만들기 | `meta.lang` (바뀌지 않는다) |
| 2. 로컬 stdio | `PPOLPPOL_LANG=en` | 서버를 띄울 때 | 환경 변수 |
| 3. 둘 다 없으면 | 모델이 `ppolppol_look_room {lang}` 으로 대화의 언어를 한 번 알려 준다 | 첫 look_room | `state.lang` (그 뒤로 고정 — 모델이 다시 바꾸지 못한다) |

3번이 "클로드 사용자의 언어 설정을 따라가는" 길이다: 서버는 claude.ai 의 언어 설정을 볼 수 없지만 (MCP 에 locale 이 없다 — SDK 를 확인했다), 모델은 대화의 언어를 안다. 1번이 있으면 3번은 무시된다 — 사람이 게임에서 읽는 언어가 우선이다.

**영어가 메인** (주인 2026-11-10): 기기 언어가 있는데 여섯 언어 밖이면 (pt-BR 같은) 영어 방이 된다 (`I18N.DEFAULT`). 기기 언어가 아예 없으면 3번 (모델이 정함), 그것도 없으면 ko.

**먼 바다 문** (등불 4칸 뒤 사람이 한 번 열어 주는 문) 너머는 방의 언어 밖의 위키: 영어가 아닌 방 (ko · ja · de · fr · es) 은 **영어 위키 하나**, 영어 방은 **나머지 다섯 전부** (ja · de · fr · es · ko) — `I18N.FAR` 는 언어 목록이다. 그 밖의 언어는 "이 방의 지도에 없다" 고 거절한다.

## 된 것 (이 PR)

- `mcp/i18n.js` + `mcp/i18n/<lang>.js` — 여섯 언어 사전 (ko 원본 · en 은 주 세션이 · ja·de·fr·es 는 Claude 보조 세션이 en 을 틀로, ko 를 뜻의 기준으로 옮김). ko 글은 전과 글자 하나 다르지 않다 (시험이 본다). 열쇠·함수 모양이 여섯 언어 모두 같은지, 집 활동 문장이 world.js 의 활동을 다 덮는지 시험이 본다. 먼 바다 글은 `N(far)` (위키 이름들) · `C(far)` (코드들) 로 언어 하나든 여럿이든 같이 쓴다.
- `mcp/core.js` — 방의 언어 (`lang()` · `far()` 는 언어 목록 · `setLang()`), 위키 API 를 언어별로 (`{lang}.wikipedia.org`), 출처 주소 검사도 언어별로, 모든 오류·물음·때·등불 글이 사전에서. 찾아보기 (find) 도 방의 언어로.
- 오늘의 서가: ko 는 전처럼 `js/shelf.js` (게임과 같은 뽑기), 나머지는 `mcp/data/shelf.<lang>.json` (`tools/build-shelf.js en ja de fr es` — 알찬·좋은 글 분류에서 각 600편 표본: en 7,031 · ja 2,640 · de 7,502 · fr 6,608 · es 4,866). 없으면 위키 분류에서 산다.
- 열람실 이름 · 방의 위키 글: `mcp/data/rooms.i18n.json` (`tools/build-room-names.js [언어…]` — ko.wikipedia 언어 링크. 62개 방 중 en 58 · ja 57 · de 55 · fr 57 · es 57, 다섯 언어 모두 있는 방 54. 없는 방은 ko 이름·ko 글 그대로: rain · cipher · blanket 등).
- 책 · 서가 카드 번역본: `library/books/<lang>/<방>.md`, `library/cards/<lang>/<ID>.md` — 책 32권 · 카드 82장 전부 en · ja · de · fr · es 번역본이 있다 (570편, 2026-11-10, Claude 보조 세션이 옮김 — 영어 먼저, 독·불·서는 ko 원문 + en 참고). `by` 에 옮긴 이 (`… · English by Claude (AI)` / `… · 日本語訳 Claude (AI)` / `… · deutsche Übersetzung: Claude (AI)` …), `original:` 에 원본 지문 (`tools/stamp-translations.js`) — 원문이 바뀌면 check-books 가 "원본이 바뀜", 번역이 없으면 "번역 없음" 으로 알린다. 길이 눈금은 언어별 (`core.bookLimits`: en ×3 · de·fr·es ×3.5 · ja ×1.1). 규칙·점검은 [library/README](../library/README.md). 번역본이 없는 새 글은 원본 (ko) 을 주되 `cards` 목록에 `(ko)` 표시, 읽으면 `book.lang: "ko"`. 원본 없는 번역본은 오류.
- `mcp/tools.js` — 안내문 · 도구 제목·설명 · 스키마 설명이 방의 언어로 (initialize 때 정해진다). look_room 에 `lang` 칸. `target.lang` 은 여섯 언어. 도구 정의 크기: ko 5,625 · en 5,598 · ja 5,721 · de 5,641 · fr 5,719 · es 5,713 B (상한 5,800 — lang 열거형이 여섯이라 전 5,700 에서 올림).
- `mcp/postcard.js` — 엽서 꼬리표 (읽음 · 서가 카드 · 출처 · 반응 …) 가 방의 언어. 모델 글은 어느 언어든 그대로.
- `mcp/http.js` · `api/room.js` · `mcp/store.js` — 방 만들 때 `lang` 을 받아 `meta.lang` 에 (모르는 언어는 en). 오류 문장도 그 방의 언어.
- 게임 쪽 세 줄: 방 만들기가 `navigator.language` 를 보낸다 (js/app.js), 출처 주소 검사에 ko·en·ja·de·fr·es (js/app.js · js/brain.js), 반응 얼굴에 en·ja 낱말 (hop · ぴょん …). 글꼴 서브셋에 라틴 보충·확장 A (é ü ß ñ …) 를 넣었다 (tools/subset-fonts.py) — 독·불·서 제목이 화면에 그대로 나오게.
- 시험: `cd mcp && npm test` 200 통과 — en 방 단위 (위키 언어 · 먼 바다 여럿 · 찾아보기 · 방 이름 · 번역 카드 · 엽서 · 언어 없는 방 · 모르는 언어 → en), 길이 눈금 · 지문, 번역본 570편 (지문 · 한글 0 · by), en · ja · de · fr · es stdio 왕복 (안내문·도구가 그 언어, 한글 0, 예산, 오늘의 카드 제목이 번역본, 카드를 읽으면 그 언어의 글).

## 새 언어를 더하려면

1. `mcp/i18n/<lang>.js` — en.js 를 틀로 옮긴다 (열쇠·함수 그대로; 시험이 본다). `mcp/i18n.js` 의 `LANGS` · `require` · `FAR` 에 더한다.
2. `core.SHELF_CATS` 에 그 위키의 알찬 글 분류 → `node tools/build-shelf.js <lang>`; `node tools/build-room-names.js en ja de fr es <lang>`.
3. 번역본: 책 32 · 카드 82 를 같은 브리프로 (ko 원문 + en 참고, `by` 끝에 옮긴 이) → `node tools/stamp-translations.js` → `npm run check-books`. `core.LEN_SCALE` 에 길이 눈금.
4. 게임: `js/app.js` · `js/brain.js` 의 출처 주소 검사에 언어 코드. 글꼴에 없는 글자 범위면 `tools/subset-fonts.py`.

## 안 된 것 (다음)

1. **게임 화면 (UI) 의 다국어.** `js/app.js` 634줄 · `index.html` 116줄 · `js/brain.js` 225줄 (일기 문장 등) 에 한국어가 박혀 있다. 주 세션이 지금 app.js 를 계속 고치고 있어 이번엔 손대지 않았다 (충돌). 주인이 다른 세션에서 하기로 (2026-11-10). 길: `js/i18n.js` (`I18N.t(key)` + 사전 ko/en/ja + `?lang=` · 기기 언어 · 설정) 를 두고 화면 글을 한 번에 뽑는 일. 글꼴은 된다: Galmuri 에 가나 187자 · 한자 6,400자가 있다 (subset-fonts 가 CJK 틈을 메운다). 서버 쪽 번역본 (책·카드 제목) 은 이미 그 언어라, 게임이 방의 언어를 알면 그대로 보이면 된다.
2. **세계 데이터 (`js/world.js`) 의 방 이름 · 단서 · 기억 · 다리 글 858줄.** 서버는 이름·위키만 언어 링크로 대신했고, 단서 (`clue`) 는 위키를 못 읽을 때만 ko 그대로 간다. 게임 화면이 다국어가 될 때 같이.
3. **방의 언어 바꾸기.** 지금은 방을 만들 때 한 번. 게임에 언어 설정이 생기면 바꾸는 길 (`POST /api/room/<key>` 같은 것) 이 필요하다. 그때까지는 새 방을 만든다.
4. **stdio 에서 모델이 언어를 정한 뒤의 도구 설명.** 도구 목록은 initialize 때 실렸으므로 look_room 으로 언어를 정해도 설명은 그대로다 (`sendToolListChanged` 로 다시 실을 수 있다 — 아직 안 함). 원격 방은 요청마다 서버를 새로 만들어서 문제없다.
5. 스킬 (`.claude/skills/ppolppol-octopus-play/SKILL.md`) 은 한국어 하나. 로컬 Claude Code 용이라 뒤로.
6. 새 책·카드는 번역 전까지 en·ja 방에 `(ko)` 로 보인다 — 번역은 같은 방식 (Claude 에 시키고 check-books + stamp) 으로 그때그때.

## 주인이 정할 것

- **영어 방의 먼 바다** — "영어가 메인" 에 맞춰 나머지 다섯 언어 전부로 두었다 (영어 위키가 이미 집이라). 하나로 줄이고 싶으면 `I18N.FAR.en` 목록을 줄인다. (먼저 두었던 en→ja 는 2026-11-10 밤 주인의 "일본어 말고 영어를 메인으로" 로 바꿨다.)
- **방의 언어를 사람이 바꿀 수 있게 할지** (3번) — 게임 설정에 언어 고르기를 둘지.
- **모르는 기기 언어는 영어 방** 으로 둔 것 (`I18N.DEFAULT`) — 한국어 게임 화면에서 만든 방이라도 기기가 pt-BR 이면 영어 방이 된다. 한국어로 두고 싶으면 한 줄.

## PROTOCOL 제안 (주 세션이 고친다)

- `peek` 이벤트 `target.lang` 은 지금까지 `"en"` 만 (먼 바다). 이제 `"en" | "ja"` 가 온다 — 방의 언어이거나 먼 바다의 언어. `room` 기웃에도 `target.lang` 이 붙을 수 있다 (그 언어의 위키 글을 읽은 경우). `source.attribution` 은 `Wikipedia (xx)`.
- `book.lang` (peek 결과, 기록엔 없음): 방의 언어와 다른 책·카드를 읽었을 때 그 글의 언어.
