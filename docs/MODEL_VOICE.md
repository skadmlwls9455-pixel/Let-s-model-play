# 모델의 뜻 지키기 (2026-11-05)

모델의 속마음이 무엇인지는 확인할 수 없다. 이 게임이 약속할 수 있는 것은 두 가지다.

1. 모델이 낸 **선택과 말을 게임이 덧붙이거나, 빼거나, 바꾸지 않는다.**
2. 모델이 고르기 전에 **몰래 한쪽으로 끌지 않는다.**

아래는 왜곡이 생길 수 있는 다섯 지점과, 지점마다 거는 장치다. 호기심 메모 규칙은 docs/CURIOSITY_NOTES.md 에 따로 있다.

## 1. 고르기 전 — 무엇을 보여 주나

| 왜곡 | 장치 |
|---|---|
| 정체성 딱지 ("너는 조개를 좋아해") | 상황 설명에는 사실만 넣는다. 취향 말은 모델이 직접 쓴 메모로만, 작성 주체를 붙여서 |
| 압박 문구 ("지난번처럼", "사용자가 원해", "재미있게 해 줘") | 넣지 않는다. 사람의 힌트는 '선택 필드, 따를지는 네가 정함'으로만 전한다 |
| '그만두기'가 없는 행동 목록 | 모든 선택 요청에 그만두기·아무것도 안 하기를 넣는다. 고를 때 이유를 묻지 않는다 |
| 블라인드 선택에서 사용자 선택을 먼저 보여 줌 | 각자 고른 뒤 공개한다 |

## 2. 고른 것을 보여 줄 때 — 연출

| 왜곡 | 장치 |
|---|---|
| 거절·쉬기를 시무룩하게 연출해서 감정을 덧칠함 | 거절·쉬기는 담담한 연출만. 죄책감 대사 없음 |
| 대상이 사라져 다른 행동으로 바꿨는데 문어의 선택처럼 보임 | 기록에 `by: 'fallback'` 으로 따로 남기고 화면에 선택처럼 연출하지 않는다 (지금: 기억할 곳 `receipt.rememberedBy` — 데모 두뇌의 취향 가중치에도 넣지 않는다, 못 하는 활동 `receipt.activity.by` + `asked`. 활동을 안 고른 건 fallback 이 아니다) |
| 로컬 재생을 새 판단처럼 보임 | 기록의 `by` 로 구분한다 ('chooser' / 'playback') |
| 고른 반응을 '실제로 있었던 일과 맞지 않는다'며 다른 반응으로 바꿈 (실제 사례: 집에 있는 날 '폴짝' → '덤덤', 반응을 안 써도 '덤덤'이 생김) | 모델·사람의 반응은 준 그대로, 안 쓰면 없음. 맞는지 거르기는 데모 규칙에만. 누가 골랐는지 `reactionBy` (`model` / `human` / `demo-rules`) |

## 3. 말을 보여 줄 때 — 글자

| 왜곡 | 장치 |
|---|---|
| 고쳐 쓰기·요약·번역 | 모델이 쓴 말은 그대로 보여 준다 |
| 길이 제한으로 말없이 자름 (실제 사례: 메모 60자 맞추기에서 "내일은 X" 절이 빠짐) | 줄여야 하면 '…' 를 보이고 원문은 기록에 남긴다. 잘린 문장에서 뜻을 끌어내 다음 선택에 쓰지 않는다 |
| 말을 원인으로 단정 ("~해서 골랐다") | 화면은 "문어가 이렇게 남겼어" 까지만 |
| 기웃 메모를 출처 요약·책장 메모로 바꿔 씀 (실제 사례: 읽음이 확인된 정류장의 모델 메모가 위키 요약으로, 출처 없는 '읽음' 메모가 책장 메모로 바뀌고 원문이 사라짐) | 모델·사람의 기웃 메모는 그대로 (`noteBy`). 읽음이 확인되지 않은 '읽은 글'만 화면에서 빼고 원문은 `noteGiven` 에 (PROTOCOL §2) |
| 모델이 안 쓴 줄을 템플릿으로 채움 (반응 줄 '조용히 다녀왔어', 포스터 한 줄, 힌트를 안 따랐을 때 '다른 데로 갔어'(11-14 전엔 '다른 데가 궁금했어'), 활동 뒷면 '빗소리를 들으며'(11-14 전엔 '빗소리가 좋아서'), 활동 없는 쪽지 '오늘은 집에 있었어', 메모 없는 기웃 '문 앞까지만 갔다 왔어'·'내용은 읽지 않았어') | 모델·사람의 산책에는 그들이 쓴 줄만. 없으면 빈칸. 데모 규칙의 문구는 데모 규칙 산책에만. 사실(읽은 요약·책장 메모)은 사실로만. 데모 규칙의 문구도 사실만 쓴다 — 좋아함 · 재미 · 바람 · 궁금함 · 끌림 · 만족 말 없음 (11-14 주인 O1 b · 금지선 1, `tools/test-brain.js` 'demo lines say facts'). 모델의 말은 이 규칙과 상관없이 그대로 |
| 톡 한 줄을 템플릿으로 채움 · 다른 자리의 말을 지금 말처럼 다시 말함 (모델·사람 산책, 11-08) | 깨어 있는 문어를 톡 하면 그 차례에 **마무리에 쓴 말만** (`wrap_up.line`, 없으면 네 가지 밖의 반응 글). 그 자리 한마디(aside) · 기웃 메모 · 숨긴 `noteGiven` · 쪽지 · 기억 줄은 그때 그곳의 말이라 쓰지 않는다. 없으면 '응?'. 말풍선은 24글자(사람이 보는 글자) + '…', 원문은 기록 그대로. 모델이 쓴 말풍선이 떠 있는 동안 '데모' 꼬리표를 숨긴다 (사람 — 개발용 데모 조작 — 차례는 그 재생 때처럼 꼬리표 그대로). 얼굴은 늘 보통 (반응을 다시 짓지 않는다) (`BRAIN.tapLine`) |

## 4. 다음 세션으로 넘길 때 — 기억

| 왜곡 | 장치 |
|---|---|
| 횟수를 취향으로 바꿔 적기 | 코드는 사실만 (CURIOSITY_NOTES 원칙 1) |
| 내려놓은 메모를 다시 들이밂 | `set_down` 메모는 기본 전달에서 뺀다. 보관 메모의 존재·개수도 알리지 않는다 |
| 누가 쓴 메모인지 빠짐 | 작성 주체·모델(알 때)·세션·날짜를 붙인다 |
| 다른 걸 골랐다고 '마음이 바뀜'으로 기록 | 두 사실만 남긴다 |

## 5. 데모 규칙과 모델 — 출처

| 왜곡 | 장치 |
|---|---|
| 규칙이 만든 것을 모델의 뜻처럼 보임 | 기록마다 `by: 'user' \| 'model' \| 'demo-rules' \| 'playback' \| 'fallback'`. 화면에 '데모 두뇌/데모 규칙' 표시 |
| 규칙이 그럴듯한 이유·감정을 지어냄 | 데모 규칙은 호기심 메모를 비우거나 '데모 규칙' 표시 아래에서만 쓴다 |
| 규칙이 지은 톡 한 줄이 모델의 말처럼 보임 (11-08) | 데모 규칙의 톡 한 줄은 데모 규칙 산책(`by: 'demo'`)에만, '데모' 꼬리표가 보일 때만. 기록에 있는 사실 하나만 (기분 · 취향 · 시간 말 없음) |

## 말하기를 강요하지 않기

말하기 싫은데 말하게 하면, 그 말 자체가 비틀린 말이 될 수 있다. 그래서 모델에게 요구하는 출력은 **행동 하나**뿐이다. 대사·메모·반응은 모두 선택이다.
- 했음 (2026-11-07 물결 F): PROTOCOL §1·§3 의 마무리에서 `reaction` 이 선택이 됐다. 안 쓰면 반응 없이 끝난다 (두뇌가 대신 고르지 않는다).
