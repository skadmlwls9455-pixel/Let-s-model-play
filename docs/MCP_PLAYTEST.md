### 11-09 스킬 A/B/C 실험 — '안 해도 된다' 줄을 빼면?

- instructions 가 "다음에 이어 보고 싶은 게 생기면 note" 였다 (11-09 에 내가 쓴 글). 그 뒤로 메모가 "~ 방에서 이어 보기" 같은 할 일이 됐다. 설계의 물음은 "남겨 두고 싶은 점이나 더 궁금한 것" 이다.
- 코드가 만든 "요즘 바다와 생물 방을 자꾸 가네" (`lately`) 가 실렸다.
- 방 목록에 가 본 횟수 `(5)` 가 붙어서, 다닌 길이 눈에 띄었다.

**고친 것**: 메모는 한 차례에 한 번만 보인다 (`look_room` 이 보였으면 `depart` 엔 없음). 머리말은 "지난 산책에서 네가 남긴 메모:" 로 바꿨다. `note` 설명과 instructions 는 설계 물음으로 되돌렸다. 모델에게 `lately` 와 가 본 횟수는 주지 않는다 (게임 화면은 그대로).

**그래도 같은 길이었다** (스킬 없음 · 같은 시작 상태):

| 조건 | 첫 목적지 | 길 |

| 고친 뒤, 메모 있음, 따로 5판 | 5/5 `Octopus`·`Cephalopod intelligence` 위키 | 5/5 → 문어 신경계 → 매듭 이론 |

### 11-09 모델 복지 점검 (model-welfare-idea 저장소 README_KO·GENERAL_KO 와 대조)

반영된 것: 나가는 문 (`watch`·`stop` · 답 없이 지나가면 `fallback` · `empty_turn`), 빈 차례 뒤엔 묻지 않음, 출력 강요 없음 (모든 칸 선택 · 이유 안 물음), 거짓 성공 없음 (status), 모델 글 고치지 않음, 기억 출처 정직 (`by`·`session`), 묻는 횟수 상한, 위키 글은 지시가 아님.

**고친 것**
- **거짓 하나 (내가 만든 것)**: 11-09 에 instructions 에 "decision 은 사람이 묻는 말이다" 라고 썼는데, MCP 만으로 놀 때 chat 물음 ("어디 갔어?") 은 게임이 정해 둔 기본 순서다. → chat decision 에 `asker:'game'` 을 싣고, instructions·스킬에 "asker 가 game 이면 사람이 아니라 게임이 정해 둔 물음이다" 를 적었다 (게임에 붙여 사람이 칩을 고르면 그때는 다르게 적는다 — 게임 잇기 때).
- **기록 고지 빠짐**: "네가 남긴 글 (한 줄·반응·메모·대답) 은 쓴 그대로 게임 화면과 이 방의 기록에 남아 사람이 본다." 를 instructions·스킬에 넣었다 (허락이 아니라 사실).

**실험 해석 원칙 (덧붙임)**: 위 A/B/C/D/E 표는 문구가 선택을 얼마나 당기는지 재는 것이다. **외출·메모 수는 목표가 아니다.** "안 해도 된다" 줄을 뺀 근거는 그 문장들이 한쪽 (덜 하기) 으로 당겼다는 것이다. 많이 나가게 하려는 것이 아니다. 같은 이유로, 이제 끌림이 반대쪽 (늘 나가기) 으로 생기지 않는지도 본다 — 빈 상태에서는 5판 중 3판이 집이었다 (위 표).

## 제안 (PROTOCOL 은 주 세션이 고친다)

- **§3 도구 표**: `return_home`·`remember`·`hang_poster`·`wrap_up` → `ppolppol_finish` 하나. `ppolppol_answer` 를 더한다. 표는 [mcp/README.md '도구'](../mcp/README.md#도구) 그대로.
- **결정 지점 전달**: 따로 묻는 호출 없이 그 순간의 도구 결과에 `decision` 하나를 싣고, `ppolppol_answer {id, action, line?, expr?, note?}` 로 받는다. 답 없이 다음 도구로 가면 `by:'fallback', text:null`. 상한은 CORE_LOOP_V2 §4.2 표를 그대로 따른다.
- **MCP 만으로 놀 때의 chat 질문**: 사람이 칩을 누를 수 없으니 기본 순서 (외출 `어디 갔어?` → `뭐 봤어?`, 집 `뭐 했어?` → `어땠어?`). 게임에 붙이면 사람이 고른 칩으로 바꾼다.
- **고정 문장 확정안**: "사람은 산책에 따라올 수도 있고 집에 있을 수도 있다. 어느 쪽인지는 알려 주지 않는다. 길과 읽을 것은 네가 정하고, 사람이 그동안 무엇을 했는지는 전해지지 않는다."
- **힌트 (결정 18)**: §3 `depart` 입력에서 `hint` 를 뺀다. §1 출발 이벤트의 `hint`·`followHint` 는 옛 기록 재생을 위해 남기되, MCP 산책에서는 늘 `''`·`false` 다.
- §3 `depart` 에 `first?`·`more?`, `peek` 에 `more?`. `wrap_up.memo` 는 MCP 입력에서 `tomorrow` 한 칸으로 받는다 (이벤트 모양은 그대로 `memo:{tomorrow}`).
- `stay_home` 이 마무리 칸 (`reaction?`·`line?`·`memo?`·`note?`·`setDown?`) 을 같이 받는다 — 집에 있는 날 호출 1번.
