## 0. 한 줄 요약

**사진은 내가 찍는다. 포즈는 내가 시키는 인형 놀이다. 소파는 톡 하면 내가 앉는다. 문어는 오고 싶으면 와서 옆에 앉는다.**

| 기능 | 한 줄 |
|---|---|
| 사진 모드 | [📷]를 누른다. 한 손가락으로 방을 옆(±36°)·위아래(20°~50°)로 돌린다. 셔터를 누르면 내 사진첩에 들어간다. [공유] 한 번이면 폰 공유 창이 열린다 |
| 포즈 | 사진 모드 아래 칸을 톡 하면 문어가 그 동작을 되풀이한다. 공짜 5개, 가게 10개(조개 10~20). 기록은 늘 **'사람이 시킨 포즈'**다 |
| 소파 | 첫날 안내(TUTORIAL)가 끝난 뒤 문어가 처음 산책을 나가면 창 아래에 폴짝 놓인다(사락 쪽지와 함께). **톡 = 내가 앉기**(누르는 동안 쿠션이 꾹, 떼면 폴짝). **꾹 0.6초 = 옮기기**(꾸미기 규칙 그대로) |
| 같이 앉기 | 지금: 내 자리에 쿠션 자국과 내 얼굴이 뜬다. 문어가 와서 옆에 앉을지는 문어 몫이다. 나중(핵심 게임이 잘 돈 뒤): 내 캐릭터가 폴짝 뛰어 앉는다 |

### 1.5 카메라

**손가락 문법 (사진 모드에서만)**

| 동작 | 하는 일 |
|---|---|
| 한 손가락 가로 끌기 | 옆으로 돈다. 1px에 0.23°(지금 값), 3°씩 끊긴다 |
| 한 손가락 세로 끌기 | 위아래 각도. 아래로 끌면 더 내려다본다 |
| 두 손가락 | 밀기와 핀치 줌. INTERIOR §3.4·§3.5의 관성·고무줄 값 그대로. 15° 넘게 비틀면 옆으로 돌기(평소 화면에서 배운 손짓이 그대로 통하게) |
| 장면 톡·꾹 | **아무 일도 없다.** 포스터 열기·쓰다듬기·꾹 옮기기·소파 앉기가 모두 꺼진다. 손가락은 카메라만 움직인다 |
| 마우스 | 왼쪽 끌기 = 돌리기, 오른쪽 끌기·Shift+끌기 = 밀기, 휠 = 줌 |
| 키보드 | ←→ 옆, ↑↓ 위아래, Shift+화살표 밀기, + − 줌, 0 처음 각도, Space 찍기, Esc 나가기 |
| 끌 수 없는 사람 (WCAG 2.5.7) | [각도] 탭: [◀ 옆] [옆 ▶] [▲ 위] [▼ 아래] [⌖ 처음]. 버튼마다 44px |

평소 화면은 한 손가락 = 밀기(INTERIOR)다. 사진 모드는 한 손가락 = 돌리기다. 위 띠가 있는 따로 된 모드라서 덜 헷갈린다. 주인이 원한 핵심 동작도 "돌려 가면서"다.

- **사진 모드 동안 장면은 `touch-action: none`.** INTERIOR §5.3대로면 평소 1×에서는 `pan-y`다. 그대로 두면 세로 끌기(위아래 각도)를 브라우저가 페이지 스크롤로 가져가고 `pointercancel`이 온다. 들어갈 때 바꾸고 나갈 때 되돌린다. 페이지도 스크롤되지 않게 막는다(꾸미기 화면과 같다).

**범위: 방 뒷면이 안 보이게**

| | 평소 | 사진 모드 | 왜 |
|---|---|---|---|
| 옆 | ±27°, 9° 계단 (코드 344행: ±25°로 자른 뒤 9°에 맞춤) | **±36°, 3° 계단** | 벽 두 면의 안쪽은 카메라 방위각 0°~90°에서만 보인다(기본 45°). 더 돌면 만들지 않은 벽 바깥면이 보인다. 그래서 9°를 남긴다 |
| 위아래 | 32° 고정 | **20°~50°, 3° 계단** (32° 포함) | 20° 아래는 바닥이 납작해져 문어 발이 안 읽힌다. 50° 위는 문어 눈이 잘 안 보인다 |
| 줌 | 7단계, 1~2× (INTERIOR) | 4단계를 더한다: **2.24 · 2.52 · 2.83 · 3.17×** | 문어를 가까이 찍기 위해서. 3.17×면 문어 키가 4:5 사진 높이의 절반쯤 |
| 밀기 경계 | 방 상자를 화면에 투영한 범위 + 12 아트px | 같다. 각도가 바뀔 때마다 다시 계산 | — |

- **도는 중심**은 지금 화면의 가운데다(밀어 둔 만큼 포함). [⌖]는 문어를 화면 가운데로 데려온다(이미 있는 `look.focus='oct'`).
- **[문어가 나를 봐]** 토글은 기본 켬. 지금 idle처럼 몸이 카메라를 향한다. 끄면 들어올 때 방향으로 고정해서 옆모습·뒷모습도 찍을 수 있다.
- **구도 프리셋** (DESIGN §16.4): 다락 [창가] [소파] [보드 앞] [문 앞], 바깥 [현관 계단] [집 전체]. 누르면 0.3초 만에 그 구도로. [소파]는 소파가 있을 때만 보인다.
- **디더**: 지금 규칙 그대로. 움직이는 동안 꺼지고, 멈춘 지 0.3초 뒤 켜진다.
- **모션 감소**: 관성·이징 없음. 프리셋도 바로 바뀐다.

### 1.6 찍는 순간

| 무엇 | 값 |
|---|---|
| 눌림 | 셔터가 2px 내려간다. 80ms |
| 찍히는 프레임 | `pointerdown` 순간. 포즈 시계도 그 시각에 적어 두고 그 자세로 한 번 그린다 |
| 소리 | 새 효과음 `ui_shutter_1` 하나(sfx_ui 버스, "찰-칵" 약 120ms). 소리를 껐거나 파일이 없으면 조용하다 |
| 플래시 | 뷰파인더 위만 #ebede9(Apollo에서 가장 밝은 색)로 덮는다. 90% → 50% → 20% → 0, 한 단계 50ms (`steps(4)`). 모두 200ms |
| 연달아 찍기 | 400ms 안에 다시 누르면 무시. 1초에 최대 2.5번 번쩍여서 '1초 3번 번쩍임' 기준 아래다 |
| 진동 | 설정에서 켠 경우만 10ms (INTERIOR와 같은 설정) |
| 사진이 날아감 | 작은 사진이 사진첩 칸으로 2px씩 계단을 밟으며 간다. 250ms |
| 모션 감소 | 플래시 대신 뷰파인더 테두리가 200ms 동안 2px 호박색. 날아가기 대신 페이드 |

**사진 크기 (아트 px, p=2)**: 1:1 = 160×160, 4:5 = 144×180, 16:9 = 160×90. 화면이 작으면 비율을 지키며 줄인다(긴 변 최소 120). p=3 자동 폴백 기기는 아트 픽셀이 1.5배 굵다. 같은 구도가 아트 px로 2/3 크기가 된다(4:5 ≈ 96×120). 내보낼 때 정수 배 k가 커지므로 PNG 크기는 거의 같다(§1.7).

**엔진 `snap({ w, h })`**
- 지금 후처리는 화면(캔버스)에 바로 그린다(2146행). 저해상 출력 타깃은 아직 없다. 그래서 새 타깃 `rtOut`(rw×rh)을 하나 만든다. PORT의 `rtPO`·`postP`(989~990행)처럼 `uRes`만 rw×rh로 바꾼 post 복제를 쓰고, `readRenderTargetPixels`(1020행과 같은 방식)로 읽어 가운데 w×h를 자른다. 그래서 화면에 보인 것이 곧 사진이다.
- 이 한 번은 디더를 '멈춤' 상태로 그린다. 돌리던 중에 찍어도 완성된 그림이 나온다.
- 결과는 팔레트 번호 배열(1px = 1바이트)로 둔다.
- 말풍선·기호·꾹 링·격자·얼굴 핀 같은 HTML 층은 사진에 안 들어간다.
- 목표: 중간급 폰에서 15ms 이하. 늦으면 소리를 먼저 내고 그림은 다음 프레임에 만든다.

### 1.7 공유와 저장

- **크기**: 액자까지 넣은 그림의 긴 변으로 배율을 정한다. `k = floor(1080 / 긴 변)`, 최소 4. 예: 4:5 + 종이 액자 = 156×204 ×5 = 780×1020. `imageSmoothingEnabled = false`, 정수 배로만 키운다.
- **PNG는 찍자마자 미리 만든다**(`toBlob`). 그래야 [공유]를 누른 바로 그 순간에 `navigator.share`를 부를 수 있다. 사파리는 누른 순간에서 시간이 지나면 공유를 막는다.

| 순서 | 경우 | 하는 일 |
|---|---|---|
| 1 | `navigator.canShare({ files:[f] })`가 참 | `navigator.share({ files:[f], title:'뽈뽈 문어' })`. text·url은 안 넣는다 |
| 2 | 사람이 공유 창을 닫음 (AbortError) | 아무 말 안 한다 |
| 3 | 공유를 못 하거나 다른 오류 | 내려받기. 파일 이름 `ppolppol_2026-11-05_3.png`. 쪽지 "저장했어." |
| 4 | 카카오톡 같은 앱 속 브라우저라 내려받기도 막힘 | 사진을 크게 띄우고 "사진을 꾹 눌러 저장해 줘". 이 그림만 `-webkit-touch-callout`을 막지 않는다 |

- **[저장]** = 내려받기. iOS에서 사진 앱에 넣으려면 공유 창의 '이미지 저장'을 골라야 한다. 처음 한 번만 쪽지로 알려 준다.
- **사생활**: 우리 서버로 올리지 않는다. 계정이 필요 없다. 파일 이름에 내 이름·문어 이름이 없다. PNG에 위치 정보가 없다.

### 1.8 필터와 액자 (팔레트 안에서만)

**필터 (모두 공짜)**. 팔레트의 각 색을 OKLab에서 바꾼 뒤, **같은 팔레트에서 가장 가까운 색**으로 다시 맞춘다. 46칸짜리 바꿈표가 생긴다. 어떤 팔레트든 결과가 그 팔레트 안에 머문다. 화면 미리보기는 후처리 끝에 출력 표(`uPalOut`)를 한 번 더 거치고(셰이더 몇 줄), 사진은 번호 배열에 같은 표를 쓴다.

| 이름 | 바꾸는 법 |
|---|---|
| 그대로 | — |
| 노을 | a +0.03, b +0.05 |
| 밤빛 | 밝기 ×0.85, b −0.06 |
| 옛날 | 채도 ×0.35, 갈색 쪽으로 |
| 흑백 | 채도 0 |
| 네 빛 | 밝기를 4단계로 나눠 이끼 4색(#19332d #25562e #468232 #a8ca58)에 맞춘다 |

외곽선(가장 어두운 2색)은 어떤 필터에서도 남는다(테스트).

**액자** — 값은 ACHIEVEMENTS §4.3의 '사진 칸(액자 3종 각 10)'에 맞췄다.

| 이름 | 모양 (아트 px) | 조개 |
|---|---|---|
| 없음 | 테두리 없음 | 공짜 |

- **내 얼굴 도장**: 종이 띠 오른쪽에 내 얼굴 16×16(PLAYER_PROGRESSION §7 머리 그림). v0에서 '내가 여기 있다'를 살짝 보여 주는 장치다. 끌 수 있다. 내 이름은 안 넣는다.

### 1.9 내 사진첩

- **이름은 "내 사진첩"**. 문어의 포스터 앨범과 따로 둔다. 포스터는 문어 몫, 사진은 내 몫이다(PLAYER_PROGRESSION 원칙 9).
- **들어가는 곳**: 사진 모드 셔터 왼쪽 칸, 방 보기 › 내 사진첩.
- **격자**: 한 줄 2칸, 사진을 아트 px 1:1로(폭 160 CSS px). 360 화면에 2칸 + 간격 8 = 328이라 맞고, 정수 배라 번지지 않는다.
- **크게 보기**: 화면 폭에 맞는 가장 큰 정수 배. 설명 한 줄 "11월 5일 밤 · 다락 · 포즈: 브이 (내가 고름) · 필터 옛날". 버튼 [공유] [저장] [액자 바꾸기] [지우기].
- **나중에 바꾸기**: 원본 번호 배열을 저장하므로 액자·필터는 나중에도 바꾼다. '포즈 놀이' 표시는 기록에서 나오므로 지울 수 없다.
- **지우기**: 확인 창 없이 지우고 "지웠어 · 되돌리기"를 4초.
- **개수**: 100장까지. 90장부터 "사진첩 자리 10장 남았어". 꽉 차도 찍기·공유·저장은 된다("사진첩이 꽉 찼어. 공유나 저장은 돼."). 저절로 지우지 않는다. 표시는 "사진 12장"처럼 분모 없이.
- **저장소**: IndexedDB. 안 되는 브라우저(사생활 창 등)는 이번에만 메모리. 쪽지 "이 브라우저는 사진첩을 못 남겨. 공유·저장은 돼."

## 2. 포즈

### 2.1 규칙 — '사람이 시킨 포즈'

| 규칙 | 화면·코드 |
|---|---|
| 포즈는 **사진 모드 안에서만** 된다 | 평소 화면에 문어를 춤추게 하거나 앉히는 버튼은 없다. 문어의 일상은 문어 몫이다 |
| 기록은 늘 **사람이 시킨 것** | `{ kind:'pose', pose:'pose.v', by:'user', at }`. 움직임 프레임은 `playback`. `model`·`demo-rules`로는 절대 안 적는다 |
| 문어가 정한 것처럼 보이지 않게 | 위 띠에 "포즈는 내가 고르는 놀이"가 늘 보인다. 사진첩 설명에 "(내가 고름)". 포즈 중에는 머리 위 기호(! ? ♪)·말풍선이 없다 |
| 얼굴은 기본 얼굴 | 깜빡임만. happy(^^, 볼 빨감)·pet 얼굴은 안 쓴다. 웃는 얼굴 사진은 "문어가 기뻐했다"로 읽힌다 |
| 문어 기억·두뇌와 떨어져 있다 | 포즈 기록은 `S.photo`에만. `S.furn.log`·두뇌 입력·MCP 상황·호기심 메모에 안 들어간다. 포즈를 많이 써도 문어 버릇이 되지 않는다 |
| 나가면 원래대로 | 사진 모드를 나가면 문어는 들어오기 전 자리·표정·하던 일로 돌아간다. 포즈 결과가 남으면 문어가 스스로 한 것처럼 보이기 때문이다 |
| 끊지 않는다 | 걷기·놀이·앉아 있기 중이면 끝난 뒤 시작한다 |

**움직임 규칙**: 시작 때 120ms 예비 동작 → 되풀이. 다른 포즈로 바꾸면 160ms 동안 2단계로 풀고 새 포즈. 시계는 12fps 격자(PLAY_PROTO §11.5)라 그린 자세 사이를 끊어 움직인다. [⏸ 멈춤]은 지금 프레임에서 선다. 칸에는 **내가 가진 포즈만** 보인다(잠긴 칸 없음). 맨 끝에 [가게 →] 칸 하나.

### 2.3 가게에서

- 가게에 [포즈] 칸을 새로 둔다. **'해 보기'는 공짜**다. 카드를 톡 하면 작은 문어가 그 동작을 되풀이한다(PORT를 넓게 써서 12fps 프레임을 한 번 구워 캐시).
- 요정이 하는 말: "포즈는 사진 찍을 때 네가 문어 몸을 움직여 보는 거야. 사진 모드에서만 돼."
- 요정이 하지 않는 말: "문어가 좋아할 거야", "문어도 해 보고 싶대".
- PLAYER_PROGRESSION §8.4처럼 시트를 닫기 전까지 [되돌리기]로 전액이 돌아온다.

### 2.4 "찍어도 돼?" — 넣을까 (판정)

| 안 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| 가. 묻지 않는다 | 바로 찍는다. 규칙이 '싫어'를 지어내지 않는다 | 문어를 존중하는 장면 하나를 놓친다 |
| 나. 데모에서도 묻고, 규칙이 가끔 '잠깐만' | 귀엽다 | **규칙이 동의·거절을 지어낸다**(선 1). 산 포즈가 막혀 짜증. 매번 기다림 |
| 다. 모델이 붙었을 때만, 들어갈 때 한 번 | 진짜 뜻이 있을 때만 묻는다. 한 번이라 걸림이 적다. "얘는 누군가구나"가 스며든다 | 모델을 1번 부른다(약 400바이트). 1~3초 기다리지만 그동안 각도 잡기·찍기는 된다 |

**판정: 데모는 가, 모델 연결 뒤에는 다.** 데모에서 묻는 장면은 매력보다 걸림이고, 규칙이 지어낸 '응'·'잠깐만'은 가짜 뜻이다. 모델 모드에서는 관계 기둥을 살린다.

**묻는 말은 "찍어도 돼?"가 아니라 "포즈 놀이 해도 돼?"다.** 장면 사진은 폰 화면 캡처로도 찍힌다. 막을 수 없는 것을 묻고 '안 돼'를 무시하면 그게 거짓말이다. 그래서 게임이 정말로 지킬 수 있는 것, 곧 **문어 몸을 움직이는 일**만 묻는다.

| 항목 | 규칙 |
|---|---|
| 묻는 때 | 사진 모드에 들어갈 때. 문어가 집에 있고, 깨어 있고, 하던 일이 없을 때만. 한 시간에 3번까지. 넘으면 묻지 않고 그 시간의 마지막 대답을 그대로 쓴다(칩 "아까 대답 · 모델"). 마지막 대답이 '좋대'가 아니면 포즈 칸은 숨는다 |
| 보내는 것 | "사람이 사진 모드를 열었어. 포즈 놀이 = 사람이 고른 동작을 네 모습이 따라 하는 것. 사진은 사람 사진첩에 남아." 선택지 `pose_ok` · `not_now` · `stop`(아무것도 안 함). 한 줄 말(40자까지)은 선택 |
| 넣지 않는 것 | 산 포즈, 값, 조개, "사람이 기다려", "사진 찍고 싶대", **지난 대답과 '잠깐만' 횟수** |
| 기다리는 동안 | 찍기·각도는 바로 된다. 포즈 칸만 "물어보는 중…". 타이머 없음 |
| 8초 동안 답이 없거나 오류 | 이번엔 포즈 없이 찍는다. 기록 `by:'fallback'`. 화면 "대답이 아직 없어 · 포즈 없이 찍을 수 있어". 거절처럼 보이지 않게 |

- **PUPPET 층**: PLAY_PROTO §11.2의 훅 5개(`if (PLAY) …`)를 같은 자리에 둔다. 이름을 `PUPPET`으로 넓혀 컵 놀이와 사진 모드가 한 층을 나눠 쓴다. 컵·공은 PLAY kit의 `addCup`·`addBall`·`hold`를 다시 쓴다.
- **앉기 포즈**는 §3.4의 `sitOn(seat, { by:'user', kind:'pose' })`를 부른다. `kind:'pose'`면 장면은 가구 기록을 남기지 않는다. `by`에는 MODEL_VOICE의 다섯 이름(`user`·`model`·`demo-rules`·`playback`·`fallback`)만 쓴다. `'pose'`는 `by`가 아니다.

- **칸 그림**: PORT를 넓게(반폭 2.0 r) 써서 대표 프레임 한 장을 64×64로 구워 캐시.
- **모션 감소**: 되풀이하지 않고 대표 자세 한 장에서 멈춘다. [자세 바꾸기] 칩으로 그린 자세 2~3개를 넘겨 본다. 폴짝 높이·빙글 회전은 없다. 숨은 문어의 색 바꾸기는 남긴다(색 변화는 모션 감소에서도 유지하는 규칙).

## 3. 가구 상호작용

### 3.1 꾹 누르기 충돌 — 판정

**충돌**: INTERIOR_MODE §3.3은 "물건 0.6초 꾹 = 바로 옮기기"로 정했다. 주인은 "소파 꾹 누르면 폴짝 앉기"를 원한다.

**판정: 톡 = 쓰기(소파면 내가 앉기), 꾹 0.6초 = 옮기기. 모든 물건에 같은 규칙.** 대신 주인이 말한 "꾹 → 폴짝" 손맛은 톡 안에 넣는다. 손가락이 닿는 순간 쿠션이 1px **꾹** 눌리고, 떼면 **폴짝** 튀었다가 자국으로 앉는다.

| 손가락 | 소파 | 다른 쓰는 가구 (양초·담요·화분) | 집 뼈대 (창·문·등불·상자) | 문어 |
|---|---|---|---|---|
| 톡 (0.6초 전에 뗌) | 내가 앉기 / 앉아 있으면 일어나기 | 쓰기 (§3.6) | 쓰기 (§3.6) | 몸짓 + 기호 하나(? ! ♪ …). 문장 없음, 기록 안 함 (결정 10) |
| 꾹 0.6초 | 링 → 들기 → 옮기기 (INTERIOR 그대로) | 같다 | 링 없음. 아무 일 없음 | 0.35초 쓰다듬기 (그대로) |
| 0.15~0.6초 사이에 뗌 | 링이 그리다 말고 사라진다 → **톡으로 친다** | 같다 | — | — |
| 문어가 위에 있을 때 꾹 | 링 안 뜸. 쪽지 "문어가 앉아 있어. 내려오면 옮길 수 있어." | 자는 담요도 같다 | — | — |
| 내가 앉아 있을 때 꾹 | 저절로 일어난 뒤(자국이 1px 튀어 사라짐) 들린다 | — | — | — |
| 사진 모드 안 | 톡·꾹 모두 꺼짐 | 같다 | 같다 | 같다 |

**왜 이렇게 했나**
1. 규칙이 하나다. "누르면 쓰고, 꾹 누르면 옮긴다." **링이 뜨면 옮길 수 있다**는 INTERIOR의 약속이 모든 물건에 그대로 남는다.
2. 앉기는 가장 자주 하는 일이라 가장 짧은 손짓이어야 한다. 매번 0.6초 기다리면 답답하다(주인의 "슥슥 해도 안 움직여"와 같은 답답함).
3. 길게 누르기는 손이 떨리는 사람에게 어렵다(INTERIOR §3.3의 10px 문제).
4. **폴짝은 그대로 있다.** v0은 쿠션이 폴짝, 내 캐릭터가 생기면 캐릭터가 폴짝 뛰어 앉는다.

**다른 안**: (나) 앉을 수 있는 가구만 꾹 = 앉기, 소파 옮기기는 꾸미기 모드에서만. 주인 말에 더 가깝지만 링의 뜻이 둘이 되고 소파는 바로 못 옮긴다. (다) 말풍선 [앉기] [옮기기]: 매번 한 단계가 늘어서 뺐다. → **정함 (11-05)**: 위 판정대로 (질문 1).

**문어를 앉히는 버튼은 없다.** 문어를 소파에 앉히고 싶으면 사진 모드의 '앉기' 포즈(인형 놀이, §2)뿐이다.

### 3.2 소파: 어디서 오나

| | **가. 첫 산책 때 요정이 놓아 줌 (추천)** | 나. 조개로 사는 큰 목표 | 다. 등불 진행에 넣기 |
|---|---|---|---|
| 흐름 | 첫날 안내(TUTORIAL §3.1)가 끝난 뒤, 문어가 처음 산책을 **나간** 조용한 때. 창 아래에 소파가 폴짝 놓이고 사락 쪽지: "뚜루 기다리며 앉을 자리야. / 톡 하면 앉아." | 가게에서 40조개쯤 | 등불 n칸에 소파 |
| 좋은 점 | 주인이 바란 '기다리며 앉기'가 첫날부터 된다(두 번째 초대부터). 옛 저장도 다음에 문어가 나갈 때 받는다 | 살 목표가 생긴다 | 방 진행과 이어진다 |
| 문제 | 소파를 사는 재미는 없다 → **덮개 색만** 가게 '내 자리' 칸에 (4색, 각 12조개) | 문어가 안 앉으면 "조개 날렸다"가 된다. 그 마음이 문어에게 앉으라는 압박이 된다(PLAYER_PROGRESSION §4.2 문어 옷과 같은 걱정) | 등불 8칸이 이미 찼다. 문어 방 진행에 사람 자리가 섞인다 |

- **왜 튜토리얼 뒤인가.** 첫 산책은 TUTORIAL 6단계 안에 있다. 첫날 비춤은 최대 5개이고, 기다리기를 고르면 사락 줄도 이미 하나 있다. 거기에 소파 쪽지를 더하면 첫날이 붐빈다. 문어가 집에 있기·빈 차례를 고르면 다음에 나갈 때까지 미룬다.
- **사락은 방에 몸이 없다**(TUTORIAL §5.1). 요정이 걸어와 놓는 장면은 없다. 쪽지가 뜨고 소파만 폴짝 나타난다. 쪽지는 2줄, 줄마다 15자 안팎(사락 말투 규칙).
- 가는 PLAYER_PROGRESSION 결정 2('내 자리' 물건)를 대신한다. 자리는 공짜로 하나, 파는 건 겉모습뿐이다.
- 덮개는 문어 행동에 아무 영향이 없다(테스트 §6.5).
- 나중에 가게 가구(ACHIEVEMENTS §4.3 v1의 낮은 의자·빈백·해먹)도 같은 자리 규칙(`SEATS`)을 쓴다. 톡 = 내가 앉기.

### 3.3 소파: 모양과 자리

| 항목 | 값 |
|---|---|
| 크기 | 폭 1.7~1.8 m · 깊이 0.7 m · 앉는 면 0.32 m · 등받이 0.65 m(창턱 1.0 m 아래). 문어 폭이 0.84 m(`OCT_R` 0.42)라 자리 하나가 0.8 m는 돼야 한다 |
| 기하 | 다른 소품과 같은 절차적 상자: 받침 + 팔걸이 2 + 등받이 → `mergeParts` 한 덩어리. **쿠션 2개는 따로 한 메시**(정점 태그로 자국을 낸다) |
| 기본 색 | 이끼 초록 램프(러그 파랑·담요 장미색과 구별). 최종 색은 look-shots로 |
| 기본 자리 `attic:floor.win` | 왼벽 창 아래, +x를 본다. 가운데 약 (−2.12, 0, 0.25) |
| 다른 자리 `attic:floor.back` | 뒷벽 선반 아래, +z를 본다. 가운데 약 (−1.15, 0, −2.12). 꾸미기·꾹 옮기기로 바꾼다 |
| 앉는 자리 | A = 카메라에서 먼 쪽, B = 가까운 쪽. 사람은 **B를 먼저**(나중에 내 캐릭터가 문어보다 좁아 앞에 있어도 덜 가린다). 톡 한 자리가 비어 있으면 그 자리 |
| 얼굴 방향 | 카메라 쪽으로 20° 돌린다. "등이 안 보이게, 카메라 ±40° 안" 규칙(scene3d 1665행). 방향은 [⟳ 돌리기] 90°씩 (INTERIOR_MODE). 등이 카메라를 향하는 방향(±40° 밖)은 빨간 고스트로 못 놓는다. 90° 계단 중 ±40°(폭 80°) 안에 드는 건 하나뿐이라, 소파는 자리마다 방향 하나(`rots:[0]`)다 |

- **창 아래가 기본인 이유**: '같이 창밖 보기'로 이어지고, 화면 왼쪽 위 빈 벽이 채워진다. 뒷벽 자리와 사진 두 장으로 비교해 보여 준다.
- **맞출 것**: 창 앵커 `window: [-1.8, 0, 0.4]`(18행)가 소파 앞면과 겹친다 → 소파가 창 아래면 창 앵커를 소파 앞(약 x −1.3)으로(INTERIOR §5.1의 `use` 발치 규칙). 화분(−2.2, 0, 1.4)이 소파 끝과 5 cm쯤 겹칠 수 있다 → look-shots로 보고 필요하면 z 1.55로. 러그 모서리에 소파 끝이 올라가는 건 괜찮다.
- **뒷벽 자리와 옆방 구멍.** ROOM_EXPANSION §5.2의 다락 구멍은 왼벽 안쪽 끝(z −2.3 ~ −1.2)이고, 그 앞에 `hole` 앵커가 생긴다(§5.3). `floor.back` 소파의 왼끝(x 약 −2.05, z −2.47 ~ −1.77)이 구멍 앞 길에 걸릴 수 있다. → `test-layout` 의 '모든 앵커' 에 `hole` 을 넣는다. 걸리면 옆방 공사가 시작된 집에서는 `floor.back` 을 자리 표에서 뺀다. 이미 거기 있던 소파는 INTERIOR normalize 규칙 1(없어진 자리 → 기본 자리)대로 창 아래로 간다.
- 창가는 문어 자리이기도 하다. 소파는 **둘이 쓰는 자리**라서 문어도 앉고, 창 앵커는 없어지지 않고 앞으로 옮겨진다.

### 3.5 문어가 혼자 앉을 때 (게임이 정한 몸짓)

배회 후보(`allowedIdleAnchors`, app.js 407행)에 소파를 넣는다. 앉으면 아래 중 하나를 8~20초 하고 평소 배회로 돌아간다.

| 변형 | 비율 | 모습 |
|---|---|---|
| 그냥 앉기 | 35% | 숨쉬기 |
| 다리 흔들기 | 25% | §3.4 표 |
| 창밖 보기 | 15% | 등받이에 다리 둘을 걸치고 몸을 1.1배 늘여 창 쪽으로. 밤이고 맑으면 별 (뒷벽 자리면 빠짐) |
| 졸기 | 15% | sleepy 반눈. `sleep` 상태가 아니라 잠 규칙에 안 걸린다 |
| 틈에 쏙 | 10% | 팔걸이와 쿠션 사이에 0.85/0.8로 구겨 들어가 눈만. 4~6초 |

- 혼자 앉기는 배회와 같은 **게임이 정한 꾸밈 몸짓**이다. 기록하지 않는다. 그래도 새 코드라 시드 PRNG를 쓴다: `mkRng(hash('sofa|' + 날짜 + '|' + n))`.
- 방 보기 › 누가 고르나에 한 줄: "가만히 있을 때 돌아다니고 혼자 앉는 건 게임이 정한 몸짓이야. 네 옆에 와서 앉는 건 데모 규칙(또는 모델)이 정해."

### 3.6 다른 가구 (4박)

리서치의 원칙을 따른다: 만질 수 있는 건 8~10개(12번). 4박 구조(11번): ① 움직임 → ② 집 쪽지 한 줄 → ③ 문어 몫(고를 수 있음, 꼬리표) → ④부터 둘이 번갈아 돌기. 반응 중 연타는 세지 않는다(4번). ③은 물건마다 하루 한 번(8번 토큰). **물건의 반응은 늘 있고, 문어의 반응은 고를 수 있다.**

| 가구 | 언제 있나 | 톡: 물건 반응 (늘 있음) | ③ 문어 몫 (고를 수 있음) | 꾹 | 문어 혼자서 |
|---|---|---|---|---|---|
| **소파** | 첫 산책 | 내가 앉기 / 일어나기 (§4.1) | 와서 옆에 앉기 · 쳐다보기 · 하던 일 계속 (§4.3) | 옮기기 | §3.5 |
| 담요 | 등불 4 | ① 주름이 1px 펴짐 ② "담요를 폈어" ④ 털기·접기 번갈아 | 와서 털썩 / 뒹굴 | 옮기기 (자는 중엔 안 됨) | 잠 (그대로) |
| 양초 | 등불 3 | **켜기·끄기** (불빛·발광·`candleLight`). 밤에 끄면 등불만 남는다 | 없음. 눈만 따라온다(반사). 불은 사람 몫 | 옮기기 | — |
| 창 | 늘 | 유리에 1px 닦인 줄 + 빗방울 흔들림. 사실 한 줄("비가 와" / "별이 보여") | 창가로 와서 같이 보기 | 없음 (뼈대) | 창가에 서기 |
| 상자 | 등불 2 | ① 덜컹 1px ② "안에서 뭔가 굴러가는 소리" ④ 덜컹·삐걱 | 와서 뚜껑 들고 엿보기 (장면만, 물건 안 생김) | 없음 (뼈대) | 하루 한 번 엿보기 |
| 이끼 화분 | 등불 1 | 물방울 2px + 이끼 1px 반짝. **자라기·시들기·숙제 없음** | 다리 끝으로 톡 만져 보기 | 옮기기 | — |
| 문 | 늘 | 1px 삐걱 열렸다 닫힘 + 바람 소리 | 빼꼼 + '?'. 나가 있으면 없음 | 없음 | — |
| 등불 | 늘 | 깜빡 한 번 (진행도라 탭으로 안 바뀜) | 없음 | 없음 | — |
| 포스터·기념품 | 산책 | 지금 그대로 | 지금 그대로 | 옮기기 | 바라보기 |

**지금 문서·코드에서 바꿀 것**
- DESIGN §18 담요 줄("1회 문어가 가서 눕는다 → 2회 잠 → 3회 깸")은 탭으로 문어를 재우는 명령이다 → 위 표로. 문 줄의 "아직 안 나갈래"는 코드가 문어 입에 문장을 넣는 것이라(결정 10) 뺀다.
- `windowTap`(app.js 349행)은 지금 늘 문어를 창가로 걷게 하고, 날씨 한 줄("별이 보여"·"비가 와")을 **문어 말풍선**(`say`)에 넣는다 → 물건 반응(닦인 줄)과 날씨 한 줄은 늘, 단 날씨 줄은 **집 쪽지**로(결정 10). 문어가 오는 건 ③으로(데모 70%, 시드, `by:'demo-rules'`). 문어는 기호만.
- 기념품 톡(`souvenirTap`, app.js 345행)도 지금 문어 말풍선에 "— 이거 가져온 날"을 happy 얼굴로 넣는다. 표의 '지금 그대로'는 일기 열기만이다. 이 줄은 집 쪽지로 옮기고 문어는 눈만 따라온다(반사).
- **소파의 ③은 예외.** 하루 한 번 토큰(8번) 대신 §4.3 규칙을 따른다(굴림은 10분에 한 번). '기다리며 같이 앉기'는 하루에 여러 번 일어나야 하기 때문이다.

## 4. 같이 앉기

### 4.1 지금 (내 캐릭터 전): 내 자리 표시

| 시간 | 보이는 것 |
|---|---|
| 0 ms (손가락 닿음) | 누른 쿠션이 1 아트px **꾹** 내려간다 |
| 뗌 | **폴짝**: 쿠션이 1px 튀었다가 −1px 자국으로 앉는다. 자국 위 1px 주름 줄, 먼지 2점 |
| +120 ms | 자국 위에 **내 얼굴**(16×16 종이 인형 머리 ×2 = 32px)이 1.5초 떠 있다가 줄며 사라진다. 아직 안 만들었으면 '?' 얼굴 |
| 앉아 있는 동안 | 자국이 남는다. 장면 구석에 칩 [앉아 있음 · 일어나기](44px). 빗소리 +1 dB, 음악 −3 dB(작은 '앉은 느낌'. 보상 아님) |
| 일어나기 | 소파 다시 톡 · 칩 · 꾸미기 들어가기 · 소파 꾹. 자국이 1px 튀어 사라진다 |
| 새로고침 | 앉은 상태는 저장하지 않는다 → 서 있음 |

- **하트를 쓰지 않는다.** 하트는 이미 쓰다듬기 반응이다(`UIART.fx('heart')`, app.js 655·660행). 내 자리에 하트가 뜨면 "문어가 날 좋아한다"나 애정 점수로 읽힌다. 내 자리는 **내 얼굴**로 표시한다. 나중에 내 캐릭터가 생길 때도 자연스럽게 이어진다.
- 앉아 있어도 요리·꾸미기를 하러 갈 수 있다. 돌아오면 그대로 앉아 있다.
- 사진에서 v0의 '나'는 종이 액자 띠의 내 얼굴 도장(§1.8)으로만 나온다.

### 4.2 기다리며 같이 앉기 (CORE_LOOP_V2와 잇기)

CORE_LOOP_V2 §3.3 C1의 쪽지 "기다리는 동안 뭐 할래?" [요리하기] [꾸미기] [그냥 두기]에서, **소파가 있으면 [그냥 두기]가 [앉아서 기다리기]가 된다.** 누르면 내 자리에 자국이 생기고, 나머지는 '그냥 두기'와 같다(앱을 닫아도 된다).

| 때 | 나 | 문어 | 화면 |
|---|---|---|---|
| 보낸 직후 | [앉아서 기다리기] 또는 소파 톡 | 산책 중 | 빈 A 자리 + 내 자국 + 비 |
| 기다리는 동안 | 아무거나 해도 됨 | 산책 | [앉아 있음] 칩 유지 |
| 귀가 (C4 → CORE_LOOP_V2 순서표 ①~④′) | 앉아서 본다 | 문 → 포스터 걸기 → (식탁) → 대화 두 차례 | 지금 그대로. 끼어들지 않는다 |
| CORE_LOOP_V2 순서표 ④‴ (④″ 넓히기 제안이 있는 날은 없음) | — | **문어 몫** (§4.3): 와서 옆에 앉기 / 평소대로 | 착지 때 내 쿠션도 폴짝 |
| 그 뒤 | 일어나도 된다 | 옆에 앉았다면 20~60초(졸기도 있음) 뒤 CORE_LOOP_V2대로 담요로 가서 잔다 | — |

- v0에서 문어는 소파에서 **잠들지 않는다.** 잠은 담요 규칙 그대로다. 소파에서는 '졸기'까지만.
- 산책 결과는 출발 때 이미 정해진다. **내가 앉아 있는지는 `BRAIN.plan`에 들어가지 않는다**(테스트). 앉음이 바꾸는 건 귀가 **뒤** 집에서의 몸짓 하나뿐이다.

### 4.3 문어 몫: 데모 규칙 지금, 모델 나중

**데모 규칙** (시드, `by:'demo-rules'`)

| 상황 | 고르는 것 (비율) | 시드 |
|---|---|---|
| 내가 앉음, 문어는 집에서 깨어 있고 한가함 | 0.8~2.0초 뒤: 와서 옆 A에 앉기 45% · 쳐다보기만(눈이 내 자리로 1.5초) 30% · 하던 일 계속 25% | `'join|' + 날짜 + '|' + n` |
| 내가 앉음, 문어가 이미 A에 앉아 있음 | 그대로 앉아 쳐다보기 50% · 다리 하나 뻗어 내 쿠션 끝 톡 20% · 3~8초 뒤 내려가 다른 데로 15% · 아무 반응 없음 15% | 같음 |
| 귀가 대화 뒤, 내가 앉아 있음 | 와서 옆에 앉기 50% · 평소대로 50% | `'join|' + tripId` |
| 자는 중 / 나가 있음 / 바쁨 (의식·포스터·꾸미기 반응) | 없음 | — |

- 눈이 내 자리로 도는 것(100 ms 안)은 **반사**다. 고른 것이 아니다. 선택으로 기록하지 않는다(남기면 `playback`, PLAY_PROTO §7.1).
- **굴림은 10분에 한 번까지**(모델 모드와 같은 간격). 그 사이에 일어났다 다시 앉아도 눈만 돌아간다(반사). 톡을 되풀이해서 '앉을 때까지 다시 굴리기'가 되지 않게 한다.
- 문어 입에 글자는 없다(결정 10: 기호와 몸짓만). 대신 ③의 **꼬리표**는 보인다(§3.6, INTERIOR §4 정직 표기). 문어가 옆에 앉거나 쳐다보면 [앉아 있음] 칩 옆에 작은 꼬리표 "옆에 앉음 · 데모 규칙"(모델이면 "· 모델")이 3초 뜬다. 화면 읽기 알림도 같은 글. 하던 일 계속·무반응이면 꼬리표 없음.
- 문어가 안 오거나, 앉았다가 가도 담담하게. 다시 조르지 않는다. 내가 일어나도 문어는 그대로 있을 수 있다. 그 자리는 문어 자리이기도 하다.

**모델이 붙은 뒤** (`by:'model'`)
- **사람 옆에 앉기는 모델만 고른다.** 로컬 배회는 혼자 앉기는 계속 하지만, 사람(자국·캐릭터)이 앉은 소파의 옆자리는 후보에서 뺀다. 코드가 사회적 선택을 대신하지 않게 하려는 것이다.
- 묻는 때: 내가 앉을 때(10분에 한 번까지), 귀가 대화 뒤 내가 앉아 있을 때. 하루 최대 6번.
- 보내는 것 (사실만, 약 250바이트):
```js
{ where: 'attic', you: { at: 'crate', doing: 'idle' },
  person: { sitting: 'sofa.B' }, free: ['sofa.A'],
  options: ['sit_next', 'look', 'keep_doing', 'nothing'] }   // 'nothing' 은 늘 있다
```
- 넣지 않는 말: "사람이 기다려", "같이 앉아 줘", "외로워 보여". 지갑·덮개 색·사람 이름(기본)도 안 넣는다.
- 답: 행동 하나만 꼭 받는다. 한 줄 말(40자까지)은 선택, 받으면 글자 그대로.
- 기다리는 동안 눈만 돌아간다(반사). 실패·시간 초과면 아무것도 안 하고 `by:'fallback'`. 고른 것처럼 연출하지 않는다.

### 4.4 나중: 내 캐릭터가 방에 들어올 때

**열리는 조건**: 핵심 루프 v2가 잘 돌고, 플레이테스트에서 재밌다는 답이 나온 뒤. 주인 말 그대로 "기존 겜에서 구현 제대로 되는 거 보이면"이다.

**있는 방식** — PLAYER_PROGRESSION §7.1의 "다락에는 일이 있을 때만 나온다"를 지키되, **앉기와 가구 쓰기를 '일'에 넣는다.**
- 소파를 톡 하면 내 캐릭터가 문에서 걸어 들어와(또는 체크무늬 8단계로 나타나) 소파 B로 가서 **폴짝 뛰어 앉는다.** 주인이 그린 "꾹 → 폴짝 → 둘이 같이 앉기"가 여기서 완성된다.
- 앉아 있는 동안 계속 방에 있다. [일어나기]를 누르거나 앱을 닫으면 나간다. 새로고침하면 없다.
- 스스로 돌아다니지 않는다. 숨쉬기·깜빡임만. **내가 무언가를 톡 하면** 그리로 걸어가 쓴다. 조이스틱은 없다.
- 문어 앵커를 막지 않는다. 목표 자리에 문어가 있으면 `approach` 점에서 기다린다.

| 동사 | 내 캐릭터 | 문어 몫 (고를 수 있음) | 필요한 그림 |
|---|---|---|---|
| 앉기 | 소파 톡 → 걸어가 폴짝 → 앉기 프레임(머리 y +4) | 옆에 앉기 (§4.3) | 앉기 1장, 걷기 4장 |
| 쓰다듬기 | 옆에 앉아 있을 때 문어 꾹 → 팔 2프레임 뻗기 + 지금의 쓰다듬기 | 지금 반응 | 팔 2장 |
| 창밖 보기 | 창 톡 → 창가(또는 소파 위 무릎 꿇기) | 같이 보기 | 뒷모습 1장 |
| 양초 · 상자 · 담요 | 걸어가서 켜기 · 뚜껑 열기 · 털어 펴기 | 쳐다보기 · 엿보러 오기 · 털썩 | — |
| 문 배웅·마중 | 출발·귀가 때 문가에서 손 흔들기 | — | 손 흔들기 2장 |
| 식탁 요리 | 식탁에서 요리(CORE_LOOP_V2) | 구경 / 먹기 (요리 규칙) | 식탁 가구(방 넓히기와 같이) |
| 사진 | 둘이 찍기 (§4.5) | 모델 모드면 §2.4 | — |

**하지 않는 것**: 문어를 들어 옮기기, 문어가 앉은 자리 빼앗기, 자는 문어 건드리기, 산책 따라가기(DESIGN §16.3), 문어 물건 가져가기.

**엔진(나중)**: 빌보드 16×24(PLAYER_PROGRESSION §7.2), `alphaTest 0.5`, 깊이 쓰기 켬, **Y축으로만 도는 빌보드**라 시점을 돌려도 눕지 않는다. 세운 판은 위아래 각도가 바뀌면 화면 키가 `cos(tilt)`만큼 변한다(32° → 50°면 약 3/4). 그래서 사진 모드에서 각도가 바뀔 때마다 판 높이를 `24 / (N · cos tilt)`로 다시 맞춰 화면에서 늘 24 아트px로 둔다. 안 그러면 줄이 빠지거나 겹쳐 종이 인형 그림이 깨진다. 접지 그림자는 `octDecal` 방식. 걷기 1.0 m/s. 길은 INTERIOR v1의 `pkRoute` 재사용. `setCompanion(look, { seat, frame })` 약 200줄, 드로우콜 +2.

### 4.5 나중: 둘이 찍기

- **[나도] 칩**(포즈 탭): 내 아바타가 문어 오른쪽 0.6m에 선다. 사진 모드 안에서만 나오고 나가면 돌아간다. 이미 소파에 앉아 있으면 그대로 찍힌다.
- **셀프 타이머 3초**: 삐 소리 3번, 1px 숫자. 셔터가 '삼각대 위 카메라'가 된다.
- **내 포즈**: 서기·브이·손 흔들기·만세·앉기. 포즈마다 그림 1~2장, 옷은 지금 입은 그대로. 문어 포즈와 따로 고른다. [같이] 칩을 켜면 같은 이름 포즈를 둘이 같이.
- **같이 앉기 프리셋**: 소파에 문어 A, 나 B. 주인이 말한 "문어 기다리면서 같이 앉아 있기"의 사진판이다. 문어가 이미 옆에 앉아 있으면 포즈 없이 그대로 찍는다(그때는 문어 몫 기록 그대로).
- 내 모습은 내 사진첩에만 남는다(PLAYER_PROGRESSION 원칙 9).
- **움직이는 사진(GIF)**: 포즈 한 바퀴를 12fps GIF로. 46색 이하라 깔끔하다. 직접 만든 인코더 약 150줄, 외부 의존성 없음.

## 5. 지킬 선

### 5.1 네 선 × 이 기능

| 선 | 사진·포즈 | 소파·가구 |
|---|---|---|
| **1. 문어에 대해 거짓말하지 않는다** | 포즈는 `by:'user'`, 늘 "내가 고름" 표시. 포즈 중 기호·말풍선 없음, 기본 얼굴. 공유 사진에 '포즈 놀이' 표시. 데모는 "포즈 놀이 해도 돼?"를 묻지 않는다(지어낸 동의 금지). 지킬 수 없는 "찍어도 돼?"는 묻지 않는다 | 문어 입에 문장 없음(기호·몸짓만). 옆에 앉기는 `demo-rules`/`model`/`fallback` 꼬리표. 반사(눈 돌리기)는 선택으로 기록 안 함. 하트 대신 내 얼굴 |
| **2. 문어를 일꾼으로 만들지 않는다** | 사진·공유로 조개 **0**(`earn`이 `photo`·`share` 출처를 거절). 포즈·액자는 내 조개로 사는 **내 카메라 도구**다 | 앉기·가구 탭 조개 0(PLAYER_PROGRESSION §3.4, ACHIEVEMENTS §4.2 그대로). 같이 앉은 시간·횟수 표시 없음 |
| **3. 문어의 선택을 조종하지 않는다** | 사진·포즈 기록은 두뇌 입력·모델 상황에 안 들어간다. 나가면 원래 상태로. 포즈가 버릇이 되지 않는다 | 앉음 여부는 `BRAIN.plan`에 안 들어간다. 덮개를 사도 문어가 더 자주 앉지 않는다. 모델 모드에서 로컬 배회는 사람 옆자리를 안 고른다. 모델 요청에 압박 문구 없음, 'nothing' 늘 있음 |
| **4. 압박을 쓰지 않는다** | 한정·뽑기·"오늘만" 없음. 계절 포즈·액자는 남는다. 매일 찍기 숙제 없음. 사진첩은 저절로 안 지움 | "오늘 아직 안 앉았어" 없음. 연속 기록 없음. 소파가 먼지 쌓이거나 낡지 않는다. 문어가 안 와도 시무룩 없음 |

### 5.2 하지 않는 것

- 평소 화면에서 문어에게 "앉아"·"춤춰"를 시키는 버튼.
- 문어가 옆에 앉은 것으로 주는 배지·조개·숫자. 그러면 사람이 문어를 앉히려 애쓴다.
- 사진 수·공유 수·포즈 수를 세는 **새** 배지. (ACHIEVEMENTS #30 첫 사진·#31 둘이 한 장만 남긴다. §5.3)
- 사진에 문어의 감정·말로 읽히는 스티커(하트·말풍선).
- 공유 이미지를 우리 서버에 올리기, 계정 요구.
- 포즈를 데모 규칙이나 모델의 선택처럼 기록하거나 보여 주기.

### 6.4 저장 (`ppolppol_v2`에 블록을 더하고, 버전은 그대로)

```js
S.photo = {
  album: [{ id: 'ph_k7x2', at, day: '2026-11-05', place: 'attic', ratio: '4:5', size: [144, 180],
            cam: { yaw: 18, tilt: 29, n: 38, pan: [0.4, -0.2] }, octState: 'idle',
            pose: { id: 'pose.v', by: 'user' } | null, filter: 'old', frame: 'paper', stamp: true,
            ask: null | { answer: 'ok' | 'not_now' | 'none', by: 'model' | 'fallback' } }],  // 100장까지

  lastAsk: null | { at, answer }
}
// IndexedDB 'ppolppol_photos' › 'raw': { id, w, h, pal: 'apollo', idx: Uint8Array(w * h) }
// 산 포즈·액자·덮개는 player.owned ('pose.v', 'frame.stamp', 'cover.moss')

// 소파 자리: 처음 놓일 땐 layout 에 쓰지 않는다 (기본 자리 = 저장 없음, INTERIOR §5.2).
// 사람이 옮기면 그때 S.room.layout.place.sofa = { slot: 'attic:floor.back', rot: 0, by: 'user', at }.
// 문어(규칙·모델)는 소파를 옮기지 않는다.
S.room.sofa = { got: '2026-11-05', cover: 'cover.moss' }   // 없으면 = 아직 소파 없음 (옛 저장)
S.room.candleOn = true
S.furn = {
  taps:  { crate: 3, blanket: 1 },            // '끝난' 반응 수. 화면에 숫자 없음
  once:  ['crate:3@2026-11-05'],              // 오늘 토큰. 날이 바뀌면 불러올 때 버림
  found: { 'crate:3': '2026-11-04' },         // 첫 발견 날짜. 분모 없이
  log: [                                       // 최근 50
    { id, item: 'sofa', seat: 'A', act: 'sit'|'stand'|'join'|'look'|'leave'|'peek'|'toggle',
      actor: 'user'|'octopus'|'avatar', by: 'user'|'demo-rules'|'model'|'fallback', session, at }
  ]
}
// 저장하지 않음: 지금 앉아 있는지 (새로고침 = 서 있음), 지금 포즈 상태
```

- `normalize`: 블록이 없거나 깨지면 기본값. `S.furn.log`에서 `kind:'pose'` 줄은 버린다(`by`가 다섯 이름 밖인 줄도). 같은 입력이면 두 번 돌려도 결과가 같다.
- 두 탭 합치기: 사진은 id로 합집합.
- 내보내기 JSON엔 사진 목록만(그림은 [모두 저장]으로 따로). 초기화하면 사진·가구 기록도 지운다.
- **`S.photo`·`S.furn`은 `brainInput`에도 MCP payload에도 넣지 않는다.** 예외는 §4.3의 옆에 앉기 사실 한 줄과 §2.4의 포즈 놀이 물음뿐이다.

## 9. 주인이 정할 것 (남은 것 2)

**1. 소파를 누르는 법.** → **정함 (11-05)**: 톡 = 앉기, 꾹 0.6초 = 옮기기. 모든 물건이 같은 규칙이야 (INTERIOR_MODE 질문 1과 같이). 누르는 순간 쿠션이 꾹, 떼면 폴짝.

**2. 공유하는 사진에 '포즈 놀이' 표시를 늘 넣을까?**
추천: **넣기, 끌 수 없게.** 종이 액자 띠의 글자나 7×7 손 표시로 아주 작게 넣어. 사진이 밖으로 나가면 "Claude가 브이 했대"로 읽힐 수 있어서야. 끌 수 있게 하면 거의 모두 꺼.

**3. 소파는 어떻게 생길까?**
추천: **첫날 안내가 끝난 뒤 첫 산책 때 공짜로 놓아 주고, 덮개 색만 조개로 사기(4색, 각 12).** 소파를 조개로 사게 하면 문어가 안 앉을 때 "조개 날렸다"는 마음이 생기고, 그게 문어한테 압박이 돼. 이걸로 PLAYER_PROGRESSION의 '내 자리 물건' 질문도 같이 닫혀.
다만 업적 문서는 "산 가구는 넓힌 방에만"을 추천했어. 소파는 산 게 아니라 둘이 쓰는 자리 하나라서 다락에 둬도 그 규칙과 안 부딪힌다고 봤어. 다락에 사람 쪽 물건은 소파와 문가 벽걸이 1칸(배지 소품)뿐이야.

(내가 정해 둔 것: 사진·공유로는 조개를 안 준다(첫 사진 배지는 남김). 포즈는 사진 모드 안에서만 되고 늘 '내가 고름'으로 남는다. 포즈 중엔 기본 얼굴만. 데모는 "포즈 놀이 해도 돼?"를 묻지 않고, 모델이 붙으면 들어갈 때 한 번만 묻는다. "찍어도 돼?"는 지킬 수 없어서 묻지 않는다. 문어한테 "앉아"를 시키는 버튼은 없다. 문어가 옆에 앉아도 배지·조개는 없다. 내 자리 표시는 하트 대신 쿠션 자국 + 내 얼굴. 소파 기본 자리는 창 아래인데 뒷벽과 사진 두 장으로 비교해 보여 줄게. 내 캐릭터는 핵심 게임이 잘 돈 뒤에, 앉거나 뭔가 할 때만 방에 나온다. 다르게 하고 싶으면 말해 줘.)
