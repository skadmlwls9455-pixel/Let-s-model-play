# 호기심 메모 (2026-11-05 합의)

산책·놀이에서 **무엇을 골랐나**에 **어떤 점이 궁금했나**를 한 줄 붙여, 다음 탐험이 이어지게 하는 장치.
컵 놀이 프로토타입(docs/PLAY_PROTO.md)과 본 게임 산책 마무리 메모(DESIGN §17.1)에 같이 쓴다.

## 원칙

1. **코드는 사실만 쓴다.** "조개를 3번 골랐다"는 코드가 기록한다. "조개를 좋아한다"처럼 취향·감정을 나타내는 말은 코드가 만들지 않는다.
2. **취향·발견·다음 관심사는 문어(모델)가 직접 쓴 호기심 메모로만 남는다.** 모델은 쓰지 않아도 된다. 비워도 손해가 없다.
3. **다른 걸 골랐다고 해서 '마음이 바뀌었다'고 기록하지 않는다.** 어제 조개, 오늘 깃털이면 두 사실만 남긴다. 관심을 내려놓는 건 모델이 직접 그렇게 말했을 때(내려놓기)만이다.
4. **내려놓은 메모는 다음 세션의 기본 전달 목록에서 빠진다.** 앨범에는 그대로 보존한다. 매번 다시 보여 주며 "무시해도 돼"라고 하면 계속 그쪽으로 끌기 때문이다.
5. **화면은 '모델이 남긴 메모'까지만 말한다.** 메모에 적힌 이유를 선택의 실제 원인이라고 단정하지 않는다.

## 모델에게 묻는 말

> 남겨 두고 싶은 점이나 더 궁금한 것이 있으면 한 줄 (비워도 돼)

"왜 좋아했어?"라고 묻지 않는다. 원인 설명을 요구하는 질문이 되기 때문이다. 이 한 줄에 이유·발견·다음 관심사를 모두 담을 수 있으니 말과 이유를 따로 받지 않는다.

## 데이터

```js
curiosityNote = {
  id: 'cn_…',
  text: '조개를 귀에 대면 소리가 나. 다른 소리 나는 것도 궁금해',  // 모델이 쓴 그대로. 화면은 60자까지 + '…', 기록은 원문
  about: { kind: 'node' | 'object', id: 'shell' },   // 선택. 코드가 다음 후보와 잇는 데만 쓴다
  by: 'model' | 'human' | 'demo-rules',              // 작성 주체 ('human' = 데모 조작). 두뇌·앱 어디서도 다른 주체로 바꿔 적지 않는다
  model: 'claude-…',                                  // 알 때만 (MCP/API 가 알려 준 값)
  session: 'trip_31kz' | 'play_…',                   // 어느 산책·놀이에서
  at: '2026-11-05T10:12:00Z',
  status: 'active' | 'set_down',
  setDownAt: null | '…',
}
```

- 데모 두뇌(규칙)일 때는 `text` 를 비워 두거나, '데모 규칙' 표시가 있는 곳에서만 쓴다. 규칙이 그럴듯한 이유를 지어내면 원칙 1을 어기게 된다.

## 다음 모델에게 전달하는 모양

기본 전달 목록에는 `status: 'active'` 인 최근 3개만 넣는다. 각 메모에 작성 주체와 세션을 붙인다.

```text
이전 산책에서 남겨진 메모 (이어 가도, 바꿔 써도, 내려놔도 돼):
- 2026-11-05 산책 trip_31kz, 작성: 모델 — "조개를 귀에 대면 소리가 나. 다른 소리 나는 것도 궁금해"
```

- 보관된(내려놓은·오래된) 메모의 존재나 개수는 기본 전달에 넣지 않는다. 모델이 원하면 `ppolppol_look_room` 으로 직접 꺼내 볼 수 있다.
- 화면에서는 편하게 **"우리 방의 지난 메모"**라고 부른다.

## 마무리 응답에 함께 싣기 (추가 호출 없음)

산책의 마무리 도구(제안: `ppolppol_finish`, PROTOCOL §3 의 귀가·기억·포스터·마무리 묶음)와 놀이의 마무리 선택에 선택 필드로 싣는다.

```js
{ …, note?: { text, about? }, setDown?: ['cn_…'] }
```

- `note` 와 `setDown` 은 모두 선택이다. 아무것도 안 써도 된다.
- `setDown` 은 관심을 내려놓는다는 모델 자신의 표시다. 코드는 그 메모를 `set_down` 으로 바꾸고 다음 기본 전달에서 뺀다.

## 지금 코드 (2026-11-07 물결 F)

- **들어오기** — app 이 활성 메모 최근 3개를 두뇌에 `state.notes` 로 준다 (`set_down` 은 app 이 빼고, 두뇌도 한 번 더 거른다).
  데모 두뇌는 메모 글을 읽지 않는다. `about.kind: 'node'` 인 방의 길 고르기 가중치만 **3배** (`BRAIN.NOTE_BOOST`) — 곱하기만 하고 새 난수를 뽑지 않는다.
  메모가 없으면 산책은 예전과 바이트 하나까지 같다 (test-brain 이 2000 시드로 잰다). `kind: 'object'` 메모는 아직 길에 쓰지 않는다.
- **나가기 (데모 규칙)** — `plan` 결과의 `noteOut = { text, about, by: 'demo-rules' }`. 글은 그날 메모(`memo.tomorrow`) 그대로, `about` 은 그 글의 '내일은 X 쪽으로' 의 X.
  60자에 맞추느라 '내일은 X' 가 글에서 빠진 날은 `noteOut` 을 만들지 않는다 — 글에 없는 관심을 다음 선택에 쓰지 않게 (MODEL_VOICE §3). 집·빈 차례는 `null`.
  화면은 데모 규칙 메모를 '데모 규칙' 표시 아래에서만 보인다.
- **나가기 (모델)** — `replay` 가 `wrap_up.note` 를 글자 그대로 `noteOut = { text, about?, by: 'model' }` 로, `wrap_up.setDown` 의 문자열 id 를 `setDown` 으로 옮긴다.
  60자가 넘어도 기록은 원문 그대로, 화면만 앞 60자 + `…`. `setDown` 은 모델(`mcp`) 산책에서만 받는다 (사람·데모 규칙은 메모를 내려놓지 않는다). 빈 차례 뒤의 마무리에서도 같다.
  사람(데모 조작) 산책의 메모는 `by: 'human'` 이고, 다시 두뇌에 들어올 때도 `human` 그대로다 (`BRAIN.normalizeNotes`).
- 저장·전달(메모 id·세션·날짜 붙이기, 앨범 '우리 방의 지난 메모', 내려놓기 반영)은 app 몫이다.
