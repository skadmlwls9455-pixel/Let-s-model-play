# 요리 반응 스티커 (COOK_STICKERS)

> 11-08. 부엌(카드 7, `cook.html`)에서 요리하는 동안 **요리사 모자 쓴 문어 스티커**가 톡 떴다 사라진다. 방송 이모트 세트처럼 따봉·만세·한 접시 같은 그림 19종.
> 요리 순간(열기·톡톡·불 켜기·뒤집기·썰기·접시)마다 **자동으로** 뜬다. 요리마다 '요리 스크립트'를 두어 그 요리의 특정 순간에 특정 스티커가 뜨게 할 수 있다.
> 11-15 (5차, 가까이 보기 부엌). 상단 줄 바로 아래 띠의 왼쪽 · 오른쪽 끝에만 뜨고, 띠가 들어갈 자리가 없는 낮은 화면(320×568 등)에서는 띠째 숨는다 (아래 '자리'). 주인 답 (나): 기분 얼굴 7종은 부엌에서 뜨지 않는다.

## 움직이는 스티커

움직여야 뜻이 사는 것만 칸 몇 개짜리 스트립으로 만든다. 지금은 여섯: **짝짝** (맞닿음↔벌림) · **휘휘** (국자 오른쪽↔왼쪽) · **꾸벅** (졸기↔숙임, 느리게) · **퓻** (퍼짐→뿜음→퍼지는 중, 빠르게) · **만세** (번쩍↔내림) · **두근** (분홍이 차올랐다 빠짐). 나머지 13종은 멈춘 그림이 더 이모트답다. 부엌에서 뜨는 것은 짝짝 · 휘휘 · 만세다.

- 그림: `tools/ui-art/cook-stickers.js` 의 `def(id, …, draw, frames)` — `frames` 배열의 칸 0 은 정지 그림과 **같아야** 한다 (검사가 픽셀까지 본다).
- 파일: `assets/stickers/cook/<id>_anim.png` (32×칸 수 · 32), manifest `sticker.cook.<id>.anim` `{ frames, cell: 32 }`. 정지 그림 `<id>.png` 도 그대로 있다.
- 런타임: `CATALOG[id].anim = 칸 수`, `fps` (없으면 4). 칸 단위로 톡톡 넘긴다 (CSS `steps`, 보간 없음). 1.4 초 머무는 동안 짝짝은 세 번쯤, 꾸벅은 한 번 반쯤.
- 모션 줄이기면 정지 그림(칸 0)을 띄운다. 스트립을 못 받으면 정지 그림으로, 그것도 없으면 지운다.

## 자동 발동

순간 이름은 **진짜 부엌 놀이** (`js/cook.js`, docs/COOK_PROTO.md §8) 가 소리 훅 `AUDIO.on('cook', { act, … })` 으로 보내는 act 그대로다.
(11-08 첫 판은 카드 7 의 옛 계획 '재료 떨어뜨려 합치기' 를 보고 `drop`·`merge`·`full` 과 가짜 요리 6개를 두었다. 11-10 에 진짜 놀이의 act 로 전부 바꿨다.)

잇는 법은 둘 중 하나:

```js
COOK_STICKERS.listenAudio();   // (가) cook.js 를 고치지 않는다 — 그 소리 훅을 한 겹 감싸 같은 act 를 듣는다. 원래 소리는 그대로
window.COOK_STICKERS && COOK_STICKERS.cue(act, detail);   // (나) cook.js 가 소리 훅 옆에서 직접 (그러면 (가) 는 쓰지 않는다 — 둘 다 하면 두 번 뜬다)
```

부엌은 (나) 다. `js/cook.js` 의 `sticker()` 가 소리 act 가 붙은 사건마다 그 act 와 detail 을 넘기고, 판을 시작할 때 (`begin()`: 열기 · '다시') `pick` 을 넘긴다. 소리가 꺼져 있어도 같다. `cook.html` 은 `listenAudio()` 를 부르지 않는다 ((가) 는 무대 `.ck-stage` 에 바로 붙어 아래 '자리' 의 띠를 쓰지 않는다).
`cook.html` 은 `css/cook-stickers.css` · `js/cook-stickers.js` 를 `js/cook.js` 뒤에 싣는다. 둘이 없거나 스티커 쪽이 오류를 내도 부엌은 똑같이 논다 (`sticker()` 가 삼킨다. live 검사 K9 · K10).

| act | 언제 | detail | 기본 스티커 |
|---|---|---|---|
| `pick` | 판 시작: 부엌을 열 때 (이어 하는 판도) · '다시' | `{ dish }` | 빼꼼 |
| `tap` | 톡톡 한 번 | `{ i }` 0~8 | 첫 톡 = 바빠 · 가운데(4) = 짝짝 |
| `sizzle` | 불 켬 · 굽기가 바뀜 | `{ band }` 0 · 1 · 2 | 불 켬 = 휘휘·솔솔 · 노릇 · 바삭 = 솔솔·빼꼼 (두 굽기가 같은 묶음) |
| `flip` | 뒤집음 | `{ band }` | 만세·따봉·짝짝 (어느 굽기든 같다) |
| `cut` | 썰기 한 줄 | `{ i }` 0~1 | 첫 줄 = 바빠 |
| `step` | 단계 하나 끝 | `{ kind }` | 따봉·짝짝 (가끔) |
| `quiet` | 소리 내리기 | — | 없음 |
| `done` | 접시 공개 | `{ dish }` | 한 접시·다 됐다 |
| `stir` · `simmer` · `place` | 조각 2 (cook.js 가 아직 안 보냄) | — | 휘휘 · 맛보기 · 솔솔 |
| `serve` · `eat` · `idle` | 본 게임 쪽: 식탁에 차리기 · 냠 · 한참 손 안 댐 | — | 한 접시 · 냠·맛보기 · 꾸벅 |

탭이 숨었다 돌아올 때 cook.js 가 다시 보내는 `sizzle` 은 소리에만 간다 (스티커 없음).

고르는 순서:

1. **요리 스크립트** `RECIPES[요리].cues` — 위에서부터 보고 먼저 맞는 줄 하나.
2. 없으면 **공통 규칙** `RULES`.
3. 줄의 `pick` 이 배열이면 판 시드(FNV-1a + mulberry32)로 고른다. `chance` 도 같은 시드.

조건 키: `on`(act) · `is: { 키: 값 }` · `atLeast` · `atMost` · `nth` · `every` · `once` · `force`.
스티커 사이 쉬는 틈 0.9초, 화면에 최대 3장 (부엌은 자리가 둘이라 두 장, 아래 '자리'). `pick` · `flip` · `done` · `serve` 와 `force` 줄은 틈과 상관없이 뜬다.
요리 스크립트는 `pick` · `done` 의 `dish` (요리 id) 로 정해진다. 부엌은 `pick` 에 요리 판의 시드를 `runId` 로 붙여 넘기므로, 스티커 판 id 가 곧 요리 판의 시드다.

### 요리 스크립트

```js
jeon: { name: '해초전', cues: [
  { on: 'tap', is: { i: 8 }, pick: 'clap', force: true },   // 반죽 다 폄
  { on: 'flip', pick: ['cheer', 'thumbs'] },                // 휙 뒤집음
  { on: 'cut', is: { i: 1 }, pick: 'thumbs' },              // 열십자 다 썲
  { on: 'done', pick: ['heart_plate', 'star'] }             // 접시 공개
] }
```

지금 있는 요리는 해초전 하나다. 조각 2 가 미역국 · 톳 주먹밥을 더하면 그 요리 id 로 `RECIPES` 에 한 덩이씩 더한다 (검사가 act 이름·스티커 id 를 확인한다).

## 자리 (11-15, 가까이 보기 부엌)

부엌은 무대 `.ck-stage` 안에 스티커 띠 `.ck-stick` 하나를 둔다 (`build()`: 캔버스 `ck-cv` · 논리 상자 `ck-sim` 다음 셋째. `aria-hidden`, `pointer-events: none`, 밖으로 넘치는 것은 자른다). 스티커는 이 띠에만 붙는다. 크기 · 자리 · 숨김은 `fit()` 이 정한다 (열 때 · `resize` · `visualViewport` `resize` · `COOK.refit()`).

- **띠.** 상단 줄 (단계 띠 · 닫기) 바로 아래, top = hudB + 4 (hudB = 위 안전 여백 + 64). 너비는 화면 전체, 높이는 스티커 한 장 s = 32·n/dpr CSS px (n = floor(2·dpr)). 스티커 한 칸이 기기 화소 n 개다: DPR 1 · 2 · 3 에서 s = 64, DPR 2.625 에서 s = 60.95 (한 칸 5 기기 px).
- **zoom.** 엔진은 배율 2 (한 칸 = CSS 2 px) 로 그리고, `fit()` 이 띠에 CSS `zoom` n/dpr/2 를 건다. DPR 1 · 2 · 3 에서는 1 이라 걸지 않고, 2.625 에서는 0.952. 띠의 top · 너비 · 높이와 두 자리 값은 zoom 앞 길이 (÷ zoom) 로 넣는다.
- **두 자리.** 0 은 왼쪽 끝 (left = max(8, 왼쪽 안전 여백 + 8)), 1 은 오른쪽 끝 (오른쪽 가장자리가 오른쪽에서 max(8, 오른쪽 안전 여백 + 8)). 둘 다 띠의 top 0. `fit()` 이 둘 다 왼쪽에서 잰 값을 기기 화소에 맞춰 띠의 `--ck-s0` · `--ck-s1` 에 넣고, `css/cook.css` 의 `.ck-stick > [data-slot]` 이 엔진이 넣는 자리 (`js/cook-stickers.js` `slots`: 같은 두 끝을 `calc()` 로 적은 것) 를 `!important` 로 덮는다. 안전 여백은 `.ck-probe` 가 잰 값이다: `env(safe-area-inset-*)` 와 게임 안 창에서 게임이 보낸 `--ck-safe-*` 중 큰 쪽.
- **한 자리에 한 장.** 새 스티커가 찬 자리에 오면 그 자리의 먼저 것을 지운다 (`sticker()`). 부엌에는 한 번에 두 장까지다.
- **숨김.** hudB + 4 + s + 8 ≤ (44 + oy)·css 일 때만 띠를 보인다. 띠 밑 8 px 까지가 무대 그림 44 행 (팬 테두리 46 행 바로 위) 보다 위에 있어야 한다는 뜻이다. 아니면 띠에 `hidden` 이 붙는다. 그래도 스티커는 고르고 띄우지만 보이지 않는다. 지금 보이는지는 `COOK.live().stick`.

| 화면 @DPR | hudB + 4 + s + 8 ≤ (44 + oy)·css | 띠 |
|---|---|---|
| 360×740 @2 | 140 ≤ 198 | 보임 |
| 360×740 @3 | 140 ≤ 208 | 보임 |
| 412×915 @2.625 | 136.95 ≤ 272.38 | 보임 |
| 412×915 @2 | 140 ≤ 270 | 보임 |
| 390×844 @3, 안전 여백 위 47 · 아래 34 | 187 ≤ 252 | 보임 |
| 320×568 @2 · @3 | 140 > 132 | 숨김 |
| 360×560 @2 | 140 > 128 | 숨김 |

- **가리지 않는 것.** 띠는 상단 줄 아래 · 무대 44 행 위에만 있어서 음식 · 톡 표시 · 썰기 안내선 · 손 그림 · 단계 띠 · 닫기 · 아래 단추 (동사 · '다시') 와 겹치지 않는다. 스티커 위를 눌러도 무대가 받는다 (거기서 시작한 쓸기 · 긋기도 뒤집고 썬다).
- **비우기.** 닫을 때와 '다시' 를 누를 때 띠를 비운다 (`unstick()`). 닫혀 있는 동안에는 뜨지 않는다.
- **검사.** `tools/test-cook-stickers-live.js` K2 (s = 32·n/dpr · 두 자리 · 기기 화소 · 여덟 크기에서 보임과 숨김 · 한 자리에 한 장) · K3 (안 가림 · 누름 통과 · 320×568 과 360×560 에서 숨김).
- **캡처** (`docs/shots/cook/`): 이름 끝이 `-360x740` · `-412x915` 인 것은 띠가 보이는 크기, `-320x568` 은 숨는 크기다.

## 지키는 것

- **글자 없음.** 스티커는 그림뿐. 맛 평가·취향 말을 코드가 쓰지 않는다 (카드 7 금지 낱말 검사를 이 파일에도 건다). 대체 글은 그림 설명("엄지 척 하는 요리사 문어 스티커")이지 문어의 말이 아니다.
- **장식이지 문어의 반응 기록이 아니다.** 요리는 주로 문어가 산책 간 동안 하므로, 스티커를 '문어가 지금 이렇게 느꼈다'로 쓰지 않는다. 기록(`COOK_STICKERS.log()`)은 `by: 'demo-rules'` 이고 문어 기록(`trips`) · 두뇌 입력 · 모델 요청에 넣지 않는다 (CORE_LOOP_V2 약속 2).
- **기분 얼굴 없음** (11-15 주인 답 (나)). 감동 `moved` · 뿅 `love` · 두근 `flush` · 깜짝 `shock` · 퓻 `ink` · 갸웃 `hmm` · 진땀 `sweat` (`COOK_STICKERS.FEELINGS`) 은 부엌 순간 (`pick` · `tap` · `sizzle` · `flip` · `cut` · `step` · `done` · `quiet`) 이 닿는 공통 규칙 · 해초전 줄 어디에도 없다. 문어가 무엇을 느꼈다고 비치는 그림이라서다. 그림 파일 · CATALOG · 엔진은 그대로 둔다. 검사: `test-cook-stickers.js` (줄마다 · 1200 판에 0 장) · live K1.
- **벌 없음.** 굽기(부드럽게·노릇·바삭)는 고르는 것이지 맞고 틀림이 아니다 — 어느 굽기로 뒤집어도, 굽기가 바뀔 때도 같은 묶음에서 뜬다 (11-10 주인: 굽기가 바뀔 때는 노릇 · 바삭 모두 솔솔 · 빼꼼만. 맛보기는 맛봤다고 읽혀서 굽기에서는 저절로 뜨지 않는다). 우는 그림은 '감동'(반짝 눈물)뿐이고, 그것도 부엌에서는 뜨지 않는다.
- **시드.** 같은 판 id + 같은 순간 순서 = 같은 스티커. 시드 없는 난수 0건 (검사).
- **모션.** 등장 250 ms (6px 아래 → 2px 넘침 → 제자리) · 머묾 1.4 s · 퇴장 180 ms. 픽셀 그림이라 배율 대신 이동. 모션 줄이기(`data-motion="reduce"` 또는 OS 설정)면 투명도만.
- 그림이 안 오면 그 스티커를 지운다 (이모지로 대신하지 않는다). 번들(`dist/`)은 `ASSETS_INLINE['sticker.cook.*']` 를 쓴다.
