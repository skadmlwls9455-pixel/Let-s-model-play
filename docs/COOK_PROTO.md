## 0. 한눈에

- 폰으로 `cook.html` 을 열면 (게임에서는 놀이방 조리대를 톡) 바로 해초전 요리다: **톡톡 → 뒤집기 → 썰기** → 접시. 고르는 화면이 없다. 하다 만 판이 있으면 그 단계 처음부터 이어 한다.
- 단계마다 그 자리를 위에서 가까이 본 그림 하나가 화면을 가장자리까지 채운다 (전이 화면 너비의 69~73 %). 단계가 바뀌면 화면이 옆으로 미끄러진다: 조리대 (톡톡) → 화구 (뒤집기) → 도마 (썰기) → 접시. 다 되면 접시가 크게 놓이고 그림 단추 둘만 남는다: 다시 (새 판, 조리대로 미끄러져 돌아온다) · 닫기.
- 화면에 글자가 없다 (글자 · 숫자 · 이모지 · 기호 0). 닫기 · 다시 · 동사는 픽셀 그림 단추이고, 이름은 aria-label 과 숨은 aria-live 줄에만 있다.
- 실패 · 점수 · 시간 제한 · 메달이 없다. 진행은 오르기만 한다. 기다려도 타지 않는다.
- 소리가 꺼진 것이 기본 경우다 (켜면 §8 의 소리가 난다). 센 입력마다 **바로 다음 프레임**에 무대가 바뀐다 (밝은 테두리 · 찌그러짐 · 부스러기 · 남는 자국). 진동은 기본 켬이다: 웹 진동이 되는 폰에서 톡 · 불 켜기 · 뒤집은 전의 착지 · 한 줄 썰기에 아주 짧게 (§5. 접시가 놓일 때는 울리지 않는다 — 주인: 요리 톡 · 뒤집기 · 썰기). 본 게임 설정 › 화면 › 진동 으로 끈다 (그 줄은 웹 진동이 되는 기기에만 있다). 아이폰 사파리는 웹 진동이 없어 아무 일도 없다.
- 손이 먼저다. 동사 칩 (아래 가운데 그림 단추) 은 늘 있지만 터치에서는 조용하다 (`opacity 0`, 자리는 그대로). 5초 멈추면 흐린 손 그림이 한 번 나오고, 그때부터 칩이 보인다. 키보드면 처음부터 보이고 포커스를 받는다. **조용한 칩 자리를 손가락 · 마우스로 누르면 칩이 드러나기만 하고 동작은 하지 않는다** (빗맞은 톡이 전을 뒤집지 않게). 그 자리에서 시작한 획은 무대 입력이라 아래에서 올려 쓸어도 뒤집힌다. 포인터 누름 없는 클릭 (키보드 · 화면 읽기) 은 바로 동작한다.
- 저장 키는 따로다: `cook.html` 은 (게임 안 창에서도) `ppolppol_cook_v0`. `COOK.open` 에 키를 주지 않으면 `ppolppol_cook`. 본 게임 기록에는 쓰지 않는다 (읽는 것은 따로 연 쪽 머리 스크립트가 보는 글꼴 설정 `pixelFont` 하나, §9).

## 3. 단계 종류 (판정 요약)

거리는 논리 px (무대 288 × 320 = 아트 px × 2), 시간은 단계 시계 ms. 진행은 오르기만 한다. 손 떼기 · `pointercancel` · 엉뚱한 방향은 아무것도 깎지 않는다.

판정은 4차 그대로다 (`TUNE` 바이트 그대로, §4). 달라진 것은 화면 위 크기뿐이다: 가까이 보기에서 아트 px 하나가 CSS 4~5 px 라 (320 × 568 은 4, 360 × 740 @2 는 4.5, 412 × 915 @2.625 는 약 4.95, @2 · @3 은 5. §5) 같은 판정이 손가락에는 4차 (360 × 740 에서 CSS 2 px) 의 2~2.5 배로 크게 잡힌다. 아래 괄호는 4 / 4.5 / 5 배일 때의 CSS px 다.

## 5. 화면 · 배치 · 포커스

- **창** (`build()`): `dialog#cook-dlg.ck-dlg` (aria-label 해초전) 하나가 화면을 가득 채운다 (`position: fixed; inset: 0`, 100dvh, 틀 · 그림자 · 애니메이션 없음, 바탕과 `::backdrop` 은 `#a8b5b2`). 안에는 `.ck-stage` (모든 포인터 처리, tabindex -1: `canvas.ck-cv` · 보이지 않는 논리 288 × 320 상자 `.ck-sim` · 스티커 띠 `.ck-stick`), `.ck-hud` (단계 띠 `.ck-strip` · `button.ck-close`), `button.ck-verb` (칩), `.ck-note` (잠든 쪽지), `p.ck-say` (숨은 aria-live), `.ck-probe` (안전 여백을 재는 보이지 않는 상자). `title` 속성은 하나도 없다. 부엌은 늘 밝다 (밤 색 없음).
- **배치** (`fit()`: 열 때 · `resize` · `visualViewport` 의 `resize` · `COOK.refit()`). 수치는 `js/cook.js` 의 `LAY` 에 있다 (TUNE 밖이라 저장된 판은 그대로 유효하다):

```
vw, vh       창의 clientWidth, clientHeight (visualViewport 가 더 낮으면 그 높이)
safeT/R/B/L  .ck-probe 의 계산된 padding = max(env(safe-area-inset-*), var(--ck-safe-*)), 0~200 CSS px
hudB    = safeT + 64                             8 + 48 + 8
chipTop = vh - safeB - 16 - 64
k    = max(1, min(floor(vw·dpr/80 + .01), floor((chipTop - hudB)·dpr/104 + .01), floor(6·dpr + .01)))
css  = k / dpr                                   아트 px 하나 = 기기 px k 개 (보이는 너비 약 80 아트 px, 아트 px 하나는 CSS 6 px 까지)
W, H = ceil(vw / css), ceil(창 높이 / css)        W·css · H·css 가 정수 CSS px 가 될 때까지 4 아트 px 안에서 늘린다 (안 되면 그대로)
ox   = round(vw / 2 / css) - 72                  음식 중심 x 72 → 화면 가운데
oy   = round((hudB + chipTop) / 2 / css) - 80    무대 28..132 줄 (볼 곳) 의 가운데 80 → HUD 와 칩 사이 가운데
STRIDE = W + 8                                   미끄러짐 거리 (아트 px)
```

### 5.1 그림이 받는 값 (기름 방울 · 김 · 윤기 · 가까이 본 접시)

`COOK_ART` 의 장면 그림은 받은 값만으로 그린다 (안에 남는 것은 캐시뿐이다): 같은 값을 주면 같은 바이트가 나온다. 불 위의 기름 방울 · 김 · 윤기와 접시가 쓰는 프레임 수는 `js/cook.js` 의 `fxNow(run, t)` 가 그릴 때마다 다시 센 정수다. 한 칸은 12 fps 한 프레임 (83 ms) 이다.

| 값 | 뜻 | 언제 있나 |
|---|---|---|
| `seed` | 그 판의 그림 시드 (`fxSeed(run.seed, 0)` 의 아래 31비트). 뒤집기 장면 (화구) · 썰기 장면 (도마) · 접시 공개, 미끄러질 때의 `base` · `carry` 가 같은 값을 받는다. 톡톡 장면은 받지 않는다 | 판이 있는 동안 늘 |
| `fh` | 불 켠 뒤 지난 프레임 수 | 뒤집기 단계에서 불이 켜져 있을 때 |
| `fbc` | 굽기가 마지막으로 바뀐 뒤 프레임 수 | 뒤집기 단계에서 굽기가 1 · 2 일 때 |
| `fl` | 뒤집은 전이 내려앉은 뒤 프레임 수 | `L.landAt` (뒤집은 때 + 3프레임 = 호의 착지 그림) 부터, 화구와 도마에서만. 48 (4 s) 에서 멈춘다 |
| `t` | 접시 공개가 시작된 뒤 프레임 수. `revealScene` 은 `geo: 'close'` 와 함께 받는다 (가까이 본 접시 `GEO.rev2`) | 접시 공개 (`L.revealAt` 부터). 동작 줄이기면 없다 |

| t | 보이는 것 |
|---|---|
| 0~2 | 도마 → 접시 미끄러짐 (§5). 썬 전을 들림 2 로 들고 간다 (`carry('cut')`) |
| 3 | 접시 위 들림 2 + 체크 그림자. 도마의 마지막 프레임과 같은 모양 (고명 없음) |
| 4 | 들림 1 |
| 5 (417 ms) | 내려앉음: 놓인 모양 (시드로 조각을 조금씩 밀고 고명 8), 1프레임 찌그러짐 (rx + 2 · ry - 1), 화면 전체 1 px 흔들림 (5 · 6), 접시 소리 (`done` act 의 +0.4 s, §8). 진동은 없다 (5차 검증 O-5) |
| 6 부터 | 쉼: 김 · 반짝임 둘 · 가끔 번쩍임, 96프레임마다 되풀이 |
| `null` | 쉬는 그림 (동작 줄이기 · 시험) |

- 없는 값은 `null` 로 가고, 그래도 모든 장면이 그려진다 (`js/cook-art.js` 머리 주석의 `FOOD` 칸). 고른 상태의 그림은 96프레임 (8 s) 마다 되풀이된다.
- 입력이 없을 때 다시 그릴지는 `frameSig(t)` 가 정한다: 12 fps 눈금, 반응 · 입자 · 손 그림 · 미끄러짐 저마다의 프레임 수, 위의 `fh` · `fbc` · `fl` · `t` 가운데 하나라도 바뀌면 그린다. 카운터마다 제 사건에서부터 세므로 프레임 하나하나가 한 번씩 그려진다 (한 프레임을 두 번 보이고 다음을 건너뛰지 않는다).
- `L.landAt` 은 썰기 단계로 넘어가도 남는다 (첫 단계나 뒤집기 단계를 시작할 때만 지운다). 그래서 착지 때 피어오른 김이 도마 위에서 이어진다 (`fl` 36 까지).
- 김이 밝은 바탕 (화구 에나멜 · 도마) 을 지날 때는 한 단계 밝은 체크 베일이다: 꼬리 선은 한 단계 밝게, 몸통은 그 50 % 체크, 테는 그리지 않는다 (5차 검증 K-4: 화구 위에서는 하얀 `#fffef2` 한 줄로 그려져 S · C · < 처럼 보였다). 팬 · 기름 위의 김은 그대로다.
- 동작 줄이기: `f` 는 0, `still` 은 참이고, 이 카운터들로는 다시 그리지 않는다. 그림은 멈춘 한 장이다 (자리 잡은 방울 몇 개 · 멈춘 김, 반짝임 없음, 접시는 쉬는 그림).
- 색: 음식 · 장 · 기름 · 반짝임 · 김만 음식 색 `FOOD` 24 색을 쓰고, 소품 (팬 · 화구 · 도마 · 칼 · 뒤집개 · 접시 · 손 그림 · HUD 아이콘) 은 Apollo 46 색에 남는다. 알파는 0 아니면 255 다 (시험 16 · 17).

## 6. 저장

```js
localStorage[storeKey] = { v: 1, day: 'YYYY-MM-DD', dayN: 3, seen: ['tap', 'flip', 'slice'],
  pot:    null | { ver: 'cook-1', tune: 2827089308, runId, seed, recipe, swaps, si, looks: [...], tags: [...], at },
  potOld: [ { … }, … ],   // 있을 때만: 이어 하지 못한 판을 그대로 (최근 것이 앞, 최대 4개)
  book:   [ { id: 'ck_…', recipe, seed, swaps, look, day, madeAt } ] }   // 최근 것이 앞, 최대 300줄
```

- 판(`pot`)은 **단계 경계**에서만 쓴다: 새 판을 열 때 바로 (열기 · 다시), 단계가 끝날 때, 탭이 숨을 때 (`visibilitychange`), `pagehide`, 닫기, [보러 가기]. 이어 하면 지금 단계를 처음부터 한다 (끝난 단계의 모양은 그대로).
- **11-18 고른 요리와 판** (`begin`, '다시' 가 아닐 때): 단계를 하나라도 끝낸 판 (`si ≥ 1`) 이 이어지면 무엇을 골랐든 그 판이 이긴다 (두 탭 · 주소에 친 `?recipe=` 가 진행을 치우지 않게). 아니면, 고른 요리가 있을 때: 그 요리의 빈 판 (`si 0`) 은 이어 하고 (같은 시드), **다른 요리의 빈 판은 바이트 그대로 `potOld` 로** 옮기고 고른 요리를 새로 연다. 고른 요리가 없으면 이어지는 판이면 무엇이든, 없으면 해초전. '다시' 는 지금 요리를 한 번 더. 판의 `tune` 은 그 요리의 `tuneOf` (§2).
- **열 때** (`begin`): 판이 맞으면 (`resumeRun`) 미끄러짐 없이 그 단계의 자리에서 이어 한다. 맞지 않으면 (`ver` · `tune` · 레시피 · 시드 · `swaps` · `si` · 모양 · `tag` · 판 id 가운데 하나라도 틀리거나 깨짐) 그 판을 바이트 그대로 `potOld` 맨 앞에 넣고 (`[pot].concat(potOld).slice(0, 4)`) `pot` 을 비운 뒤 새 판을 연다. `potOld` 의 판은 이어 하지 않고 내보내지 않으며, 가져오기도 건드리지 않는다. 수첩은 그대로다.
- `normStore` 는 `potOld` 에서 보통 객체인 칸을 크기와 상관없이 앞에서 4개 남기고, 객체가 아닌 칸 (글 · 배열 · 숫자) 은 버린다. 남는 칸이 없으면 열쇠를 두지 않는다. `'{{{'` 는 여전히 6 열쇠 기본값이다. 5차 검증 O-6: 예전에는 JSON 이 2048 바이트가 넘는 칸도 버려서, 2 KB 가 넘는 판은 `potOld` 로 갔다가 다음에 읽을 때 사라졌다 (기록은 잃지 않는다는 규칙). 지금은 바이트 그대로 남는다. 객체가 아닌 판 (글 · 배열) 은 `pot` 자리에서부터 남지 않는다 (게임이 쓰는 판은 늘 객체다. §14).
- **새 판** (열기 · 다시): `dayN` + 1 (날이 바뀌면 처음부터, 첫 판이 1), 시드 = `hash32(day + '|cook|' + dayN)` (`?seed=` 면 그 값), 판 id = `'ck_' + hash32(day|dayN|난수).toString(36)` (`crypto.getRandomValues`, 없으면 수첩 줄 수). **시작 시각은 쓰지 않는다**: 수첩 줄에 `madeAt` 이 같이 있어서, 시작 시각이 id 에 들어가면 걸린 시간을 거꾸로 찾을 수 있다 (설계 §4.2 의 `startedAt` 에서 바꿈, 주인 확인 거리). 날짜는 로컬, 시험은 `window.__ppolTest.today`.
- 마지막 단계가 끝나면 (`step`, 접시 공개 400 ms 전) 판을 지우고 수첩에 한 줄을 넣는다. 수첩 화면은 조각 2 에 온다 (조각 1 에는 수첩을 볼 곳이 없어서 "요리 수첩에 넣었어." 도 아직 말하지 않는다).
- 저장 키는 부엌 것만 받는다: `ppolppol_cook` 또는 `ppolppol_cook_…` (`cook.html` 은 게임 안 창에서도 `ppolppol_cook_v0`). 다른 키를 넘기면 `ppolppol_cook` 을 쓴다. 본 게임 저장 키는 읽지도 쓰지도 못한다.
- 저장이 실패해도 (사생활 모드 · 가득 참) 놀이는 그대로다. 오류 글 없음.

결과 봉투 (`onResult` 로 넘긴다; `ms` 는 늘 `null`, `status` 는 `done` 만):

```js
{ v: 1, id: 'ck_…', by: 'user', game: 'cook', status: 'done', ms: null,
  out: { dish: { id: 'jeon', name: '해초전', tier: 1, ingredients: ['batter', 'parae'] },
         recipe: 'jeon', seed, swaps: { herb: 'parae' },
         steps: [{ kind: 'tap', status: 'done', tag: null }, { kind: 'flip', status: 'done', tag: 'golden' }, { kind: 'slice', status: 'done', tag: 'straight' }],
         look: { v: 1, dents: [[x, y] …], band: 1, cuts: [0, -6], offs: [2, -1], plate: 1 }, madeAt, day } }
```

## 8. 소리 (act 표 · 무엇이 나나)

부르는 곳은 하나다: `window.AUDIO && AUDIO.on && AUDIO.on('cook', { act, … })`. 입력 처리기 안에서 바로 부른다 (한 프레임 늦지 않게). 시간으로 생기는 것 (굽기가 바뀜 · 꾹 자동 톡 · 접시 공개) 은 그 프레임에 부른다. 실패 · 빗나감 소리는 **없다**. 받는 곳은 `js/audio.js` 의 `case 'cook'` (`onCook`) 이고, 무엇을 틀지는 `foley/manifest.json` 의 `map.cook` 표가 정한다 (녹음 소리 층. 칩튠 한 벌 `audio/` 와 따로). cook.js 는 부르기만 한다: `AUDIO` 가 없거나 소리가 꺼져 있으면 조용히 논다. 11-15 가까이 보기는 `js/audio.js` · `foley/` · act 이름을 바꾸지 않았다.

| act | 언제 | 덧붙임 | `js/audio.js` 가 트는 것 (`foley/cook/` 의 소리 이름) |
|---|---|---|---|
| `pick` | 판을 열 때 (새 판 · 이어 하기 모두) 와 다시 때 | `{ dish: 'jeon' }` | `cook_pick` 한 번 (팬 들기). 열 때는 보통 소리가 아직 잠겨 있어 버려진다 (아래 '켜기') |
| `tap` | 톡톡에서 센 한 번 (손 · 꾹 · 칩 모두) | `{ i }` 0~8 | `cook_pat` 한 번 (변형 4개 중 바로 앞에 고른 것과 다른 것). `i` 따라 빠르기가 조금씩 올라 9번째가 +3 반음 |
| `sizzle` | 불 켤 때 (`band` 0) · 굽기가 바뀔 때 (1, 2) · 숨었던 탭이 돌아왔는데 불이 아직 켜져 있을 때 (지금 굽기) | `{ band }` | 굽기마다 다른 루프 `cook_sizzle_0` · `_1` · `_2` (귀로 고르는 길). 불 켜기: `cook_heat_on` 한 번 + 루프를 1 s 에 올린다. 굽기가 바뀜: 다음 루프로 0.15 s 크로스페이드 + '치익' (새 루프가 +4 dB 까지 올랐다가 0.5 s 에 제 크기로). 탭 복귀: `cook_heat_on` 없이 루프만 0.3 s 에. 같은 굽기가 이미 돌면 아무것도 안 한다 |

| `ding` | 6차 (11-18): 뒤집기 단계에서 노릇노릇이 되는 순간 (`band` 1 사건, 뒤집기 단계마다 한 번) | — | 파일 없이 `js/audio.js` 가 만든 '띵' (`ckDing`, 아래) 한 번. 부엌 목록 (`foley/manifest.json`) 을 기다리지 않는다 |
| `cut` | 썰기 한 줄이 잘림 | `{ i }` 0~1 | `cook_cut` 한 번 (변형 3개) |
| `step` | 단계 하나 끝 | `{ kind }` | `cook_step` 한 번 (작은 나무 톡). 뒤집기 단계 끝의 것은 철퍽 0.1 s 뒤로 미룬다. 철퍽은 뒤집기 소리가 정말 난 때부터 잰다 (파일이 늦게 와도 톡이 철퍽보다 먼저 나지 않는다). 뒤집기 소리가 버려졌으면 (처음 받느라 0.3 s 넘게 늦음 등) 이 톡도 내지 않는다. 뒤집기 파일을 둘 다 못 받아 고를 변형이 없을 때도 같다 |
| `quiet` | 단계 끝마다 (뒤집음 뒤에도), 탭 숨김, 닫기, [보러 가기] | — | 도는 루프를 0.25 s 에 내리고 멈춘다. 한 번짜리 소리는 끝까지 울린다 (뒤집은 바로 뒤의 `quiet` 에는 루프만 내려가고, 뒤집기 소리 안의 잦아드는 지글 꼬리가 이어 울린다). 파일은 없다 |
| `done` | 접시 공개 | `{ dish: 'jeon' }` | 접시가 놓이는 때 (+0.4 s = 가까이 본 접시의 t 5) `cook_plate` (변형 2개) + 0.15 s 뒤 `cook_steam`. 동작 줄이기면 바로 |
| `stir` · `clink` · `simmer` · `place` · `lift` · `back` | **cook.js 가 아직 보내지 않는다** (조각 2 몫: 젓기 · 올리기) | — | 표와 파일만 먼저 있다: `cook_stir` (변형 3개) · `cook_clink` · `cook_simmer` (루프, `quiet` 로 멈춤) · `cook_place` (변형 2개) · `cook_lift` · `back` = `cook_lift` 를 절반 크기로 |

해초전 한 판의 순서 예: `pick` → `tap` × 9 → `step` `quiet` → `sizzle(0)` → `sizzle(1)` `ding` → `flip` → `step` `quiet` → `cut` → `cut` → `step` `quiet` → `done` (다시 → `pick` 부터 새 판).

- **'띵' (6차, 11-18)**: 새 파일 · 새 출처 · 받기가 없다 — 문 끼익처럼 `js/audio.js` 가 소리를 켰을 때 한 번 만들어 둔다 (`makeDing`, 모노 0.9 s: C6 1046.5 Hz (1.0, 감쇠 0.32 s) + C7 2093 Hz (0.35, 0.18 s) + 2888 Hz (0.15, 0.08 s), 2 ms 어택, 한 극 LPF 7 kHz, 끝 30 ms 페이드, 크기는 문 끼익과 같은 RMS 맞춤으로 `cook_step` 쯤 (rel -16 dB), 피크 -3 dBFS 아래). `onCook` 에서 `active()` 바로 뒤, 부엌 목록 차례 앞에서 `ckDing` 으로 가므로 `foley/manifest.json` 을 못 받아도 운다. 늦음 규칙은 다른 한 번짜리와 같다 (0.3 s 넘게 늦으면 버림). 부엌 한 번짜리 길 (`ckShot`: 효과음 버스 · 부엌 덕킹). 꺼져 있거나 잠겨 있으면 버퍼도 AudioContext 도 만들지 않는다 (잠금 전에 온 것도 기억하지 않는다). 진동은 없다.
- **미리 받기 (`COOK_NEXT`)**: act 가 오면 곧 쓸 소리의 바이트를 미리 받는다. 6차: `open` (부엌 층을 처음 받을 때) 에 `cut` 을 더했고 (과일 꼬치는 썰기로 시작한다), `cut` 다음에 `place` · `step` · `done` 을 받는다 (과일 꼬치: 썰고 꽂고 접시, 뒤집기 없음).
- **간격**: cook.js 는 같은 act 를 120 ms (`TUNE.sndGapMs`) 안에 다시 보내지 않는다. `tap` · `step` · `done` · `pick` · `quiet` 은 이 문을 거치지 않는다 (`js/cook.js` 의 `SND_FREE`. 손과 꾹으로 센 톡은 이미 90 ms 이상 떨어져 있다). 지금 이 문에 걸리는 것은 `sizzle` · `flip` · `cut` 이다. 받는 쪽에도 소리마다 최소 간격이 있다 (`foley/manifest.json` 의 `min_gap_ms`: 톡톡 80 ms · 썰기 120 ms 등). 그래서 칩 한 번은 `tap` 을 세 번까지 한꺼번에 보내지만 소리는 한 번 난다 (변형은 셋을 고르지만, 간격 문이 버린 둘은 '바로 앞에 고른 것' 으로 남지 않는다. 그래서 칩 길에서도 같은 변형이 이어 들리지 않는다). 끝내 틀지 않은 고르기는 어느 길이든 그렇게 되돌린다: 간격 문 · 동시 한도 · 처음 받느라 늦어서 버림 · 못 받음, 그리고 변형이 둘뿐인 뒤집기도.
- **켜기**: 소리는 꺼진 것이 기본이다. 본 게임 설정에서 소리를 켜 두었거나 (같은 저장 `ppolppol_audio`), `cook.html?sound=1` 로 열었을 때만 난다. `?sound=1` 은 그 쪽에서만 켜고 저장하지 않는다 (본 게임의 설정은 그대로다). 어느 쪽이든 소리는 첫 손길 (누름 · 키) 뒤에 난다: 그 전에는 `AudioContext` 를 만들지 않는다. 소리가 풀리기 전에 온 한 번짜리 act 하나는 기억했다가 풀린 뒤 0.3 s 안이면 튼다. 열 때의 `pick` 은 첫 손길이 보통 그보다 늦어서 버려지고, 첫 소리는 그 손길의 소리다 (톡톡이면 `cook_pat`, 뒤집기 단계를 이어 하면 불 켜기: 시험 I · H. 5차 설계 R13). 다시 때의 `pick` 은 이미 풀려 있어 바로 난다. 소리가 켜지는 순간 불이 켜져 있으면 그 굽기의 지글부터 난다. `file://` 로 열면 늘 조용하다.
- **필요할 때만 받는다**: `foley/manifest.json` 은 부엌 소리가 처음 필요할 때 받는다 (켠 채로 부엌 act 가 올 때, 켜는 순간 부엌이 열려 있을 때, 켜 둔 채 부엌 쪽을 열 때). 본 게임만 하면 `foley/` 요청이 없다. 켜 둔 채 (또는 `?sound=1` 로) 부엌 쪽을 열면 첫 손길 전에 목록 둘 (`audio/` · `foley/`) 과 `pick` · `tap` · `step` 소리의 바이트만 받아 두고, 그 뒤로는 곧 쓸 소리를 한 걸음 먼저 받는다 (`tap` 때 불 켜기 · 지글 0, `sizzle` 때 지글 1 · 2 · 뒤집기, `flip` 때 썰기 · 접시 · 김). 해초전 한 판이 받는 부엌 소리는 19개다 (`.ogg` 로 약 360 KB, `.m4a` 로 약 440 KB). 목록을 못 읽으면 부엌 소리 없이 놀고, 1분 동안은 다시 받지 않는다. 본 게임의 소리 목록 (`audio/manifest.json`) 을 못 읽으면 (쪽을 열 때와 첫 손길, 두 번) 소리 없이 놀고 `AudioContext` 를 쉬게 둔다 (그 순간의 상태가 `running` 인지 묻지 않고 멈추고, 쉬는 중에 뒤늦게 `running` 이 되면 다시 멈춘다). 그 뒤 1분이 지난 손길이 다시 받아 보고, 되면 새로고침 없이 소리가 켜진다 (`cook.html` 에는 켜고 끄는 곳이 없어서 이 길뿐이다. 본 게임에서는 '켜기' 칸을 껐다 켜면 바로 다시 받고, 칸을 그대로 두어도 같은 1분 뒤의 손길이 다시 받는다: 켜 둔 채 새로고침했든 칸을 방금 켰든). 처음 받느라 0.3 s 넘게 늦은 한 번짜리 소리는 버린다 (불 켜기 소리만 1 s 까지 기다린다).
- **파일 형식**: 소리마다 `.ogg` (Opus) 와 `.m4a` (AAC) 둘이다. 브라우저가 Opus 를 틀 수 있다고 하면 `.ogg`, 아니면 `.m4a` 를 받는다. `.ogg` 를 못 받거나 못 풀면 그 소리를 `.m4a` 로 한 번 더 받고, 그것이 되면 그 뒤로는 모두 `.m4a` 다. 그래도 못 튼 변형은 한동안 빼고 고른다 (변형 둘 중 하나가 없어도 조용한 뒤집기가 없게).
- **음악 내리기** (`ckBed`): 소리를 켠 `cook.html` 에서는 본 게임의 집 음악과 환경음도 같이 흐른다 (날씨를 넘기지 않아 늘 비 오는 날 것). 부엌이 열려 있으면 음악 -6 dB · 환경음 -9 dB, 지글 (조각 2 의 보글도) 루프가 도는 동안은 -10 dB · -13 dB 로 내린다. `quiet` 뒤에는 앞의 값으로, 부엌을 닫으면 제자리로 돌아온다 (내릴 때 약 0.8 s, 올릴 때 약 1 s). 효과음 크기가 0 이면 내리지 않는다. 부엌 목록 (`foley/manifest.json`) 을 못 받았을 때도 내리지 않는다 (부엌이 낼 소리가 없다. 목록이 오면 그때부터 내린다). 징글이 음악을 내리는 것과는 다른 노드라 서로 덮지 않는다. 이 크기는 주인이 아직 듣고 정한 것이 아니다 (§14).
- **그 밖**: 크기는 효과음 슬라이더 (`sfx_event`) 와 밤 마스터 (-3 dB) 를 따른다. 모르는 act 는 조용히 지나간다. 파일이 없거나 못 풀어도 놀이로 오류를 던지지 않는다 (부엌 소리 없이 끝까지 논다).

## 9. 본 게임에 잇기 (11-15: 게임 안 창)

부엌은 따로 쪽 (`cook.html`) 그대로이고, 게임은 그 쪽을 화면 가득한 창 안에 띄운다. `index.html` 은 `cook.js` 를 싣지 않는다.

- **11-18 6차 요리 쟁반** (`<dialog id="dish-pick" aria-label="요리 고르기">`): 조리대를 누르면 `openCook` 이 먼저 `mealBusy()` (M, 문어를 부르는 동안 참) 면 아무것도 안 하고, 부엌 저장 (`ppolppol_cook_v0`) 을 **읽기만** 해서 (`cookPot()`) 이어 갈 판 — 보통 객체 · `ver 'cook-1'` · 아는 요리 · `tune === COOK_TUNES[recipe]` · `si ≥ 1` — 이면 쟁반 없이 바로 그 판으로. 그 밖 (판 없음 · 빈 판 `si 0` · 옛 판 · 깨진 판) 은 쟁반: 종이 칩 셋 (64 × 64, 틈 16, 아래 `max(16, 안전 + 16)`), 16 × 16 그림 (`assets/icons/dish/*.png`, `node tools/make-dish-icons.js`) 을 `floor(3·dpr)` 기기 px 배로, `aria-label` 해초전 · 주먹밥 · 과일 꼬치, 보이는 글자 0 · `title` 없음, 투명 배경. 칩 밖 톡 · Esc · 뒤로 = 닫기 (포커스는 조리대 단추). 키로 열면 첫 칩에 포커스. 칩을 고르면 쟁반을 닫고 `openCook(opener, kbd, recipe)`. 게임은 `js/cook.js` 를 싣지 않아서 `COOK_TUNES` (`jeon 2827089308 · jumeokbap 1403436335 · kkochi 3381042548`) 를 `js/app.js` 에 적어 둔다 (스모크 Z 가 부엌의 `COOK.tuneOf` 와 같은지 본다). 빈 판을 세지 않는 까닭: 부엌은 요리를 시작하자마자 `si 0` 판을 쓰고 닫을 때 저장하므로, 그것까지 세면 거의 늘 쟁반이 안 뜬다.
- **11-18 못 열린 부엌** (점검 rel-01): `ready` 를 기다린 지 300 ms 가 지나면 덮개 위에 기어가는 문어 (로딩 그림 한 칸, `round(2·dpr)` 기기 px 배) 와 게임 쪽 닫기 단추 `#cook-close` (부엌 안 닫기와 같은 그림 `assets/icons/dish/close.png`, `aria-label` 닫기, 오른쪽 위 안전 여백 안) 가 뜬다. `ready` 가 오면 둘 다 사라진다. 6 초 안에 안 오면 덮개를 닫고 토스트 '부엌을 못 열었어. 다시 눌러 줘.'. `ready` 전에 덮개가 닫히면 iframe 을 `about:blank` 로 멈추고 (늦게 열려 판을 쓰지 않게), 다음 열기는 주소를 새로 넣는다. 저장은 그대로다.
- 놀이방 조리대 단추 `#btn-cook` (`aria-label="부엌"`) → `js/app.js` `openCook`: 화면 가득한 `<dialog id="cook-overlay">` 안에 `cook.html?embed=1` iframe 을 (처음 열 때 하나) 만들고 연다. 놀이방에 있을 때만 열린다. 닫으면 놀이방 그대로, 포커스는 `#btn-cook` (손가락으로 닫았으면 테 없이).
- `?embed=1` 쪽: 문 단추와 크레딧 링크를 숨기고 열자마자 부엌을 연다. 5차 검증 K-1: `<head>` 의 작은 스크립트가 `<body>` 를 읽기 전에 `ck-embed` 와 `ck-boot` (따로 연 쪽에서도 첫 열기 전엔 문을 숨김) 를 붙여서, 스크립트를 받는 동안에도 문 · 링크가 한 프레임도 그려지지 않는다. 그동안 보이는 것은 `#d7b594` 한 색이다 (게임의 `dialog.cook-overlay` 와 iframe 쪽 바탕이 같은 색, 어두운 모드에서도). 게임은 주소에 `&reduced=1` (게임 설정 모션 줄이기) · `&kbd=1` (조리대를 키로 열었을 때) 을 붙인다. 저장 키는 따로 연 `cook.html` 과 같은 `ppolppol_cook_v0` (같은 판 · 수첩 · `seen`). 소리 · 진동 설정도 같은 저장 (`ppolppol_audio` · `ppolppol_haptics`). 본 게임의 기록 · 내보내기 · 불러오기 · 처음부터는 부엌 키를 건드리지 않는다.
- 메시지 (`{ ppolCook: … }`, 부모 창과만, 출처를 본다):

| 방향 | 메시지 | 언제 |
|---|---|---|
| 부엌 → 게임 | `ready` | 쪽을 다 읽고 부엌을 연 뒤 |
| 부엌 → 게임 | `close` + `kbd` | 부엌이 닫혔다 (닫기 · Esc · 뒤로). `kbd` 는 `onClose({ kbd })` 그대로 (§7). 게임이 창을 닫고, 키로 닫혔으면 조리대 단추의 테를 남긴다 |
| 부엌 → 게임 | `result` + `v` `id` `recipe` `seed` `look` `day` (11-18) | 접시 공개 때 한 판에 한 번 (`onResult`). 게임은 `typeof mealDish === 'function'` 이면 `mealDish(d)` (M: 식탁에 놓기). 공개와 메시지 사이에 쪽이 죽으면 요리는 부엌 수첩에만 남는다 |
| 게임 → 부엌 | `open` + `kbd` + `recipe` (11-18) | 다시 열 때 (하다 만 판이면 이어 하기). `recipe` 는 쟁반에서 고른 요리 (처음 열 때는 주소 `&recipe=`). `cook.html` 은 열 때마다 `recipe` 를 넘긴다. `kbd` 는 조리대를 키로 열었나 (5차 검증 K-11: Esc 로 닫은 뒤 손가락으로 다시 열어도 칩에 포커스 링이 남았다) |
| 게임 → 부엌 | `motion` + `reduce` | `ready` 를 받았을 때 · `open` 바로 전 · 게임의 모션 설정이 바뀔 때 (5차 검증 K-5). 부엌 쪽 `<html>` 의 `data-motion="reduce"` 를 붙이거나 떼고, 다음 열기의 `reduced` 가 된다 (`reduce` 가 아니면 기기 설정을 그대로 따른다) |
| 게임 → 부엌 | `close` | 게임 쪽에서 창이 닫혔을 때 (부엌이 판을 저장하고 조용히) |
| 게임 → 부엌 | `safe` + `t` `r` `b` `l` | `ready` 를 받았을 때 · `open` 바로 전 · 크기 · 방향이 바뀌면 (100 ms 모아서). 게임이 보이지 않는 상자로 잰 `env(safe-area-inset-*)` 의 CSS px (0~200 으로 자름, 숫자가 아니면 0). 부엌은 `--ck-safe-*` 로 받고, 열려 있으면 `COOK.refit()` (iframe 안의 `env()` 는 0 일 수 있어서) |

- 주간 할 일 'kitchen' (놀이방 들르기: 놀이방에 가면 센다) 은 그대로다. 부엌 창이 열려 있는 동안 주간 알림은 닫힌 뒤로 미룬다 (`weekTell`).
- 설계 §6.4 의 직접 잇기 (`index.html` 에 `cook.js` 싣기 · 장면의 `kitchenBox` · `COOK.open` · 내보내기 `extras` · 귀가 때 `COOK.notice`) 는 쓰지 않았다. `COOK.notice` 는 남아 있지만 아무도 부르지 않는다 (글을 띄우는 것이라 쓰려면 주인 결정).
- 따로 연 `cook.html` 의 닫힌 쪽 (5차 검증 T-10): '부엌' · '만든 것들' 은 게임의 글꼴 설정을 따른다 (`credits.html` 과 같은 한 줄로 저장된 `pixelFont` 만 읽는다. 픽셀 글꼴을 껐으면 기기 글꼴 — 이 쪽은 Noto 웹 글꼴을 받지 않는다). 픽셀 글꼴이면 `js/fs-snap.js` 의 `--fs-u24f` (24 밑으로 안 내려감) · `--fs-m16` 크기이고, 글자 시작이 기기 px 위다 (가운데 맞춤이 남긴 끝수만큼 `translate`).
- 시험: 스모크 **Z** (`tools/smoke.js` `scenarioSceneTap`) 와 N1 의 게임 안 창 줄 (§12).

## 10. `COOK.start` 계약 (문서만 · 코드 없음)

같이 가기 · 시험대처럼 창 없이 다른 요소 안에 무대만 띄우는 손잡이다. v0 에는 만들지 않는다.

```js
COOK.start(el, { recipe, seed, reduced, onResult, onEnd }) → handle | null   // never throws
handle.stop() → result | null    // 주인이 아니라 바깥이 끝낼 때
handle.live() → COOK.live() 와 같은 모양
```

- `el` 안에 무대 캔버스와 동사 칩만 넣는다 (HUD · 저장 없음, 판은 저장하지 않는다).
- 결과 봉투는 §6 과 같고 `status` 만 셋 중 하나다: `done` (접시까지) · `cut` (`stop()` 으로 중간에 끝남: 끝난 단계의 모양만 `look` 에) · `empty` (아무 진행 없이 끝남, `look` 은 기본 모양). `ms` 는 늘 `null`. 점수 · 시간 · 손/칩 구분 칸은 없다.
- 차리기 기록 (식탁 · 같이 가기 v1 에): `{ id: 'serve_…', at, runId, dish: { id, name, tier }, by: 'user' }` — 글자 그대로 계약만 둔다.

## 11. 쿠킹 마마와 다른 점 (글로만 적는다)

| 쿠킹 마마 (기계에서 배운 것) | 우리 |
|---|---|
| 진행자가 지시 · 칭찬 · 꾸중한다 | 진행자 없음. 아무도 판정하지 않는다. 문어는 부엌에 나오지 않는다: 요리사 모자 쓴 문어 그림의 반응 스티커가 위쪽 벽 모서리에 잠깐 뜰 뿐이다 (그림뿐인 장식. 말 · 점수가 없고, 기분 얼굴 일곱은 부엌에서 뜨지 않는다: 11-15 주인 답 (나), §5) |
| 위 지시 화면 + 아래 손 화면 | 한 화면. 팬 · 도마를 위에서 가까이 본 그림 하나가 가장자리까지 (전이 너비의 69~73 %), 위에 작은 HUD (단계 띠 · 닫기), 아래에 칩 하나 |
| 외침 제목 문장 | 화면에 글이 없다. 단계는 옆 자리로 미끄러짐 · 음식 위 신호 하나 (고리 · 위 화살표 · 점선) · 단계 띠 · 처음 손 그림이 알린다. 동사는 화면 읽기에만 |
| 목표 구간 게이지, 빗나감, 탐 | 게이지 없음. 불 켜고 위로 쓸어 뒤집기. 굽기 셋 다 좋은 결과, 기다려도 타지 않는다 |
| 진행 막대 | 진행은 음식에 보인다 (자국 · 굽기 색 · 칼집). 단계 띠는 그림 셋뿐 (숫자 없음) |
| 요리 아이콘 메뉴판 | 메뉴 없음. 열면 바로 해초전 (하다 만 판이면 그 단계부터) |
| 메달 · 점수 결과 화면 | 결과는 접시 그림 하나 (화면 가장자리까지, 놀이한 자국 · 굽기 · 칼집 그대로) 와 그림 단추 둘 (다시 · 닫기) |
| 고기 · 생선 레시피 | 바다 식물 · 곡물로 만든 우리 요리 (해초전) |

이름 · 캐릭터 · 그림 · 음악 · 단계 제목 · 화면 모양은 가져오지 않았다. 가져온 것은 "한 동사 짧은 단계 사슬, 요리는 늘 끝난다, 손이 곧 음식에 자국" 이라는 기계뿐이다. 11-15 가까이 보기 (UI 조사 뒤, 5차 설계 §17) 에서 더 배운 것도 일반 원리뿐이다: 위의 작은 '보기' 띠와 큰 '하기' 면, 재료가 곧 화면, 누를 자리에 그린 신호 하나, 보여 주고 비키기 (처음 · 5 s 쉼 · 들썩 세 번 뒤의 손 그림), 결과는 요리 그 자체. 제목 막대 · 안내 캐릭터 · 접시 시계 · 말 칸 · 체크무늬 천 · 분홍 하늘색 · 파란 화살표 · 실감 나는 1인칭 손 · 등급 · 메달 · 별점 · 'Perfect' · 실패 얼굴 · 식탁보 · 커튼 무대 · 깃발 · 팡파르는 가져오지 않았다.

허용 라이선스 코드도 줄 단위로 옮기지 않았으므로 `docs/THIRD_PARTY.md` 는 필요 없다. GPL · 라이선스 없는 코드는 읽기만 했다. 그림 (`js/cook-art.js`) 은 모두 코드로 그린 우리 픽셀이다.

부엌 소리는 남이 나눠 준 소리로 만들었다. 직접 녹음하지 않았고 AI 로 만들지 않았다. 거의 모두 진짜 녹음이고, 김 쉬익 (`cook_steam`) 의 원본만 가공한 잡음일 수 있다 (`foley/CREDITS.md` 머리말). CC BY 두 줄은 `foley/CREDITS.md` 와 `credits.html` 에 글자 그대로 있어야 한다 (`tools/test-cook-audio.js` 의 장면 G 가 본다). `credits.html` 은 따로 연 `cook.html` 의 닫힌 화면과 본 게임 설정 맨 아래에서 갈 수 있다 (부엌 창 안에는 링크가 없다). 젓기 소리 (CC BY 3.0) 는 아직 게임에서 나지 않지만 파일이 저장소와 배포에 들어 있어서 크레딧에 이미 적었다.

## 14. 알려진 한계 · 다음

- 실제 폰 점검 전이다 (설계 §6.8 점검표와 5차 설계 §16.4: iOS 사파리 · 안드로이드 크롬, 소리 끔). 특히: 안드로이드에서 톡 · 불 켜기 · 뒤집기 착지 · 썰기의 가벼운 진동 (접시엔 없다) 과 설정 › 화면 › 진동 끄기, 아이폰에서 진동이 없어도 빠진 느낌이 없는지, 위로 쓸기 거리 (16 아트 px = CSS 64~80 px) 가 자연스러운지 (바꾸려면 `flip.flick`: 해시가 바뀌고 하다 만 판은 `potOld` 로), 게임 안 창의 안전 여백 (iframe 안 `env()` 가 정말 0 인지, 게임이 잰 값이 맞는지), 꾹 3 s (글자 돋보기 · 메뉴가 안 뜨는지), 사파리 아래 도구 막대, 화면 가장자리 뒤로 쓸기, VoiceOver · TalkBack 으로 조용한 칩 누르기: 화면 읽기의 두 번 톡이 진짜 터치 누름으로 오면 (iOS VoiceOver 가 그럴 수 있다) 첫 두 번 톡은 칩을 드러내기만 하고 둘째에 눌린다. 포인터 없는 클릭으로 오면 (키보드 · TalkBack 의 클릭) 바로 눌린다.
- 설계에서 바꾼 것 셋 (주인 확인 거리): ① 썰기 세로줄 안내선이 64 가 아니라 44 아트 px (음식 + 3, 전 위아래를 다 그어도 안 잘리던 것을 고침) ② 판 id 에 시작 시각 대신 난수 ③ 조용한 동사 칩을 손가락으로 처음 누르면 드러나기만 한다 (설계 §2.4 '조용할 때도 눌린다' 와 §2.2 ④ '톡은 절대 뒤집지 않는다' 가 부딪혀서, 뒤쪽을 지켰다).
- 이어 하지 못한 판은 `potOld` 에 크기와 상관없이 그대로 남는다 (5차 검증 O-6 에서 2 KB 한도를 뺐다). 객체가 아닌 판 (글 · 배열) 은 남지 않는다 (§6). 게임이 쓰는 판에서는 생기지 않는다.
- HUD 아이콘 (단계 띠 · 닫기 · 칩) 은 아이콘 px 하나를 기기 px n 개로 그리고 자리도 기기 px 에 맞추지만, DPR 2.625 · 2.75 에서는 Chrome 의 1/64 px 배치 단위 때문에 칸 크기가 정수 기기 px 에서 0.02 px 쯤 어긋날 수 있다 (시험 N4 는 0.05 px 까지 허용한다). 캔버스에는 영향이 없다.
- 캔버스 크기: W · H 를 4 아트 px 까지 늘려도 정수 CSS px 가 안 되는 화면 (예: 384 × 832 @2.8125 의 가로, 411 × 891 @2.625 의 세로) 에서는 늘리지 않고 둔다. 그때는 기기 줄 하나가 두 번 그려질 수 있다 (실제로 보지 않았다). 목표 크기 일곱과 390 × 844 @3 은 정수다 (N2 · N10).
- 가로 화면 · 태블릿은 목표가 아니다: 레터박스 없이 같은 그림이 옆으로 이어지고 (568 × 320 @2 에서 아트 px 하나 = CSS 1.5 px, 전은 너비의 15 %), 시험은 넘침이 없는지만 본다 (L5).
- 뒤집은 뒤: 예전에는 400 ms 뒤 바로 도마로 넘어가 착지가 금방 지나갔다. 지금은 뒤집은 전이 팬에 1 s 머문다 (`TUNE.flip.betweenMs`, §4): 착지의 기름 튐 · 끓음 · 김이 팬에서 보이는 시간이다. 1 s 가 알맞은지는 주인이 아직 보지 않았다.
- 새 그림 (가까이 보기: 화구 · 미끄러짐 · 들고 가기 · 가까이 본 접시 · 아이콘, 그리고 `cook-art-2` 의 기름 방울 · 김 · 윤기 · 음식 색) 은 주인이 실제 폰에서 아직 보지 않았다. 자동 시험은 그림 함수가 그리는 것 (시험 16 · 17), `js/cook.js` 가 그 함수에 넘기는 값 (L19), 화면 맞춤 (N2 · N3 · N4) 을 본다. 그 그림이 먹음직스러운지는 시험이 알 수 없다. `docs/shots/cook/` 캡처는 11-15 에 가까이 보기로 다시 찍었다 (§12).
- 소리는 붙었지만 (§8) 사람이 듣고 정한 것이 아니다. 만든 쪽은 소리를 들을 수 없어서, 고른 구간 · 겹치기 · 크기를 숫자와 스펙트로그램으로만 정했다. 귀로 확인할 것은 `foley/README.md` 의 '정직 메모' 에 있다 (뒤집기 철퍽 · 톡톡 · 지글 세 결 · 10 s 바삭 루프의 되풀이 · 썰기 변형 · 불 켜기). 음악과의 섞임도 주인이 폰 스피커로 아직 듣지 않았다: 음악 내리기 -6 / -10 dB 가 알맞은지, `cook.html` 이 늘 같이 트는 빗소리가 지글을 가리지 않는지.
- 게임 안 창에서 소리를 켠 경우는 시험이 없다: 부엌 쪽 iframe 은 제 `js/audio.js` 를 싣고 (§8 의 집 음악 · 환경음 · 음악 내리기도 그 안에서만 돈다), 놀이방 쪽 소리와 어떻게 겹치는지는 아직 보지 않았다.
- `cook.html` 안에는 소리를 켜고 끄는 곳이 없다 (본 게임 설정에 저장된 것을 따르거나 `?sound=1`). 소리 목록을 못 읽어 조용해졌을 때 다시 켜는 길은 1분 뒤의 손길 하나다 (§8). 그 1분은 부엌 목록의 것과 같은 값으로 두었을 뿐, 실제 폰의 흔들리는 망에서 알맞은지는 보지 않았다. 목록을 못 읽었을 때 `AudioContext` 를 쉬게 두는 것은 Chromium 에서만 돌려 봤다 (Firefox · Safari 는 흉내로만).
- 조각 2 몫의 소리 여덟 개 (`cook_stir` 셋 · `cook_clink` · `cook_simmer` · `cook_place` 둘 · `cook_lift`) 는 파일과 표만 있다. 게임도 시험도 아직 틀어 보지 않았다.
- 부엌의 브라우저 시험 셋 (`test-cook-live.js` · `test-cook-audio.js` · `test-cook-stickers-live.js`) 과 스모크 Z 는 CI 의 느린 묶음 (`suites` · `smoke`) 에서 돈다 (11-14 부터 실패하면 run 이 빨갛다). 빠른 묶음 (`test-cook.js` · `test-cook-stickers.js` · `test-haptics.js`) 은 소리 갈래 · 크레딧 · 화면 배치를 보지 않는다.
- 자동 시험은 Chromium 에서만 돈다. `.m4a` (AAC) 로 실제로 트는 길, iOS 사파리의 첫 손길 풀기, 파이어폭스의 페이드는 실제로 돌려 보지 않았다 (장면 L 이 `cancelAndHoldAtTime` 없는 경우를 흉내 낼 뿐이다). WebKit 에서는 부엌 시험도 아직 돌려 보지 않았다 (설계의 선택 시험: `npx playwright install webkit` 뒤 L5 · L6 · 배관만). 진짜 진동기 (안드로이드) 도 시험은 가짜 `navigator.vibrate` 로만 본다 (N6).
- `foley/listen.html` · `foley/README.md` · `foley/CREDITS.md` 는 만드는 사람용 글이라 배포에 나가지 않는다 (11-10 부터: `tools/export-site.js` 가 게임 파일만 내보낸다, README '배포'). 플레이어가 보는 크레딧은 `credits.html` 이다. `listen.html` 은 저장소에서 열어 듣는다 (`noindex`, 크레딧 링크 있음).
