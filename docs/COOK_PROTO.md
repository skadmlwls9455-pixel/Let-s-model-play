## 0. 한눈에

- 폰으로 `cook.html` 을 열면 바로 부엌(조리대)이다. 팬을 누르면 해초전이 시작된다: **톡톡 → 뒤집기 → 썰기** → 접시가 오른다 → 톡 하면 조리대로 돌아오고, 방금 만든 접시가 팬 옆에 놓여 있다.
- 실패 · 점수 · 시간 제한 · 메달이 없다. 진행은 오르기만 한다. 기다려도 타지 않는다.
- 소리가 꺼진 것이 기본 경우다 (켜면 §8 의 소리가 난다). 센 입력마다 **바로 다음 프레임**에 무대가 바뀐다 (밝은 테두리 · 찌그러짐 · 부스러기 · 남는 자국).
- 손이 먼저다. 동사 단추는 늘 있지만 터치에서는 조용하다 (`opacity 0`, 자리는 그대로). 5초 멈추면 흐린 손 그림이 한 번 나오고, 그때부터 단추가 보인다. 키보드면 처음부터 보이고 포커스를 받는다. **조용한 단추 자리를 손가락 · 마우스로 누르면 단추가 드러나기만 하고 동작은 하지 않는다** (빗맞은 톡이 전을 뒤집지 않게). 그 자리에서 시작한 획은 무대 입력이라 아래에서 올려 쓸어도 뒤집힌다. 포인터 누름 없는 클릭 (키보드 · 화면 읽기) 은 바로 동작한다.
- 저장 키는 따로다: `cook.html` 은 `ppolppol_cook_v0`, 본 게임에 이을 때는 `ppolppol_cook`. 본 게임 기록은 읽지도 쓰지도 않는다.

## 3. 단계 종류 (판정 요약)

거리는 논리 px (무대 288 × 320 = 아트 px × 2), 시간은 단계 시계 ms. 진행은 오르기만 한다. 손 떼기 · `pointercancel` · 엉뚱한 방향은 아무것도 깎지 않는다.

| 종류 | 손동작 | 판정 | 단추 (조용한 동사 단추) | 남는 모양 · 꼬리표 |
|---|---|---|---|---|
| `tap` 톡톡 | 음식 위를 톡톡, 꾹 눌러도 됨, 두 손가락 번갈아도 됨 | 모든 `pointerdown` 을 센다. 덜 된 표시 중 가장 가까운 곳에서 80 px 안. 90 ms 안의 두 번은 하나로. 꾹: 400 ms 뒤부터 250 ms 마다 (정해진 시각표대로, 화면 주기와 상관없음). 3 · 6번에 반죽이 넓어진다 | 한 번 = 다음 표시에 3번 | 자국 (최대 9) · 꼬리표 없음 |
| `flip` 뒤집기 | 첫 누름 = 불 켜기. 위로 쓸어 올리면 뒤집힘 | 위로 32 px 이상, 위쪽 ±45° 안, 빠르기 상관없음. 판정 굽기 = 그 획을 누른 순간의 굽기. 톡은 절대 뒤집지 않는다 (불 켠 뒤 톡은 1프레임 들썩). 불 켠 뒤 0~3 s 보들보들 · 3~6 s 노릇노릇 · 6 s~ 바삭바삭에서 기다린다 | 첫 번 = 불 켜기, 둘째 = 지금 굽기로 뒤집기 | 굽기 0~2 · `soft` `golden` `crisp` |
| `slice` 썰기 | 점선 안내선을 따라 쓸기 (방향 · 속도 상관없음, 떼었다 이어도 됨), 또는 가로질러 한 번 긋기 | 안내선은 그 줄 방향의 음식 크기 + 양 끝 3 아트 px (해초전: 가로줄 64, 세로줄 44 아트 px). 40칸 중 80 % 칠하면 그 줄이 잘린다 (띠 32 px, 진행 방향 ±40°): 전 끝에서 끝까지 한 번 그으면 (90 % 만 그어도) 잘린다. 가로지르기: 15~85 % 구간을 50° 이상으로, 16 px 이상. 각도 = 띠 안 표본의 최소제곱 주축, 6° 계단, \|각\| ≥ 12° 면 어슷 | 한 번 = 다음 줄을 반듯하게 | 줄마다 각도 · `straight` `slant` |

화면 읽기 (`aria-live="polite"`, 매 프레임이 아니다): 단계 시작 동사 · 톡톡 '반쯤' · 썰기 줄마다 '한 줄' · 굽기가 바뀔 때만 굽기 낱말 · '다 됐어' · 접시 공개 때 접시 설명 ("해초전. 노릇노릇 구웠어. 반듯하게 썰었어."). 굽기 낱말은 화면 DOM 에 없다 (전의 색이 곧 정보).

## 5. 화면 · 배치 · 포커스

- **배치** (설계 §5.2): 무대 = 아트 144 × 160 을 기기 px 정수 배로 (`k = max(1, floor(min(가로여유 × dpr / 144,세로여유 × dpr / 160)))`, `k / dpr ≤ 3`). 무대 틀은 그림 안 2 아트 px. 무대는 56 px 동사 단추 칸 바로 위, 남는 세로 공간은 모두 머리줄 위로. 좌우 거터 16. 320 폭에서 가로 스크롤 없음. 위치는 기기 px 에 맞춘다 (DPR 2.625 에서도 선이 떨리지 않게).
- **머리줄**: 단계 그림 띠 (그림 3개, 지금 단계는 2 px 위 + 호박색 2 px 줄, 숫자 없음) + [닫기]. 조리대에서는 [닫기] 만.
- **제목 꼬리표**: 단계 시작에 동사 하나 (600 ms, 누르면 바로 사라짐). 종이 9-slice 틀, 24 px.
- **처음 보는 종류**: 이 기기에서 처음 보는 단계 종류면 제목 직후 흐린 손 그림이 한 번 동작을 보여 준다 (뒤집기는 불 켜기 톡, 불 켠 직후 위로 쓸기). 본 종류는 저장의 `seen` 에.
- **놀이 힌트**: 5 s 진행이 없으면 손 그림 한 번 (그 뒤 동사 단추가 그 판 끝까지 보인다). 뒤집기는 불 켠 뒤엔 바삭바삭 + 5 s 에만. 손 그림은 **진행** (자국 · 불 켜기 · 뒤집기 · 칼집 · 잘림) 이 있을 때만 비켜 주고, 아무것도 안 바꾸는 누름으로는 지워지지 않는다. 처음 보는 종류는 그 손 그림이 끝까지 돈 뒤 (또는 단계가 끝난 뒤) 에야 `seen` 에 남는다. 불 켠 뒤 안 뒤집히는 누름이 이어지면 위로 쓸기 손 그림을 한 번 더 보여 주고 단추를 드러낸다 (재촉이 아니라 대답: 한 단계에 두 번까지).
- **접시 공개**: 접시가 다 오르고 5 s 동안 누름이 없으면 접시 위에 톡 손 그림 한 번 + '돌아가기' 단추가 드러난다. 저절로 넘어가지 않는다. 조리대로 돌아온 뒤 500 ms 안에 시작한 누름 (접시 두 번 톡) 은 새 판을 열지 않는다.
- **뒤 배경**: 창 전체 뒤는 놀이방의 판자 벽 (`COOK_ART.wallTile`) 을 무대와 같은 정수 배로 깐다. 큰 폰에서 무대 위 빈 자리가 빈 종이 대신 부엌 벽이 된다. 어두운 색 모드면 같은 벽의 밤 색. 무대 · 단추 자리는 그대로다.
- **포커스** (설계 §3.3): 열기 → 팬 / 조리대 → 단계: 마지막 입력이 키면 동사 단추, 아니면 무대 상자 / 단계 → 단계: 그대로 / 접시가 다 오른 뒤 (450 ms) 같은 규칙 / 접시 공개 → 조리대: 팬 / [닫기] · Esc: opener (없거나 숨었으면 `#btn-play-door` → `#btn-go`) / 쪽지는 포커스를 가져가지 않는다 / [보러 가기] 는 opener 로 돌리지 않는다. 포커스 테는 키 입력 뒤에만 그린다.
- **동작 줄이기**: `COOK.open({ reduced })` 또는 `prefers-reduced-motion` 또는 `data-motion="reduce"`. 밝은 테두리와 남는 것 (자국 · 칼집 · 굽기) 만. 찌그러짐 · 입자 · 흔들림 · 호 · 손 그림 움직임 없음 (손 그림은 정지 그림). 불 위의 기름 방울 · 김도 멈춘 그림이다 (§5.1).
- **소리 없이 손맛**: 센 입력은 그 입력 처리기 안에서 시뮬레이션을 지나고, 다음 그리기에서 무대가 바뀐다. 손이 직접 움직이는 칼 · 뒤집개는 화면 주기대로 아트 px 에 붙어 움직인다. 반응 애니메이션은 12 fps 계단. 입자 난수는 `mulberry32(COOK.fxSeed(seed, si))` (놀이 시드와 따로).

### 5.1 그림이 받는 값 (기름 방울 · 김 · 윤기)

`COOK_ART` 의 장면 그림은 받은 값만으로 그린다 (안에 남는 것은 캐시뿐이다): 같은 값을 주면 같은 바이트가 나온다. 불 위의 기름 방울 · 김 · 윤기가 쓰는 프레임 수는 `js/cook.js` 의 `fxNow(run, t)` 가 그릴 때마다 다시 센 정수다. 한 칸은 12 fps 한 프레임 (83 ms) 이다.

| 값 | 뜻 | 언제 있나 |
|---|---|---|
| `seed` | 그 판의 그림 시드 (`fxSeed(run.seed, 0)` 의 아래 31비트). 뒤집기 장면 (팬) · 썰기 장면 (도마) · 접시 공개가 같은 값을 받는다. 톡톡 장면은 받지 않는다 | 판이 있는 동안 늘 |
| `fh` | 불 켠 뒤 지난 프레임 수 | 뒤집기 단계에서 불이 켜져 있을 때 |
| `fbc` | 굽기가 마지막으로 바뀐 뒤 프레임 수 | 뒤집기 단계에서 굽기가 1 · 2 일 때 |
| `fl` | 뒤집은 전이 내려앉은 뒤 프레임 수 | `L.landAt` (뒤집은 때 + 3프레임 = 호의 착지 그림) 부터, 팬과 도마에서만. 48 (4 s) 에서 멈춘다 |
| `t` | 접시 공개가 시작된 뒤 프레임 수 | 접시 공개 (`L.revealAt` 부터). 동작 줄이기면 없다 |
| `still` | 동작 줄이기 | 늘 (`L.reduced`) |

- 없는 값은 `null` 로 가고, 그래도 모든 장면이 그려진다 (`js/cook-art.js` 머리 주석의 `FOOD` 칸). 고른 상태의 그림은 96프레임 (8 s) 마다 되풀이된다.
- 입력이 없을 때 다시 그릴지는 `frameSig(t)` 가 정한다: 12 fps 눈금, 반응 · 입자 · 손 그림 저마다의 프레임 수, 위의 `fh` · `fbc` · `fl` · `t` 가운데 하나라도 바뀌면 그린다. 카운터마다 제 사건에서부터 세므로 프레임 하나하나가 한 번씩 그려진다 (한 프레임을 두 번 보이고 다음을 건너뛰지 않는다).
- `L.landAt` 은 썰기 단계로 넘어가도 남는다 (첫 단계나 뒤집기 단계를 시작할 때만 지운다). 그래서 착지 때 피어오른 김이 도마 위에서 이어진다 (`fl` 36 까지).
- 동작 줄이기: `f` 는 0, `still` 은 참이고, 이 카운터들로는 다시 그리지 않는다. 그림은 멈춘 한 장이다 (자리 잡은 방울 몇 개 · 멈춘 김, 반짝임 없음).
- 색: 음식 · 장 · 기름 · 반짝임 · 김만 음식 색 `FOOD` 24 색을 쓰고, 소품 (팬 · 도마 · 칼 · 뒤집개 · 접시 · 손 그림) 은 Apollo 46 색에 남는다. 알파는 0 아니면 255 다 (시험 16).

## 6. 저장

```js
localStorage[storeKey] = { v: 1, day: 'YYYY-MM-DD', dayN: 3, seen: ['tap', 'flip', 'slice'],
  pot:  null | { ver: 'cook-1', tune: 2827089308, runId, seed, recipe, swaps, si, looks: [...], tags: [...], at },
  book: [ { id: 'ck_…', recipe, seed, swaps, look, day, madeAt } ] }   // 최근 것이 앞, 최대 300줄
```

- 판(`pot`)은 **단계 경계**에서만 쓴다: 단계가 끝날 때, 탭이 숨을 때 (`visibilitychange`), `pagehide`, 닫기, [보러 가기]. 이어 하면 지금 단계를 처음부터 한다. `ver` · `tune` · 레시피 · `si` · 모양이 맞지 않거나 깨졌으면 조용히 버린다 (조리대에 "이어서" 가 안 나올 뿐).
- 접시가 끝나면 판을 지우고 수첩에 한 줄을 넣는다. 수첩 화면은 조각 2 에 온다 (조각 1 에는 수첩을 볼 곳이 없어서 "요리 수첩에 넣었어." 도 아직 말하지 않는다).
- 시드 = `hash32(day + '|cook|' + dayN)`, 판 id = `'ck_' + hash32(day|dayN|난수).toString(36)` (`crypto.getRandomValues`, 없으면 수첩 줄 수). **시작 시각은 쓰지 않는다**: 수첩 줄에 `madeAt` 이 같이 있어서, 시작 시각이 id 에 들어가면 걸린 시간을 거꾸로 찾을 수 있다 (설계 §4.2 의 `startedAt` 에서 바꿈, 주인 확인 거리). 날짜는 로컬, 시험은 `window.__ppolTest.today`.
- 저장 키는 부엌 것만 받는다: `ppolppol_cook` 또는 `ppolppol_cook_…` (`cook.html` 은 `ppolppol_cook_v0`). 다른 키를 넘기면 `ppolppol_cook` 을 쓴다. 본 게임 저장 키는 읽지도 쓰지도 못한다.
- 저장이 실패해도 (사생활 모드 · 가득 참) 놀이는 그대로다. 오류 글 없음.

결과 봉투 (`onResult` 로 넘긴다; `ms` 는 늘 `null`, `status` 는 `done` 만):

```js
{ v: 1, id: 'ck_…', by: 'user', game: 'cook', status: 'done', ms: null,
  out: { dish: { id: 'jeon', name: '해초전', tier: 1, ingredients: ['batter', 'parae'] },
         recipe: 'jeon', seed, swaps: { herb: 'parae' },
         steps: [{ kind: 'tap', status: 'done', tag: null }, { kind: 'flip', status: 'done', tag: 'golden' }, { kind: 'slice', status: 'done', tag: 'straight' }],
         look: { v: 1, dents: [[x, y] …], band: 1, cuts: [0, -6], offs: [2, -1], plate: 1 }, madeAt, day } }
```

## 7. API (`COOK`)

| 부름 | 무엇 |
|---|---|
| `COOK.open({ opener, reduced, palette, day, storeKey, onResult, onClose })` → boolean | 부엌 창을 연다. 던지지 않는다 (안에서 터지면 정리하고 `false`). 이미 열려 있으면 `true`. `storeKey` 는 `ppolppol_cook` · `ppolppol_cook_…` 만. 시험 · 개발용 옵션: `seed`, `recipe`, `slow`, `rec`. `palette` 는 받아 두기만 한다 (조각 1 에서는 그림에 쓰지 않음) |
| `COOK.close()` · `COOK.isOpen()` | 닫기 (판 저장 · `quiet`) · 열림 여부 |
| `COOK.notice({ text, short, label, fn })` → boolean | 머리줄 바로 위 정해진 칸에 쪽지. 짧은 화면이면 단계 그림 띠 자리에 `short`. 포커스를 가져가지 않고 무대를 밀지 않는다. [`label`] = 판 저장 → 창 닫기 → close 이벤트 끝에서 `fn` |
| `COOK.exportData()` · `COOK.importData(obj)` | 수첩 (`seen` · `book`) 만 오간다. 판은 가지 않는다. 둘째 인자로 다른 부엌 키를 줄 수 있다 (부엌 키가 아니면 `null` · `false`) |
| `COOK.live()` | 시험용 읽기 전용 사본: `screen` (`closed` · `counter` · `step` · `reveal`), `recipe`, `si`, `kind`, `phase`, `progress`, `done`, `tag`, `band`, `quiet`, `fx` (센 반응 수), `verb`, `hint`, `k`, `css`, `tight`, `reduced`, `stats`, `said`, `look`, `st`, `err` … |
| `COOK.auto(on)` | 시험용: 동사 단추 길로 한 접시 (짧게 쉬며) → 접시 공개 → 조리대 |
| 시뮬레이션 | `createRun` · `resumeRun` · `input` · `tick` · `drain` · `simulate` · `resultOf` · `drawDish` 등 (`js/cook.js` 맨 위 계약 주석). `simulate(recipe, seed, steps, { cadence, until, pot })`: `cadence` 1~1000 Hz, `until` 10분 이하로 자른다. `pot` 을 주면 이어 한 판 (`?rec=1` 기록의 `pot`) 을 그 단계부터 다시 돌린다 |

## 8. 소리 (act 표 · 무엇이 나나)

부르는 곳은 하나다: `window.AUDIO && AUDIO.on && AUDIO.on('cook', { act, … })`. 입력 처리기 안에서 바로 부른다 (한 프레임 늦지 않게). 시간으로 생기는 것 (굽기가 바뀜 · 꾹 자동 톡 · 접시 공개) 은 그 프레임에 부른다. 실패 · 빗나감 소리는 **없다**. 받는 곳은 `js/audio.js` 의 `case 'cook'` (`onCook`) 이고, 무엇을 틀지는 `foley/manifest.json` 의 `map.cook` 표가 정한다 (녹음 소리 층. 칩튠 한 벌 `audio/` 와 따로). cook.js 는 부르기만 한다: `AUDIO` 가 없거나 소리가 꺼져 있으면 조용히 논다.

| act | 언제 | 덧붙임 | `js/audio.js` 가 트는 것 (`foley/cook/` 의 소리 이름) |
|---|---|---|---|
| `pick` | 조리대에서 소품을 누름 | `{ dish: 'jeon' }` | `cook_pick` 한 번 (팬 들기) |
| `tap` | 톡톡에서 센 한 번 (손 · 꾹 · 단추 모두) | `{ i }` 0~8 | `cook_pat` 한 번 (변형 4개 중 바로 앞에 고른 것과 다른 것). `i` 따라 빠르기가 조금씩 올라 9번째가 +3 반음 |
| `sizzle` | 불 켤 때 (`band` 0) · 굽기가 바뀔 때 (1, 2) · 숨었던 탭이 돌아왔는데 불이 아직 켜져 있을 때 (지금 굽기) | `{ band }` | 굽기마다 다른 루프 `cook_sizzle_0` · `_1` · `_2` (귀로 고르는 길). 불 켜기: `cook_heat_on` 한 번 + 루프를 1 s 에 올린다. 굽기가 바뀜: 다음 루프로 0.15 s 크로스페이드 + '치익' (새 루프가 +4 dB 까지 올랐다가 0.5 s 에 제 크기로). 탭 복귀: `cook_heat_on` 없이 루프만 0.3 s 에. 같은 굽기가 이미 돌면 아무것도 안 한다 |
| `flip` | 뒤집음 | `{ band }` | `cook_flip` 한 번 (변형 2개. 휙 뒤 0.256 s 에 철퍽 = 호의 착지 그림). `band` 는 쓰지 않는다. 동작 줄이기면 휙을 건너뛰고 0.21 s 부터 튼다 |
| `cut` | 썰기 한 줄이 잘림 | `{ i }` 0~1 | `cook_cut` 한 번 (변형 3개) |
| `step` | 단계 하나 끝 | `{ kind }` | `cook_step` 한 번 (작은 나무 톡). 뒤집기 단계 끝의 것은 철퍽 0.1 s 뒤로 미룬다. 철퍽은 뒤집기 소리가 정말 난 때부터 잰다 (파일이 늦게 와도 톡이 철퍽보다 먼저 나지 않는다). 뒤집기 소리가 버려졌으면 (처음 받느라 0.3 s 넘게 늦음 등) 이 톡도 내지 않는다. 뒤집기 파일을 둘 다 못 받아 고를 변형이 없을 때도 같다 |
| `quiet` | 단계 끝마다 (뒤집음 뒤에도), 탭 숨김, 닫기, [보러 가기] | — | 도는 루프를 0.25 s 에 내리고 멈춘다. 한 번짜리 소리는 끝까지 울린다 (뒤집은 바로 뒤의 `quiet` 에는 루프만 내려가고, 뒤집기 소리 안의 잦아드는 지글 꼬리가 이어 울린다). 파일은 없다 |
| `done` | 접시 공개 | `{ dish: 'jeon' }` | 접시가 다 오른 때 (+0.4 s) `cook_plate` (변형 2개) + 0.15 s 뒤 `cook_steam`. 동작 줄이기면 바로 |
| `stir` · `clink` · `simmer` · `place` · `lift` · `back` | **cook.js 가 아직 보내지 않는다** (조각 2 몫: 젓기 · 올리기) | — | 표와 파일만 먼저 있다: `cook_stir` (변형 3개) · `cook_clink` · `cook_simmer` (루프, `quiet` 로 멈춤) · `cook_place` (변형 2개) · `cook_lift` · `back` = `cook_lift` 를 절반 크기로 |

해초전 한 판의 순서 예: `pick` → `tap` × 9 → `step` `quiet` → `sizzle(0)` → `sizzle(1)` → `flip` → `step` `quiet` → `cut` → `cut` → `step` `quiet` → `done`.

- **간격**: cook.js 는 같은 act 를 120 ms (`TUNE.sndGapMs`) 안에 다시 보내지 않는다. `tap` · `step` · `done` · `pick` · `quiet` 은 이 문을 거치지 않는다 (`js/cook.js` 의 `SND_FREE`. 손과 꾹으로 센 톡은 이미 90 ms 이상 떨어져 있다). 지금 이 문에 걸리는 것은 `sizzle` · `flip` · `cut` 이다. 받는 쪽에도 소리마다 최소 간격이 있다 (`foley/manifest.json` 의 `min_gap_ms`: 톡톡 80 ms · 썰기 120 ms 등). 그래서 동사 단추 한 번은 `tap` 을 세 번까지 한꺼번에 보내지만 소리는 한 번 난다 (변형은 셋을 고르지만, 간격 문이 버린 둘은 '바로 앞에 고른 것' 으로 남지 않는다. 그래서 단추 길에서도 같은 변형이 이어 들리지 않는다). 끝내 틀지 않은 고르기는 어느 길이든 그렇게 되돌린다: 간격 문 · 동시 한도 · 처음 받느라 늦어서 버림 · 못 받음, 그리고 변형이 둘뿐인 뒤집기도.
- **켜기**: 소리는 꺼진 것이 기본이다. 본 게임 설정에서 소리를 켜 두었거나 (같은 저장 `ppolppol_audio`), `cook.html?sound=1` 로 열었을 때만 난다. `?sound=1` 은 그 쪽에서만 켜고 저장하지 않는다 (본 게임의 설정은 그대로다). 어느 쪽이든 소리는 첫 손길 (누름 · 키) 뒤에 난다: 그 전에는 `AudioContext` 를 만들지 않는다. 첫 손길이 곧 팬 누르기여도 팬 들기 소리는 난다 (소리가 풀리기 전에 온 한 번짜리 act 하나를 기억했다가 0.3 s 안이면 튼다). 소리가 켜지는 순간 불이 켜져 있으면 그 굽기의 지글부터 난다. `file://` 로 열면 늘 조용하다.
- **필요할 때만 받는다**: `foley/manifest.json` 은 부엌 소리가 처음 필요할 때 받는다 (켠 채로 부엌 act 가 올 때, 켜는 순간 부엌이 열려 있을 때, 켜 둔 채 부엌 쪽을 열 때). 본 게임만 하면 `foley/` 요청이 없다. 켜 둔 채 (또는 `?sound=1` 로) 부엌 쪽을 열면 첫 손길 전에 목록 둘 (`audio/` · `foley/`) 과 `pick` · `tap` · `step` 소리의 바이트만 받아 두고, 그 뒤로는 곧 쓸 소리를 한 걸음 먼저 받는다 (`tap` 때 불 켜기 · 지글 0, `sizzle` 때 지글 1 · 2 · 뒤집기, `flip` 때 썰기 · 접시 · 김). 해초전 한 판이 받는 부엌 소리는 19개다 (`.ogg` 로 약 360 KB, `.m4a` 로 약 440 KB). 목록을 못 읽으면 부엌 소리 없이 놀고, 1분 동안은 다시 받지 않는다. 본 게임의 소리 목록 (`audio/manifest.json`) 을 못 읽으면 (쪽을 열 때와 첫 손길, 두 번) 소리 없이 놀고 `AudioContext` 를 쉬게 둔다 (그 순간의 상태가 `running` 인지 묻지 않고 멈추고, 쉬는 중에 뒤늦게 `running` 이 되면 다시 멈춘다). 그 뒤 1분이 지난 손길이 다시 받아 보고, 되면 새로고침 없이 소리가 켜진다 (`cook.html` 에는 켜고 끄는 곳이 없어서 이 길뿐이다. 본 게임에서는 '켜기' 칸을 껐다 켜면 바로 다시 받고, 칸을 그대로 두어도 같은 1분 뒤의 손길이 다시 받는다: 켜 둔 채 새로고침했든 칸을 방금 켰든). 처음 받느라 0.3 s 넘게 늦은 한 번짜리 소리는 버린다 (불 켜기 소리만 1 s 까지 기다린다).
- **파일 형식**: 소리마다 `.ogg` (Opus) 와 `.m4a` (AAC) 둘이다. 브라우저가 Opus 를 틀 수 있다고 하면 `.ogg`, 아니면 `.m4a` 를 받는다. `.ogg` 를 못 받거나 못 풀면 그 소리를 `.m4a` 로 한 번 더 받고, 그것이 되면 그 뒤로는 모두 `.m4a` 다. 그래도 못 튼 변형은 한동안 빼고 고른다 (변형 둘 중 하나가 없어도 조용한 뒤집기가 없게).
- **음악 내리기** (`ckBed`): 소리를 켠 `cook.html` 에서는 본 게임의 집 음악과 환경음도 같이 흐른다 (날씨를 넘기지 않아 늘 비 오는 날 것). 부엌이 열려 있으면 음악 -6 dB · 환경음 -9 dB, 지글 (조각 2 의 보글도) 루프가 도는 동안은 -10 dB · -13 dB 로 내린다. `quiet` 뒤에는 앞의 값으로, 부엌을 닫으면 제자리로 돌아온다 (내릴 때 약 0.8 s, 올릴 때 약 1 s). 효과음 크기가 0 이면 내리지 않는다. 부엌 목록 (`foley/manifest.json`) 을 못 받았을 때도 내리지 않는다 (부엌이 낼 소리가 없다. 목록이 오면 그때부터 내린다). 징글이 음악을 내리는 것과는 다른 노드라 서로 덮지 않는다. 이 크기는 주인이 아직 듣고 정한 것이 아니다 (§14).
- **그 밖**: 크기는 효과음 슬라이더 (`sfx_event`) 와 밤 마스터 (-3 dB) 를 따른다. 모르는 act 는 조용히 지나간다. 파일이 없거나 못 풀어도 놀이로 오류를 던지지 않는다 (부엌 소리 없이 끝까지 논다).

- `cook.html` 만 보는 시험은 이미 돈다: `package.json` 의 `test` 에 `tools/test-cook.js`, `test:slow` 에 `tools/test-cook-live.js` 와 `tools/test-cook-audio.js`. CI 도 빠른 일에서 앞의 것을, 느린 일 (선택) 에서 뒤의 둘을 돌린다 (§12).

## 10. `COOK.start` 계약 (문서만 · 코드 없음)

같이 가기 · 시험대처럼 창 없이 다른 요소 안에 무대만 띄우는 손잡이다. v0 에는 만들지 않는다.

```js
COOK.start(el, { recipe, seed, reduced, onResult, onEnd }) → handle | null   // never throws
handle.stop() → result | null    // 주인이 아니라 바깥이 끝낼 때
handle.live() → COOK.live() 와 같은 모양
```

- `el` 안에 무대 캔버스와 동사 단추만 넣는다 (머리줄 · 조리대 · 저장 없음, 판은 저장하지 않는다).
- 결과 봉투는 §6 과 같고 `status` 만 셋 중 하나다: `done` (접시까지) · `cut` (`stop()` 으로 중간에 끝남: 끝난 단계의 모양만 `look` 에) · `empty` (아무 진행 없이 끝남, `look` 은 기본 모양). `ms` 는 늘 `null`. 점수 · 시간 · 손/단추 구분 칸은 없다.
- 차리기 기록 (식탁 · 같이 가기 v1 에): `{ id: 'serve_…', at, runId, dish: { id, name, tier }, by: 'user' }` — 글자 그대로 계약만 둔다.

## 11. 쿠킹 마마와 다른 점 (글로만 적는다)

| 쿠킹 마마 (기계에서 배운 것) | 우리 |
|---|---|
| 진행자가 지시 · 칭찬 · 꾸중한다 | 진행자 없음. 문어도 나오지 않는다. 아무도 판정하지 않는다 |
| 위 지시 화면 + 아래 손 화면 | 한 화면, 무대 하나 |
| 외침 제목 문장 | 평범한 동사 낱말 하나 (종이 꼬리표, 600 ms) |
| 목표 구간 게이지, 빗나감, 탐 | 게이지 없음. 불 켜고 위로 쓸어 뒤집기. 굽기 셋 다 좋은 결과, 기다려도 타지 않는다 |
| 진행 막대 | 진행은 음식에 보인다 (자국 · 굽기 색 · 칼집) |
| 요리 아이콘 메뉴판 | 우리 조리대의 소품 (팬) 을 누른다 |
| 메달 · 점수 결과 화면 | 접시가 오르고 이름 꼬리표만. 조리대의 팬 옆에 접시가 남는다 |
| 고기 · 생선 레시피 | 바다 식물 · 곡물로 만든 우리 요리 (해초전) |

이름 · 캐릭터 · 그림 · 음악 · 단계 제목 · 화면 모양은 가져오지 않았다. 가져온 것은 "한 동사 짧은 단계 사슬, 요리는 늘 끝난다, 손이 곧 음식에 자국" 이라는 기계뿐이다.

## 14. 알려진 한계 · 다음

- 실제 폰 점검 전이다 (설계 §6.8 점검표: iOS 사파리 · 안드로이드 크롬, 소리 끔). 특히 꾹 3 s (글자 돋보기 · 메뉴가 안 뜨는지), 사파리 아래 도구 막대, 화면 가장자리 뒤로 쓸기, VoiceOver · TalkBack 으로 조용한 단추 누르기: 화면 읽기의 두 번 톡이 진짜 터치 누름으로 오면 (iOS VoiceOver 가 그럴 수 있다) 첫 두 번 톡은 단추를 드러내기만 하고 둘째에 눌린다. 포인터 없는 클릭으로 오면 (키보드 · TalkBack 의 클릭) 바로 눌린다.
- 설계에서 바꾼 것 셋 (주인 확인 거리): ① 썰기 세로줄 안내선이 64 가 아니라 44 아트 px (음식 + 3, 전 위아래를 다 그어도 안 잘리던 것을 고침) ② 판 id 에 시작 시각 대신 난수 ③ 조용한 동사 단추를 손가락으로 처음 누르면 드러나기만 한다 (설계 §2.4 '조용할 때도 눌린다' 와 §2.2 ④ '톡은 절대 뒤집지 않는다' 가 부딪혀서, 뒤쪽을 지켰다).
- 단계 그림 띠: 자리는 기기 px 에 맞추고 (머리줄 위치 · 띄움 2 px 도 기기 px 로) 그림은 기기 해상도로 그리지만, DPR 2.625 · 2.75 에서는 Chrome 의 1/64 px 배치 단위 때문에 16 px 그림 칸이 80 이 아니라 79.98 기기 px 가 되어 가장자리 한 줄이 섞여 보일 수 있다 (0.4 CSS px 너비). 무대 캔버스에는 영향이 없다.
- DPR 2.8125 폰에서는 무대 CSS 크기 (예: 307.2 px) 가 Chrome 의 1/64 px 단위로 정확히 안 떨어져 아트 px 몇 줄이 5 · 7 기기 px 가 될 수 있다. 설계가 이름 붙인 2.625 · 2.75 는 정확하다. 고치려면 무대를 한 단계 작게 해야 해서 그대로 둔다.
- 조리대 벽이 비어 보일 수 있다: 병 선반은 조각 2 에 진짜 소품으로 온다 (안 되는 소품은 그리지 않는다는 규칙).
- 남는 세로 공간은 설계대로 머리줄 위로 간다 (엄지 자리). 큰 폰에서 그 자리는 이제 빈 종이가 아니라 놀이방 판자 벽이다. 벽에 더 걸 것 (창 · 선반) 은 되는 소품이 생길 때.
- 뒤집은 뒤: 예전에는 400 ms 뒤 바로 도마로 넘어가 착지가 금방 지나갔다. 지금은 뒤집은 전이 팬에 1 s 머문다 (`TUNE.flip.betweenMs`, §4): 착지의 기름 튐 · 끓음 · 김이 팬에서 보이는 시간이다. 1 s 가 알맞은지는 주인이 아직 보지 않았다.
- 새 그림 (`cook-art-2`: 기름 방울 · 김 · 윤기 · 음식 색) 은 주인이 실제 폰에서 아직 보지 않았다. 자동 시험은 그림 함수가 그리는 것 (시험 16) 과 `js/cook.js` 가 그 함수에 넘기는 값 (L19) 을 본다. 그 그림이 먹음직스러운지는 시험이 알 수 없다. `docs/shots/cook/` 캡처는 11-10 에 새 그림으로 다시 찍었다 (§12).
- 소리는 붙었지만 (§8) 사람이 듣고 정한 것이 아니다. 만든 쪽은 소리를 들을 수 없어서, 고른 구간 · 겹치기 · 크기를 숫자와 스펙트로그램으로만 정했다. 귀로 확인할 것은 `foley/README.md` 의 '정직 메모' 에 있다 (뒤집기 철퍽 · 톡톡 · 지글 세 결 · 10 s 바삭 루프의 되풀이 · 썰기 변형 · 불 켜기). 음악과의 섞임도 주인이 폰 스피커로 아직 듣지 않았다: 음악 내리기 -6 / -10 dB 가 알맞은지, `cook.html` 이 늘 같이 트는 빗소리가 지글을 가리지 않는지.
- `cook.html` 안에는 소리를 켜고 끄는 곳이 없다 (본 게임 설정에 저장된 것을 따르거나 `?sound=1`). 소리 목록을 못 읽어 조용해졌을 때 다시 켜는 길은 1분 뒤의 손길 하나다 (§8). 그 1분은 부엌 목록의 것과 같은 값으로 두었을 뿐, 실제 폰의 흔들리는 망에서 알맞은지는 보지 않았다. 목록을 못 읽었을 때 `AudioContext` 를 쉬게 두는 것은 Chromium 에서만 돌려 봤다 (Firefox · Safari 는 흉내로만).
- 조각 2 몫의 소리 여덟 개 (`cook_stir` 셋 · `cook_clink` · `cook_simmer` · `cook_place` 둘 · `cook_lift`) 는 파일과 표만 있다. 게임도 시험도 아직 틀어 보지 않았다.
- 부엌의 브라우저 시험 둘 (`test-cook-live.js` · `test-cook-audio.js`) 은 CI 에서 선택인 느린 일에만 있다. 깨져도 run 이 빨개지지 않으니 결과를 따로 봐야 한다. 꼭 도는 빠른 묶음은 소리 갈래와 크레딧을 보지 않는다.
- 자동 시험은 Chromium 에서만 돈다. `.m4a` (AAC) 로 실제로 트는 길, iOS 사파리의 첫 손길 풀기, 파이어폭스의 페이드는 실제로 돌려 보지 않았다 (장면 L 이 `cancelAndHoldAtTime` 없는 경우를 흉내 낼 뿐이다). WebKit 에서는 부엌 시험도 아직 돌려 보지 않았다 (설계의 선택 시험: `npx playwright install webkit` 뒤 L5 · L6 · 배관만).
- `foley/listen.html` · `foley/README.md` · `foley/CREDITS.md` 는 만드는 사람용 글이라 배포에 나가지 않는다 (11-10 부터: `tools/export-site.js` 가 게임 파일만 내보낸다, README '배포'). 플레이어가 보는 크레딧은 `credits.html` 이다. `listen.html` 은 저장소에서 열어 듣는다 (`noindex`, 크레딧 링크 있음).
- 진동은 v0 에서 뺐다.
