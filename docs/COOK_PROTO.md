# 요리 시제품 · 조각 1 (해초전, cook.html)

> 상태: **조각 1 구현됨.** `cook.html` 하나로 따로 논다. 본 게임(`index.html` · `js/app.js` · 장면)에는 아직 잇지 않았다.
> 설계: 9물결 요리 설계 2판 (`COOK_DESIGN.md`, **아직 저장소에 없다**: 조사 문서에서 디컴파일 저장소 줄을 지운 뒤 주 세션이 `docs/` 로 옮긴다). 이 문서의 § 번호는 그 설계의 번호이고, 이 문서만 읽어도 되도록 필요한 수치와 규칙은 여기 다시 적었다.
> 조각 문(설계 §11): 이 조각이 끝나면 **멈추고** 주인이 폰에서 소리를 끈 채로 해 본다. 손맛이 되면 조각 2 (미역국 · 톳 주먹밥 · 젓기 · 올리기 · 요리 수첩 화면).

## 0. 한눈에

- 폰으로 `cook.html` 을 열면 바로 부엌(조리대)이다. 팬을 누르면 해초전이 시작된다: **톡톡 → 뒤집기 → 썰기** → 접시가 오른다 → 톡 하면 조리대로 돌아오고, 방금 만든 접시가 팬 옆에 놓여 있다.
- 실패 · 점수 · 시간 제한 · 메달이 없다. 진행은 오르기만 한다. 기다려도 타지 않는다.
- 소리가 꺼진 것이 기본 경우다. 센 입력마다 **바로 다음 프레임**에 무대가 바뀐다 (밝은 테두리 · 찌그러짐 · 부스러기 · 남는 자국).
- 손이 먼저다. 동사 단추는 늘 있지만 터치에서는 조용하다 (`opacity 0`, 자리는 그대로). 5초 멈추면 흐린 손 그림이 한 번 나오고, 그때부터 단추가 보인다. 키보드면 처음부터 보이고 포커스를 받는다. **조용한 단추 자리를 손가락 · 마우스로 누르면 단추가 드러나기만 하고 동작은 하지 않는다** (빗맞은 톡이 전을 뒤집지 않게). 그 자리에서 시작한 획은 무대 입력이라 아래에서 올려 쓸어도 뒤집힌다. 포인터 누름 없는 클릭 (키보드 · 화면 읽기) 은 바로 동작한다.
- 저장 키는 따로다: `cook.html` 은 `ppolppol_cook_v0`, 본 게임에 이을 때는 `ppolppol_cook`. 본 게임 기록은 읽지도 쓰지도 않는다.

## 3. 단계 종류 (판정 요약)

거리는 논리 px (무대 288 × 320 = 아트 px × 2), 시간은 단계 시계 ms. 진행은 오르기만 한다. 손 떼기 · `pointercancel` · 엉뚱한 방향은 아무것도 깎지 않는다.

| 종류 | 손동작 | 판정 | 단추 (조용한 동사 단추) | 남는 모양 · 꼬리표 |
|---|---|---|---|---|
| `tap` 톡톡 | 음식 위를 톡톡, 꾹 눌러도 됨, 두 손가락 번갈아도 됨 | 모든 `pointerdown` 을 센다. 덜 된 표시 중 가장 가까운 곳에서 80 px 안. 90 ms 안의 두 번은 하나로. 꾹: 400 ms 뒤부터 250 ms 마다 (정해진 시각표대로, 화면 주기와 상관없음). 3 · 6번에 반죽이 넓어진다 | 한 번 = 다음 표시에 3번 | 자국 (최대 9) · 꼬리표 없음 |
| `flip` 뒤집기 | 첫 누름 = 불 켜기. 위로 쓸어 올리면 뒤집힘 | 위로 32 px 이상, 위쪽 ±45° 안, 빠르기 상관없음. 판정 굽기 = 그 획을 누른 순간의 굽기. 톡은 절대 뒤집지 않는다 (불 켠 뒤 톡은 1프레임 들썩). 불 켠 뒤 0~3 s 보들보들 · 3~6 s 노릇노릇 · 6 s~ 바삭바삭에서 기다린다 | 첫 번 = 불 켜기, 둘째 = 지금 굽기로 뒤집기 | 굽기 0~2 · `soft` `golden` `crisp` |
| `slice` 썰기 | 점선 안내선을 따라 쓸기 (방향 · 속도 상관없음, 떼었다 이어도 됨), 또는 가로질러 한 번 긋기 | 안내선은 그 줄 방향의 음식 크기 + 양 끝 3 아트 px (해초전: 가로줄 64, 세로줄 44 아트 px). 40칸 중 80 % 칠하면 그 줄이 잘린다 (띠 32 px, 진행 방향 ±40°): 전 끝에서 끝까지 한 번 그으면 (90 % 만 그어도) 잘린다. 가로지르기: 15~85 % 구간을 50° 이상으로, 16 px 이상. 각도 = 띠 안 표본의 최소제곱 주축, 6° 계단, \|각\| ≥ 12° 면 어슷 | 한 번 = 다음 줄을 반듯하게 | 줄마다 각도 · `straight` `slant` |

화면 읽기 (`aria-live="polite"`, 매 프레임이 아니다): 단계 시작 동사 · 톡톡 '반쯤' · 썰기 줄마다 '한 줄' · 굽기가 바뀔 때만 굽기 낱말 · '다 됐어' · 접시 공개 때 접시 설명 ("해초전. 노릇노릇 구웠어. 반듯하게 썰었어."). 굽기 낱말은 화면 DOM 에 없다 (전의 색이 곧 정보).

## 5. 화면 · 배치 · 포커스

- **배치** (설계 §5.2): 무대 = 아트 144 × 160 을 기기 px 정수 배로 (`k = max(1, floor(min(가로여유 × dpr / 144,세로여유 × dpr / 160)))`, `k / dpr ≤ 3`). 무대 틀은 그림 안 2 아트 px. 무대는 56 px 동사 단추 칸 바로 위, 남는 세로 공간은 모두 머리줄 위로. 좌우 거터 16. 320 폭에서 가로 스크롤 없음. 위치는 기기 px 에 맞춘다 (DPR 2.625 에서도 선이 떨리지 않게).
- **머리줄**: 단계 그림 띠 (그림 3개, 지금 단계는 2 px 위 + 호박색 2 px 줄, 숫자 없음) + [닫기]. 조리대에서는 [닫기] 만.
- **제목 꼬리표**: 단계 시작에 동사 하나 (600 ms, 누르면 바로 사라짐). 종이 9-slice 틀, 24 px.
- **처음 보는 종류**: 이 기기에서 처음 보는 단계 종류면 제목 직후 흐린 손 그림이 한 번 동작을 보여 준다 (뒤집기는 불 켜기 톡, 불 켠 직후 위로 쓸기). 본 종류는 저장의 `seen` 에.
- **놀이 힌트**: 5 s 진행이 없으면 손 그림 한 번 (그 뒤 동사 단추가 그 판 끝까지 보인다). 뒤집기는 불 켠 뒤엔 바삭바삭 + 5 s 에만. 손 그림은 **진행** (자국 · 불 켜기 · 뒤집기 · 칼집 · 잘림) 이 있을 때만 비켜 주고, 아무것도 안 바꾸는 누름으로는 지워지지 않는다. 처음 보는 종류는 그 손 그림이 끝까지 돈 뒤 (또는 단계가 끝난 뒤) 에야 `seen` 에 남는다. 불 켠 뒤 안 뒤집히는 누름이 이어지면 위로 쓸기 손 그림을 한 번 더 보여 주고 단추를 드러낸다 (재촉이 아니라 대답: 한 단계에 두 번까지).
- **접시 공개**: 접시가 다 오르고 5 s 동안 누름이 없으면 접시 위에 톡 손 그림 한 번 + '돌아가기' 단추가 드러난다. 저절로 넘어가지 않는다. 조리대로 돌아온 뒤 500 ms 안에 시작한 누름 (접시 두 번 톡) 은 새 판을 열지 않는다.
- **뒤 배경**: 창 전체 뒤는 놀이방의 판자 벽 (`COOK_ART.wallTile`) 을 무대와 같은 정수 배로 깐다. 큰 폰에서 무대 위 빈 자리가 빈 종이 대신 부엌 벽이 된다. 어두운 색 모드면 같은 벽의 밤 색. 무대 · 단추 자리는 그대로다.
- **포커스** (설계 §3.3): 열기 → 팬 / 조리대 → 단계: 마지막 입력이 키면 동사 단추, 아니면 무대 상자 / 단계 → 단계: 그대로 / 접시가 다 오른 뒤 (450 ms) 같은 규칙 / 접시 공개 → 조리대: 팬 / [닫기] · Esc: opener (없거나 숨었으면 `#btn-play-door` → `#btn-go`) / 쪽지는 포커스를 가져가지 않는다 / [보러 가기] 는 opener 로 돌리지 않는다. 포커스 테는 키 입력 뒤에만 그린다.
- **동작 줄이기**: `COOK.open({ reduced })` 또는 `prefers-reduced-motion` 또는 `data-motion="reduce"`. 밝은 테두리와 남는 것 (자국 · 칼집 · 굽기) 만. 찌그러짐 · 입자 · 흔들림 · 호 · 손 그림 움직임 없음 (손 그림은 정지 그림).
- **소리 없이 손맛**: 센 입력은 그 입력 처리기 안에서 시뮬레이션을 지나고, 다음 그리기에서 무대가 바뀐다. 손이 직접 움직이는 칼 · 뒤집개는 화면 주기대로 아트 px 에 붙어 움직인다. 반응 애니메이션은 12 fps 계단. 입자 난수는 `mulberry32(COOK.fxSeed(seed, si))` (놀이 시드와 따로).

## 6. 저장

```js
localStorage[storeKey] = { v: 1, day: 'YYYY-MM-DD', dayN: 3, seen: ['tap', 'flip', 'slice'],
  pot:  null | { ver: 'cook-1', tune: 3684023978, runId, seed, recipe, swaps, si, looks: [...], tags: [...], at },
  book: [ { id: 'ck_…', recipe, seed, swaps, look, day, madeAt } ] }   // 최근 것이 앞, 최대 300줄
```

- 판(`pot`)은 **단계 경계**에서만 쓴다: 단계가 끝날 때, 탭이 숨을 때 (`visibilitychange`), `pagehide`, 닫기, [보러 가기]. 이어 하면 지금 단계를 처음부터 한다. `ver` · `tune` · 레시피 · `si` · 모양이 맞지 않거나 깨졌으면 조용히 버린다 (조리대에 "이어서" 가 안 나올 뿐).
- 접시가 끝나면 판을 지우고 수첩에 한 줄을 넣는다. 수첩 화면은 조각 2 에 온다 (조각 1 에는 수첩을 볼 곳이 없어서 "요리 수첩에 넣었어." 도 아직 말하지 않는다).
- 시드 = `hash32(day + '|cook|' + dayN)`, 판 id = `'ck_' + hash32(day|dayN|난수).toString(36)` (`crypto.getRandomValues`, 없으면 수첩 줄 수). **시작 시각은 쓰지 않는다**: 수첩 줄에 `madeAt` 이 같이 있어서, 시작 시각이 id 에 들어가면 걸린 시간을 거꾸로 찾을 수 있다 (설계 §4.2 의 `startedAt` 에서 바꿈, 주인 확인 거리). 날짜는 로컬, 시험은 `window.__ppolTest.today`.
- 저장 키는 부엌 것만 받는다: `ppolppol_cook` 또는 `ppolppol_cook_…` (`cook.html` 은 `ppolppol_cook_v0`). 다른 키를 넘기면 `ppolppol_cook` 을 쓴다. 본 게임 저장 키는 읽지도 쓰지도 못한다.
- 저장이 실패해도 (사생활 모드 · 가득 참) 놀이는 그대로다. 오류 글 없음.

결과 봉투 (`onResult` 로 넘긴다; `ms` 는 늘 `null`, `status` 는 `done` 만):

```js
{ v: 1, id: 'ck_…', by: 'user', game: 'cook', status: 'done', ms: null,
  out: { dish: { id: 'jeon', name: '해초전', tier: 1, ingredients: ['batter', 'parae'] },
         recipe: 'jeon', seed, swaps: { herb: 'parae' },
         steps: [{ kind: 'tap', status: 'done', tag: null }, { kind: 'flip', status: 'done', tag: 'golden' }, { kind: 'slice', status: 'done', tag: 'straight' }],
         look: { v: 1, dents: [[x, y] …], band: 1, cuts: [0, -6], offs: [2, -1], plate: 1 }, madeAt, day } }
```

## 7. API (`COOK`)

| 부름 | 무엇 |
|---|---|
| `COOK.open({ opener, reduced, palette, day, storeKey, onResult, onClose })` → boolean | 부엌 창을 연다. 던지지 않는다 (안에서 터지면 정리하고 `false`). 이미 열려 있으면 `true`. `storeKey` 는 `ppolppol_cook` · `ppolppol_cook_…` 만. 시험 · 개발용 옵션: `seed`, `recipe`, `slow`, `rec`. `palette` 는 받아 두기만 한다 (조각 1 에서는 그림에 쓰지 않음) |
| `COOK.close()` · `COOK.isOpen()` | 닫기 (판 저장 · `quiet`) · 열림 여부 |
| `COOK.notice({ text, short, label, fn })` → boolean | 머리줄 바로 위 정해진 칸에 쪽지. 짧은 화면이면 단계 그림 띠 자리에 `short`. 포커스를 가져가지 않고 무대를 밀지 않는다. [`label`] = 판 저장 → 창 닫기 → close 이벤트 끝에서 `fn` |
| `COOK.exportData()` · `COOK.importData(obj)` | 수첩 (`seen` · `book`) 만 오간다. 판은 가지 않는다. 둘째 인자로 다른 부엌 키를 줄 수 있다 (부엌 키가 아니면 `null` · `false`) |
| `COOK.live()` | 시험용 읽기 전용 사본: `screen` (`closed` · `counter` · `step` · `reveal`), `recipe`, `si`, `kind`, `phase`, `progress`, `done`, `tag`, `band`, `quiet`, `fx` (센 반응 수), `verb`, `hint`, `k`, `css`, `tight`, `reduced`, `stats`, `said`, `look`, `st`, `err` … |
| `COOK.auto(on)` | 시험용: 동사 단추 길로 한 접시 (짧게 쉬며) → 접시 공개 → 조리대 |
| 시뮬레이션 | `createRun` · `resumeRun` · `input` · `tick` · `drain` · `simulate` · `resultOf` · `drawDish` 등 (`js/cook.js` 맨 위 계약 주석). `simulate(recipe, seed, steps, { cadence, until, pot })`: `cadence` 1~1000 Hz, `until` 10분 이하로 자른다. `pot` 을 주면 이어 한 판 (`?rec=1` 기록의 `pot`) 을 그 단계부터 다시 돌린다 |

## 8. 소리 act 표 (소리 세션에게)

부르는 곳은 하나다: `window.AUDIO && AUDIO.on && AUDIO.on('cook', { act, … })`. 입력 처리기 안에서 바로 부른다 (한 프레임 늦지 않게). 시간으로 생기는 것 (굽기가 바뀜 · 꾹 자동 톡 · 접시 공개) 은 그 프레임에 부른다. 같은 act 는 120 ms 이상 간격 (`step` · `done` · `pick` · `quiet` 은 예외). 실패 · 빗나감 소리는 **없다**. 지금 `js/audio.js` 에는 `case 'cook'` 이 없다 (cook.js 는 audio.js 를 고치지 않는다).

| act | 언제 | 덧붙임 | 느낌 (F 장조 · F 5음) |
|---|---|---|---|
| `pick` | 조리대에서 소품을 누름 | `{ dish: 'jeon' }` | 나무 톡 |
| `tap` | 톡톡에서 센 한 번 (손 · 꾹 · 단추 모두) | `{ i }` 0~8 | i 따라 한 음씩 위로 |
| `sizzle` | 불 켤 때 (`band` 0) · 굽기가 바뀔 때 (1, 2) · 숨었던 탭이 돌아왔는데 불이 아직 켜져 있을 때 (지금 굽기) | `{ band }` | 지글. 굽기마다 결이 바뀐다 (귀로 고르는 길). 루프로 만들면 `quiet` 로 멈추고, 탭이 돌아오면 다시 받는 `sizzle` 로 다시 튼다 |
| `flip` | 뒤집음 | `{ band }` | 휙 + 툭 |
| `cut` | 썰기 한 줄이 잘림 | `{ i }` 0~1 | 사각 |
| `step` | 단계 하나 끝 | `{ kind }` | 짧고 부드러운 똑 |
| `quiet` | 단계 끝마다 (뒤집음 뒤에도), 탭 숨김, 닫기, [보러 가기] | — | 지글 끄기 (탭이 돌아오면 불이 켜져 있는 한 `sizzle` 이 다시 온다) |
| `done` | 접시 공개 | `{ dish: 'jeon' }` | 세 음 |
| `stir` · `lift` · `place` · `back` | 조각 2 (젓기 · 올리기) | `{ i }` 등 | 찰랑 · 아주 작게 · 퐁 · lift 와 같은 결 더 작게 |

해초전 한 판의 순서 예: `pick` → `tap` × 9 → `step` `quiet` → `sizzle(0)` → `sizzle(1)` → `flip` → `step` `quiet` → `cut` → `cut` → `step` `quiet` → `done`.

## 10. `COOK.start` 계약 (문서만 · 코드 없음)

같이 가기 · 시험대처럼 창 없이 다른 요소 안에 무대만 띄우는 손잡이다. v0 에는 만들지 않는다.

```js
COOK.start(el, { recipe, seed, reduced, onResult, onEnd }) → handle | null   // never throws
handle.stop() → result | null    // 주인이 아니라 바깥이 끝낼 때
handle.live() → COOK.live() 와 같은 모양
```

- `el` 안에 무대 캔버스와 동사 단추만 넣는다 (머리줄 · 조리대 · 저장 없음, 판은 저장하지 않는다).
- 결과 봉투는 §6 과 같고 `status` 만 셋 중 하나다: `done` (접시까지) · `cut` (`stop()` 으로 중간에 끝남: 끝난 단계의 모양만 `look` 에) · `empty` (아무 진행 없이 끝남, `look` 은 기본 모양). `ms` 는 늘 `null`. 점수 · 시간 · 손/단추 구분 칸은 없다.
- 차리기 기록 (식탁 · 같이 가기 v1 에): `{ id: 'serve_…', at, runId, dish: { id, name, tier }, by: 'user' }` — 글자 그대로 계약만 둔다.

## 11. 쿠킹 마마와 다른 점 (글로만 적는다)

| 쿠킹 마마 (기계에서 배운 것) | 우리 |
|---|---|
| 진행자가 지시 · 칭찬 · 꾸중한다 | 진행자 없음. 문어도 나오지 않는다. 아무도 판정하지 않는다 |
| 위 지시 화면 + 아래 손 화면 | 한 화면, 무대 하나 |
| 외침 제목 문장 | 평범한 동사 낱말 하나 (종이 꼬리표, 600 ms) |
| 목표 구간 게이지, 빗나감, 탐 | 게이지 없음. 불 켜고 위로 쓸어 뒤집기. 굽기 셋 다 좋은 결과, 기다려도 타지 않는다 |
| 진행 막대 | 진행은 음식에 보인다 (자국 · 굽기 색 · 칼집) |
| 요리 아이콘 메뉴판 | 우리 조리대의 소품 (팬) 을 누른다 |
| 메달 · 점수 결과 화면 | 접시가 오르고 이름 꼬리표만. 조리대의 팬 옆에 접시가 남는다 |
| 고기 · 생선 레시피 | 바다 식물 · 곡물로 만든 우리 요리 (해초전) |

이름 · 캐릭터 · 그림 · 음악 · 단계 제목 · 화면 모양은 가져오지 않았다. 가져온 것은 "한 동사 짧은 단계 사슬, 요리는 늘 끝난다, 손이 곧 음식에 자국" 이라는 기계뿐이다.

- Playwright (L1~L18): 터치 길 끝까지 (DPR 2 · 2.625, 캡처) · 키보드만 (옮길 때마다 `document.activeElement`) · 조용한 단추 · 뒤집기 굽기 (가짜 시계, 굽기 낱말은 `aria-live` 노드에서 직접 읽음) · 배치 다섯 크기 + DPR 2.625 (무대 · 단계 그림이 기기 px 위에) · 소리 없이 다음 프레임 반응 + 가짜 AUDIO act · 동작 줄이기 · 새 브라우저에서 이어 하기 · 나쁜 판 · 저장 가득 · Enter 꾹 · 쪽지 · `?rec=1` 기록 → 노드 `simulate` 같은 모양 · DOM 글 숫자 0 · 콘솔 오류 0 · L15 조용한 단추 자리 (빗맞은 톡은 드러내기만, 거기서 시작한 쓸기는 뒤집음, 포인터 없는 클릭은 바로) · L16 손 그림 (안 바뀌는 누름에 안 지워짐, 다시 가르치기 두 번까지, 접시 공개 5 s 뒤 손 그림 + 돌아가기, 접시 두 번 톡) · L17 가장자리 24 px · 제목 600 ms · 처음 보는 손 그림과 `seen` · 이름 꼬리표 늦춤 · `?slow=4` · 밝은 테두리 한 프레임 · L18 판 id 에 시계 없음 · 부엌 키만 · 탭 복귀 뒤 `sizzle` · `auto` · 잃은 포인터 잡기 · 이어 한 판의 `?rec=1` 다시 돌리기.
- 터치는 CDP `Input.dispatchTouchEvent` 로 보낸다 (Playwright `touchscreen` 은 톡만 된다). Chromium 은 `touchmove` 를 다음 실제 프레임에 넘기므로, 프레임 단위로 재는 시험은 움직임 뒤에 잠깐 실제 시간을 기다린다.

## 14. 알려진 한계 · 다음

- 실제 폰 점검 전이다 (설계 §6.8 점검표: iOS 사파리 · 안드로이드 크롬, 소리 끔). 특히 꾹 3 s (글자 돋보기 · 메뉴가 안 뜨는지), 사파리 아래 도구 막대, 화면 가장자리 뒤로 쓸기, VoiceOver · TalkBack 으로 조용한 단추 누르기: 화면 읽기의 두 번 톡이 진짜 터치 누름으로 오면 (iOS VoiceOver 가 그럴 수 있다) 첫 두 번 톡은 단추를 드러내기만 하고 둘째에 눌린다. 포인터 없는 클릭으로 오면 (키보드 · TalkBack 의 클릭) 바로 눌린다.
- 설계에서 바꾼 것 셋 (주인 확인 거리): ① 썰기 세로줄 안내선이 64 가 아니라 44 아트 px (음식 + 3, 전 위아래를 다 그어도 안 잘리던 것을 고침) ② 판 id 에 시작 시각 대신 난수 ③ 조용한 동사 단추를 손가락으로 처음 누르면 드러나기만 한다 (설계 §2.4 '조용할 때도 눌린다' 와 §2.2 ④ '톡은 절대 뒤집지 않는다' 가 부딪혀서, 뒤쪽을 지켰다).
- 단계 그림 띠: 자리는 기기 px 에 맞추고 (머리줄 위치 · 띄움 2 px 도 기기 px 로) 그림은 기기 해상도로 그리지만, DPR 2.625 · 2.75 에서는 Chrome 의 1/64 px 배치 단위 때문에 16 px 그림 칸이 80 이 아니라 79.98 기기 px 가 되어 가장자리 한 줄이 섞여 보일 수 있다 (0.4 CSS px 너비). 무대 캔버스에는 영향이 없다.
- DPR 2.8125 폰에서는 무대 CSS 크기 (예: 307.2 px) 가 Chrome 의 1/64 px 단위로 정확히 안 떨어져 아트 px 몇 줄이 5 · 7 기기 px 가 될 수 있다. 설계가 이름 붙인 2.625 · 2.75 는 정확하다. 고치려면 무대를 한 단계 작게 해야 해서 그대로 둔다.
- 조리대 벽이 비어 보일 수 있다: 병 선반은 조각 2 에 진짜 소품으로 온다 (안 되는 소품은 그리지 않는다는 규칙).
- 남는 세로 공간은 설계대로 머리줄 위로 간다 (엄지 자리). 큰 폰에서 그 자리는 이제 빈 종이가 아니라 놀이방 판자 벽이다. 벽에 더 걸 것 (창 · 선반) 은 되는 소품이 생길 때.
- 뒤집기 호는 4프레임이고 단계 사이가 400 ms 라, 착지 뒤 썰기 화면으로 금방 넘어간다. 썰기 도마 위 전이 같은 굽기 색이라 이어져 보인다.
- 소리는 아직 없다 (`AUDIO.on('cook')` 은 부르지만 audio.js 에 갈래가 없다). 진동은 v0 에서 뺐다.
- WebKit 에서는 아직 돌려 보지 않았다 (설계의 선택 시험: `npx playwright install webkit` 뒤 L5 · L6 · 배관만).
