## 3. 장면 패치 `docs/shots/intro-slow/scene3d-intro.patch`

`js/scene3d.js` 는 잠긴 파일이라 커밋하지 않았다. 입장 부분만 바꾼 패치다. 주 세션이 장면 열쇠 차례에 넣는다.


| 바꾼 곳 | 무엇 · 까닭 |
|---|---|
| `INTRO` | 필드 `top`(맨 위 멈춤 초) · `bands`(하늘 띠 2개) · `band` · `bg0`(원래 배경) · `pass`(뚫는 높이) · `covered` 를 더했다. 새 `EASE = { a 0.28, d 0.38, land 0.9, bump 0.86 }`, `introK()` (멈춤 뒤 움직임 진행도) |
| `introOffset` | 곡선을 easeOutCubic(처음이 가장 빠름)에서 **멈춤 → 사다리꼴 속도**로 바꿨다. 처음 28 % 가속, 가운데 일정, 끝 38 % 감속, 움직임의 90 % 에 착지. 86~100 % 에 착지 눌림 2 px (예전 3 px). 주인 말 "처음 천천히 · 중간 일정 · 부드러운 착지" 그대로다. 속도가 이어지는 닫힌 식이라 프레임 dt 와 상관없이 결정적이다 |
| `var CLOUD` | 가까운 층 196×98 · ×1.75, 먼 층 `far` 136×68 · ×1.2, `pass` 0.58 (뚫는 구름이 화면 가운데 오는 높이 = H 의 비), `near` (가까운 층 자리표: 높이 비 · 왼쪽/오른쪽) |
| `buildSky` | 수를 줄였다 (드로우콜 §4). 먼 층은 출발 화면 둘레 높은 곳에만 둔다 — 뚫는 구름이 지날 땐 이미 화면 위로 나가 있어야 다 덮는 프레임이 길어지지 않는다. 가까운 층은 뚫는 구름보다 위에서 화면 옆을 반쯤 걸치고 스친다. **뚫는 구름**: 폭 = 화면 + 24 px, 높이 = 몸 + 몽우리 아래 절반이 화면 높이 + 0.02 s 이동만큼. 그리는 순서는 먼 층(5~) → 뚫는 구름(30) → 가까운 층(40~). 비·눈은 그 구름 밑면부터만 (`sky.rainTop`). 별은 밤·노을·새벽이면 날씨와 상관없이 구름 위에만 (밤 28 · 노을 12) |
| `skyLayout` | 매 프레임 하늘 띠를 고른다 (`off > pass` 면 위 띠). 띠가 바뀌는 순간은 뚫는 구름이 화면을 덮고 있을 때다. 다 덮였는지(`covered`)를 화면 px 로 잰다 |
| `skyHex` | 입장 중에는 **띠마다 따로** 읽는다. 매 프레임 불러도 된다 — 실제 `readPixels` 는 띠가 바뀐 뒤 몇 번(최대 4)뿐이고, 덮인 동안은 안 읽는다. 입장이 아닐 때는 예전 그대로 |
| `skyEstimate(hex?)` | **어림 버그 고침.** 배경색은 `C()`(sRGB→선형)로 렌더 타깃에 들어가는데 후처리가 그 값을 다시 sRGB 로 읽는다. 그래서 낮 허공 `#1b1522` 도 화면엔 `#090a14` 로 나온다. 예전 어림은 `#241527` 이라 틀렸고 `readPixels` 가 바로잡았다. 이제 지금 배경 값 그대로(`scene.background.getHexString()`)로 어림해서 처음부터 맞는다. 그래서 띠가 바뀐 프레임에 덮개가 바로 따라간다. 결과는 팔레트가 같으면 캐시한다 |
| `startIntro` | `o.top` (dur 의 30 % 까지) · 띠 둘: 위 띠는 `C()` 없이 그 값 그대로 넣어 화면에 그 칸이 그대로 나온다. 아래 띠 = 원래 배경. 돌려주는 Promise 에 `skyLive = true` (입장 레이어가 매 프레임 `skyHex` 를 불러도 된다는 표시) |
| `finishIntro` | 배경을 원래 값으로 되돌리고 띠·읽은 색을 비운다 |

`stepIntro` · 공개 API 표 · `probeSky` 는 그대로다. 새 API 는 없다 (`intro()` 옵션 `top` 과 Promise 의 `skyLive` 표시만 늘었다).

### 패치 없이 (지금 scene3d) 돌면

`intro.js` 는 `top` 을 넘기지만 옛 장면은 모른 체한다. `skyLive` 가 없으니 예전처럼 처음 몇 프레임만 `skyHex` 를 읽는다 (매 프레임 `readPixels` 를 하지 않는다). 그래서 옛 곡선(easeOutCubic) 그대로 3.0 s 동안 2.6 화면 높이에서 내려오고, 옛 구름이 그 높이에 퍼진다. 타이틀은 진행도 0.92 에 뜬다 (옛 곡선은 0.86 에 착지하므로 착지 뒤다). 깨지는 것은 없다 (§5).

## 4. 잰 값 (SwiftShader, 360×740 · 412×915 · 1280×800)

> 11-11 덧붙임: 이 절의 값은 부팅 뒤에 `APP.scene.intro()` 를 다시 불러서 잰 것이다 (맞는 크기의 하늘). 진짜 부팅 흐름은 11-11 까지 다른 크기로 지어졌다 — §8.

**다 덮인 프레임** (60 fps 스텝, 장면에 하늘색 픽셀이 0.2 % 미만인 프레임 수):

| 화면 | 낮 가랑비 | 노을 맑음 | 낮 맑음 | 낮 비 |
|---|---|---|---|---|
| 360×740 | 4 | 3 | — | — |
| 412×915 | — | — | 3 | — |
| 1280×800 | — | — | — | 3 |

그 앞뒤로 2~8 프레임은 몽우리 사이로만 하늘이 조금 보인다 (5 % 미만). 밤 눈은 1 로 재지는데, 밤 눈구름 램프의 가장 어두운 칸이 하늘색 `#172038` 과 같아 잰 값이 적게 나온 것이다 (눈으로 보면 다른 날씨와 같다).

**드로우콜** (`stats().calls`, 하늘 단계 동안 1/40 s 스텝, 다락 평소 = base):

| 시각 · 날씨 | base | 전 최대 / 평균 | 후 최대 / 평균 |
|---|---|---|---|
| 낮 맑음 | 71 | 72 / 59.7 | 72 / 32.7 |
| 낮 가랑비 | 77 | 81 / 68.9 | 80 / 41.2 |
| 밤 비 | 77 | 82 / 69.9 | 81 / 42.7 |
| 밤 눈 | 73 | 77 / 64.9 | 76 / 37.7 |
| 노을 맑음 | 71 | 73 / 60.8 | 73 / 33.8 |

최대는 같거나 1 적다 (착지 직전, 방 + 남은 하늘). 평균은 방이 화면 밖에 있는 시간이 길어져 절반쯤이다.

**연출 시작 비용** (`intro()` 한 번, 하늘 만들기, 중앙값): 전 13 ms → 후 23 ms. 구름 그림이 커지고 뚫는 구름이 늘었다. `clouds.js` 를 `ImageData` 한 번 쓰기 + 먼 덩어리 건너뛰기로 고쳐서 53 ms 에서 줄였다. 화면이 아직 덮개 색일 때 한 번뿐이다. 매 프레임 비용은 늘지 않았다.

**시간** (가짜 시계로 잰 실제 속도, `?intro=1`): 타이틀이 뜨는 때 **전 1.12 s → 후 2.71 s**. 하늘 단계는 3.0 s, '딱' 계단 0.2 s, 반짝 0.4 s, 안내 글은 2.16 s 뒤 멈춘다.
