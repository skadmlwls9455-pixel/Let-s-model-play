`APP` 은 `SCENE = SCENE3D.supported() ? SCENE3D : SCENE2D` 하나만 본다(DESIGN §13.1). `?scene=2d` 로 폴백을 강제할 수 있다.

## 공간 · 카메라
- 방 5×5 m, `x,z ∈ [-2.5, 2.5]`, 벽 높이 3 m. 왼쪽 벽(x=-2.5)에 창, 뒷벽(z=-2.5)에 보드·선반·**문(오른쪽 끝, 어둠으로 뚫림)**.
  §13.2 의 앞쪽 문은 직교 시점에서 바닥을 가려 뒷벽으로 옮겼다.
- 직교 다이메트릭: 틸트 32°, 요 45°(드래그 ±25°, **9° 스냅**), 타깃 `(0, 0.75, -0.4)` 를 아트 픽셀 격자에 스냅.
- **픽셀 스냅 (룩 패스 5·8)**: `S.pw` = pixelWorldSize = 직교 프러스텀 폭 / 렌더 타깃 폭 = 1/N (**기본 p=2 줌 1 → 1/27 m = 3.7 cm**, p=3 → 1/18 = 5.56 cm, p=2 줌 ×2 → 1/54). 매 프레임 `snapScreen` 이 카메라 타깃을 카메라 우/상 축 기준 pw 격자에 올리고(패닝·추적 중 크리프 없음), 문어의 논리 위치 `oct.pos` 를 같은 격자에 스냅해 `octG.position` 에 쓴다(걷기 보간은 매끄럽게, 보이는 위치는 정수 픽셀; 폴짝·통통은 `snapUp` 으로 세로 정수 px). 정적 소품(등불·옹이·상자 더미·깔개·화분·이끼·양초·담요·보드·선반·커튼·포스터 칸·기념품)의 x·z 는 빌드 때 `snapPos` 로 **1/27 m**(`SNAP_N` = 18 × 3 / 기본 p 2) 격자에, 받침 치수는 픽셀 배수(p=3 폴백에선 반 픽셀 위상 — 폴백은 느린 기기 전용). `stats().pw`.
- 비율 **18 아트픽셀/m × 3/p**: 기본 **p=2 → 27/m** (1 px ≈ 3.7 cm; 룩 패스 8 — p=3 은 '거칠다'는 피드백), p=3 → 18/m (5.5 cm). 핀치/휠 줌은 `{1, 1.25, 1.5, 2}` 정수 단계.
- 렌더 타깃 = `⌊W/p⌋ × ⌊H/p⌋`, p = 설정 1~4(**기본 2**, `DEF_P`), `W/480` 이상. 360×326 폰 → **178×162** (p=3 → 118×108). `setPixelRatio(1)`, 캔버스 `image-rendering: pixelated`.
- **자동 픽셀 폴백 (룩 패스 8)**: init 뒤 첫 2 s 의 평균 ms/frame(메인 스레드, `frame()` 전체)이 **24 ms** 를 넘으면 이 세션만 p=3 (`st.look.pixelSize`/`autoPixel` 에만, 저장 X; 데브 슬라이더가 덮어쓴다). `stats().autoMs/autoPixel`, 콘솔 `[scene3d] auto pixel 3`. SwiftShader 메인 스레드 평균 10~14 ms 라 폴백 안 됨. 데브 슬라이더의 초기 표시값은 app.js 기본 3 이라 장면의 2 와 다를 수 있다(UI 단계에서 `stats().pixel` 을 읽게).

## 문어 (DESIGN §7.1 · `assets/ref/octopus-ref.png`)
- 로컬 단위 = 머리 반지름 r, 전체 **0.42 배(r = 0.42 m ≈ 방 폭 8%)**. 머리 = 구 r1 (중심 y 0.92, y 0.88 찌그림 → 바닥 틈 1.7 cm), 눈 흰자 2(r 0.24, 둘 다 정면 y 0.67) + 하이라이트 타원(좌상) + 흰 점 + `_` 입(폭 0.3 r × 0.07 r, 눈 아래 — p=2 에서 3×1 px) → **정점색 1메시**. 동공(r 0.13, 검정 + 흰 글린트 r 0.07 ≈ 3 cm = p=2 에서 1 px) 2, 눈꺼풀(몸색) 1, 홍조 원판 2(1메시), `^ ^` 토러스 반원 2(1메시), `— —` 선 2종·큰 흰자·`u` 입(표정, 아래). 다리 8 = 바깥·아래로 말리는 테이퍼 사슬 4마디(두께 0.38 r → 0.13 r, **길이 ≈ 0.9 r**, 밑면이 바닥 y=0 에 닿고 끝이 들림) + 관절 구 + **빨판 점 3**(끝마디 밑면 2 + 그 앞 마디 1, r 0.07~0.08 ≈ 3 cm → p=2 에서 1 px 연한 점), 각각 1메시. 토운 3단(gradientMap 92/170/255 → 문어 램프의 밝은/기본/−2칸)이 p=2 에서 밝은 윗면 · 중간 · 그늘진 오른쪽 아래로 읽히고, 몸 밑은 깊이 외곽선이 1px 어두운 테를 두른다(8-close). 흔들림·걷기는 다리를 위로만 든다. 히트 구 r 0.67 m(≈72 CSS px), 접지 데칼 1.34 m. 패스 기록: `docs/LOOK_LOG.md`.
- 재질 `MeshToonMaterial` + 3단 gradientMap, 정점색. 색은 설정(hue 슬라이더 + 프리셋 6, `settings.octColor`, 기본 `#e8463c`)에서 하이라이트(L+0.14, b+0.07)·빨판(L+0.26)·입(L−0.32) 파생. 색을 바꾸면 한 번 흔들고 팔레트의 문어 램프 5칸만 교체.
- 상태: idle(숨 4 s, 깜빡임 3~7 s, 다리 흔들) · anticipate(600 ms 눌림 + 반눈 `calm`) · walk/carry(1.2 m/s **뒤뚱 걸음** — 아래 "움직임" 표, 도착 시 0.4 m 폴짝) · away(숨김) · carry(포스터 평면 들기) · hang(포스터가 보드 칸으로 500 ms 날아감) · happy(폴짝 2 + 꼭대기에서 다리 바깥 ×1.3) · sleep(`— —` 눈 + 6 % 납작 + hue ±18° 12 s) · stay · peek(좌우 흔들) · pet(`^ ^` + 홍조 원판 2 + 12 % 눌림 + ±4° 느린 흔들 + 색이 따뜻해짐. 2 s 뒤 APP 이 70% 기대기 / 30% 산책을 고른다 — 시무룩 없음). 눈·입·홍조는 **표정**이 그린다(아래 "초상·표정") — 상태는 기본 표정을 고를 뿐.
- 동공은 포인터를 따라간다(`lookAt` 으로 입력칸도). 가만히 있으면 카메라 쪽을 본다.
- 위치는 `oct.pos`(논리, 걷기 보간)이고 `octG.position` 은 매 프레임 그걸 카메라 우/상 축 픽셀 격자에 스냅한 값(룩 패스 5) — 걷는 동안 실루엣이 반 픽셀로 흐르지 않는다.

## 초상·표정 (룩 패스 8 · DESIGN §15.2 · `assets/ref/ui-ref-portrait-dialog.jpg`)
**표정** `setExpression(expr)` — 장면과 초상이 하나의 표정 상태를 공유한다. 상태(`setOctState`)는 기본 표정만 고른다(`happy→happy · pet→pet · sleep→sleep · anticipate→calm · 나머지→idle`), app.js 가 나중에 `setExpression` 으로 덮어쓴다(로그 대화창 행에서 같은 표정의 초상을 붙인다). `expression()` 로 현재 표정, `SCENE3D.EXPRESSIONS` / `scene.EXPRESSIONS` 로 목록. 모르는 이름은 `idle`.

- **출발 의식** `departCeremony(onDone) → Promise`: (바깥이면 다락으로 즉시) → `setOctState('walk')` → 다락 **문 앵커까지 걷기**(1.2 m/s × speed) → **전환 0.6 s** → 현관문 열림 0.2 s → 문 안(−0.02, 0.48, −1.1)에서 나타나 마루로 0.25 s → **계단 3 폴짝**(0.22 s × 3, 호 0.16 m; 첫 폴짝에 문 닫힘) → **길 따라** 1.8 m/s 로 가장자리(3.18, 0, 0.42)까지 2.8 m ≈ 1.6 s → 가장자리 너머로 폴짝(0.22 s, (3.8, −1.5, 0.82) — 받침 밖으로 떨어지며 화면 아래로) → `setOctState('away')` → `onDone`. 계단~가장자리 너머 ≈ 2.5 s, 전환 시작부터 ≈ 3.5 s. **바깥은 그대로 유지**(입자·창 불빛).
- **귀가 의식** `returnCeremony(onDone)`: (바깥이 아니면 즉시 바깥) → 가장자리 아래에서 폴짝 올라옴 → 길 거꾸로 1.8 m/s → 계단 3 + 마루 폴짝 → 문 열림 0.2 s → 문 안으로 0.25 s · 숨김 · 문 닫힘 0.15 s → **전환 0.6 s**(반 지점에서 `jumpTo('door')`) → 다락 문 앵커에 선 문어 → `walk` 였으면 `idle` → `onDone`. 그 뒤(보드까지 걸어가 포스터 걸기)는 APP 몫.

## 방 셋 · 놀이방 (8물결 · 카드 18 · 주인 11-07 "방 클릭하면 … 캐릭터가 그 방문 앞으로 가면 끼익 열리면서 다른 방으로")
세 방 = 왼쪽 옷방(나중) · **가운데 문어 방**(지금의 다락) · **오른쪽 놀이방**(부엌 + 다락방 달리기). 화살표 · 밀어서 넘기기 · 문 앞 질문은 없다 — 문을 누르면 문이 열리고 그 방으로 넘어간다. 문어는 놀이방에 오지 않는다(문어 그룹은 다락 그룹 안).
- **장소 말 셋**: `place()` = 이야기 장소(`attic`|`exterior` — 의식 · 앱 · 스모크 I 가 보는 값, **`play` 는 없다**) · `view()` = 지금 그린 곳(`attic`|`exterior`|`play`, 전환 앞 0.3 s 는 나가는 곳) · `room()` = 플레이어가 있는 방(`play`|`null`, 다락 문이 열리기 시작한 때부터 나오는 전환의 가운데 프레임까지). `PLACES = ['attic','exterior','play']`.
- **붙잡기 규칙** (한 곳 `setPlaceNow`): `room()` 이 `play` 인 동안 `setPlace('attic'|'exterior')` 는 이야기 장소만 바꾼다 — 문어 그룹을 옮기고 의식의 `onSwap` 은 안 보이는 곳에서 바로, 전환 없음, 화면은 놀이방 그대로. 출발 · 귀가 · 기웃 · 퇴장 · 취소 의식과 앱의 `ensureAttic` · 부팅 · `resumeRunning` 이 모두 이 길이라 **산책이 플레이어를 놀이방에서 끌어내지 못한다**. 놀이방을 나가면 늘 **그 순간의 `place()`** 로 간다(문어가 집이면 다락, 아직 나가 있으면 바깥). `on.place` 는 놀이방에서도 온다.
- **다락 문** (카드 18 후보 (나)): 오른쪽 바닥 끝에 선 문틀 + 문짝, 문틀 가운데 (2.37, 0, 1.0), 얼굴은 +x (왼쪽 벽처럼 45° 로 보인다). 열림 0.72 × 1.68 m · 틀 높이 1.80 · 문턱 판. 칠(Apollo 램프): 크림 틀 `paper[1]` · 초록 문짝 `moss[2]` + 판 `moss[1]` · 둥근 창 · 호박 손잡이 — 어두운 바깥 문(뒷벽 x 1.5~2.4)과 헷갈리지 않는다. 둥근 창은 낮엔 하늘, 노을~밤엔 호박빛 + 발광 쌍둥이(문 너머 불 켜진 방). **밤엔 문틈 불빛**: 손잡이 쪽 틈 세로 한 줄 + 문턱 위 한 줄, 빛 안 받는 호박색(`D.seam`, 노을 · 밤 · 닫혀 있을 때만 — 등불 0칸 밤에도 문 윤곽이 읽힌다; 낮 그림은 그대로, 밤 픽셀 차이도 문 윤곽 안). 열면 문짝이 +x 쪽(놀이방 쪽)으로 −z 경첩에서 돌고 뒤로 따뜻한 호박 문간이 보인다. 그림자 안 던짐, 받음. 다락 그림은 문 픽셀 밖에선 예전과 같다(문을 숨기면 HEAD 와 픽셀 0 차이, 보이면 차이는 문 윤곽 안 + 바닥 닿는 곳 1~4 아트px 외곽선 고리). (가) 뒷벽 오른쪽은 빈 폭이 0.3 m 뿐이라 지도 · 목도리 뒤 바깥 문 조각처럼 읽혀 버렸다 (캡처 비교).
- **놀이방** (`buildPlayRoom`, **처음 들어갈 때 짓는다** — 안 열면 시작 비용 0, `stats().playBuilt`): 바닥 **3.4 × 3.4 m · 벽 2.2 m** (`SCENE3D.PLAY_SIZE` — ROOM_EXPANSION §5.2 의 3.6 × 2.4 는 360×640 장면 139 아트px 에 145 px 가 필요해 위아래가 잘렸다; 3.4/2.2 는 360×640 위아래 4~5 px 남고 다 보인다). **짧은 장면**(높이 250 px = 아트 125 px: 320×568 · 가로 폰)엔 방(받침 포함 ≈ 136 아트px)이 다 안 들어가므로 위를 지킨다 — `framePlay()` 가 `PLAY_TARGET` 을 올려 벽 꼭대기 · 문 · 오락기 · 등이 위 여백 3 px 로 다 보이고, 잘리는 건 아래 받침(≈ 11 px)과 빈 바닥 앞 끝뿐 (각도 · 1× 밀도 27 px/m 는 그대로, 다 들어가면 예전처럼 가운데). 다락과 같은 바닥 널(시드 길이) · 0.3 m 벽 판자 + 1px 이음 · 기둥 · 받침 지층 · 재질 · 팔레트 · 카메라 각도 · 27 px/m, 틀은 `PLAY_TARGET` + `PLACE_BOX.play`. 왼쪽 벽: **문어 방으로 가는 문**(같은 문 모델 · 칠) + 깔개 + 앞쪽 창(해가 다락처럼 −x 에서 들어와 빈 바닥 가운데에 창 모양 빛). 뒷벽: **'다락방 달리기' 오락기**(아래 몸통 · 기운 조작판 막대 + 단추 2 · 화면 테 · 남색 화면에 초록 땅과 0.5 s 마다 두 프레임 깡충하는 칸(모션 감소면 정지) + 발광 · 호박 머리판 · 옆 줄무늬) · **부엌 자리**(조리대 몸통 · 문 2 · 손잡이 · 윗판 · 발판 · 뚜껑 냄비 · 프라이팬 · 병 3 선반 — 요리는 9물결). 가운데 바닥은 비워 둔다(나중 꾸미기). 벽등 2(따뜻한 갓 + 전구 + 발광, 낮에도 밤에도 켜짐) = 점광 2 — 다락(등불 + 양초)과 같은 수라 첫 전환에 셰이더가 늘지 않는다.
- **`goRoom(room, { walkFirst, instant, onDoor }) → Promise<{ ok, reason?, view, room, place }>`**: `'play'` = 지금 보이는 곳에서 놀이방으로(다락이면 다락 문을 열고, 바깥이면 문 그림 없이 알림만) · 그 밖(`'attic'`·`'back'`) = 놀이방 문을 열고 `place()` 로. 순서: [`walkFirst` — 문 앞까지 걷기, 지금은 캐릭터가 없어 바로] → `on.door({act:'open'})` + 문짝 4프레임(12 fps) → **가로 전환 0.6 s**(앞 0.3 s 나가는 방이 카메라 화면 가로 축으로 정수 아트px 씩 밀려 나가며 디더로 허공색, 가운데 프레임에 바꿈, 뒤 0.3 s 들어오는 방이 반대쪽에서 들어옴 — 위아래 움직임 0, 한 프레임엔 한 장소; 다락 → 놀이방은 다락이 왼쪽으로 나가고 놀이방이 오른쪽에서 · 나올 땐 거울) → 도착한 쪽 문이 열린 채 보였다가 `on.door({act:'close'})` + 4프레임 닫힘 → 풀림(≈ 1.3 s). 모션 감소 = 열린 문 한 장 0.15 s → 컷 → 닫힌 문 (알림 둘은 같다). `instant` = 문 프레임 없이 컷. 실패는 바로: `busy`(문 작업 · 걷기 중) · `intro` · `here` · `walk`(걷기가 `false`/`{ok:false}`). 탭이 숨었거나 컨텍스트를 잃었으면 저절로 instant — Promise 가 걸려 있지 않다. `destroy()` · 컨텍스트 잃음도 돌던 문 작업을 끝낸다. `finishRoom()` = 지금 끝내기. `setPlace('play', o)` = `goRoom('play', o)`.
- **내 캐릭터 걷기**: `walkFirst: true` 는 내장 `playerWalkTo(anchorName)` 을, 함수면 그 함수 `(anchorName, [x,y,z]) → Promise` 를 문이 열리기 **전에** 기다린다(다락 → 놀이방 = `atticPlayDoor`, 놀이방 → 밖 = `playAtticDoor`; 바깥에서 들어갈 땐 걷기 없음). `playerWalkTo` 는 내 캐릭터가 그 방에 있으면 문 앞 앵커까지 걸어가 문을 보고 서면 `{ ok:true, walked:true, anchor, at }` 로 풀린다(없거나 모션 감소면 `walked:false` 로 바로). 앱은 늘 `walkFirst: true` 로 부른다. 아래 '내 캐릭터'.
- **누르는 곳** `hotspots({ atticPlay, playAttic, machine }, { edge })`: 앱이 넘긴 진짜 `<button>`(`#scene` 안, `aria-hidden` 인 `#scene3d` 밖, `position:absolute`)을 매 프레임 3D 문 · 기계의 투영 상자 위에 맞춘다 — 투영 상자를 **장면 안으로 자른 보이는 부분** 위에 (확대 · 밀기로 문이 가장자리를 넘어도 단추가 문 밖 바닥으로 밀려 나지 않는다), 그 부분이 44×44 보다 작으면 가운데로 넓혀 장면 안으로 자름, 보이는 부분이 8 px 보다 좁으면 숨김, 확대 · 밀기 · 크기 바뀜을 따라감, 바뀔 때만 인라인 `left/top/width/height` 를 쓴다. **손가락 · 마우스는 캔버스가 받는다**: 그림 위(`over`) 단추는 CSS `pointer-events: none` 이라 밀기 · 핀치 · 휠이 문 · 오락기 위에서 시작해도 장면으로 가고, 톡은 `pick()` 이 그린 순서대로 가린다 — 다락 문 메시도 포스터 · 기념품 · 문어 몸과 같이 거리순 레이캐스트(문이 문어 앞이면 문, 문어가 문 앞이면 문어), 다 빗나가면 문어 히트 구 · 창 다음에 문 단추 칸(44×44 이상) — 문 · 오락기로 정해지면 그 단추를 `click()` 한다(`pickAt` → `{ kind:'spot', id }`). 키보드 Tab/Enter · 화면 낭독기는 단추 그대로. 숨기는 순간 포커스를 쥐고 있던 단추는 다시 보일 때 포커스를 돌려받는다(그새 포커스가 body 에만 있으면 — 산책 중 바깥 문 단추에 있다가 문어가 돌아오는 전환 등), 링이 없던 포커스는 링 없이. **장면이 `hidden` 을 쥔다**: `atticPlay` 는 다락이 보이고 방 · 문 작업 · 걷기 · 전환 · 입장 연출이 없을 때만, `playAttic` · `machine` 은 놀이방이 보일 때만, 상자가 화면 밖이면 숨김. `data-spot="over"`(그림 위) · 바깥이 보이는 동안 `atticPlay` 는 `data-spot="edge"`(인라인 자리를 비워 앱 CSS 의 오른쪽 아래 픽셀 문 단추로 — 산책 중에도 놀이방에 갈 수 있게; `edge:false` 면 숨김). `spotRect(id)` = 같은 규칙의 순수 조회(`#scene` 기준 CSS px + `client` 뷰포트 px + 투영 `art`). 이름표 · 클릭 · `aria-haspopup`(오락기만) · 모양 · 입장 CSS · 포커스는 앱 몫.

## 성능 · 접근성 · 폴백
- 기본 p=2 (178×162 타깃, 자동 폴백 p=3 — 위 "공간·카메라"), `antialias:false`, `setPixelRatio(1)`, 섀도맵 2048 PCF(태양만, `autoUpdate` 끄고 뷰티 패스에서만 갱신, 카메라는 방에 꼭 맞춤), 정적 방 = 2메시(`room` + 그림자 안 던지는 `roomHi`) + 보이지 않는 차폐 1메시, 가만히 있을 땐 30 fps, `document.hidden` 이면 rAF 정지, dt ≤ 0.1 s, `destroy()` 가 RT·기하·재질·텍스처 해제 + `forceContextLoss`.
- 모션 감소(설정 또는 OS): 숨쉬기·흔들림·비 정지, 먼지 숨김, 양초 불꽃 깜빡임 정지(중간값), `moveTo` 즉시, 디더 0, 색 전환은 유지.
- WebGL/THREE 없음 또는 `init` 예외 → `SCENE2D`(js/scene2d.js, 1차 구현의 인라인 SVG 레이어 + DOM 문어)가 같은 API(`setCarry`, `jumpTo`, `lookAt`, `setLook`, `palette`, `stats`, `refresh`, `setReducedMotion` 확장 포함 · 8물결 방 API 포함)로 받는다. 놀이방에 있다가 컨텍스트를 잃어 2D 로 내려가면 앱이 쪽지 · 단추를 걷고 2D 는 문어 방에서 다시 시작한다 (장면 `destroy()` 와 앱이 `#oct` 의 인라인 `display:none` 을 걷어 문어 · 이름표 · 말풍선도 다시 보인다). 두 장면 모두 호스트에 `data-items`, `data-posters` 를 쓴다(스모크가 본다).
- 증거: `node tools/evidence3d.js` → `tests/evidence/3d-{lantern0-night,lantern4-day,lantern8-night-clear,pet,away,dark-ui}.png` + 순도·드로우콜·에러 0 검사.
