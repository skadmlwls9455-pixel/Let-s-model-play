# 식탁 — 문어와 같이 먹기 (설계 기록, 11-18)

주인 답 (docs/OWNER_DECISIONS.md, 11-18 6차):

> 문어와 같이 먹기: **문어가 그때 고른다** — 미용실처럼 모델이 붙으면 모델, 지금은 데모 규칙. 누가 골랐는지 표시하고, '싫어서'
> 같은 감정 말은 쓰지 않는다. 안 먹으면 옆에 앉아만 있고, 먹으면 문어에게도 효과. · 효과 시간: **그날 하루** — 날이 바뀌면
> 사라지고, 그 사이 다른 요리를 먹으면 그 효과로 바뀐다.

스펙: `wip/round6/eat-spec.md` §4.3–§6, §9, §10.2–§10.3. 코드: `js/meal.js` (규칙, DOM 없음, 전역 `MEAL`), `js/app.js` 의 `meal` 블록
(흐름 · 단추 · 저장), 장면은 `js/scene3d.js` (식탁 · 앉기 · 한 입 · 효과 — 장면 API 는 §6). 시험: `tools/test-meal.js` (node),
스모크 **EAT** (`tools/smoke.js scenarioEat` — 장면에 식탁이 없으면 `tools/meal-stub-scene.js` 대역으로 돈다).

## 1. 흐름

| 박자 | 보이는 것 | 저장 |
|---|---|---|
| 요리가 옴 | 부엌이 닫히면 요리가 식탁에 나타난다 (나타나기 박자). 놀이방에 들어올 때는 박자 없이 놓여 있다 | `user.table` (기다리던 요리는 바뀐다 — 부엌 수첩엔 남는다) |
| 앉기 | 식탁 (`#btn-table`) 이나 내 자리 노란 점 (`#btn-seat`) → 내 캐릭터가 걸어가 앉는다 | — |
| 고르기 | 요리가 있고 문어를 부를 수 있으면 문어 자리 위에 **부르기 칩** (`#btn-call`). 이때 식탁을 누르면 혼자 먹는다 | — |
| 부르기 | 칩 → 저장소 다시 읽기 → `MEAL.canCall` → 장면 `octCanCome()` → **대답 저장** → 문어가 놀이방 문으로 들어와 맞은편에 앉는다 (이미 앉아 있으면 걸어오지 않는다) | 그 요리의 `ask` (한 번) |
| 생각 | 1.0 s, 말풍선 '…' (1.2 s, 소리 없음) | — |
| 대답 | 움츠림 (두 답이 같다) → 알림 `[결정 줄, ' ', 꼬리]` → 먹기: 식탁 쪽으로 8° / 보기만: 바로 앉음 | — |
| 식사 | **식사 저장** → 대답 행 (문어가 앉아 있던 식사만) → 한 입씩 (같이: 나 · 문어 · 나 · 문어, 아니면 나 넷) → 효과 피어나기 → 식사 행 | `ate` · `table = null` (한 번) |
| 뒤 | 내가 앉아 있는 동안 문어도 앉아 있다. 앉은 채 다른 요리를 하면 그 요리가 식탁에 오고, 칩이 문어 위에 다시 뜬다 (걸어오지 않고 새 요리를 묻는다). 일어나면 문어는 걸어 나가고, 방을 나가면 바로 다락으로 | — |

- **연출은 저장된 사실을 다시 보여 줄 뿐이다.** 대답은 누른 순간, 식사는 먹기 시작하는 순간 저장한다. 새로고침 · 다른 탭 · 앨범은 기록의 행을 그린다.
- **막기** (`mealBusy()`: 부름을 누른 때부터 마지막 한 입까지 — 혼자 먹는 한 입들도): 조리대 (`openCook`, 부엌 갈래의 줄) 와 오락기 (`openMachine`) 가
  아무것도 안 한다. 식탁 단추 · 칩 · 점은 숨는다 (`#scene.meal-busy`). 발자국 손잡이는 그대로 (일어나기 = 멈춤).
- **멈춤**: 식사 저장 전 (오기 · 생각 · 대답) 에 일어남 · 놀이방을 나감 · 산책 초대 · 숨은 탭 · 장면 잃음 · 장면이 거절 → 문어가 나간다 (방이 바뀌었거나
  숨었으면 바로). 요리는 남고, 적힌 대답은 그 요리에 그대로 (다시 부르면 같은 대답). 식사 저장 뒤에는 끝 상태로 감는다 (조각 치움, 효과 켬, 남은 행).
- **문어를 아무것도 끌고 가지 않는다**: 식탁에 앉아 있는 동안 (`octAtTable()`) 돌아다니기 · 생각 말풍선 · 쉬는 차례 (`syncRest` · `lieDown` · `sleepNow`) ·
  스스로 깸 · 창문 걷기 · 쓰다듬기를 미룬다. 다른 탭이 쉬는 차례를 끝내도 식탁에서 잠들지 않고, 집에 간 뒤 (`mealLeave` → `syncRest`) 잔다.
  의식 (산책 출발) 은 장면이 먼저 내려놓는다.
- **소리 · 진동 없음** (이번엔). 생각 말풍선은 `bubble(…, { silent: true })`.
- **얼굴은 늘 idle.** 코드가 고른 순간이라 표정을 짓지 않는다 (모델의 `expr` 만 바꿀 수 있다 — 모델 길, 나중).
- **2D 폴백 · WebGL 없음**: 식탁이 없다 (마당처럼 3D 만). 요리는 기다리고 (`mealDish` 는 그대로 적는다), 단추는 하나도 안 보인다.

## 2. 누가 고르나 — 데모 규칙

`MEAL.demoAnswer({ dish, name, born, asksBefore })`:

- 맨 처음 부름 (대답이 적힌 식탁 기록 0) 은 **먹기** (`rule: 'first'`) — 부르면 무엇이 되는지 보여 준다 (미용실 첫 물음과 같은 생각).
- 그 밖엔 `hashSeed('meal', 요리 id, 이름, born)` 의 mulberry32 첫 값 `< P_EAT (0.6)` 이면 먹기, 아니면 보기만 (`rule: 'seed'`). 약 5번에 3번.
- **입력은 이 넷뿐이다.** 요리 종류 · 효과 · 시각 · 지난 대답 · 쓰다듬기는 넣지 않는다. 어떤 요리를 덜 먹는 규칙은 문어에게 없는 입맛을 지어낸다 —
  그래서 같은 요리 id 면 해초전이든 과일 꼬치든 대답이 같다 (`tools/test-meal.js` 3).
- **요리 하나에 대답 하나**: 같은 요리로 다시 부르면 적힌 대답을 그대로 (`makeAsk` 가 다시 뽑지 않는다).
- 보이는 곳: 대답 박자의 알림, 로그 '식탁' 행의 꼬리 (`데모 규칙` · `모델` · `사람이 정함`, 아무도 안 골랐으면 없음), 늘 보이는 '데모' 꼬리표,
  설정 › 누가 고르나 ('…미용실 · 식탁 줄에 적혀.').
- 개발용: `?dev=1` 을 직접 붙인 탭에서 `APP.mealNext('eat' | 'watch' | 'stop' | 'none')` → 다음 대답 하나를 사람이 정한다 (`by: 'human'`, 결정만).

## 3. 모델 길 — 약속 (이번엔 코드 없음, 스펙 R11)

미용실의 모델 길과 함께 나중에 짓는다. 그때 지킬 것:

- 보내는 것 (≤ 400 B):
  `{ v: 1, point: 'table', id: <식탁 기록 id>, offer: { kind: 'dish', name: '해초전', steps: ['톡톡', '뒤집기', '썰기'], fx: '반짝이', by: 'user' },
  oct: { place: 'play', seat: true }, menu: ['eat', 'watch', 'stop'] }`. 지난 대답 · 확률 · 맛 · 기분은 보내지 않는다.
- 기다림: 최대 8 s, 문어는 생각 중 ('…').
- 받는 것: `{ action, line?, expr? }`. `action` 필수 — 모르는 값이면 대답 없음 (fallback). `expr` 는 `idle | happy | curious | calm` 만.
- eat → 먹는다 (효과). watch → 앉아 있다. stop → 담담하게 다락으로 돌아간다 (그 박자에 행 '{이름}{은/는} 다락으로 돌아가기로 했어.' + 모델 꼬리 — 말이 있으면 말 그대로).
- 8 s 안에 대답이 없으면 `by: 'fallback'`: 앉아만 있고, 행은 '대답이 없었어.' (꼬리 없음, 식사와 함께).
- 모델의 `line` 은 **글자 그대로** (말풍선은 24자 + '…', 기록엔 전부 — `ask.line`, 원문은 `ask.raw`). 꼬리 '모델'. 다시 묻지 않는다.
- 서버 쪽: 이미 있는 MCP `table` 메뉴 (`mcp/core.js` `MENU.table`) 를 `eat · taste → eat`, `save · watch → watch`, `stop → stop` 으로 맞춘다.
- 기록과 행은 지금도 모든 `by` 를 안다 (`MEAL.rows`) — 나중 빌드의 모델 대답이 이 빌드에서도 정직하게 보인다.

## 4. 데이터 (`localStorage ppolppol_v2` 의 `S.user` 안 — 없앤 칸 · 바꾼 이름 없음)

```
S.user.table = null | { v: 1, id: 'ck_…', recipe, seed, look, day, at }          // 기다리는 요리 하나
S.user.meals = [ { id: 'ml_…', dish: 'ck_…', recipe, date, at,                     // 오래된 것부터 · 지우지 않는다
                   ask: null | { at, action: 'eat'|'watch'|'stop'|null, by: 'demo-rules'|'model'|'human'|'fallback', rule?, seed?, model?, line?, expr?, raw? },
                   ate: null | { at, date, me: true, oct: true|false|null, fx: 'sparkle'|'star'|'petal' } } ]
```

- `ate.oct`: `true` 문어가 앉아서 먹음 (효과), `false` 앉아서 봄 (보기만 골랐거나, 앞 식사에서 앉아 있던 채 내가 묻지 않고 먹음), `null` 식탁에 없었음 (혼자).
- 부엌 → 게임: `{ ppolCook: 'result', v: 1, id, recipe, seed, look, day }` 를 `MEAL.normDish` 가 본다 (id `ck_[0-9a-z]{1,13}`, recipe ASCII ≤ 16,
  seed uint32, look 평범한 객체 JSON ≤ 2048 B, day `YYYY-MM-DD` 또는 '').
- `userState()` 가 `MEAL.normalize(u)` 를 부른다: 객체가 아닌 것만 버리고, 모르는 recipe · fx · by 는 그대로 둔다 (나중 빌드가 알 수 있다 — 이 빌드는 그리지 않는다).
- 요리 셋: `jeon` 해초전 · 반짝이 (`sparkle`), `jumeokbap` 주먹밥 · 별 (`star`), `kkochi` 과일 꼬치 · 꽃잎 (`petal`).

## 5. 효과 — 그날 하루

- 저장하지 않고 **기록에서 끌어낸다** (`MEAL.active(state, today)`): 나 = 오늘 내가 먹은 것 가운데 가장 늦은 것의 효과, 문어 = 오늘 `ate.oct === true` 인
  것 가운데 가장 늦은 것. 그 효과를 이 빌드가 모르면 없음 (옛 효과로 되돌리지 않는다).
- 그래서 날이 바뀌면 저절로 없고, 다른 요리를 먹으면 바뀌고, 두 탭도 같다. `mealApply()` 가 부팅 · 식사 뒤 · 다른 탭 · 1분 틱 · 다시 보일 때 장면에 준다.
- 장면은 효과를 각 캐릭터를 따라다니는 픽셀 점으로 그린다 (스펙 §5). 하트 · 얼굴 바꾸기는 없다.

## 6. 장면 API (lane D, 스펙 §10.3) — 앱은 하나하나 있는지 보고 부른다

`setTableDish(dish, { appear })` · `tableInfo()` · `playerSitTable()` · `playerStandTable()` · `octCanCome()` · `octToTable({ instant })` ·
`octTableBeat(name)` · `mealBite(who)` · `octLeaveTable({ instant })` · `octAtTable()` · `setAura(who, fx, { bloom })` · 이벤트 `on.tableSpot({ seat, call, dish })` ·
hotspot `'table'` → `#btn-table`. 앱은 식탁 자리 숫자를 쓰지 않는다 (단추 자리는 `tableSpot` 과 hotspot 에서, 시험은 `tableInfo().geom` 에서).

## 7. 기록 행 (로그 · 앨범 일기)

- **먹은 기록만** 그린다 (`MEAL.rows`). 먹은 시각 순으로 산책 · 미용실 행 사이에 끼운다 (`dayRows`), 지난 날은 앨범 › 일기.
- 1 대답 행 '식탁' — 문어가 그 식사에 앉아 있었을 때만 (`ate.oct !== null`) 이고 대답이 있을 때. 부른 뒤 멈춰서 문어가 앉지 못한 대답은 행이 없다.
- 2 식사 행 '식탁' — 이 빌드가 아는 요리일 때.
- 연출 중인 식사는 지금 박자까지 (두 번 그리지 않는다).

## 9. 정직 (금지선)

- 마음 · 맛 말이 없다 (좋아 · 싫 · 맛있 · 싶 · 배불러 …). 결정은 '-기로 했어', 일어난 일은 '-었어'. `tools/test-brain.js` 가 `js/meal.js` 의 글을 같이 본다.
- 코드가 쓴 줄은 집 목소리 (초상 · 얼굴 없음) 이고 늘 누가 정했는지 꼬리가 붙는다. 데모 대답이 모델로 적히지 않는다.
- 부름은 초대다: '아니'(보기만) 는 아무것도 잃지 않고 담담하다 (시무룩 · 징글 · 다시 묻기 없음). 자는 문어는 깨우지 않는다 (칩이 숨는다, 말 없음).
- 효과는 그날의 선물이다: 남은 시간 표시 · 연속 기록 · 놓치면 아까운 것 없음.

## 10. 두 탭 · 저장 (`MEAL.merge` · `MEAL.slim`)

- `adoptRemote` 가 `SALON.merge` 옆에서 `MEAL.merge(S, R, mineMeals, now)` 를 부른다: 기록은 id 로 합친다 (같은 문어일 때만 이 탭 것도 — 지우지 않는다;
  같은 id 면 `ate` 있는 쪽, 그다음 `ask` 있는 쪽). 이 탭이 `MINE_MS` (60 s) 안에 놓은 요리는 그쪽 것보다 새로우면 남기고, 어느 쪽에서든 먹은 요리는
  식탁에서 비운다. 다른 문어 (born 이 다름) 면 이 탭 것은 버린다. 바뀌었으면 저장한다.
- 부르기를 누르는 순간 `syncFromStore()` (다른 탭이 이미 먹었으면 칩이 다시 숨는다).
- 쿼터: 저장 사본에서만 1년 넘은 기록의 `ask.seed` · `ask.raw` 를 뺀다 (`line` 은 안 뺀다) — `slimAsks` 와 같다.
- 내보내기 · 불러오기 · 초기화: `S.user` 가 지금처럼 같이 간다 (새 맨 위 칸 없음). 식탁에 문어가 앉아 있으면 먼저 접고 바로 다락으로 (`mealDrop`) — 그다음 `octInitial`.
- `normalize`: 같은 id 가 둘이면 먹은 · 물은 쪽을 남긴다 (식사를 잃지 않게). 모르는 `ate.oct` 값은 저장엔 그대로, 읽을 땐 '식탁에 없었음'.
