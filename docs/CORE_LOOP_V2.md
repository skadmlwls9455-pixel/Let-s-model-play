## 1. 한 줄 요약

**문어가 나가기로 정하면 문 앞에서 잠깐 바깥을 보고 나간다. 묻지 않는다: 기본은 집에서 기다리기고, 주 버튼 옆 '같이' 아이콘을 켜 두었으면 같이 간다. 어느 쪽이든 문어의 산책은 한 글자도 안 바뀐다. 네가 한 일은 네 것으로 옆에 따로 남는다. 돌아오면 둘의 것을 나란히 놓는다.**

- **같이 가기**: 방과 방 사이를 같이 헤엄친다. 문어가 읽는 것을 어깨 너머로 본다. 너는 너대로 작은 것을 줍는다.
- **집에서 기다리기** (기본): 놀이방에서 요리하거나 달리고, 방을 꾸미고, 앱을 그냥 닫아도 된다. 돌아오면 문어가 다녀온 이야기를 한 줄씩 본다.
- 등불·포스터·기념품·벽은 어느 쪽을 골라도 **똑같다.** 고르기 전에 이미 정해져 있다.

## 2. 왜

| 지금 | 문제 | v2 |
|---|---|---|
| 문어는 혼자 나간다. 너는 기다렸다가 기록을 읽는다 | 주인: 소외된 느낌. 오래 하면 주기만 하는 일, 곧 자선처럼 느껴진다 (PLAYER_PROGRESSION §1) | 떠날 때마다 묻지는 않는다. 같이 가고 싶은 날만 아이콘을 켜 둔다. 아니면 집에서 네 일을 한다 |
| 손으로 하는 일이 없다 | 보내 놓고 기다리기만으로는 다시 보낼 마음이 약하다 (VISION) | 헤엄·줍기·요리·꾸미기 |
| 산책 줄이 아래로 길게 쌓인다 | 폰 피드백 (1): 레퍼런스의 대화 상자와 안 맞는다 | 한 줄씩 넘기는 대화 상자 + 대사 다시 보기 (DIALOGUE_UI) |
| 돌아오면 포스터 한 장 | 둘이 만나는 순간이 없다 | 문어 카드와 네 카드를 나란히 놓고, 대화 두 차례 |

그런데 산책은 **문어의 것**이다 (MODEL_VOICE). 그래서 네 놀이는 문어 옆에 따로 둔다. 네가 무엇을 해도 문어가 갈 곳·읽을 것·기억할 것은 바뀌지 않는다.
그리고 두 선택이 **똑같이 좋아야** 한쪽으로 끌리는 압박이 없다.

**헤엄 규칙**

- 헤엄은 **산책 하나에 4번까지**다. 기웃 앞마다 하나, 마지막 하나는 집 가는 길이다. 넘치는 기웃 앞은 지금처럼 짧은 틈으로 지나간다.
- **숫자가 없다.** 거리·충돌 수·남은 정류장 수·진행 막대가 없다. 몇 군데 들를지 너는 모른다. 문어가 정한다.
- 뒤처지지 않는다. 늦으면 물살이 살살 밀어 준다. 문어를 앞지를 수도 없다. 너는 위아래로만 움직인다.
- 헤엄 화면 속 '너'가 누구인지는 주인이 정할 것 1이다. 추천은 **네 모습**(PLAYER_PROGRESSION의 아바타, 만들기 전이면 기본 모습)이다.
- 같이 가기는 한 번에 **1~3분쯤** 걸린다 (헤엄 2~4구간 × 8~12초 + 기웃 2~5곳 × 5~8초 + 출발·귀가 연출). 정류장 머무는 시간과 헤엄 구간 수는 폰으로 해 보고 조절한다 (§7).

**줍기 규칙**

- 줍는 것은 **방과 묶지 않는다.** 조약돌, 깃털, 단추, 바다 유리, 씨앗, 마른 잎, 종이 조각 같은 흔한 것이다. 계절·날씨·그 정류장 상태로만 고른다.
  - 이름에만 장소가 붙는다: "모자의 방 앞에서 주운 단추".
  - 방마다 특별한 것이나 희귀한 것은 없다. 있으면 문어가 그 방에 가기를 바라게 된다.
  - '조개'라는 이름은 쓰지 않는다. 조개는 돈 이름이다 (결정 19).
- 문어가 못 읽은 곳에도 주울 것이 있다. 문어가 '문 앞까지만' 갔으면 너도 **문 앞 것**을 줍는다 ("문 앞 조약돌"). 문어가 못 읽어도 네가 손해 보지 않고, 정직함도 지킨다.
- 고르는 난수는 따로 쓴다: `hash(trip.seed, 'user', 정류장 번호)`. 문어의 난수 순서를 건드리지 않는다.
- 누르는 자리는 44px 이상이다. 주운 것은 **바로 저장**한다.
- v1의 쟁반은 장면 밖 오버레이다. 땅 위에서 반짝이는 것으로 바꾸는 일은 v1.2다 (장면 파일 손질이 필요하다).

**대화 상자는 자막처럼 흐른다**

- 산책은 너를 기다리지 않는다. 다음 줄이 와 있으면 지금 줄은 다 찍힌 뒤 읽을 시간(DIALOGUE_UI §5.5 공식 하나)만큼 머물다 넘어간다. 톡 하면 바로 넘어간다.
- 예외는 하나다. 기웃에서 네가 아직 어깨 너머 글을 펼쳐 보고 있으면 문어가 **최대 6초** 더 서 있다. 재생 시계만 늦춘다. 문어의 결정과 모델은 그대로다.
- 못 읽고 지나간 줄은 대사 다시 보기에 그대로 남는다.
- 네가 한 일(주웠다 등)은 상자에 띄우지 않는다. 탭을 빼앗지 않으려는 것이다. 그 자리에서 쏙 들어가는 반응만 보이고, 다시 보기에 '너' 줄로 남는다.

**중간에 빠지기**

| 버튼 | 무엇이 되나 |
|---|---|
| 주 버튼 "다녀오는 중…" (바로 돌아오기) | 산책을 끝까지 감고 다시 만나기로 간다. 남은 헤엄은 '끊김'으로 적는다. 주운 것은 남는다. 문어 결과는 똑같다. 따로 된 [건너뛰기] 단추는 없다 (11-07) |
| [먼저 집에 갈래] (헤엄 중에만, 작게) | 화면이 다락으로 간다. 남은 산책은 문어 혼자 이어 가고, 너는 '집에서 기다리기'가 된다. 다시 합류하는 길은 없다 |

두 버튼 모두 아쉬움·미안함을 담은 문구가 없다.

- **시간 제한 없음.** 귀가 의식(30초 감시 `runCeremony`)은 뒷면을 든 문어가 다락 문에 닿으면 끝난다. 보드까지 걷기, ①·② 주머니 고르기, ③ 걸기(첫 핀 포함)는 그 뒤 앱 차례에서 돌아서 감시에 걸리지 않는다.

- 간직한 것은 앨범의 **'내 것'** 칸으로 간다 (§5.2). 옆방(ROOM_EXPANSION '네 선반')이 생기기 전에는 **앨범에만** 있고 방 안 자리는 없다.
- 꾸민 것은 방에 이미 보이니 v1에서는 카드로 만들지 않는다.
- ③′의 소품 줄(지금의 ITEM_LINE, "창턱에 이끼 화분을 올려뒀어")은 문어 1인칭으로 되어 있다. 결정 10~12에 맞춰 집 쪽지로 바꾸는 일은 DIALOGUE_UI §4.3 몫이다.

**식탁에서 문어가 고르는 것** — 결정 지점 하나. 데모 규칙이나 모델이 고른다.

| 메뉴 | 연출 |
|---|---|
| `eat` 먹기 | 팔로 집어 한입에. 볼이 불룩 (6프레임) |
| `taste` 맛보기 | 팔 끝으로 콕 |
| `save` 아껴 두기 | 접시를 식탁 끝으로 민다 |
| `watch` 보기만 | 가만히 본다 |
| `stop` 지금은 안 하기 | 창 쪽으로 돈다. 담담하게 |

- 말은 기호(`♪` `…` `!`)만 쓴다. 데모 규칙은 문장을 쓰지 않는다. 모델이 한 줄을 쓰면 **글자 그대로** 보여 준다 (24자 권장, 넘치면 '…'와 원문 보관).
- 코드가 "맛있대", "좋아해"를 쓰지 않는다.
- 문어가 무엇을 고르든 네 그릇은 먹을 수 있다. 조개는 요리가 완성될 때 이미 정해졌다 (PLAYER_PROGRESSION §3).
- 문어가 자고 있으면 "식탁에 올려 둘게."라고만 한다. 깨면 그때 한 번 고른다. 기다리는 접시는 하나까지다.
- 요리는 산책과 상관없이 **언제든** 할 수 있다 (놀이방 부엌). 다 된 요리는 문어가 깨어 있고 집에 있을 때 언제든 차릴 수 있다.

|---|---|
| 문어가 정하기 전 | 지금처럼 다시 계획한다 (오프라인). 사람 기록은 생기지 않았다 |
| 같이 가는 중 | 문어 쪽은 지금처럼 바로 마무리된다. 주운 것은 이미 저장돼 있다. 열면 집 줄 "네가 없는 동안 뚜루가 다녀왔어." (복구 줄은 이 글 하나, DIALOGUE_UI §4.3) → ① 남은 이야기 → ② "지난 산책 주머니: 조약돌 · 깃털. 하나 간직할래?" [하나 고르기] [괜찮아] → ③ 이미 반영됐으니 등불이 한 번 반짝이기만 → ④ |
| 기다리는 중 | 같은 순서. 냄비는 그대로 남아 있다 |
| 다시 만나기 ①~④ 도중 | 같은 다시 만나기를 남은 박자부터 연다 |

- 다시 만나기는 **한 번만** 열린다. 건너뛰어도 된다. **대신 골라 주지 않는다.**
- 다시 여는 길: 부팅에서 `resumeRunning()` 이 끝나면 **돌려준 값과 상관없이** `TOGETHER.resume()` 을 부른다. 열린 일은 `S.user.tracks[*].status === 'open'` 에서 찾는다. 산책은 '귀가' 때 이미 `done` 이 되므로 '진행 중 산책'으로는 못 찾기 때문이다.
- 산책 뒤 20분 안에 다시 열어 문어가 아직 자고 있으면 집 줄 “뚜루는 아직 자고 있어.” (초상 없음) + 문어는 ‘…응?’ 하고 눈만 뜬다 (결정 11). 그 뒤나 새날엔 스스로 깨 있다 (물결 E).
- 옛 저장(사람 줄기가 없는 산책)은 지금처럼 동작한다.

### 3.7 이 루프가 더하는 안내 (폰 피드백 2)

안내 글과 언제 뜨는지는 **TUTORIAL §3.6·§3.7 표 한 곳**에 있다. 장치도 TUTORIAL 의 `js/guide.js` (`GUIDE.register`·`GUIDE.ready`)다. 여기에는 등록할 id 만 둔다.

### 4.1 두 선택이 똑같이 좋은지

| 무엇 | 같이 가기 | 집에서 기다리기 | 앱 닫기 |
|---|---|---|---|
| 등불·포스터·기념품·벽 | 같음 | 같음 | 같음 |
| 산책에서 본 것 | 그 자리에서 | 돌아와서 이야기로 (같은 줄 전부) | 다시 열 때 이야기로 |
| 네 것 | 주머니에서 0~1개 | 요리 0~1개 (요리는 언제든 가능) | 0개 (다음에 한 번 고를 기회) |
| 조개 | 직접 헤엄친 구간만큼 | 요리 한 접시만큼 | 0 |
| 이쪽에만 있는 순간 | 같이 보기, 어깨 너머 읽기 | 맞이하기, 같이 먹기, 이야기 듣기 | — |
| 드는 시간 | 약 1~3분 | 0초여도 됨 | 0초 |
| 문어의 반응 | 같음 | 같음 | 같음 |

### 4.2 진짜 모델이 붙었을 때 문어가 보는 것

| | 산책 도구 (`look_room` · `depart` · `peek` · `finish` …) | 식탁 결정 (`table`) |
|---|---|---|
| 자기 산책 기록·자기 메모 | 본다 (지금 규칙) | 자기 메모 1개 (있으면) |
| 같이 왔나, 집에 있었나 | **안 본다** | **안 본다** |
| 헤엄·주운 것·요리 중인지 | 안 본다 | 안 본다 |
| 네가 간직한 것 | 안 본다 | 안 본다 |
| 네가 차린 요리 | — | 그 한 접시만 (이름·단계·`by:'user'`) |

- 고정 문맥에 **한 문장**을 둔다. 모든 모드에서 같은 글이라 모드가 새지 않는다. 숨기지 않고 사실을 말한다. 문구는 MCP 세션(카드 9)에서 확정한다.
  > 사람은 산책에 같이 따라올 수도 있고 집에 있을 수도 있다. 어느 쪽인지는 알려 주지 않는다. 길과 읽을 것은 네가 정하고, 사람이 무엇을 하며 지냈는지는 전달되지 않는다.
- MCP 로 붙일 땐 “내 Claude 에게 방을 준다” (결정 20). 서버는 Claude 의 메모리·대화 기록을 읽지 않고 사용자 프로필을 만들지 않는다. 대화 속 화면(MCP Apps)으로 띄워도 같은 규칙이다. 모델 호출 상한은 이 절 끝 표 한 곳에 모은다 (카드 9 가 이 표를 쓴다).
- "사람이 기다려", "같이 와서 즐거워해" 같은 압박 문구는 넣지 않는다.
- 식탁 결정에 보내는 상황 설명 (사실만):

```js
{ v: 1, id: 'tb_3fa', point: 'table',
  offer: { kind: 'dish', name: '미역탕', tier: 4, by: 'user' },  // "너를 위해 만들었어" 같은 말 없음
  oct: { place: 'attic', awake: true },
  note: null,                                   // 자기가 지난번에 쓴 메모 원문, 또는 null
  menu: ['eat', 'taste', 'save', 'watch', 'stop'] }   // watch·stop 은 늘 있다
// 돌려받는 것: { action, line?, note? } — action 만 필수. 이유를 묻지 않는다
```

- 8초 안에 답이 없으면 `watch`로 두고 `by:'fallback'`으로 적는다. 고른 것처럼 연출하지 않는다. 접시는 식탁에 그대로 있다.
- **산책의 `finish` 안에 끼우지 않는다.** 순서는 늘 `finish` → (네가 차리면) `table`이다. 그래야 문어가 기억할 곳을 고를 때 네 것을 모른다.
- 상한: 30초에 1번, 하루 5번. 넘으면 묻지 않고 식탁에 올려 둔다. 결정이 없으니 기록도 없다.
- 첫인사(폰 피드백 3)는 결정 지점 `meet` 이다 (DIALOGUE_UI §4.4, TUTORIAL). 모델이 `wave` 를 고르면 손만 흔든다. 답이 없으면 가만히 있는다 (`fallback`). 돌아와서 대화는 결정 지점 `chat` 이다 (DIALOGUE_UI §4.5). 둘 다 같이 왔는지·네 물건을 보내지 않는다.
- 헤엄 구간은 모델의 다음 `peek`이 올 때까지 이어진다. 30초가 넘으면 구간을 조용히 끝내고, 문어는 물속에 가만히 떠 있다 (`playback`). "생각 중" 같은 말은 붙이지 않는다.
- (v1.2) 기웃 뒤 '다음 쪽 가리키기'는 모델의 다음 `peek`이 **실제로 온 뒤에만** 나온다. 집 쪽 가리키기는 `finish`가 온 뒤에만 나온다.
- 토큰 (어림값, 실측 아님): 산책 +0. 고정 문장 +60~70 (캐시됨). 식탁은 차릴 때만 1번 (입력 60~100, 출력 10~40). API를 붙이면 `usage` 값으로 바꾼다.

**모델 호출 상한 (문서마다 흩어진 것을 한 곳에)** — 넘으면 묻지 않는다. 묻지 않았으니 반응도 기록도 없다.

| 결정 지점 | 상한 | 정한 곳 |
|---|---|---|
| 첫인사 `meet` | 처음 만날 때 1번 | DIALOGUE_UI §4.4 |
| 식탁 `table` | 30초에 1번 · 하루 5번 | 이 절 |
| 돌아와서 대화 `chat` | 귀가 한 번에 2번 | DIALOGUE_UI §4.5 |
| 배지 알아보기 | 하루 3번 | ACHIEVEMENTS §7.4 |
| 옆에 앉기 | 10분에 1번 · 하루 6번 | PHOTO_AND_FURNITURE §4.3 |
| 넓히기 `room_expand` | 하루 1번 (MCP 에선 마무리에 실어 추가 호출 0) | ROOM_EXPANSION §3.6 |
| 꾸미기 반응 | 꾸미기 한 번에 2번 | INTERIOR_MODE §4 |
| 포즈 놀이 물음 | 한 시간에 3번 | PHOTO_AND_FURNITURE §2.4 |

### 4.3 하지 않는 것

- 산책마다 묻는 질문 (문 앞 [같이 가기]/[집에서 기다리기], "기다리는 동안 뭐 할래?"), '같이' 아이콘을 켜라고 권하는 글·반짝임 (주인 11-07)
- '같이 간 횟수', 연속 기록, "오늘도 같이 가자" 알림, 같이 가야만 받는 보너스·희귀 물건
- 문어가 네 선택에 기뻐하거나 서운해하는 연출·문장
- 헤엄 점수·거리·충돌 수·남은 정류장 수
- 정류장에서 길을 고르는 버튼, 지도 미리보기
- 네 놀이나 네 물건을 산책 중에 모델에게 보내기
- 네 물건을 다음 산책 주제로 넘기는 통로
- 문어가 네 물건을 자기 선반(기념품)으로 가져가기
- "맛있대", "좋아해" 같은 코드 문구
- 숫자 배지 ("새 소식 2" 같은 것)
- 대신 골라 주기

| 부팅: `resumeRunning()` 이 끝난 뒤 (돌려준 값과 상관없이) | `TOGETHER.resume()` — `S.user.tracks` 에서 `status:'open'` 을 찾는다 (§3.6) | — |
| `normalize` / `adoptRemote` | 기본값 가드 / id 합집합 | 지금 그대로 |

- 훅은 대부분 1~3줄이지만, 걸기·마무리 미뤄 두기와 기다리기 귀가 길 때문에 v1 `app.js` 는 **약 100~160줄**이다 (문 앞 카드가 빠져서 조금 준다). **모듈이 없으면 오늘의 게임과 똑같이 돈다** (순서도 지금 그대로). 처음엔 `?together=1`일 때만 켜고, 폰으로 해 본 뒤 기본으로 켠다.
- 헤엄 구간은 의식(출발·귀가 연출) 밖의 틈에서만 돈다. 그래서 의식의 30초 감시에 걸리지 않는다. 구간 동안 `scene.pause()`, 끝나면 `resume()` (이미 있는 함수).
- 요리 오버레이가 화면을 다 덮으면 `scene.pause()`. 지금은 모달 아래에서도 3D가 계속 그려져 폰 배터리를 쓴다.
- 탭이 숨겨지면: 헤엄 구간은 '저절로'로 끝나고, 요리는 멈춘 뒤 저장한다. 문어 산책은 사람을 기다리지 않는다. 진짜 모델도 기다릴 수 없으니 둘이 같다.
- **v1에서 scene3d.js·scene2d.js 수정은 0줄이다.** 장면 다듬기는 v1.2에서 한다 (§6).

**미니게임 끼우기 계약** — 미니게임 속(물리·재료·장애물)은 각 세션 몫이다. 여기서는 만나는 모양만 정한다.

```js
var h = GAME.start(el, { seed, reduced, speed, scale, palette, resume, onEvent });
h.pause()  → state            // JSON 그대로 저장 가능, 8KB 이하
h.resume()
h.finish() → Promise<result>  // 사람이 끝냄("이걸로 할래") 또는 본 게임이 끝냄
h.cut()    → Promise<result>  // 본 게임이 바로 끝냄 (바로 돌아오기·먼저 집에 갈래): 지금까지 한 것만
h.destroy()
result = { v: 1, id, by: 'user', game: 'cook' | 'swim', status, ms, out: { … } }  // 점수·실패·등수 없음

SWIM.segment(el, { seed, ms: 8000..12000, until: Promise | null,
                   lead: 'octopus', player: 'me' | 'octopus',   // 주인 결정 1
                   homeLight: 0..8, reduced })                   // out = {} (부딪힌 수 안 남김)
COOK.start(el, { seed, resume })   // out = { dish: { id, name, tier, ingredients }, madeAt }, 빈 냄비면 dish: null
```

- `result.id`는 판 id다. PLAYER_PROGRESSION의 조개 기록이 같은 판을 두 번 세지 않게 하는 데 쓴다.
- `until`: 진짜 모델일 때 다음 사건이 오면 풀리는 약속. 구간은 `ms`가 지나고 **그리고** 다음 사건이 왔을 때 끝난다 (최대 30초).
- 미니게임이 하면 안 되는 것:

| 금지 | 이유 |
|---|---|
| `ppolppol_v2`·`APP`·`BRAIN`·`S` 읽기·쓰기 | 사람 놀이가 문어 기록에 닿는 길을 없앤다 (자기 설정 키는 써도 됨) |
| 결과를 정하는 코드에 `Math.random` | 시드 원칙 (중요 4) |
| 결과에 점수·실패·등수 | 두 모드 사이에 보상 차이가 생기면 안 된다 |
| 네트워크 기다리기, 한 번에 16ms 넘게 막기 | 폰에서 산책 재생이 멈춘다 |
| 소리 파일 직접 재생 | audio/는 소리 세션 소유. 그 순간마다 `window.AUDIO && AUDIO.on && AUDIO.on(이름, { act })` 한 줄만 (11-07 카드 검토. `onEvent` 로는 소리를 내지 않는다 — 두 번 울리지 않게) |

### 5.2 저장

`ppolppol_v2` 안에 블록 두 개를 더한다. 버전 `v:2`는 그대로 둔다 (덧붙이기만).

```js
S.user = {        // 사람 줄기. PLAYER_PROGRESSION 의 S.player(내 모습·조개)와는 다른 블록
  together: false,  // 주 버튼 옆 '같이' 아이콘 (기본 꺼짐, 11-07). 두뇌·모델에 안 보낸다
  items: [ { id: 'u_k7x2a', by: 'user', kind: 'keepsake' | 'dish',
             at, date, tripId: 'trip_k7x2' | null,
             from: { stopIdx: 1, nodeId: 'hat' } | null,   // 어디서 주웠나 (문어 기록을 가리키기만)
             thing: 'button', name: '모자의 방 앞에서 주운 단추',
             dish: { id, name, tier, ingredients } | null } ],
  tracks: { 'trip_k7x2': {
      mode: 'together' | 'wait',            // 나갈 때의 '같이' 아이콘 값 (묻지 않는다. 옛 how 칸은 없앴다)
      log: [ { t: 0,     by: 'user', type: 'mode', mode: 'together' },
             { t: 4100,  by: 'user', type: 'swim', seg: 0, status: 'played', ms: 9800 },
             { t: 14200, by: 'user', type: 'pick', stopIdx: 0, thing: 'pebble' },
             { t: 15000, by: 'user', type: 'open', stopIdx: 0 },      // 어깨 너머 쪽을 펼쳐 봄
             { t: 52000, by: 'user', type: 'keep', itemId: 'u_k7x2a' } ],
      pocket: ['pebble', 'button'],          // 고르기 전까지만. 고르거나 놓아주면 비운다
      sealed: true | false,                  // 기다리기에서 이야기 전까지
      status: 'open' | 'closed',
      closedBy: null | 'keep' | 'let_go' | 'skip' | 'resume' } },
  pot: null | { v: 1, seed, state, at }      // 끓이던 냄비 하나
};
S.table = [ { id: 'tb_3fa', at, tripId: 'trip_k7x2' | null, point: 'table',   // 식탁 결정. 'meet' 은 첫인사 이름이라 쓰지 않는다
              offer: { itemId: 'u_…', kind: 'dish' },
              action: 'eat' | 'taste' | 'save' | 'watch' | 'stop',
              by: 'demo-rules' | 'model' | 'fallback', model?, line?, note? } ];
```

| 일 | 규칙 |
|---|---|
| 문어 기록 `trips[]` | 사람 키(`mode`·`track`·`pocket`·`user`·`dish`·`keep`·`photo`)를 하나도 넣지 않는다. 이유: 두뇌 입력이 `trips`를 읽고, 다른 탭 합치기(`carry`)가 옛 사본으로 덮어쓸 수 있다 |
| 저장 시점 | 바뀔 때마다 바로: 아이콘 켬·끔, 나갈 때 모드, 구간 끝, 줍기, 간직, 냄비 멈춤, 탭 숨김 |
| 시계 | `log[].t`는 재생 시계(ms)다. 문어 이벤트의 `t`(두뇌 시간)와 비교하거나 섞지 않는다 |
| 헤엄 상태 | `played` 한 번 이상 누름 · `auto` 입력 없이 지나감(탭 숨김 포함) · `cut` 끊김 (바로 돌아오기·먼저 집에 갈래) · `still` 동작 줄이기로 그림 한 장 |
| 옛 저장 | `normalize`에 가드: 없거나 모양이 틀리면 `{together:false, items:[], tracks:{}, pot:null}`, `table`이 없으면 `[]` |
| 다른 탭 | id 합집합. `items`·`table`은 id, `tracks`는 tripId(같으면 `log`가 긴 쪽), 냄비는 `at`이 늦은 쪽. 다른 문어(`born` 다름)면 합치지 않는다 |
| 용량 | 오래된 산책의 events를 비울 때 그 track의 `log`도 비운다 (`mode`는 남김). `items`는 남긴다 |
| 내보내기·초기화 | 같이 들어가고 같이 지워진다 |
| 두뇌 입력 | 두뇌 입력과 MCP 산책 요청을 만드는 코드는 `S.user`·`S.table`을 읽지 않는다 (점검 3) |
| 진행 | `S.user`는 등불·`posterOrder`·귀가 요약 줄·벽 꽉 참(ROOM_EXPANSION)·설정 › 기록 줄에 안 들어간다 |
| 본 안내 | 어떤 비춤을 봤는지는 이 브라우저에만 (`ppolppol_ui`, TUTORIAL 몫) |
| 앨범 | 필터를 하나 더한다: 전체 · 포스터 · 쪽지 · **내 것**. 내 것 카드는 연필 테두리 종이다. 날짜만 붙이고 총수는 없다 |

`by` 값 헷갈리지 않기: `trip.by`의 `human`은 개발용 데모 조작(`?dev=1`)에서 사람이 문어 **대신** 고른 것이다. `S.user`의 `user`는 사람이 **자기 몫으로** 한 놀이다. 둘을 섞지 않는다.

### 5.3 2D 대체 화면

- 2D에는 바깥 장면이 없다. 그래도 거의 다 같다. 헤엄·쟁반·주머니·두 카드·요리·식탁 버튼은 모두 **장면 밖 오버레이**라 2D와 3D가 같다.
- 같이 가기의 기웃: 2D는 지금처럼 문어가 숨은 상태다. 기웃은 대화 상자 줄 + 쟁반 + 그 방 스티커를 얹은 종이 카드로 보여 준다.
- 기다리기: 지금 2D와 거의 같다. 문어가 문으로 나가 숨는다.
- (v1.2) 창밖 먹물 점: 창 효과 층(`window-fx`)에 점 하나.
- 2D에서 못 하는 팔 동작(가리키기, 식탁에서 집기)은 몸 전체 기울기와 기호로 대신한다.

### 5.4 동작 줄이기 · 움직임 (폰 피드백 4)

- **동작 줄이기**: 헤엄 구간은 그림 한 장으로 지나간다 (3초 또는 톡, `still`). 설정 › 모션에서 '그대로 움직이기' 를 고르면 (새 줄 없이 고르기 하나 더) 흔들림·시차 없이 실제 구간이 돈다. 카드 뒤집기는 크로스페이드로 바뀐다. 비춤은 움직이지 않는다.
- 이 루프에서 새로 생기는 움직임 — 깜빡임 대신 1~2px 이동, 몇 번 돌고 멈춤:

| 것 | 프레임 | 이동 | 반복 |
|---|---|---|---|
| 문 앞 멈춤 (바깥 보기) | 4프레임 / 320ms | 머리 1px | 1번 |
| 선택 버튼 등장 (주머니·식탁) | 2계단 | 2px 위로 | 1번 |
| 쟁반 물건 반짝 | 5프레임 (점→십자→별→십자→점) | — | 3번 뒤 멈춤. 한 번에 하나만 |
| 내 헤엄 발차기 | 6프레임 | 1~2px | 누를 때만 |
| 문어 먹물 퓻 | 6프레임 + 퍼프 4프레임 | — | 헤엄 중 2~3초마다 |
| 카드 뒤집기 | 4프레임 | — | 1번 |
| 식탁 '냠' (볼 불룩) | 6프레임 | 1px | 1번 |

- ▼·하트·zzz 와 "반복은 한 화면에 2개까지, 대사창 둘레 1개, 큰 몸짓은 한 번에 하나" 규칙은 **DIALOGUE_UI §5.9 한 곳**을 따른다. 헤엄 배경의 겹 움직임(시차)은 2겹까지다.
- 에셋(`assets/ui`, `assets/fx`)은 UI 아트 세션 몫이다 (카드 12). 넘길 것 (▼ 는 DIALOGUE_UI 부탁에 있다): 반짝 5프레임, 집 쪽지 아이콘 16×16 (멈춘 그림), 선택 버튼 9-slice (눌림 상태만, 깜빡임 없음), 카드 뒤집기 4프레임.
- 헤엄 속 내 모습은 헤엄 세션이나 아트 세션이 그린다. PLAYER_PROGRESSION v0.5의 '헤엄 2장'을 **4~6장**으로 늘려 달라고 부탁한다 (2장은 깜빡임으로 읽힌다).

### 5.5 소리 (소리 세션 몫)

- 지금 있는 것 다시 쓰기: 문 앞 멈춤 = `curious_1/2`, 카드 뒤집기 = `card_flip_1/2`, 집 쪽지 = `card_flip`·`toast`, 포스터 걸기 = `hang_poster_1/2`.
- 집 쪽지에는 문어 목소리(`voice_a`·`voice_u`)를 쓰지 않는다.
- 새로 부탁: 내 발소리 (문어 '뽈'보다 작고 낮게), 풍덩 둘 (문어·나), 헤엄 거품, 먹물 퓻, 살짝 부딪힘 '퐁', 줍기 '바스락', 만남 짧은 소리 (작게. 결정 16 의 톤. 딩 같은 징글 아님), 접시 내려놓기, 냠, 냄비 퐁 (요리 세션과 같이).
- 규칙은 manifest 그대로: F장조 / F 펜타토닉, 변형은 시드로 고른다.

### 5.6 자동 점검 (테스트로 넣는다)

1. **모드 무관**: 같은 날짜·순번에서 '같이' 아이콘 켬 / 끔 / 한 번도 안 만짐만 바꿔 돌린다. 일기(코드 이름 `receipt`)·포스터·기념품·등불·벽 순서가 시각 값을 빼고 바이트까지 같다.
2. **문어 기록 허용 목록**: `trips[]`에 사람 키가 0개다.
3. **두뇌 입력**: 두뇌 입력과 MCP 산책 요청의 키가 허용 목록 안에만 있다. `S.user`를 바꿔도 결과가 같다.
4. **반응 같음**: 두 모드에서 문어 표정·말풍선 순서가 같다. 문 앞 이후 카메라 길만 다르다.
5. **헤엄 정직**: 입력 없는 구간 → `auto`, 탭 숨김 → `auto`, 바로 돌아오기 → `cut`, 동작 줄이기 → `still`. 입력 없이 `played`인 경우 0건.
6. **대신 안 고름**: 다시 열기·바로 돌아오기·탭 숨김 뒤에도 사람이 안 눌렀으면 `items`가 늘지 않는다.
7. **블라인드 순서**: 같이 가기에서 '간직' 전에는 `remember` 줄과 문어 카드 **앞면**이 어디에도 없다 — 들고 오는 그림, 벽, 앨범, 토스트. 보통·바로 돌아오기·동작 줄이기 세 경우를 다 돈다. 순서는 §3.4 순서표대로 (②가 ③보다 먼저). `table` 결정은 `finish` 뒤에만 만들어진다.
8. **숫자 없음**: '내 것' 화면에 N/M·모은 개수가 없다. 설정 › 기록 줄 항목이 늘지 않는다. 집 쪽지·버튼 글자에 "아쉽", "미안", "같이 가자", "기다렸"가 0건이다.
9. **식탁 메뉴**: 늘 `watch`·`stop`이 있다. `fallback`은 반응 연출이 없다. 데모 규칙은 `line`을 쓰지 않는다. 코드 문구에 '맛있', '좋아해'가 0건이다.
10. **다시 열기·두 탭**: 재생의 모든 단계에서 닫았다 열기 → 사람 기록 손실 0, 중복 0. 다시 만나기의 모든 박자(①~④)에서 닫았다 열기 → 다시 만나기가 **정확히 한 번** 열린다. 두 탭에서 줍고 간직 → 합집합, 중복 0.
11. **시드**: `together.js` 결정 코드에 `Math.random` 0건. 사람 쪽 난수는 `hash(trip.seed, 'user', stopIdx)`.
12. **모듈 끄기**: `together.js`가 없으면 기존 스모크 A·B 결과가 같다.
13. **조개**: 같이 가기 산책에서 헤엄을 한 번도 안 누르면 조개 0 (PLAYER_PROGRESSION 점검과 같이 돈다).
14. **묻지 않음 (11-07)**: 산책 한 번에 사람에게 뜨는 선택 단추가 0개다 (문 앞·기다리기 모두. 주머니·식탁은 다시 만나기에서만). '같이' 아이콘 값이 두뇌 입력·MCP 산책 요청에 0바이트. 아이콘 켬 + 집에 있는 날 → 화면 글·문어 표정 변화 0.

## 8. 주인이 정할 것 (3) — 셋 다 정함 (1 가 · 2 기본값 가 · 3 가, OWNER_DECISIONS)

**1. 헤엄칠 때 누르면 움직이는 건 누구야?**
- (가, 추천) **네 모습(아바타)**이 문어를 따라 헤엄친다. 문어는 앞에서 자기 길로 가며 먹물을 뿜는다.
  - "같이" 가는 게 화면에 보인다.
  - 문어는 자기가 안 고른 움직임(부딪히기·빙글 돌기)을 하지 않는다.
  - 헤엄 속 모습만이다. 다락 안 내 모습은 따로, '나중'이다 (§6).
- (나) 카드 8 원안처럼 **문어를 직접** 조종한다.
  - 만들기는 쉽다.
  - 하지만 네가 문어를 움직이게 된다. 진짜 모델이 붙었을 때 "모델이 안 한 걸 한 것처럼" 보인다.
  - 따로 하는 헤엄(놀이방)은 (나)여도 괜찮다. 다락방 달리기가 이미 그렇다.

**2. 집에서 기다리는 동안 산책 줄을 봉해 둘까?**
- (가, 추천) **봉해 둔다.** 다락에 남아 네 일을 하고, 돌아오면 문어가 다녀온 이야기를 한 줄씩 본다.
  - 한 줄씩 넘기는 대화 상자와 잘 맞는다.
  - 앱을 닫고 와도 같은 맛이다. 잃는 줄은 없다.
- (나) 지금처럼 바깥 장면이 돌고 줄이 바로 쌓인다.
  - 궁금하면 바로 볼 수 있다.
  - 하지만 같이 가기와 차이가 줄고, 요리하는 동안 줄이 상자에 밀린다.

**3. 같이 가서 주운 것, 돌아와서 하나만 간직할까?**
- (가, 추천) **하나만.** 문어가 기억 하나를 고르듯 너도 하나를 고른다. 둘이 나란히 놓인다.
  - 같이 가기가 '더 많이 모으는 길'이 되지 않는다.
- (나) 다 간직한다.
  - 줍는 맛은 크다.
  - 하지만 같이 간 날만 네 것이 쌓인다. 두 선택 사이에 보상 차이가 생긴다.
