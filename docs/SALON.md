주인 말 (11-08 밤, 그대로): "글고 지금 생각해봤는데 물론 게임이긴 하지만 문어 외관을 내 멋대로 슥슥 염색시키는 게 좀 다소... 어색하고 우리 복지 방향이랑 안 맞게 느껴져서 그런데 처음에 선택한 이후로는 사용자가 못 바꾸게 픽스하는 건 별로일까? 흠...... 대신 이 색으로 염색해볼까? 이런 식으로 미용실 컨텐츠 추가하는 거야."

한 줄: **몸 색은 사람이 처음 한 번만 고른다. 그 뒤로는 미용실에서 사람이 색을 내밀고 묻고, 바꿀지는 문어가 정한다.**

지키는 선:
- MODEL_VOICE 두 약속. 고르기 전에 끌지 않는다. 고른 것(행동·말·표정)을 바꾸지 않는다.
- 모든 물음에 '그대로'(`keep`)가 첫째로 있다. 이유를 묻지 않는다. 받은 답을 다시 묻지 않는다.
- '그대로'는 담담하게 보여 준다. 시무룩·죄책 대사·마음 바꾸기 연출이 없다.
- 코드가 짓는 글은 사실만 쓴다('좋아해' 같은 말 0건). 데모 규칙의 말은 늘 보이는 '데모' 꼬리표 아래에서만 나온다.
- 결정은 시드로 한다. `Math.random` 0건이고, 답은 [물어보기]를 누른 순간 계산해 저장한다.
- 주인 규칙: 고를 것과 글은 적게. 화면에 이모지·꾸밈 기호가 없다. 방은 문으로 잇는다(미용실은 방이 아니라 다락 한 구석이다).
- 미용실은 아무것도 주지 않는다. 조개·등불·배지·'함께한 날'이 0이고, 대답은 취향 점수가 되지 않는다.

## 1. 몸 색 잠금 (2부)

### 1.1 첫 실행 창 (`#name-dialog`)

순서 (위 → 아래):

1. 제목 `h2#name-h` "문어 이름을 지어 줘" — `class="dlg-top"` `tabindex="-1"`
2. 한 줄 "오늘 처음 보내는 문어야." (둘째 문장 "이름은 천천히 불러 줘도 괜찮아." 는 뺀다)
3. 초상 캔버스 64×64 (CSS 64 px, 픽셀 테마 정수 배율). 지금의 `img[data-asset="oct.happy"]` 는 초상을 못 그릴 때(컨텍스트 잃음)만 남는 대체 그림이다
4. 색 6칸: `div.presets.name-colors[role=group][aria-label="몸 색"]` 안에 `button.preset[type=button][aria-pressed][aria-label="빨강"…]`
5. 이름 칸 `#name-in`
6. [이름 저장] `type=submit`
7. 정직 줄 "지금은 미리 만든 규칙으로 움직이는 체험판이야." (그대로)

규칙:
- **색 6개만** (슬라이더 없음). 순서와 값은 `SALON.PRESETS` 그대로: 빨강 `#e8463c` · 주황 `#f08a3c` · 보라 `#9a5cc8` · 파랑 `#4a86d8` · 초록 `#4fa868` · 분홍 `#f07aa8`. 처음엔 빨강(`SALON.DEFAULT_COLOR`)이 눌린 채다.
- 칸을 누르면 **창 안 초상만** 그 색으로 다시 찍는다: `scene.portrait('happy', { bg: 'transparent', color: hex })`. 표정은 바뀌지 않고 폴짝도 없다. 장면 문어는 [이름 저장] 때 한 번 `setOctColor` 로 바뀐다 (그 전에 톡톡 갈아 보는 모습이 주인이 말한 '슥슥'이다).
- 색 단추는 꼭 `type="button"` 이다. 아니면 폼이 제출되어 이름 필수 검사가 뜬다 (기술 MUST 10).
- **포커스**: 손가락 기기에선 제목에 준다(자판이 색 줄을 가리지 않는다). `(pointer: fine)` 이면 지금처럼 이름 칸에 준다. `#name-h:focus { outline: none }` 을 둔다(테두리가 생기면 입력 칸처럼 보인다). 키보드로 Tab 하면 색 칸 → 이름 칸 → 저장 순이다.
- **크기**: `.preset` 보이는 칸 36 px, 누르는 곳 `::before` 로 44 px, 간격 6 px (6×36 + 5×6 = 246 px). 320 px 폰에서 창 안쪽이 246 px 보다 좁으면(실측 픽셀 230 · 시스템 237) `#name-dialog { max-width: calc(100vw - 24px) }` 로 넓히고, 그래도 모자라면 간격을 4 px 로 줄인다. **한 줄, 줄바꿈 없음**이 합격선이다.
- **높이 합격선**: 320×568 에서 두 글꼴 모두 창이 스크롤되지 않고 정직 줄이 보인다 (경험 검토 실측: 픽셀 460 px · 시스템 395 px). 320×460 에서 [이름 저장]이 화면 안에 있다. 360 · 412 px 은 창 폭이 `min(92vw, 340px)` = 331 · 340 px 라 색 줄이 넉넉히 한 줄이다. 어두운 테마는 칸 테두리 `var(--line)`, 눌린 칸은 지금 `.preset.on` 모양 그대로다.
- 글에 "색은 못 바꿔" 같은 말을 넣지 않는다. 겁주는 말은 고르기를 무겁게 만든다. 규칙은 장면과 미용실이 보여 준다.
- 색을 안 누르고 저장하면 빨강이고 `by: 'default'` 다. 누르면 `by: 'player'`.
- 저장: `S.octopus.color = hex`, `S.octopus.colors = [{ at, date: todayKey(), color: hex, how: 'first', by }]`, `S.settings.octColor = hex` (사본).
- 전체 초기화를 하면 같은 창이 다시 뜬다(색도 다시 고른다).
- 첫인사 줄에 색을 넣지 않는다. 어디서도 '문어가 고른 색'·'원래 색'이라고 말하지 않는다.

### 1.2 설정

| 누가 | 보이는 것 |
|---|---|
| 플레이어, 거울 전 (등불 0–1칸) | '문어 색' 칸 자체가 없다 |
| 플레이어, 거울 뒤 (등불 2칸 이상) | `h3#set-color-h` "문어 색" + 바로 아래 한 줄 `#set-color` "거울 앞에서 {이름}에게 물어볼 수 있어." (누르는 것 없음. 글은 `SALON.TEXT.settingsHead` · `settings`). 11-10 부터 시트 맨 위는 문어 선물 상자이고, 문어 색 칸은 그 아래 · '내 모습' 위다 |

- **개발용 판정은 새 플래그 `DEV_EXPLICIT`** 이다: 주소에 `dev=1` 이 있거나, 같은 탭 sessionStorage 에 `ppolppol_dev = '1'` 이 있을 때(그리고 `dev=0` 이 아닐 때). file:// · localhost 의 자동 `DEV` 로는 안 켜진다. README 가 file:// 와 `dist/ppolppol.html` 을 노는 방법으로 안내하기 때문이다 (복지 MUST 6). 기존 `#demo` 패널·힌트 칸은 지금 규칙(`DEV`) 그대로다. 이 스펙이 더하는 개발용 칸 둘(바로 바꾸기 · 다음 미용실 대답)만 `DEV_EXPLICIT` 을 본다.
- 개발용 슬라이더: `input` 이벤트에선 장면만 미리 보인다(`scene.setColor(hex, { still: true })`, 저장 없음). `change` 에서 한 번 `setOctColor(hex, { how: 'dev', by: 'dev' })` 를 부른다. 한 번 끌면 기록이 한 줄 생긴다 (기술 MUST 6).
- `WHO_LINE` 을 "지금은 모델이 아니라 미리 만든 규칙이 골라. 고른 이는 포스터와 쪽지 뒷면, 미용실 줄에 적혀." 로 바꾼다.
- 칸 순서: 문어 선물 상자 → 문어 색 → 내 모습 → 소리 … (11-10). 익숙해지면 아래로 내리거나 뺀다 (나중).
- 설정 시트 **맨 아래**의 '만든 것들' 글 링크는 요리 작업(9물결) 몫이다. 미용실은 맨 위 '문어 색' 칸만 고친다 (두 작업이 깨끗이 합쳐지게).

### 1.3 바꾸는 길은 하나

```js
setOctColor(hex, meta)   // meta = { how: 'first'|'salon'|'dev', by, ask?, at? } — 없으면 { how: 'dev', by: 'dev' }
// → S.octopus.color = hex; S.settings.octColor = hex; colors.push({ at, date: todayKey(), color: hex, how, by, ask }); save();
//   salonActive 가 아니면 applyLook({ still: how !== 'salon' })
applyLook(opts)          // 장면 색 ≠ S.octopus.color 이면 scene.setColor(color, opts) + refreshPortraits(). salonActive 동안은 미룬다
```

- `applyLook()` 은 `renderScene()` 끝, 이름 저장 뒤, `adoptRemote` 뒤, `importJSON`·`resetAll` 뒤, `sceneLost` 2D 다시 그리기 뒤에 부른다 (기술 MUST 4: 그 전엔 이 길들에서 장면 색이 안 따라왔다).
- `sceneOpts().color` 는 `S.octopus.color` 를 읽는다.
- `scene.setColor(hex, { still: true })` 는 흔들기(`oct.wiggle`)를 하지 않는다. 미용실 연출만 흔든다 (털기 박자에서 장면이 따로).
- `APP.setOctColor` 는 시험용으로 그대로 공개한다. 인자 하나로 부르면 개발용 기록(`how: 'dev'`)이 된다 (스모크 S 의 다른 탭 검사가 그대로 돈다).
- 미용실의 '바꾸기'는 `setOctColor` 를 따로 부르지 않는다. `SALON.commit` 이 물음 · colors 줄 · 지금 색 · 사본을 한 번에 쓰고 앱이 `save()` 한 번 (§7.3).
- `js/runner.js` 251 행은 `octopus.color` 를 먼저, `settings.octColor` 를 다음으로 읽는다 (한 줄).

### 1.4 옛 저장

- 이미 놀던 기록(이름이나 trips 가 있음)은 **지금 색 그대로** 간다. `colors` 가 비어 있으면 `{ how: 'first', by: 'migrated', color: 지금 색, at: born || null, date: null }` 을 넣는다(`SALON.normalize`, 1부). 첫 실행 창은 다시 뜨지 않는다.
- `by: 'migrated'` 의 뜻은 "미용실 전에 사람이 설정에서 고른 색(또는 기본값)"이다. 문어가 고른 색으로 풀어 쓰지 않는다.
- v1 → v2 옮기기 결과도 `normalize()` 를 거친다. 그 전엔 `load()` 가 `migrateV1` 결과를 normalize 하지 않았다 (기술 SHOULD 10).

## 2. 자리 — 위층 다락 옷방 뒷벽 왼쪽 거울 코너 (11-11 이사 · 장면 1부 · 앱 쪽 2부)

**11-12 지금 코드**: 거울 코너는 11-11 에 거실(다락)에서 위층 옷방(`loft`)으로 이사했다 (주인 "윗층 다락방에 미용실"). 다락 뒷벽엔 이제 거울이 없다.
- 아래 §2.1 의 숫자는 **코너 좌표**다 (예전 다락 좌표 그대로). 위층 안의 감싸는 그룹 `LSALW` 를 (`LSAL.dx`, 0, `LSAL.dz`) 만큼 옮겨 위층 뒷벽 x −1.5 에 맞춘다. `scene.motion().salon.geom` · `gait.at` 은 위층 좌표다.
- 문어는 깨어서 집에 있을 때 내가 계단으로 오르면 따라 올라온다 (`octMountLoft` → `scene.octUp()`). 서는 자리는 깔개 뒤쪽 (−0.3, 0.2) — 계단 앞 길목을 비운다. 초록 방석은 깔개 뒤 오른쪽 (0.5, 0.1) 으로 옮겼다 (11-12: 문어 자리에 깔려 안 보였다 — 화면에서 문어 옆에 따로 보인다). 걷던 중이면 그 걸음은 도착으로 끝나고 (앱 상태 idle · 폴짝 0) 위층으로 간다. 내가 내려가거나 출발 · 귀가 의식이 시작되면 다락 제 자리로 돌아가고, 앱 자리도 그 자리로 맞춘다 ('바꾸기' 뒤 'salon' 이면 '방 가운데').
- 자는 중 · 나가 있는 중엔 따라오지 않는다. 문어가 혼자 층을 옮기는 일은 없다 (위의 따라 오르기 · 돌아가기뿐 — 깨우지도 데려오지도 않는다).
- **위층에서는 돌아다니지 않는다** (11-12, `scheduleWander` · `moveTo`): 돌아다닐 자리가 다락 자리뿐이라 위층에선 염색통 · 재봉대 안에 섰다. 온 자리에 있다가 '바꾸기' 때만 거울 옆('salon')으로 걷는다. **주인 결정 대기**: 위층에도 빈 자리 두세 곳을 주어 돌아다니게 할지 (더 살아 있어 보이지만 가구 · 계단 길목을 피한 자리를 새로 잡아야 한다).
- **거울을 눌렀는데 문어가 위층에 없으면 사실 한 줄** (11-12, `openSalon`): 아래층에서 자면 "지금은 아래층에서 자고 있어.", 깨어서 아래층에 있으면 "지금은 아래층에 있어.", 나가 있으면 "지금은 산책 나가 있어." — 다만 차례(나감 · 나가 있음 · 돌아옴) 동안엔 거울 단추가 숨어 있어 이 줄은 단추를 직접 부를 때만 나온다. 시트 · 물음 · 로그 행 · 소리 없음, 깨우지 않는다, 올라오게 하지 않는다. **주인 결정 대기**: 이 한 줄 대신 단추를 숨길지, 깬 문어가 혼자 올라오게 할지 (가장 자연스럽지만 문어가 저 혼자 층을 옮긴다 — '문어를 몰지 않는다' 와 견줘야 한다).
- 내 캐릭터 (11-12): 문어가 거울로 걸어갈 길 위에 서 있으면 먼저 길 옆으로 비켜선다 (`plClearPath` — 길 양옆이 가구면 둘레 16 방향에서 길과 떨어진 빈 자리). 연출 첫 박자(행 1 · 시트가 닫힌 직후 — 두 답 다, 대답이 보이기 전)에 대야 자리나 거울 자리에 서 있거나 문어 · 거울 · 대야를 가리면 옆 구경 자리 (0.35, −0.85) 로 걷는다 (`salClearView` — 앱이 `scene.salonClearView()` 로 부른다 · 11-12 검증: 예전엔 '그대로' 의 마지막 0.5 s 에야 걸어 대답 말풍선 내내 문어를 가렸다). 곧장 가는 길이 문어 둘레에 막히면 문어 둘레 바로 밖에서 한 번 꺾는다. '바꾸기' 의 대야가 놓일 때 한 번 더 본다 (그새 스틱으로 돌아왔으면) — 그때 대야 뒤 구석에 서 있으면 대야 · 문어 둘레 · 가구에 둘러싸여 나갈 길이 없어 대야 둘레 밖으로만 물러서고, 대야를 치운 뒤 스틱(화면 아래쪽)으로 나온다. 문어의 길에서 비킬 때도 대야 자리 · 그 뒤 구석으로는 가지 않는다. 거울 앞 구석에서 스틱으로 나가는 길은 화면 아래쪽 · 왼쪽 아래 두 방향이다 (오른쪽은 재봉 의자, 위 · 왼쪽은 벽 · 거울 선반). 거울 앞 둥근 의자는 뺐다 (문어의 길과 거울 구석에서 나오는 길을 막았다).
- 가구 배치는 다락 일이다: 배치 중에 계단 · 문으로 다락을 떠나면 '끝내기' 와 같이 끝난다 (11-12 — 위층에서 아무것도 안 되는 판이 거울 · 큰 버튼을 가렸다).
- 장면 설명 (화면 낭독기): 위층이면 "위층 다락 옷방, …" 으로 시작하고, 문어가 따라 올라와 있으면 "문어는 위층에서 …" (거울 옆이면 "위층 거울 옆에서 …"), 아래층에 있으면 "문어는 아래층 담요 위에서 자고 있어." 처럼 말한다 (아래층에서 걷는 중이면 "문어는 아래층에서 걸어가는 중이야.").
- 2D 대체 장면엔 위층이 없다: 거울은 2D 다락 그림에 그대로 있다 (§2.2).

다른 자리 둘과 비교했다(설계안 §1). 시트만 두면 '설정 바꾸기'처럼 읽힌다. 미용실 방을 따로 지으면 문어를 다락 밖으로 데려가야 하고, 일이 크다(L). 그래서 다락 안 한 구석이다 (기본값, 주인 확인 전 — §13). 나중에 옷방이 열리면 같은 규칙(`SALON`)과 프로토콜 그대로 자리만 옮길 수 있다. (11-10 의 판단 — 11-11 에 그대로 위층 옷방으로 옮겼다, 위.)

11-10 의 기준이 큰 것은 내 캐릭터 · 가구 · 넓어진 다락 몫이다 (코너가 더하는 콜은 그대로 +6 / +12). 등불 8칸 밤의 '바꾸기' 중 최대가 140 이라 상한까지 10 남았다.

**색이 제대로 읽히는가** (경험 MUST 2): 물을 `lambert` 로 그리면 낮엔 여섯 색이 다 흰색에 가까워지고, 밤엔 주황·분홍이 갈색으로 바뀌었다 (증거 캡처는 저장소 밖). 그래서 병·물·유리는 `basicV` 로 그린다. 합격선: 6색 × 낮(14시)·밤(21시)에서 병 가운데 아트픽셀과 물 픽셀의 색상(hue)이 원래 색과 ±25° 안이다. 못 미치는 색만 `buildPalette(octHex, source, extra)` 의 `extra` 로 팔레트에 한 칸 더한다. 1부에서 잰 결과 (Apollo):
- 덧칸은 코너가 보일 때만. 보라는 그대로 한 칸, 초록은 OKLab 색상을 청록 쪽으로 6° 돌린 한 칸(`#41a971`). 밤엔 초록의 밤 톤 한 칸을 더한다 (Apollo 51 + 2, 밤 3 ≤ `PAL_MAX`).
- 그냥 초록이나 그 밤 톤을 낮에 넣으면 다락 화분·이끼의 올리브 픽셀을 훔쳤다(청록 점). 그래서 T6 이 '코너를 켜도 코너 밖 픽셀 0개 바뀜'을 같이 잰다. 덧칸은 디더 진폭에 안 들어간다.

**누르는 곳**:
- `#btn-salon` 은 진짜 `<button class="scene-spot">` 이다 (2부). `aria-label="미용실"`, `aria-haspopup="dialog"`, `aria-controls="salon-sheet"`, `aria-describedby="scene-desc"` 를 달고, index.html 의 `#btn-machine` 뒤에 둔다. app.js `ROOM_SPOT` 에 `salon` 을 더한다 (2부).
- 장면 (1부): `SPOT_KEYS` 에 `salon` 이 있고 `hotspots({ …, salon })` 로 단추를 받는다. `spotInfo('salon')` 은 다락이 보이고 · 방 이동·문 작업·전환·입장 연출·의식이 없고 · 코너가 보이고 · 앱이 `scene.setSalonOpen(true)` 로 허락했고 · 연출 중이 아닐 때만 'over' 다. 상자 = 거울 + 병 선반의 투영 상자, 44×44 이상. 단추를 안 넘기면 거울은 톡을 가로채지 않는다.
- 톡은 캔버스 `pick` 이 받는다. 우선순위: 레이캐스트 가장 가까운 것 (문어 몸 · 포스터 · 기념품 · 놀이방 문 · 거울 메시 A·B·C — 단추가 열려 있을 때만) → 문어 히트 구 → 창 → 놀이방 문 단추 칸 → 근처 기념품·포스터 → 미용실 단추 칸 (맨 끝). 문어가 거울 옆에 서 있으면 문어를 누른 게 먼저다. 등불 8칸 기념품이 겹쳐도 기념품이 먼저다.

**v2 (나중, 스크린샷 확인 뒤)**: 대야 속 잠수. 기술 검토가 찾은 맞는 값: 대야 r 0.48–0.5 · 테 0.20–0.22, 안에 있는 동안 몸 x/z 0.9 배 · 팔 접기 · 0.05–0.08 m 가라앉기, 폴짝 꼭대기 0.65 r 이상. 0.14 m 가라앉으면 눈이 안 보인다 (캡처는 저장소 밖).

### 3.3 묻기 — 고르는 과정이 보이게

[물어보기]를 누르면:

1. **다시 읽고 확인**: 저장소에서 기록을 다시 읽어 합친다(§7.5). `SALON.canAsk(state, todayKey(), octState)` 가 거짓이면 시트를 닫고 그 토스트를 띄운다. 두 탭 · 자정 넘김을 막는다.
2. **답을 정하고 바로 저장**: 데모면 `SALON.demoAnswer(...)` (§4), 개발용 '다음 대답'이 걸려 있으면 `SALON.humanAnswer(action)` (`by: 'human'`)이다. `SALON.makeAsk` 로 물음 한 줄을 만들고 `SALON.commit` 으로 물음 한 줄과 ('바꾸기'면) 색 기록 한 줄, `octopus.color` 를 쓴 뒤 **`save()` 한 번**. 장면만 연출이 끝날 때까지 옛 색이다(`salonActive` 동안 `applyLook` 을 미룸). 모델 길(나중)은 여기서 `status: 'waiting'` 으로 먼저 저장하고 요청을 보낸다. 새로고침으로 물음을 무를 수 없다. 묻기 전에 내보낸 파일을 다시 불러와도 (같은 문어) 그 물음은 남는다 (§7.4 — 11-11, 검증 W1. 그 전엔 불러오기가 물음을 지웠다).
3. 시트가 닫히고(250 ms) `salonActive = true` 가 된다. 돌아다니기 · 생각 말풍선 · 쓰다듬기 · 톡 반응 · 창문 걷기를 멈춘다. `oct.busy` 는 `setBusy` 가 덮어쓰므로 쓰지 않는다 (기술 SHOULD 2). 톡 한 줄(0f584fd) 과 깨어 있는 틈도 같이 지킨다:
   - 연출 동안 문어를 톡 해도 톡 한 줄이 없고 깨우기도 없다.
   - 깨어 있는 틈이 연출 중에 끝나도 눕지 않는다. 낮잠은 연출이 끝난 뒤에 시작한다.
   - 내 캐릭터 (11-10): 연출은 내 캐릭터의 걷기로 끊기지 않는다. 캐릭터는 스틱 · 방향키로 그대로 걷는다. 문에 닿아 걸어도 연출 중엔 방을 옮기지 않는다 (`goRoom` 이 `salon` 으로 거절 — 연출이 끝난 뒤에도 밀고 있으면 그때 넘어간다). 문어가 설 자리(`salon`)에 캐릭터가 서 있으면 장면이 캐릭터를 옆으로 비켜 세우고 (`plAvoidOct`), 대야가 놓일 자리에 서 있으면 밀어낸다 (대야는 둥근 장애물).
4. 행 1 (집 목소리, 라벨 '미용실'): "파란색 어때? 하고 물어봤어."
5. 문어가 걷는 중이면 도착을 기다린다(최대 4 s, 넘으면 그 자리로 건너뜀). 쓰다듬기는 [물어보기] 를 누른 그 순간 (2 의 저장과 같은 일 안에서) 끝낸다 (11-11, 검증 E2): 2 s 뒤의 '…좋아' 예약을 지우고, 떠 있던 혼잣말 · 톡 한 줄 · 생각 말풍선을 내린다. 물음과 대답 사이에 뜨는 말풍선은 대답뿐이다 — 코드가 쓴 '…좋아' 뒤에 '안 바꿀래.' 가 오면 마음을 바꾼 것처럼 읽힌다.
6. 눈이 내민 병으로 간다(이미 가 있음). **숨 고르기 1.0 s + 움츠림 0.5 s**. 움츠림은 장면 상태 `ponder`(`scaleY .92 / scaleX 1.05`, 얼굴 idle)다. 출발용 `anticipate` 를 쓰지 않는다(반눈 calm 얼굴과 출발 먹물이 따라온다). 두 답 모두 같다. 모션 줄이기면 장면은 움츠리지 않고 앱이 그만큼 멈춘다. 모델 길이면 이 박자가 요청 대기를 덮는다.
7. 대답을 보인다 (§3.4).

마음 바꾸기는 꾸며 내지 않는다. '그대로' 앞에 다가가기·기울기가 없다.

### 3.4 대답 연출

공통 (대답을 보이는 순간). 연출에 쓸 값은 `SALON.staging(ask)` 하나에서 온다 (`{ action, color, expr, joy, look, bubble }`):
- 장면 얼굴 = 고른 이가 준 `expr` 이다. 데모는 '바꾸기' happy · '그대로' idle 이다. 모델이 안 줬거나 사람(개발용)이 정했으면 idle 이다. `scene.setExpression(expr)` 를 직접 부른다(말이 없어 행 2 가 없어도).
- 말이 있으면 말풍선(앞 24자 + '…', `SALON.bubble`) + 행 2 (라벨 '대답', 문어 목소리 행, 초상 = 같은 `expr`, 모델 말은 `data-raw="model"` 로 원문 전부). **말이 없으면 행 2 도 말풍선도 없다**(데모 문구로 채우지 않는다).
- `happy` 면 장면의 기본 폴짝 2번이 같이 나온다 (`joy`). 다른 표정은 폴짝이 없다.
- 소리 `window.AUDIO && AUDIO.on && AUDIO.on('salon', { act: 'answer', action, by, joy })`.

**'바꾸기' (`dye`) — v1** (보통 속도, `?slow=` 를 따른다). 장면은 `salonDye(hex, { joy, look, id, onBeat })` 하나로 아래 박자를 돈다 (걷기는 앱이 먼저):

| 박자 | 보통 | 모션 줄이기 |
|---|---|---|
| 말풍선 0.4 s 뒤 거울 옆(`salon`)으로 걷기. 이미 거기면 말풍선 1.6 s 를 기다린다 (앱) | 0 – 3.3 s | 바로 그 자리 |
| 대야가 놓인다 (2칸 @12 fps, 쿵) · 병이 선반에서 대야 테로 폴짝 (호 0.3 s) | 0.17 + 0.3 s | 1칸 |
| 멈춤 0.3–0.6 s (물음 id 시드) | 0.45 s | 0.2 s |
| 병이 기울고 (3칸) 물이 내민 색으로 물든다 (3칸) | 0.5 s | 1칸 |
| 대야 쪽으로 몸을 돌림(카메라 ±40° 안) · 예비 120 ms · 제자리 폴짝 (꼭대기 0.3 r, 대야 쪽으로 ≤ 8° 기울기) | 0.5 s | 없음 |
| 첨벙: 대야에서 물보라가 솟아 몸을 덮는다 (4칸 @12 fps = 333 ms). **둘째 칸에서 색이 바뀐다** (팔레트 문어 램프 교체 · 초상 다시 찍기) | 0.33 s | 색 2칸 교차 (섞은 색 → 새 색, 150 ms 씩) |
| 털기: 흔들기 0.7 한 번 + 새 색 물방울 2칸 | 0.4 s | 없음 |
| (`joy` 일 때만) 폴짝 2번 + 반짝 (픽셀 테마 `UIART.fx('sparkle')`, 앱) | 0.9 s | 얼굴만 |
| (`look` 일 때만: 데모, 또는 모델이 `expr` 를 줌) 거울 보기: 몸을 거울 쪽으로 0.3 s + 멈춤 0.6 s | 0.9 s | 멈춤 0.6 s 만 |
| 물이 빠지고(3칸) 병이 선반으로 · 대야가 치워진다 (동시에) | 0.3 s | 1칸 |
| 행 3 (라벨 '몸 색', 집 목소리): "뚜루 몸이 파란색이 됐어." + 고른 이 꼬리 (앱) | — | — |

대답을 보인 뒤 걷기를 빼고 약 5 s 다(그 앞에 숨 고르기 1.5 s). T6 이 장면 `salonDye` 만 잰다: 보통 속도 4–6 s 안 (`joy` · `look` 둘 다 켬), 모션 줄이기 1.5 s 이하. 숨 고르기 1.0 s 와 말풍선 1.6 s 는 모션 줄이기에서도 그대로 둔다(스킬 §4: 모션 감소에도 리듬은 유지). 대야는 문어가 자리에 선 뒤에만 놓이고 문어가 떠나기 전에 치워진다. 그래서 늘 있는 대야가 길을 막는 문제가 없다.

**'그대로' (`keep`)** — 약 3.5 s:
- 말풍선 + 행 2 (말이 있을 때만) 1.6 s. 말이 없으면 0.6 s 멈춤.
- 병이 선반 제자리로 돌아간다(0.3 s). 몸을 카메라 쪽으로 돌린다(0.3 s). 장면은 `salonKeep()`. 얼굴은 고른 이의 `expr` (데모 idle)다. 시무룩·고개 숙임·징글이 없다.
- 행 3: "색은 그대로야." + 고른 이 꼬리.
- 그 뒤 평소처럼 돌아다닌다.

**대답 없음** (`action: null`. 모델이 그날 자정까지 아무 답도 보내지 않음 · 개발용 '대답 없음'):
- 문어는 가만히 idle 이다. 말풍선이 없다. 병이 돌아간다.
- 행 3: "대답이 없었어. 색은 그대로야." 거절처럼 연출하지 않고, 이유도 짓지 않는다.

**받았지만 메뉴 밖 답** (모델, 나중): 색은 그대로다. 말이 있으면 그대로 보인다. 행 3 "색은 그대로야." (JSON 이 아니면 "답을 못 읽었어. 색은 그대로야.") 다시 묻지 않는다 (§6).

**건너뛰기 · 숨김 · 끊김**:
- 연출 중 주 버튼(뽈뽈 다녀와)을 누르면 앱 `salonFinish()` 로 남은 연출을 한 번에 감고(장면 `salonFinish()`: 새 색 · 대야 치움 · 병 제자리, 남은 행), 그다음 초대가 평소대로 간다.
  - 단, 시트가 막 닫힌 뒤 0.6 s (`SHEET_SETTLE`) 안의 누름은 주 버튼이 받지 않는다 (11-11, 검증 E1 = P1). 한 화면 배치에선 주 버튼이 시트의 [닫기] · [물어보기] 오른쪽 밑이라, 두 번 톡의 둘째가 시트가 사라진 자리의 주 버튼에 떨어져 [닫기] 뒤엔 청하지 않은 산책이 나가고 [물어보기] 뒤엔 대답 연출이 한 번에 감겼다. 어느 대화상자든 같다 (로그 · 앨범 · 살림 · 설정 · 포스터). 닫힌 때는 `open` 속성이 빠지는 순간, 누른 때는 click 의 시각으로 잰다. 실측 (손가락, 360×740 · 320×568): 닫힌 뒤 571 ms 까지의 누름은 안 받고 655 ms 부터 받는다. `APP.goResting` 이 이 틈도 알려 준다.
- 연출이 끝나면 (스스로 끝나든 감기든, 두 답 모두) 다음 돌아다니기를 20–40 s 뒤로 다시 건다 (11-11, 검증 W10 = P8 의 때 쪽 — 예전엔 연출이 끝나자마자 걸어 나갈 수 있어서 '안 바꿀래.' 뒤에 돌아서 가 버리는 것처럼 보였다). 돌아다니는 곳 목록은 그대로다.
- 연출 끝은 먼저 `salonActive` 를 풀고 그다음 남은 행을 붙인다 (11-11, 검증 E4). 행을 붙이다 오류가 나도 거울 · 문 단추 · 톡 · 돌아다니기가 돌아오고 `done` 약속이 풀린다. 장면의 `setSalonOpen` 이 던지면 준 것으로 적지 않아 다음 맞춤 (문어 상태가 바뀔 때 · 산책이 끝날 때) 에 다시 준다.
- 이 탭이 연출 중인 물음이 다른 탭의 이른 물음에 밀리면 (dropped, §7.5) 남은 연출을 그 자리에서 접는다 (11-11, 검증 E10): 행은 그쪽 물음 것, 몸 색은 기록대로.
- 연출 중엔 놀이방 문 단추 · 위층 계단 단추 (`#btn-stair`, 11-10) 와 거울 단추를 숨긴다 (기술 SHOULD 8).
- `runCeremony` 와 같은 지킴이: 250 ms 마다 본다. 탭이 숨으면 · 예상 길이 × speed + 4 s 가 지나면 끝으로 건너뛴다. 장면 Promise 는 늘 풀린다: 숨은 탭 · 화면 밖 · 컨텍스트 잃음 · 문 · 의식 · 코너가 사라짐이면 장면이 스스로 끝 상태로 감는다 (기술 MUST 9).
- 새로고침: 기록은 이미 저장돼 있다. 새 색으로 열리고 행 셋이 이미 있다. 연출을 다시 하지 않는다(재생은 결정이 아니다).

### 3.5 하루 한 번 · 같은 색 7일

- **물음은 로컬 날짜(`todayKey()`)마다 한 번**이다. 대답이 바꾸기·그대로·없음 무엇이든 같다 (`SALON.COUNT_NONE = true`). 그래서 '그대로' 뒤에 같은 날 조를 수 없고, 바꾸기도 하루 많아야 한 번이다. 자정이 지나면 다시 열린다(1분 틱 `checkDay` 와 같은 날짜 키, UTC 아님).
- **'그대로'라고 답한 그 색은 7일 쉰다** (`SALON.REST_DAYS = 7`, 기본값 — 주인 확인 전, §13): 11-09 에 파랑에 '그대로'면 파랑은 11-16 부터 다시 물을 수 있다. 다른 색은 내일 된다. 사람이 묻는 쪽의 규칙이라 취향을 지어내지 않는다. 날마다 같은 색을 다시 굴려 '아니'를 닳게 하지 못하게 한다. 진짜 모델은 어제의 거절을 전해 받지 않으니(맞는 선택) 이 규칙 말고는 자기 '아니'를 지킬 길이 없다.
  - 내보내기 → 불러오기로 이 쉼과 '하루 한 번' 을 되감지 못한다 (11-11, 검증 W1): 같은 문어 (`octopus.born` 이 같다) 의 파일을 불러오면 이 기기에서 이미 한 물음은 남는다 (§7.4). 막지 못하는 길도 있다 — 전체 초기화 뒤에 불러오면 다른 문어라 파일 그대로 들어온다. 기기에만 있는 저장이라 여기까지다.
  - 잰 숫자 (시드 규칙 그대로 돌린 시뮬레이션): 같은 색만 날마다 묻는 사람이 그 색을 얻기까지, 쉼이 없으면 평균 1.6번 · 3일 안에 95 % 다. 7일 쉼이면 평균 4.2일, 가장 길면 56일이다.
  - 대답 없음·메뉴 밖 답은 쉬게 하지 않는다. '바꾸기'도 쉬게 하지 않는다. 날짜를 못 읽는 물음도 쉬게 하지 않는다.
  - `REST_DAYS = 0` 이면 이 규칙이 꺼진다 (주인이 "다음 날 바로"를 고르면).
- 처음 색으로 돌아가기도 똑같은 물음 하나다(덤 없음).

### 3.6 무엇이 남나 · 남기지 않나

- 물을 때마다 `S.salon.asks[]` 에 한 줄 (§7). 몸이 바뀌면 `S.octopus.colors[]` 에 `how: 'salon', ask: id` 로 한 줄.
- 연출(걷기·폴짝·첨벙·거울 보기)은 결정을 다시 보여 주는 재생(playback)이라 따로 적지 않는다. 새로고침·다른 탭·앨범이 새로 고르지 않는다.
- 주지도 쓰지도 않는 것: 조개·등불·배지·'함께한 날' 0. 대답을 `affinity` · 두뇌 가중치 · 산책 요청 · '문어의 요즘' · 모델 요청의 지난 기록에 넣지 않는다. '파랑을 좋아해' 같은 말이 생길 길이 없다. `SALON.commit` 은 네 칸(물음 · colors 줄 · 지금 색 · 사본)만 쓴다 (test-salon 14 가 잰다).
- **모으기가 되지 않는다**: '입어 본 색 N/6', 색 배지, 빈칸 격자를 두지 않는다. 빈칸이 있으면 '그대로'가 완성을 막는 걸림돌이 된다 (복지 SHOULD 12).

- '대답'을 `VOICE_LABELS` 에 더한다. '미용실'·'몸 색'은 집 행이다.
- 고른 이 꼬리는 늘 단다. 몸 색은 모드가 바뀌어도 남는 결정이다. 나중에 모델이 붙어 '데모' 꼬리표가 사라져도, 데모 시절의 '바꾸기'가 모델의 동의로 읽히면 안 된다 (복지 SHOULD 8).
- 오늘 로그(`#log`)에는 연출 박자에 맞춰 행이 하나씩 붙는다. `renderLog()` 는 `S.salon.asks` 에서 다시 그리고, 산책 행들 사이에 `at` 시간순으로 넣는다. 연출 중인 물음은 지금 박자까지만 그린다 (`salonRun.n`). 두 번 그리지 않는다.
- 한 화면 배치 (11-10)에선 로그가 닫힌 '오늘의 산책' 쪽지(`#log-sheet`) 안에 있다. 행이 붙을 때마다 화면엔 한 줄 알림이 뜬다 ("미용실 · 파란색 어때? 하고 물어봤어." → "대답 · …" → "몸 색 · …", 2.5 s 씩, 넘치면 말줄임) + 오늘 단추의 점. 전문은 쪽지를 열면 있다.
- 결과 문장과 꼬리 사이는 한 칸 띈다 ("색은 그대로야. 데모 규칙" — 알림 · 낭독에서 붙어 읽히지 않게). 픽셀 글꼴에서 라벨 '미용실'(세 글자 48 px)이 44 px 칸에서 꺾이지 않게 미용실 행의 라벨 칸은 48 px · 한 줄이다.
- `dayRows(list)` 에 그날 물음도 넘긴다. `diaryDays()` 는 산책 날짜와 물음 날짜를 합친다. 물음만 있는 날도 앨범 '일기'에 나온다 (기술 SHOULD 6). 날 머리 "· N건" 은 산책 + 물음 수다.
- `status: 'dropped'` 물음(§7.5)은 그리지 않는다(내보낸 기록엔 남는다). 기다리는 물음은 행 1 만.
- 포스터·쪽지·벽·선반에는 아무것도 생기지 않는다.
- 나중 생각: 앨범 맨 위 '몸 색' 작은 칩 줄 (바뀐 기록만 시간순, 빈칸 없음). 지난 날 초상을 그날 색으로 그리기 (`portrait` 의 `color` 옵션이 이미 있다).

### 3.8 화면 낭독기

- `#btn-salon` 은 "미용실"로 읽히고, 장면 설명이 같이 읽힌다.
- 시트: 제목 "미용실" → 병 묶음 "몸 색" → 병 "파랑" / "빨강, 지금 색" / "파랑, 며칠 뒤에 물어볼 수 있어" / "처음 색" → 이름 줄 `role=status` → 단추.
- 결과는 로그 행이 순서대로 읽어 준다(`role=log`, polite). 토스트는 `output aria-live` 그대로다.
- 장면 설명(`#scene-desc`): `SPOT_DESC.salon = '거울 옆'` → "문어는 거울 옆에서 쉬고 있어." 끝에 몸 색 한 마디 "몸은 파란색이야." 를 더한다(`SALON.TEXT.desc`). 이제 색이 문어의 일이 됐으니 못 보는 사람도 안다.

### 3.9 소리 훅

`window.AUDIO && AUDIO.on && AUDIO.on('salon', { act, … })` (app.js 의 다른 훅과 같은 지킴). audio.js 는 모르는 이름을 `default: break` 로 넘기므로 먼저 넣어도 안전하다. 짝은 소리 세션 몫이다 (`audio/README.md` 는 소리 세션 것이라, 이 표는 DELEGATION_BRIEFS 카드 23 에 실었다).

| act | 언제 | 처음 짝 제안 |
|---|---|---|
| `pick` `{ color }` | 병을 골랐다 | `ui_tap` |
| `ask` | [물어보기] | 짧은 줄 소리 |
| `answer` `{ action, by, joy }` | 대답을 보였다 | 없음 (얼굴과 말풍선이 한다) |
| `tub` `{ on }` | 대야가 놓임 / 치워짐 | 나무 쿵 (작게) |
| `splash` | 첨벙 | 새 CC0 첨벙 (없으면 조용히) |
| `done` `{ color, joy }` | 색이 바뀌었다 | `joy` 일 때만 `mood_poljjak` |
| `drain` | 물이 빠진다 | (선택) 작은 물소리 |

- `keep` · 대답 없음 · `joy: false` 에는 기분 징글이 없다. `rare_sparkle` 은 날마다 올 수 있는 일에 쓰지 않는다.
- 장면은 AUDIO 를 부르지 않는다. 박자 알림은 장면의 `on.salon(ev)` 와 `salonDye` 의 `onBeat(ev)` 로 온다: `tub { on }` · `pour` · `splash` · `done { color, joy, skipped }` · `joy` · `drain`. 앱이 위 표의 이름으로 넘긴다. 끝으로 감긴 연출은 남은 박자 알림이 오지 않는다 — 아직 색이 안 바뀐 '바꾸기'면 `done { skipped: true }` 하나뿐이다 (`tub { on: false }` · `drain` 없음). 정리는 `done` 이나 Promise 에 건다.

## 4. 데모 대답 규칙 (1부 — `SALON.demoAnswer`)

```js
SALON.demoAnswer({ dateKey, name, born, asksBefore })
// asksBefore = 이 문어의 끝난 물음 수 (status 'done', 누가 답했든) = SALON.doneCount(state)
if (FIRST_DYE && asksBefore === 0) → { action: 'dye', by: 'demo-rules', rule: 'first', seed: null, line: LINES.dye[0], expr: 'happy' }   // 맨 처음 한 번 — 미용실이 무엇인지 보여 준다
seed   = hashSeed('salon', dateKey, name, String(born || 0))   // BRAIN.hashSeed 와 같은 FNV-1a ('|' 로 이음)
r      = rng(seed)()                                           // mulberry32 첫 값
action = r < P_YES ? 'dye' : 'keep'                            // P_YES = 0.625 (약 5번에 3번)
line   = LINES[action][ floor(rng((seed ^ 0x9e3779b9) >>> 0)() * 3) ]
expr   = action === 'dye' ? 'happy' : 'idle'                   // 데모는 웃는 얼굴 (결정 15). '그대로'는 보통 얼굴
by     = 'demo-rules', rule = 'seed'
```

- **색이 입력에 없다.** 그날 그 문어의 답은 어떤 색을 어떤 길(다른 탭, 내보내기 → 불러오기로 되감기)로 내밀어도 같다. 되감기가 통하지 않는 까닭은 둘이다: 색이 시드에 없고, 같은 문어의 파일을 불러와도 이미 한 물음이 남는다 (§7.4 — 11-11, 검증 W1. 그 전엔 맨 처음 물음 전의 파일을 불러올 때마다 '맨 처음은 꼭 바꾸기' 가 다시 나왔다). 규칙이 색을 보지 않으니 '파랑은 싫어한대' 같은 색 취향 오독도 생길 수 없다 (CURIOSITY_NOTES 원칙 1).
- **안 쓰는 것**: 물어본 횟수(맨 처음 제외) · 지난 대답 · 쓰다듬기·톡 횟수 · 산책·등불·`affinity` · 시각 · 시트를 연 시간 · 병을 몇 번 눌렀는지 · 처음 색인지.
- **'맨 처음'은 `asksBefore` 가 정확히 0 일 때만이다** (그리고 `SALON.FIRST_DYE` 가 켜져 있을 때 — 기본값 true, 주인 확인 전. 11-11 에 이름 있는 상수로 뺐다, 검증 W8. false 면 맨 처음도 시드 길). 수가 없거나 깨졌으면(undefined · null · NaN · 음수 · 글자) 시드 길로 간다. 수를 빠뜨린 호출이 문어의 '그대로'를 지우지 못하게 (1부에서 더한 지킴).
- **확률을 올리지 않는다**: '그대로'가 연달아 와도 다음 날 확률은 같다. 상한을 두면 "계속 물으면 결국 바꿔"를 가르친다. 대신 같은 색 7일 쉼이 '그대로'를 지킨다. 그러니 이 규칙의 '그대로'는 "그 색은 지금은 아니"다 (복지 MUST 5).
- 맨 처음 한 번 '바꾸기'는 데모 규칙의 고르기에만 거는 거르기다(스킬 §7 "데모 규칙은 1–2회차에 stop 을 고르지 않는다"와 같은 선). 모델 메뉴에는 `keep` 이 그대로 있다. 대가: 궁금해서 한 번 물어본 사람도 그날 그 색으로 산다. 다음 날 다시 물을 수 있다.
- **답을 정하는 때**: [물어보기]를 누를 때 계산해 바로 저장한다. 연출은 그다음이라 새로고침에 안전하다.
- **잰 숫자** (위 규칙 그대로, 문어 40 × 365일):
  - '바꾸기' 62.2 %. 문어별로 56.4–67.9 %.
  - 1년 동안 가장 긴 '그대로' 줄은 9번.
  - 줄 3개 고르기는 4898 / 4867 / 4835 로 고르다.
- **시험에 박아 둔 예** (`asksBefore = 1`, test-salon 2):

| dateKey | name | born | 답 | r | seed | 줄 |
|---|---|---|---|---|---|---|
| 2026-11-09 | 뚜루 | 1762600000000 | keep | 0.7523 | 3922112899 | 이대로 있을래. |
| 2026-11-10 | 뚜루 | 1762600000000 | keep | 0.9416 | 478326885 | 안 바꿀래. |
| 2026-11-11 | 뚜루 | 1762600000000 | dye | 0.0150 | 3404652688 | 그래, 바꿔 볼래. |
| 2026-11-09 | 안개 | 1762650000000 | keep | 0.8623 | 2079199854 | 지금 색 그대로 있을래. |
| 2026-11-12 | 삐죠 | 1762700000000 | dye | 0.5729 | 4065987748 | 그래, 바꿔 볼래. |

## 5. 문구 (1부 — `SALON.LINES` · `SALON.TEXT` · `SALON.TAILS`)

모두 KS X 1001 음절이라 서브셋을 다시 만들 필요가 없다(서브셋이 2,350자를 다 담는다). 아래 두 정규식에 0건이다 (test-salon 6 이 잰다).
- 취향어 (`test-model-voice`): `/좋아|좋았|사랑|싫어|싫었|미워|최애|취향|즐겨|반했|단골|그리워|설레/`
- 압박어: `/예쁘|어울|귀엽|원해|원하|해 줘|해줘|부탁|제발|한번만|한 번만|기대|실망|아쉬|미안|섭섭|서운|슬퍼|속상/`

집 목소리 글은 전부 `SALON.TEXT` 에 있다. 앱은 거기서 가져다 쓰고 글을 따로 짓지 않는다. 단 시트의 글자 넷 (제목 '미용실' · 병 묶음 이름 '몸 색' · [물어보기] · [닫기]) 은 `index.html` 에 글자로 적혀 있고 앱은 `TEXT.sheet` · `group` · `ask` · `close` 를 읽지 않는다 (검증 11-10 W9) — 둘이 같은지는 스모크 Y 가 화면 글자를 `SALON.TEXT` 와 견주어 본다 (11-11).

**문어 목소리 (데모 규칙만, '데모' 꼬리표 아래)**

| 쓰임 | 글 | 왜 정직한가 |
|---|---|---|
| 바꾸기 (3개 중 시드, 맨 처음은 첫째) | "응, 해 볼래." · "그래, 바꿔 볼래." · "이 색 해 볼래." | 결정만 말한다. 이유('예뻐서')·느낌('좋아')·사람 칭찬을 규칙이 짓지 않는다 |
| 그대로 (3개 중 시드) | "이대로 있을래." · "지금 색 그대로 있을래." · "안 바꿀래." | 결정만 말한다. '오늘은'을 뺐다. '오늘은'은 '아니'를 '아직 아니'로 만들고, 게임 규칙을 문어의 약속처럼 입에 넣는다 (복지 SHOULD 3). 미안·다음엔 꼭·슬픈 말이 없다 |

거울이 생긴 날 문어 목소리 줄은 **없다** (복지 MUST 7). 기존 `ITEM_LINE` 8줄도 같은 문제가 있었다(규칙이 지은 줄이 모든 모드에서 문어 입으로 나왔다). 11-08 부터 등불 칸 소품 줄('방')은 집 목소리 사실 문장이다 (OWNER_DECISIONS 11-08 밤 '같이 바뀐 것').

## 6. 모델 프로토콜 (1부: 순수 함수만 · 연결은 나중)

v1 코드에는 모델 길을 넣지 않는다. 저장소에 MCP 서버가 없다 (기술 SHOULD 5). `SALON.request()` · `SALON.CONTEXT` · `SALON.readReply()` · `SALON.look()` 은 순수 함수로 만들고 시험했다 (1부). 실제 연결(카드 9)이 생길 때 아래대로 잇는다. 같은 내용을 `docs/PROTOCOL.md` §5 에 '계획'으로 옮겨 적었다.

**결정 지점 `salon`**: 물음 하나에 요청 한 번이다. 받은 답은 다시 묻지 않는다.

**요청** (작게, 약 180 B, 상한 400 B):

```jsonc
{ "v": 1, "point": "salon", "id": "ask_k7x2q",
  "facts": { "now":   { "hex": "#e8463c", "name": "빨간색" },
             "offer": { "hex": "#4a86d8", "name": "파란색" } },   // 처음 색이면 name "처음 색"
  "menu": ["keep", "dye"] }                                      // keep(아무것도 안 바꿈)이 늘 첫째
```

- 이름(`name`)은 늘 색 값과 병 종류에서 다시 짓는다. 저장된 `offerName` 글을 싣지 않는다 (불러오거나 손댄 기록의 글이 요청에 들어가지 않게 — 요청은 사실만).

**고정 문맥** (도구 설명·시스템에 한 번, 캐시, `SALON.CONTEXT`):

> 미용실: 사람이 색 하나를 골라, 네 몸을 그 색으로 바꿔 볼지 물었어. 그대로 두려면 keep, 바꾸려면 dye. 바꾸면 다음에 또 바꿀 때까지 그 색이야. 이유는 안 써도 돼. 한마디(line)와 얼굴(expr: idle, happy, curious, calm)은 골라도 안 골라도 돼. line 은 24자쯤이 말풍선에 맞고, 넘으면 말풍선엔 앞부분과 '…', 기록엔 전부 남아. 어느 쪽이든 게임에서 잃는 건 없어.

- 결과가 오래 간다는 사실을 넣었다. '해 볼래'·'바꿔 볼지'가 잠깐 입어 보는 것처럼 들리지 않게 하려는 것이다 (복지 SHOULD 5).
- 하루 한 번 규칙 · 7일 쉼 · 마감은 넣지 않는다. "사람이 하루 기다려야 해"라는 죄책을 만들지 않으려는 것이다.

**보내지 않는 것**: 이유 칸(`reason` · `why`) · 압박 말('예쁠 거야' · '사람이 원해' · '한 번만' · '어제 안 했잖아') · 지난 대답·거절 횟수 · `P_YES` · 연출 설명 · 배지·조개.

**답**:

```jsonc
{ "action": "keep" }                                        // 이것만으로 충분
{ "action": "dye", "line": "파랑, 한번 해 볼게", "expr": "happy" }
```

| 받은 것 | 하는 일 (`SALON.readReply`) |
|---|---|
| `action` 이 `dye`/`keep` (대소문자 · 앞뒤 공백 무시, PROTOCOL 의 숫자 글 "1" 받기와 같은 선). JSON 없이 메뉴 낱말 하나만 와도 받는다 | 그대로 따른다 |
| `action` 이 그 밖 (`"no"`, `"그냥 둘래"` 등) | **다시 묻지 않는다.** 색은 그대로, `action: null`, `actionRaw` · `raw` 에 원문, `by: 'model'`. 행 3 "색은 그대로야." 말이 있으면 보인다. 7일 쉼은 걸지 않는다 |
| JSON 이 아님 (빈 글 · 빈칸만 있는 글 포함 — 답은 왔다) | 다시 묻지 않는다 (`unreadable`). 행 3 "답을 못 읽었어. 색은 그대로야." `raw` 에 원문 |
| 아무것도 안 옴 (null · 전송 실패, `empty`) | 같은 요청을 **한 번만** 다시 보낸다(`sent: 2`). 또 실패면 기다림으로. 다시 보낼 대상은 이것 하나다 |
| `line` | 선택. 글자 그대로. 말풍선은 앞 24글자(사람이 보는 글자) + '…', 로그 행·기록은 전문. **없으면 문어 행이 없다** |
| `expr` | 선택. `idle` · `happy` · `curious` · `calm`. 모르는 값은 `expr: null` + `exprRaw`. `calm` 이 '-_-^'로 읽히는 건 그림을 고칠 일이지 고른 표정을 바꿀 일이 아니다 |
| `action` 과 `line` 이 어긋남 (`dye` 인데 "싫어") | `action` 을 따르고 `line` 은 고치지 않는다 |

결과가 '바뀜'과 '그대로' 둘뿐이라, 받은 답을 다시 물어 달라질 수 있는 건 '그대로 → 바뀜' 하나다. 그래서 다시 묻기는 코드가 대신 조르는 셈이다 (복지 MUST 3). 일반 규칙(스킬 §5 "틀리면 한 번만 다시")보다 이 판단이 앞선다.

**기다림** (복지 SHOULD 6): sampling 클라이언트는 사람이 요청을 보고 승인하는 경우가 많다. 8 s 를 넘기면 '…' 생각 말풍선만 거두고, 물음은 `status: 'waiting'` 으로 **그날 자정까지** 남는다. 그사이 답이 오면 반영한다. 다락이 보이고 문어가 집에 있으면 연출하고, 아니면 조용히 반영하고 행만 남긴다. 자정이 지나면 `{ status: 'done', action: null, by: 'fallback' }` 으로 닫는다(행 3 "대답이 없었어. 색은 그대로야."). 늦게 온 답은 `lateRaw` 에 남기고 반영하지 않는다. 기록에는 `via: 'sampling' | 'tool'` 을 남긴다.

**도구** (카드 9 MCP 서버):

| 붙는 곳 | 도구 | 입력 | 출력 |
|---|---|---|---|
| sampling 이 되는 곳 | 서버가 sampling 으로 위 요청을 보낸다 | — | `{ action, line?, expr? }` |
| 도구 호출만 되는 곳 | `ppolppol_salon_next` | `{}` | `{ situation }` 또는 `{ waiting: true }` |
| 도구 호출만 되는 곳 | `ppolppol_salon_answer` | `{ id, action, line?, expr? }` | `{ ok: true, result: 'changed' \| 'unchanged' }` 또는 `{ ok: false, reason: 'stale' \| 'unknown_id' }` (`unknown_action` 같은 다시 묻기 신호는 없다) |

**`ppolppol_look_room` 에 더할 것** (`SALON.look(state, { salon })` 이 그대로 만든다):

```jsonc
"look": { "now":   { "hex", "name" },
          "first": { "hex", "name", "by" },                          // by: player | default | migrated (처음 줄이 없으면 null)
          "changes": [ { "date", "to": { "hex", "name" }, "by" } ] }  // 최근 5
// 달라고 할 때만 ({ salon: true }): "asks": [ { "date", "offer": { "hex", "name" }, "action", "by" } ]  // 끝난 물음 최근 5, '그대로'도
```

- `by` 는 원래 값 그대로다(`player` / `default` / `migrated` / `demo-rules` / `model` / `human` / `dev` / `unknown`).
- 글로 풀 때는 `SALON.BY_TEXT` 를 쓴다: `demo-rules` 는 "데모 규칙이 고름", `migrated` 는 "미용실 전에 사람이 설정에서 고른 색(또는 기본값)"이다. **모델이 고르지 않은 변화를 '네가 골랐어'라고 하지 않는다.**
- 산책 요청(`depart`)에는 몸 색을 싣지 않는다. 정체성 딱지가 되지 않게.
- 물음 목록은 기본으로 보내지 않는다(보관 메모와 같은 선). 모델이 자기 '그대로'를 보고 싶을 때 볼 수 있다 (복지 SHOULD 7).

**서버가 지킬 것**: 모델 대신 답하지 않는다. 받은 답을 다시 묻지 않는다. `keep` 뒤에 다른 색을 이어서 내밀지 않는다(하루 한 번). 대답을 다른 데(취향·추천)에 쓰지 않는다. PROTOCOL 에는 sampling 에서 사람이 요청을 보고 고치거나 답을 막을 수 있다는 점을 적는다. 화면은 '모델이 고름'보다 더 확신하지 않는다.

**나중 (주인 확인 뒤, 사람이 고를 것은 늘리지 않는다)**: 지금 모델이 가진 건 거부권뿐이다 (복지 SHOULD 13).
- 메뉴에 `pick` 을 더해 병 가운데 다른 하나를 문어가 직접 고르게 한다(`facts.bottles`, 데모 규칙은 쓰지 않음).
- 모델이 먼저 자기 색을 바꾼다.
- '당분간 묻지 말기' 깃발.
- 모델이 처음 붙을 때 한 번 '그대로 / 고르기'를 물을지.

규칙 쪽 (`SALON.normalize` · `commit` · `merge`) 은 1부, 앱 쪽 (`defaults` · `load` · 이름 저장 · 불러오기 · 초기화 · 다른 탭) 은 2부다.

```js
S.octopus.color  = '#4a86d8'           // 지금 몸 색. 읽는 곳은 이것 하나 (장면 · 초상 · 달리기 · 장면 설명 · 미용실)
S.octopus.colors = [                   // 바뀐 기록, 오래된 것부터

S.salon = { asks: [ {
  id: 'ask_k7x2q', date: '2026-11-09', at: 1762651800000,   // date = 로컬 dateKey (하루 한 번 규칙은 이것만 본다)
  from: '#e8463c', offer: '#4a86d8', offerName: '파란색', offerKind: 'preset',   // offerKind: preset | first · offerName 은 늘 색 값에서 다시 짓는다
```

### 7.1 `defaults()` (2부)

`octopus.color = '#e8463c'`, `octopus.colors = []`, `salon = { asks: [] }`, `settings.octColor = '#e8463c'` (사본).

### 7.2 `normalize()` (옮기기, 1부 `SALON.normalize(s, { todayKey })` 를 app.js 가 부른다)

1. `colors`: 배열이 아니면 `[]` 다. 색이 `#rrggbb`(소문자로 맞춤)이고 `how` 가 first · salon · dev 인 줄만 남긴다. 모르는 `by` 는 `'unknown'` 으로 둔다(진짜 고른 이로 올려 주지 않는다). `at` 순으로 둔다 (`at` 이 없는 줄은 앞으로). `at` · `date` 가 깨졌으면 null, `ask` 가 글이 아니면 뺀다.
2. `octopus.color`: `colors` 가 있으면 **그 마지막 줄의 색** (11-11, 검증 W3 — 그 전엔 유효한 `octopus.color` 를 그대로 믿어서, 내보낸 파일에서 `color` 한 칸만 고치면 기록 없는 색이 됐다. 놀이 중엔 늘 둘이 같다). `colors` 가 비었으면 `octopus.color` → `settings.octColor` → `'#e8463c'`. 그다음 `settings.octColor = octopus.color`.
3. `colors` 가 비었는데 놀던 기록(이름이나 trips)이면 `{ how: 'first', by: 'migrated', color: octopus.color, at: born || null, date: null }` 한 줄. v1 옮기기 결과도 여기를 지난다.
4. `salon`: 객체가 아니면 `{ asks: [] }`. 물음 줄은 `id` 글 · 날짜(달력에 있는 `YYYY-MM-DD`) · `from`/`offer` 가 `#rrggbb` 가 아니면 버린다. 같은 id 는 처음 것만. `status` 모르면 'done', `action` 이 dye/keep 이 아니면 null (원문은 `actionRaw`), `by` 모르면 'unknown', `expr` 가 넷 중 하나가 아니면 null (원문은 `exprRaw`). `offeredBy` 모르면 'unknown'. `rule` 은 demo-rules 일 때만, `seed` 는 rule 'seed' 이고 uint32 일 때만. `offerName` 은 색 값에서 다시 짓는다. `line` · `actionRaw` · `raw` · `lateRaw` 는 문자열이면 **한 글자도 안 바꾼다**(이모지 포함).
5. 오늘보다 앞선 `waiting` 은 `{ status: 'done', action: null, by: 'fallback' }` 으로 닫는다(색 그대로). `todayKey` 는 키나 키를 주는 함수다.
6. 같은 날 그날 물음이 둘 이상이면 이른 것이 정한다 (§7.5 와 같은 규칙, `settle`).
7. 새 기록(이름 없음)은 `colors: []` 그대로 두고 첫 실행 창이 첫 줄을 넣는다.
8. 'dye' 물음인데 `colors` 에 그 `ask` 줄이 없어도 지어내지 않는다(한 번에 쓰므로 생기지 않아야 한다).
9. 미용실 색 줄 (`how: 'salon'`) 의 `by` 는 그 물음이 뒷받침할 때만 남긴다 (11-11, 검증 W4): 같은 id 의 끝난 'dye' 물음이 있고 고른 이 · 색이 같아야 한다. 아니면 `by: 'unknown'` (줄과 색은 그대로 — 지어내지도 지우지도 않는다). 손으로 써 넣은 `{ how: 'salon', by: 'model' }` 줄을 `look()` 이 모델이 고른 변화로 알리지 않게. 놀이가 쓰는 줄은 늘 물음과 함께 적히니 (`commit` · `merge`) 바뀌지 않는다 — 물음 기록을 잘라 내는 일이 생기면 이 줄도 같이 봐야 한다. 반대쪽은 이번에 손대지 않았다: 색 줄 없는 끝난 'dye' 물음은 가려낼 수 있지만 그대로 두고 (위 8 — 행 3 꼬리와 `look({ salon: true }).asks` 는 그 물음의 `by` 를 그대로 보인다), 지어낸 'keep' 물음은 가려낼 길이 없다.

### 7.3 한 번에 쓰기

데모 답은 [물어보기] 순간 물음 한 줄 + ('dye'면) colors 한 줄 + `octopus.color` + `settings.octColor` 를 `SALON.commit` 이 쓰고 앱이 `save()` 한 번으로 저장한다. 같은 id 를 다시 쓰면 바꿔 쓴다(두 번 적지 않는다). 장면만 연출 끝까지 옛 색이다.

### 7.4 내보내기 · 불러오기 · 초기화 (2부)

JSON 그대로 나간다. 들어올 때는 §7.2 를 지난 뒤, **같은 문어 (`octopus.born` 이 같다) 의 파일이면 이 기기에서 이미 한 물음을 남긴다** (11-11, 검증 W1): `importJSON` 이 `SALON.merge(지금 기록, 불러온 기록, 지금 기록의 물음 전부)` 를 `now` 없이 부른다 (60 s 제한 없음 · §7.5 와 같은 규칙 — 파일에 없는 물음은 colors 줄과 함께 다시 얹고 몸 색은 마지막 줄, 같은 날 둘이면 이른 것). 그 전엔 묻기 전에 내보낸 파일을 다시 불러오면 그 물음이 사라졌다: '그대로' 와 그 색의 7일 쉼이 없어지고, 맨 처음 물음 전의 파일이면 '맨 처음은 꼭 바꾸기' 가 몇 번이고 다시 나왔다. 산책 · 등불 · 살림은 예전처럼 파일의 것으로 바뀐다 (물음만 남는다). 다른 문어의 파일은 그대로 들어온다 (전체 초기화 뒤의 불러오기 포함 — 여기는 막지 못한다). 화면 글은 그대로다 ('기록을 불러왔어'). 옛 내보내기(`settings.octColor` 만 있음)는 §7.2 로 옮겨진다. 불러온 뒤 `applyLook({ still: true })`. 모델 말은 원문 그대로다. 불러온 `offerName` 글은 믿지 않는다 (§7.2 의 4). 전체 초기화는 `defaults()` → 첫 실행 창(몸 색 포함), 물음 기록도 빈다.

### 7.5 다른 탭

- [물어보기] 순간 저장소를 다시 읽어 합친 뒤 `canAsk` 를 본다. 다른 탭이 오늘 이미 물었으면 묻지 않는다.
- 이 탭이 쓴 물음은 60 s 동안 기억한다(`mineAsks`, `SALON.MINE_MS`, 산책의 `mine`/`carry` 와 같은 생각). 받은 기록에 빠져 있으면 물음과 colors 줄을 다시 얹고 저장한다. 다른 문어(`born` 이 다름)의 기록이면 내 물음은 버린다.
- 같은 날 끝난 물음이 둘 이상이면 **그날 첫 물음(`at` 가장 이른 것)이 정한다.** 나머지는 `status: 'dropped'` 로 남기고 적용하지 않는다. 그 colors 줄은 빼고 `octopus.color` 를 다시 정한다 (복지 MUST 4 가).
- 받은 쪽에 같은 물음이 아직 `waiting` 이고 이 탭 것은 끝났으면(`done`) 이 탭 것으로 바꾼다 — 모델 답을 받은 뒤 다른 탭의 옛 저장이 와도 그 답을 잃지 않게. 그 밖엔 받은 쪽 것 그대로다 (dropped 라도).
- `SALON.merge(local, remote, mine, now)` → `{ state, changed, readded, upgraded, dropped, mine }`. `changed` 면 앱이 `save()` 한다. `adoptRemote` 뒤 `applyLook({ still: true })` 를 부른다(연출 중이면 끝난 뒤).

### 7.6 크기

물음 한 줄은 약 300 B 라 하루 한 번이면 1년에 약 110 KB 다. 쿼터를 넘으면 저장 사본에서만 1년 넘은 물음의 `seed` · `raw` 를 뺀다. `line` 은 절대 안 뺀다.

## 12. 처음 색은 누가 고르나

사람이 처음 한 번 고르는 방식을 유지한다.
- 주인이 "처음에 선택한 이후로는"이라고 직접 말했다.

조건:
- 장면 문어를 미리 칠하지 않는다(§1.1).
- 기록은 `player`/`default` 로 남기고, 어디서도 '문어가 고른 색'·'원래 색'이라고 말하지 않는다.
- 모델은 방 보기의 `first.by` 로 사람이 골랐다는 걸 볼 수 있다.

## 14. 코드가 스펙과 다른 곳 (코드가 맞다)

### 14.1 1부

스펙을 쓴 뒤 1부를 만들며 다르게 정한 것이다. 대부분은 지킴을 더 엄하게 한 것이고, 숫자는 화면에서 재고 고쳤다. 본문은 이미 코드 값으로 고쳤다.

**규칙 모듈 (`js/salon.js`)**
- **병은 날짜가 있어야 고를 수 있다.** `bottles(state, today)` 에 날짜를 못 읽으면 쉬는 색을 알 수 없으니 모든 병이 `selectable: false` 다. `canOffer` · `canAsk` 도 날짜를 못 읽으면 `no_date` 로 막고, `makeAsk` 는 null 을 돌려준다 (미용실은 날짜 없이 열리지 않는다). 쉼도 날짜가 바른 '그대로'만 센다.
- **고른 이를 모르면 몸 색을 못 바꾼다.** `makeAsk` 는 답의 `by` 가 demo-rules · model · human · fallback 일 때만 물음을 만든다. 'unknown' 은 옛 기록 옮기기(`normalize`)에서만 붙는다. 사람(개발용) 답은 결정만 남기고 말 · 얼굴을 버린다. 기다림 · fallback 은 결정도 말도 얼굴도 없다.
- **`offerName` 은 늘 색 값에서 다시 짓는다.** 요청 · 로그 행 · 방 보기 · 옮기기 모두 저장된 글을 믿지 않는다. 불러오거나 손댄 기록의 글이 모델 요청이나 집 목소리 행에 들어가지 않게 (요청은 사실만).
- **말이 없는 고른 이는 손댄 기록에 말이 있어도 문어 목소리로 안 보인다.** `rows` 는 human · fallback 의 `line` 을 그리지 않는다. `staging` 도 그들에겐 얼굴 idle · 기쁨 없음 · 말풍선 없음이다.
- **'맨 처음'은 `asksBefore === 0` 일 때만.** 수가 없거나 깨지면 시드 길이다 (수를 빠뜨린 호출이 '그대로'를 지우지 못하게).
- **빈 글 답은 '못 읽음'이다.** 답은 왔으니 다시 묻지 않고 원문을 남긴다. 다시 보낼 대상(`empty`)은 아무것도 안 온 null 하나다. JSON 없이 메뉴 낱말만 온 답(`dye`)은 받는다.
- **말풍선 24자는 사람이 보는 글자로 센다** (`Intl.Segmenter`, 없으면 코드 포인트 — 대리 쌍을 쪼개지 않는다).
- **`commit` 이 같은 날 두 물음을 바로 정리한다** (`settle`: 이른 것이 정하고 dropped 물음의 colors 줄을 뺀다). `normalize` 도 같은 정리를 한다. 같은 id 는 두 번 적지 않는다. 옮기기에서 같은 id 물음은 처음 것만 남긴다.
- **`merge`** 는 `now` 를 받아 60 s 지난 내 물음을 놓고, 다른 문어(`born` 이 다름)면 내 물음을 버린다. 받은 쪽이 기다리는 중인데 이 탭 것이 끝났으면 이 탭 것으로 바꾼다 (`upgraded`).
- **더한 함수 · 상수**: `canOffer` · `humanAnswer` · `staging` · `bubble` · `dateKey` · `addDays` · `firstColor` · `doneCount` · `isPreset` · `TEXT` · `TAILS` · `BY_TEXT` · `DEFAULT_COLOR` · `FIRST` · `MIRROR_LEVEL` · `MINE_MS`. `restingUntil` 은 세 번째 인자 `today` 를 받는다. `canAsk` 이유에 `no_date` 가 있다. `look` 의 `first` 는 처음 줄이 없으면 null 이고, `asks` 는 끝난 물음만 싣는다.
- **무채색 이름**: 프리셋이 아니고 채도가 거의 없는 색은 흰색 · 회색 · 검은색으로 부른다 (색상 띠만으로는 이름이 틀렸다).

**장면 (`js/scene3d.js` · `js/scene2d.js`)**
- **거울을 내리고 왼쪽으로 옮겼다**: 스펙 가운데 x −1.40 · 아래 y 0.62 · 위 ≤ 1.44 → 1부 x −1.48 · 아래 0.45 · 위 1.27. 등불 7칸 선반과 그 받침(x −0.95)이 화면에서 아치를 덮었다. 선반도 따라 내려 윗면 0.42 → 0.25, 폭 0.70 → 0.66 (왼쪽 샛기둥과 띄움). T6 이 등불 8칸에서 아치 둘레 2 아트px 까지 가림 0 을 잰다. 2D 는 스펙 높이 그대로다.
- **'처음 색' 병은 선반 오른쪽 옆 바닥**에 내밀 때만 보인다 (선반엔 일곱째 칸이 없다).
- **코르크는 메시 B** (`basicV`, 밤엔 한 칸 어둡게). 스펙은 메시 A 였다.
- **거울 속 문어는 ±0.08 안에서 반만 따라간다** (스펙 ±0.12). r 0.14 원이 유리 0.44 안에 다 들게.
- **밤 판정은 시각대 `em` ≥ 0.9** (노을 0.8 은 낮처럼). 밤 유리는 남색으로 진짜 창 유리보다 어둡게, 대야는 거꾸로 밝은 나무 칸으로 (검은 솥처럼 안 보이게).
- **대야가 놓이는 첫 칸부터 맑은 물**이 있다 (빈 대야 안이 검은 구멍처럼 보였다).
- **팔레트 덧칸**은 코너가 보일 때만, 보라 한 칸 + 청록 쪽으로 6° 돌린 초록 한 칸 (밤엔 초록 밤 톤 하나 더). 그냥 초록은 낮 화분·이끼 픽셀을 훔쳤다.
- **물 원판 r 0.225 + 1px 테(0.262)** (스펙 r 0.26 한 장).
- **`salonDye` 옵션과 알림**: `{ joy, look, pause | id, onBeat }` → `{ ok, skipped, color }`. 박자 알림 `tub` · `pour` · `splash` · `done` · `joy` · `drain` (장면은 AUDIO 를 안 부른다). 끝으로 감기면 남은 알림 없이 `done { skipped: true }` 하나 (색이 아직이면).
- **`salonOffer` 는 연출 중엔 안 받는다.** 반짝은 4칸 @12 fps (폰에서 2칸은 놓쳤다).
- **`ponder` 는 모션 줄이기면 움츠리지 않는다** (앱이 그만큼 멈춤만).
- **`motion().salon`** 에 스펙보다 칸이 많다 (`visible` · `open` · `bottle` · `active` · `waterK` · `splash` · `tint` · `look` · `extra` · `geom`).
- **드로우콜 실측** 76 → 82 → 88 (등불 2 낮: 기준 → 거울 앞 → '바꾸기' 중 최대), 셰이더 27 그대로.

### 14.2 2부 · 합친 뒤 (11-10)

2부는 옛 화면에서 만들었고, 11-10 에 지금 게임에 합친 뒤 독립 검증에서 맞춰 고쳤다.

**스펙 그대로 들어간 것 (문서 쓸 때 코드가 없어 짐작으로 적었던 여섯 가지 — 지금 코드와 맞춰 봄)**
- 연출 중 톡 · 낮잠: `tapOct` · `pet` · 창문 톡은 연출 중이면 아무것도 안 한다 (톡 한 줄 · '쿨쿨…' · 깨우기 없음). 깨어 있는 틈이 연출 중에 끝나도 눕지 않고 (`lieDown` 이 0.7 s 마다 다시 본다), 스스로 깨기 · 다른 탭의 쉬는 차례 맞춤(`syncRest`)도 연출 뒤로 미룬다.
- 소리 호출: `salonSound(act, extra)` 하나가 `window.AUDIO && AUDIO.on` 을 보고 `AUDIO.on('salon', { act, … })` 를 부른다 (§3.9 의 이름 그대로: `pick` · `ask` · `answer` · `tub` · `splash` · `done` · `drain`).
- 앵커 대체: 등불 2칸 전엔 `anchorName('salon')` 이 `'center'` 다. 거울이 생기면 돌아다니는 곳에 `salon` 이 더해진다.
- 달리기 색: `js/runner.js` 는 `octopus.color` 를 먼저, `settings.octColor` 를 다음으로 읽는다.
- id 와 개발용 깃발: `#btn-salon` · `#salon-sheet`. 개발용 칸 둘('바로 바꾸기' · '다음 미용실 대답')은 `DEV_EXPLICIT` 일 때만 (file:// · localhost 자동 개발 모드로는 안 보인다).
- 스모크 글자: 미용실 `Y` · 첫 실행 몸 색 `O` 의 둘째 묶음 · 설정 `S` (§9.3).

**지금 게임에 맞춰 달라진 것**
- **설정 시트 순서**: 맨 위는 문어 선물 상자다. 문어 색 칸은 그 아래 · '내 모습' 위 (스펙은 맨 위).
- **한 화면 배치**: 장면이 화면을 다 쓰고 시트가 그 아래쪽을 덮는다. 옛 화면의 '장면을 화면 안으로 굴리기' (`window.scrollBy`) 는 위아래 배치(2D 폴백)에서만 뜻이 있다. 한 화면 배치에선 밀어 둔 화면을 필요할 때만 기본 구도로 되돌린다 (§3.2).
- **로그는 닫힌 쪽지 안**: 행은 박자대로 붙지만 화면엔 한 줄 알림으로 보인다 (§3.7). 대답 행의 알림은 말풍선과 같은 말을 한 번 더 보여 준다 (새 줄 알림 규칙 그대로 둠).
- **손가락 톡으로 연 시트가 바로 닫히던 결함**을 고쳤다 (§3.2). 옛 검사는 마우스로만 재서 못 잡았다.
- **내 캐릭터** (기본값 — 주인 확인 전): 연출은 캐릭터 걷기로 끊기지 않는다 · 캐릭터는 문어의 길을 막지 않는다 (장면이 비켜 세운다) · 연출 중엔 문 · 계단으로 방을 옮기지 않는다 · 놀이방에서는 물을 수 없다 (문어가 없는 방). 11-11 이사 뒤로 미용실은 위층에 있고, 위층에서 비켜서기는 §2 의 11-12 줄이 맞다 (그 전엔 다락에서만 비켜섰다).
- **가구 배치** (기본값 — 주인 확인 전): 배치 중엔 거울 단추가 숨는다. 거울이 있으면 코너 바닥 (x −2.5 … −0.75 · z −2.5 … −0.6: 문어 자리 · 대야 자리 · 거울 앞) 엔 소파 · 상자 · 담요를 놓을 수 없다 (`SAL_KEEP`, 문 앞을 비워 두는 것과 같은 규칙). 이미 그 안에 놓여 있던 가구는 그대로 둔다.
- **재봉틀과 미용실은 따로**: 위층 옷방 재봉틀(`#sew-sheet`)은 내 캐릭터의 옷 색(`S.user.dye` → `scene.setPlayerDye`)을 조개 · 염료로 바꾼다. 문어 몸 색(`octopus.color`)은 미용실의 물음으로만 바뀐다. 서로의 기록을 건드리지 않는다 (스모크 Y 가 잰다). 미용실은 조개 · 씨앗 · 염료를 주지도 쓰지도 않는다.
- **장면 설명**: ~~위층 옷방에선 아직 다락의 설명 글이 그대로 읽힌다.~~ 11-12: 위층이면 위층 · 문어가 있는 층을 말한다 (§2).
- **연출 길이**: 느린 기기(프레임이 초당 몇 장)에선 장면 박자가 늘어져 지킴이(예상 길이 × 속도 + 4 s)가 끝 상태로 감는다 — 색 · 행은 같다. 프레임이 빠지지 않을 때의 길이 (11-10 실측 — 페이지 시계를 0.1 s 씩 밀어 잼): '바꾸기' 는 [물어보기] 뒤 0.3 s 행 1 · 1.8 s 대답 · 2.2 s 걷기 시작 · (방 가운데에서) 4.4 s 거울 옆 도착 · 4.5 s 대야 · 6.3 s 쯤 첨벙 (둘째 칸에서 새 색) · 9.2 s 쯤 끝 (붓기 전 멈춤이 물음마다 0.3 ~ 0.6 s 라 그만큼 다르다). 창가에서 물으면 3.8 s 도착 · 8.7 s 쯤 끝. '그대로' 는 1.8 s 대답 · 3.4 s 병 제자리 · 3.9 s 끝 (대야 · 걷기 없음).
