# 방 넓히기 — 합친 설계

> 2026-11-05. 설계안 두 개를 심사해서 하나로 합쳤다. 설계 1은 '그 순간과 마음'을, 설계 2는 '360px 폰에서 실제로 만들 수 있는가'를 봤다.
> **뼈대는 설계 2**에서 가져왔다: 옆방을 세 번째 장소로 붙이기, 저장, 엔진, 시험. **순간은 설계 1**에서 가져왔다: 포스터를 못 걸고 벽을 두드리는 장면, 같이 천 걷기, 넘친 포스터를 보이게 치우기, 조르지 않기. 무엇을 고르고 뺐는지는 맨 끝 부록에 있다.
> 코드는 고치지 않았다. 줄 번호 대신 **함수 이름**으로 적었다(다른 세션이 같은 파일을 고치는 중).
> 바탕: 주인 결정(11-05), 폰으로 해 본 뒤 피드백(11-05, 가장 새것이 이김), NIGHT_LOG 결정 10~19, MODEL_VOICE, CURIOSITY_NOTES, 스킬 '중요' 4규칙과 model-voice-and-play.md, 이미 합친 문서 CORE_LOOP_V2 · INTERIOR_MODE · PLAYER_PROGRESSION · ACHIEVEMENTS, 코드 사실 조사(HEAD d57573c).
> **브리프보다 새 결정을 따른 곳**
> - 결정 15: 안내는 **안내 NPC**가 맡는다. 이 문서의 '집 쪽지'는 안내 NPC가 들고 오는 쪽지다.
> - INTERIOR_MODE(이미 합침): 포스터 자리 이름(`attic:board.0`), 저장 모양(`layout.place`), 한 손가락 밀기 = 화면 밀기. 이 문서는 그 위에 얹는다.
> - ACHIEVEMENTS: 방 넓히기는 가게에서 팔지 않는다. 사람 가구는 넓히기로 생긴 자리에 놓는다.

예문 속 '뚜루'는 네가 지은 문어 이름이 들어갈 자리다.

## 1. 한 줄 요약

**다락이 다 꾸며지고 벽까지 꽉 차면, 문어가 포스터를 들고 와서 걸 데를 못 찾는다. 옆벽을 똑똑 두드리고 너를 돌아본다. "넓혀 보자"를 누르면 문어가 뚝딱뚝딱 작은 구멍을 내고 천으로 덮는다. 다음 날 아침 둘이 같이 천을 걷으면 옆방이 있다. 문어가 폴짝 뛰고, 집 쪽지가 뜬다. "이제 더 많이 포스터 걸자!"**

- 다락은 키우지 않는다. 옆방은 **바깥 마당처럼 따로 그리는 세 번째 장소**다. 그래서 픽셀 크기가 그대로다.
- 다락과 옆방은 화면 끝 ◀ ▶ 버튼, 벽 구멍 톡, 화면을 옆으로 끝까지 밀기로 오간다.
- 계기는 **사실 둘**(다락 등불 8칸, 보드 6칸이 꽉 참)이다. 친밀도·코인·조개·남은 시간은 없다.
- 산책을 많이 보내도, 같이 가도, 공사를 구경해도 **빨라지지 않는다.**

## 3. 흐름

### 3.1 언제 오나

넓히자는 제안은 아래가 **모두** 맞는 귀가에서만 온다.

| 조건 | 뜻 |
|---|---|
| 다락 등불 8칸이 다 켜졌고, **그날이 지났다** | 다락이 다 꾸며졌다. '다락 완성'과 '넓히기'가 같은 날 겹치지 않는다. 등불이 하루 1칸이라 빨라도 **9번째로 노는 날** |
| 다락 보드 6칸이 다 찼다 | 누가 걸었든 센다. 집에 있던 날 쪽지도 센다. 네 물건과 '네 자리'는 안 센다 (CORE_LOOP_V2) |
| 새 포스터(집에 있던 날은 쪽지)를 걸려는데 칸이 없다 | 숫자가 아니라, 갈 데 없는 종이 한 장이 신호다 |
| 공사 기록이 없고, 열린 제안도 없다 | 한 번에 하나 |
| 오늘 아직 묻지 않았다 | 하루 한 번까지 |
| 문어가 '넓히자'를 골랐다 | 데모 규칙은 늘 고른다. 모델은 안 고를 수 있다 (§3.6) |

- 산책 횟수는 상관없다. 등불이 하루 1칸이라 하루에 열 번 보내도 빨라지지 않는다.
- 같이 가기·집에서 기다리기 어느 쪽을 골라도 같다.
- 조개로 살 수 없다. 화면 어디에도 "넓히기까지 N" 같은 줄이 없다.
- 이미 등불 8칸인 옛 저장은 다음 '칸 없는 귀가'에서 바로 제안을 받는다.

### 3.3 제안: 대화 상자 두 줄

**줄 1. 문어 목소리** (초상 '궁금' 표정)
- 데모: **"벽이 꽉 찼어. 넓혀 볼까?"** 옆에 작은 `데모 규칙` 꼬리표. 기록 `by:'demo-rules'`. 늘 같은 고정 문장이다. 횟수로 만든 말이 아니다.
- 진짜 모델: 모델이 쓴 한 줄을 글자 그대로 보인다. 24자를 넘으면 앞부분 + '…', 누르면 원문. 안 썼으면 이 줄은 없고 몸짓(똑똑, 돌아봄, `?`)만 남는다.

**줄 2. 집 쪽지** (종이 아이콘, 초상 없음)

```
넓히면 뚜루가 옆벽을 터서 방을 하나 만들어.
하룻밤 걸려. 그동안에도 산책·놀이는 다 돼.
   [ 넓혀 보자 ]      [ 지금은 그대로 ]
```

- 이 줄은 톡으로 안 넘어간다. 버튼을 골라야 닫힌다. 바깥 톡·Esc·폰 뒤로 가기는 [지금은 그대로]와 같다.
- 제안 화면에는 비춤을 씌우지 않는다. 이미 상자 하나에 눈이 모여 있다.
- 제안 중에 앱을 닫으면 아무것도 기록하지 않는다. 다음에 열고 조용한 때 집 쪽지만 한 번 다시 묻는다. 문어 줄은 반복하지 않는다(대사 다시 보기에 있다).
- [지금은 그대로]를 골라도 **제안은 열려 있다.** 방 보기에 조용한 줄 하나가 남는다: "옆벽 넓히기 · 뚜루가 물어봤어 [넓혀 보자]". 이 버튼은 그때 받은 제안에 대한 **네 대답**이다. 문어를 다시 부르지 않는다.
- [지금은 그대로] 뒤 처음으로 포스터가 상자에 들어갈 때 집 쪽지 한 번: "옆벽 넓히기는 방 보기에서 언제든 할 수 있어." 그 뒤로는 말하지 않는다.

### 3.4 공개 박자

**언제:** 공사를 시작한 뒤 **처음 맞는 새벽 5시**가 지나고, 앱을 열거나 앱으로 돌아왔을 때.
- 오후 2시에 시작하면 다음 날 아침, 새벽 1시에 시작하면 그날 아침에 끝난다. 그래서 "아침이면 다 돼 있을 거야"가 늘 맞다.
- 앱을 켜 둔 채 5시를 넘겨도 그 자리에서 갑자기 공개되지 않는다. 다음에 열거나 돌아올 때 한다.
- 등불과 새날 깨기는 지금처럼 자정 기준이다. 공사만 쪽지 문장에 맞춰 '아침' 기준이다.

**순서:** 인트로 → (멈춘 산책이 있으면 이어받기) → 돌아온 인사(집 목소리, 결정 11) → 공개 쪽지. 그 전에 네가 산책부터 보내면 공개는 돌아온 뒤로 미룬다.

| 때 | 화면 | 소리 (§5.9) |
|---|---|---|
| 0 | 다락. 문어가 천 앞에서 팔 하나로 천 한쪽 귀퉁이를 잡고 있다 | — |
| — | 집 쪽지: **"공사가 끝났어."** [같이 열기] | 종이 사락 |
| 네 톡 | [같이 열기] 또는 늘어진 천 귀퉁이 | — |
| +0.0초 | 천이 처짐 → 접힘 → 떨어짐 (5프레임, 0.5초). 먼지 한 번 | 천 팔락 + 퐁 |
| +0.5초 | 구멍에서 빛이 다락 바닥으로 두 단계(0.25초씩) 번진다. 번쩍임 없음. 낮이면 따뜻한 햇살, 밤이면 푸른 별빛 | 반짝 |
| +1.0초 | 0.8초 멈춤. 다락 쪽에서 뚫린 구멍 너머를 먼저 본다 | — |
| +1.8초 | 문어가 구멍으로 걸어 들어감 → 가로 전환 0.6초 (다락이 오른쪽으로 밀려나고 옆방이 왼쪽에서 들어온다) | 발소리 |
| +2.4초 | 옆방. 문어가 가운데로 걸어감 → 둘러보기 (고개 왼쪽·오른쪽, 1.2초) | — |
| +5.6초 | **폴짝** 한 번 | 폴짝 징글 |
| +7초 | 기대 둔 포스터가 있으면 하나씩 들고 가서 새 벽에 건다 (한 장 1.5초, 3장까지 보여 주고 나머지는 바로) | 포스터 걸기 |
| 끝 | 집 쪽지: **"이제 더 많이 포스터 걸자!"** [포스터 고르기] [나중에] | — |

- **폴짝은 데모 규칙이다** (`by:'demo-rules'`). 모델 모드에서는 지어낸 기쁨을 넣지 않는다. 제안 때 모델이 반응을 골랐을 때만 폴짝하고, 없으면 둘러보기만 한다.
- 걷기·둘러보기·포스터 걸기는 `playback`이다.
- [같이 열기] 말고 다른 버튼은 없다. 상자를 그냥 넘기면 천 귀퉁이가 계속 기다린다. 언제든 톡하면 된다.
- 건너뛰기(대화 상자 ⏩ 또는 상자 톡): 포스터가 걸린 끝 상태로 바로 간다.
- 모션 감소: 천은 0.25초 크로스페이드, 장면은 바로 컷, 폴짝 없이 표정만, 포스터는 바로 걸림. 전체 약 3초.
- 공개를 끝까지 보기 전에 새로고침하면 다음에 처음부터 한다.

### 3.5 공사하는 동안 '짬'

- 문어가 **깨어 있고, 집에 있고, 한가할 때만** 온다. 자는 동안, 산책 중, 방 보기·꾸미기가 열려 있을 때는 없다.
- 지금의 돌아다니기 차례(20~40초마다) 가운데 1/3을 시드로 골라 짬으로 바꾼다. 앱을 한 번 열 때 **최대 2번.** 새 타이머는 없다.
- 짬 동안에는 생각 말풍선 같은 다른 반복 움직임을 쉰다 (한 번에 하나만 움직이기, 피드백 4).

| 짬 | 하는 것 | 길이 |
|---|---|---|
| 뚝딱 | 천 앞에서 망치 3타 한 묶음 | 약 2초 |
| 나르기 | 판자 하나 들고 천 뒤로 → 뒤에서 뚝딱 두 번 → 빈손으로 나옴 | 약 6초 |
| 쉬기 | 판자 더미에 앉아 창밖을 본다 | 6~10초 |

### 3.6 진짜 모델이 붙으면

결정 지점은 **하나**, `room_expand`다.

| 항목 | 값 |
|---|---|
| 언제 | §3.1 조건이 다 맞은 귀가. **하루 1번까지** |
| 보내는 것 (사실만, 약 150바이트) | `{ v, id, point:'room_expand', facts:{ room:'attic', wall_free:0, wall_total:6, attic_lantern:8, rooms:['attic'], can_open:'side' }, menu:['propose','watch','stop'] }` |
| 메뉴 뜻 | `propose` 넓히자고 하기 · `watch` 꽉 찬 벽을 잠깐 바라보기 · `stop` 아무것도 안 하기. `watch`·`stop`은 늘 있다. 이유를 묻지 않는다 |
| 받는 것 | `{ action, line?, reaction? }`. `line`(권장 24자)과 `reaction`은 선택이다 |
| MCP | 산책 마무리 도구(`ppolppol_finish`)에 선택 필드 `room?`으로 싣는다. 그날 조건이 맞을 때만 마무리 상황에 위 사실이 들어간다. **추가 호출 없음** |
| 시간 초과 (8초) | 아무 일도 없다. 기록에 `by:'fallback'`만 남고, 화면엔 선택처럼 보이지 않는다 |
| 넣지 않는 말 | "사람이 넓히고 싶어 해", "벽이 좁아 답답하지?", "넓히면 재밌을 거야", "지난번처럼", 데모 규칙의 확률 |
| 보내지 않는 것 | 네 대답([지금은 그대로] 포함)과 그 횟수. 공사 중 네가 한 일. 조개·업적 |
| `stop`이나 `watch`를 골랐을 때 | 제안 없음. 네가 조를 버튼도 없다. 다른 날 다시 칸 없는 귀가가 오면 그때 또 고를 수 있다 |
| 네가 [지금은 그대로]를 고른 뒤 | 제안은 열린 채로 남는다. 방 보기의 [넓혀 보자]는 그 제안에 대한 대답이라 모델을 다시 부르지 않는다 ("사람이 하재"를 전하면 압박이 된다) |

- 공사 짬, 공개, 포스터 나르기는 전부 `playback`이다. 모델을 부르지 않는다.
- 늘어나는 모델 호출은 칸 없는 귀가가 있는 날 최대 1번뿐이다 (MCP에선 0번).
- MCP `ppolppol_look_room`(읽기 전용)에 `rooms`, `wall:{free, total}`을 사실로 더한다.

### 3.7 대사 다시 보기에 남는 모양

```
[집] 오래된 포스터는 서랍에 들어갔어. …
── 11월 13일 ──
 · 뚜루가 포스터를 벽 아래 기대 뒀어 (행동)
[뚜루 · 데모 규칙] 벽이 꽉 찼어. 넓혀 볼까?
[집] 넓히면 뚜루가 옆벽을 터서 방을 하나 만들어. …
[너] 넓혀 보자
 · 뚜루가 옆벽에 구멍을 냈어 (행동)
[집] 아침이면 다 돼 있을 거야.
── 11월 14일 ──
[집] 공사가 끝났어.
[너] 같이 열기
[집] 이제 더 많이 포스터 걸자!
[너] '모자의 방' 포스터를 옆방에 걸었어
```

- 문어 줄은 초상 + `by` 꼬리표, 집 줄은 종이 아이콘, 네 줄은 다시 보기에만 나온다 (CORE_LOOP_V2와 같다).
- 행동 줄은 사실만 쓴다. "문어가 넓은 방을 좋아해" 같은 말은 코드가 만들지 않는다.

### 3.8 첫 사용 안내 (비춤)

한 번에 하나, 처음 한 번씩만. 방 보기에서 다시 볼 수 있다. 모션 감소면 움직이지 않는 어둡게 하기 + 테두리만. 장치는 DIALOGUE_UI 몫이다.

| 비추는 것 | 언제 | 집 쪽지 |
|---|---|---|
| 장소 버튼 (옆방에선 ▶) | 공개 끝 상자를 닫은 뒤 | "다락과 옆방은 여기서 오가. / 화면을 옆으로 끝까지 밀어도 돼." |
| 옆방 빈 칸 하나 | 처음 [포스터 고르기], 또는 처음 옆방 빈 칸을 볼 때 | "빈 칸을 누르면 / 걸 포스터를 고를 수 있어." |
| 방 보기 › '방 넓히기' 줄 | [지금은 그대로] 뒤 처음 방 보기를 열 때 | "넓히기는 여기서 / 언제든 할 수 있어." |

## 5. 만드는 방법

### 5.1 왜 '세 번째 장소'인가

| 방식 | 픽셀 크기 | 360px 폰 | 만들기 | 판정 |
|---|---|---|---|---|
| 다락 자체를 키움 (5m → 7m) | 작아진다. 문어도 | 지금도 0.5m 잘리는데 더 잘림 | 쉬움 | ✗ |
| 한 장면에 옆방을 이어 붙이고 화면을 밈 | 그대로 | 됨 | 어려움. 먼 벽(왼쪽·뒤)이 옆방을 가린다. 앞쪽에 붙이면 다락을 덮는다. 벽 잘라 보이기와 두 배 크기 빛·그림자 상자가 필요 | ✗ |
| 다락 위 다락 (로프트) | 그대로 | 위아래 이동이 페이지 스크롤과 다툼 | 사다리 오르는 동작이 없다 | 나중 후보 |
| **옆방 = 세 번째 장소** | **그대로** | **옆방이 통째로 보임** | **바깥 마당 전환(0.6초)을 다시 쓴다. 숨은 장소는 안 그리니 폰 부담 0** | **✓** |

이야기: 다락 벽 너머는 **지붕 밑에 비어 있던 칸**이다. 그래서 바깥 집 모델(고정 크기)은 그대로여도 말이 된다.

|---|---|---|
| 장소 표 (`groupOf`, `showPlace`, `setPlaceNow`) | `'exterior'`가 아니면 전부 `'attic'` | `PLACES = { attic, exterior, side }` 표 하나. 장소마다 그룹·카메라 타깃·그림자 상자·빛. 이름이 없으면 attic |
| 카메라 타깃 (`camTargetNow`) | 바깥이면 EXT_TARGET, 아니면 다락 | `PLACES[보이는 장소].target`. 옆방은 (0, 0.85, 0)에서 시작해 스크린샷으로 맞춤 |
| 그림자 상자 (`fitShadow`) | SHADE / SHADE_EXT | 옆방 상자 추가 |
| 전환 (`stepTrans`) | 늘 위아래 | **방향을 받는다.** 다락 ↔ 옆방은 **가로**로 미끄러진다 (화면 오른쪽 방향으로 그룹을 옮기고 픽셀 격자에 맞춤). 아래로 떨어지는 움직임은 없다 (INTERIOR_MODE 0단계와 같은 뜻) |
| 문어 그룹 | 보이는 장소로 문어를 옮김 | 문어는 자기 장소(`oct.place`) 그룹에 있다. 보이는 장소와 다르면 안 그린다 |
| 옆방 만들기 | 없음 | `buildSide()`. **처음 필요할 때만** 만든다 (공개 때, 또는 v0 플래그). 옆방이 없는 사람은 시작이 하나도 안 느려진다 |
| 다락 구멍 | 없음 | 왼쪽 벽 판자 루프에서 구멍 자리를 처음부터 비우고, 같은 판자로 만든 **마개** 하나로 막아 둔다. 마개가 있을 때 지금 다락과 **픽셀 하나 다르지 않아야** 한다. 공개 때 마개만 숨기고 그림자를 한 번 다시 굽는다 (`shadowMap.needsUpdate`) |
| 구멍 너머 | 없음 | 구멍 뒤에 0.6m 바닥 띠, 문설주 둘, 따뜻한 색 뒤판(빛 안 받는 재질). 뒤판이 그림자를 만들어 해가 구멍으로 새지 않게 |
| 공사 소품 | 없음 | 줄무늬 천(1.1 × 2.1m, 주름 2), 판자 더미, 열린 상자 뚜껑, 나무망치(문어가 들 때만), 빛 한 줄기(밝기만 있는 얇은 판) |
| 옆방 빛 | — | 점광 2개(벽 등잔 + 약한 짝). **다락의 점광 수(2)와 같게** 해서 첫 전환 때 멈칫하지 않게 한다. 재질은 지금 쓰는 것만 |
| 앵커 | `ANCHORS` 하나 | 장소마다: 다락 `hole`, 옆방 `door` · `board` · `cushion` · `center`. 앱 쪽 허용 목록도 장소마다 |
| 귀가 의식 (`returnCeremony`) | 바깥 → 다락 문 → 보드 | 걸 칸이 옆방이면 `hole`까지 걷기 → 가로 전환 → `door` → 옆방 보드 → 걸기를 덧붙인다. 걸기 목표는 칸 이름 → 장소·위치·회전 (`slotPos(slotId)`) |
| 출발 의식 (`departCeremony`) | 다락에서 시작 | 문어가 옆방에 있으면 `door` → 전환 → `hole`을 앞에 붙인다 |
| 고르기 (`pick`, `tapItems`) | 바깥이면 문어만 | 장소별 목록. 구멍·문은 `doorway` → 옆 장소로. 빈 칸·천 귀퉁이는 화면 거리 32px 안 최근접 (칸 사이가 29px라서) |
| 통계 (`stats`) | callsAttic, callsExt | callsSide 추가 |

- 길찾기는 만들지 않는다. 지금처럼 직선으로 걷는다. 장소를 건너는 길은 늘 `hole` → 전환 → `door` 세 마디다.
- **램프 주의:** 계산상 다락 램프(−1.6, 1.95, −0.9)가 화면에서 구멍 앞에 걸린다. 매달린 등이 문 앞에 있는 건 자연스럽다. v0 스크린샷에서 문어가 지나가는 모습이 가리면 램프를 0.3m 옮긴다 (룩 세션과 합의). 등불 7칸 선반과 겹치는지도 같이 본다.

### 5.4 앱 (app.js 등)

**공사 상태**

```
없음 ─(문어가 '넓히자')→ 제안됨 ─[넓혀 보자]→ 공사 중 ─(새벽 5시 지나고 열거나 돌아옴)→ 다 됨 ─(공개를 끝까지 봄)→ 열림
                         └[지금은 그대로]→ 제안됨 그대로 (방 보기 줄)
```

- 확인하는 때: 부팅, 화면이 다시 보일 때(`visibilitychange`), 문어가 깰 때, 귀가 뒤 조용한 때. **새 타이머는 없다.**
- '조용한 때' = 산책·의식·대화 상자 줄·비춤·꾸미기가 진행 중이 아님.
- 앱이 다락을 강제하는 곳(`ensureAttic`, 부팅, `resumeRunning`, `finalPose`)은 `homePlace()` = 문어가 있는 장소로 바꾼다. 단 `resumeRunning`은 단순하게 지금처럼 다락 담요로 보낸다.
- `finalPose`: 의식이 끝난 장소의 쉬는 자리(담요 / 방석)에서 잔다. 그 장소를 저장한다.
- 산책을 부르면 먼저 문어가 있는 장소로 화면을 옮긴다.
- 한가할 때 방을 건너 돌아다니기는 v1에 없다.
- 대화 상자·비춤은 DIALOGUE_UI의 장치를 그대로 쓴다 (예: `box.say({voice:'house'|'octopus', by, text})`, `box.ask({…, choices:[a, b]})`, `guide.once(id, el, text)`. 이름은 DIALOGUE_UI를 따른다).
- world.js에 집 쪽지 문구 약 8개와 방 한 줄 2개(공사 중 / 옆방 있음)를 더한다. `roomTitle`은 바꾸지 않는다.

**포스터가 갈 자리 (INTERIOR_MODE '새 포스터 규칙'을 넓힘)**

1. 빈 칸을 `attic:board.0` … `.5` → `side:board.0` … `.7` 순서로 찾아 첫 빈 칸에 건다.
2. 빈 칸이 없고 **공사 중**이면 천에 기대 둔다 (`build.leaning`, 보이는 건 3장까지, 나머지는 서랍).
3. 빈 칸이 없고 공사 중이 아니면, `by:'user'`가 아닌 포스터 가운데 가장 오래된 것을 **보이게** 상자(서랍)에 넣고 그 칸에 건다. 다른 칸은 안 움직인다.
4. 다 사람이 건 칸이면 서랍에만 넣는다. 문어는 보드를 한 번 보고 끝낸다 (INTERIOR_MODE와 같음).
5. 문어(모델)가 **걸지 않기로 고른** 포스터(`hang:false`)는 어느 경우에도 걸지 않는다.

- '벽 꽉 참' = `attic:board.*`에 빈 칸이 0. 장면이 몇 장을 그리는지와 무관하게 자료로 센다.
- 2D 벽도 6칸(3 × 2)으로 바꾼다 (INTERIOR_MODE 2D 자리 표). "+N"은 '벽에 없는 포스터 수 → 앨범'으로 남긴다.

**오가기**

| 길 | 규칙 |
|---|---|
| ◀ ▶ 버튼 (기본) | 진짜 `<button>`. 누르는 곳 44 × 44, 그림 16 × 16. 장면 왼쪽·오른쪽 끝 세로 가운데 (스피커·줌·꾸미기 칩과 8px 이상 떨어지게). `aria-label` "옆방 보기" / "다락 보기". 옆방이 생기기 전엔 없다 |
| 구멍·문 톡 | 화면에서 약 21 × 48 아트px라 충분히 크다 |
| 끝까지 밀기 | INTERIOR_MODE의 한 손가락 밀기가 경계에 닿아 고무줄이 걸린 뒤, **같은 쪽으로 56 CSS px 더 끌고 놓으면** 옆 장소로 간다. 그동안 그 방향 버튼이 한 번 밝아진다. 빠르게 튕기기로는 안 넘어간다 (실수로 넘어가지 않게). 옆 장소가 있는 쪽으로만 |
| 키보드 | 장면에 포커스가 있을 때 ← → |

- 장면 설명(화면 낭독기)에 옆방 문구를 더한다: "옆방. 벽에 포스터 n장." 문어가 다른 방에 있으면 "뚜루는 옆방에 있어."
- 꾸미기 모드에서도 ◀ ▶가 그대로 있다. 다른 방에 빈 칸이 있으면 그 버튼에 작은 점 (INTERIOR_MODE의 '화면 밖 자리 화살표'를 이것으로 대신).

### 5.5 망치질: 컵 놀이 팔 동작 다시 쓰기

- 컵 놀이 kit(`/home/user/ppolppol-play`, play-proto, PLAY_PROTO §11.3)를 **둘로 나눠** 본 게임에 합친다.
  - **움직임 묶음**: `reach / retract / hold / pose / tuck`과 소품 달기. 본 게임도 쓴다. 첫 망치질 때 처음 만든다 (그 전엔 비용 0).
  - **입력 묶음**(`#touch` 층 등): play.html 전용. 본 게임에 넣지 않는다.
- 나무망치: 자루와 머리 두 덩어리, 나무색 2톤, 메시 1개. 팔 하나에 단다.
- **똑똑**(제안 전): 팔을 벽에 대고 4포즈 × 2번 + 1번 더. 팔 끝 2px.
- **망치 한 타** = 5포즈(쉼 → 들기 → 꼭대기 → 치기 → 튕김), 8fps, 0.625초. 팔 끝 3~4 아트px (몸짓이라 UI의 1~2px보다 크다).
  - 한 묶음 = 3타 (뚝-딱-뚝). 묶음 사이 쉼 1.5~3초 (시드). **최대 3묶음 뒤 멈추고 팔을 오므린다.**
  - 칠 때 먼지 1번.
- 첫 뚝딱(4a)에서는 팔 셋이 일한다: 판자 잡기 · 못 잡기 · 망치. 나머지 다섯은 반쯤 오므려 몸을 받친다.
- 모션 감소: 망치를 든 멈춘 자세 하나 + 소리(켜져 있으면)만.
- kit가 아직 본 게임에 없으면: 몸 통통(지금 있는 눌림) + 소리로 대신한다. 공사 흐름은 그대로 돈다.

### 5.6 저장

```js
// defaults()에 덧붙인다. v는 2 그대로 (지금까지처럼 덧붙이기만)
room: { …,
  places: ['attic'],                    // 넓힌 뒤 ['attic', 'side']
  atticDoneOn: null | 'YYYY-MM-DD',     // 다락 등불 8칸이 다 켜진 날
  build: null | {
    id: 'side',
    stage: 'proposed' | 'building' | 'done' | 'revealed',
    proposed: { by: 'demo-rules' | 'model', on: 'YYYY-MM-DD', at, line: null | '원문 그대로' },
    answers:  [ { by: 'user', yes: true | false, at } ],   // 사실만. 화면에 횟수 없음
    startAt:  null | ISO,  doneAfter: null | ISO,            // doneAfter = 시작 뒤 첫 새벽 5시 (시작할 때 한 번 계산)
    revealedAt: null | ISO,
    leaning:  ['trip_…'],                                    // 천에 기대 둔 포스터
    log: [ { kind, by, at } ]                                // 짬·시간 초과 등. 최근 30개
  }
},
octopus: { …, place: 'attic' }
// 옆방 칸은 INTERIOR_MODE의 S.room.layout.place 에 그대로 들어간다:
//   'poster:trip_k7x2': { slot: 'side:board.3', by: 'user', at }
//   자리 이름: side:board.0~7 · side:shelf.0~2 (네 선반) · side:floor.0~3
```

**옛 저장 고치기** (`normalize()` 안에서. 두 번 돌려도 결과가 같다)
1. `places`가 배열이 아니면 `['attic']`. `build.stage`가 `done`·`revealed`인데 `'side'`가 없으면 넣는다.
2. 등불이 8인데 `atticDoneOn`이 없으면 `'0000-00-00'`(오래전에 다 꾸며짐)으로. 그래서 기존 등불 8 저장은 다음 '칸 없는 귀가'에서 제안을 받는다.
3. `octopus.place`가 `places`에 없으면 `'attic'`.
4. 칸 자료(`layout`)가 없을 때는 INTERIOR_MODE의 `normalizeLayout`이 지금 화면 그대로 채운다. 포스터는 앨범에 다 있으니 잃는 것이 없다.

- **다른 탭과 합칠 때**: `build`은 단계가 앞선 쪽(proposed < building < done < revealed), 같으면 `startAt`이 이른 쪽. `places`는 합집합. 칸은 INTERIOR_MODE 규칙대로.
- 내보내기·가져오기는 `S` 안에 있으니 그대로 따라간다. 비춤 '봤음' 표시는 DIALOGUE_UI 저장을 따른다.
- 두뇌 입력·시드·산책 요청에는 아무것도 안 들어간다. 모델에게 가는 건 §3.6 상황 하나뿐이다.

### 5.7 2D 대체 화면 (scene2d.js)

- `setPlace('side')`를 받는다. 무대에 `.st-side`를 붙여 옆방 층을 보이고 다락 층을 숨긴다. 옆방은 두 번째 320 × 240 판이다.
- 전환: 가로로 0.3초, 6계단(`steps(6)`). 모션 감소면 바로.
- 층 추가: 다락 구멍·마개·천·판자, 옆방 판(벽, 바닥, 보드 4 × 2, 문, 둥근 창, 방석, 선반 3칸).
- 공개: 천 층이 네 단계로 사라진 뒤 판이 바로 바뀐다.
- 망치질: 다리 하나(`l3`)를 5계단 0.625초 × 3번 꿈틀, 그다음 클래스를 뗀다. 폴짝은 2px 계단.
- 가로 밀기: `#scene`이 세로만 페이지 스크롤이라 가로는 JS로 받는다. `|가로| ≥ 56px`이고 `|가로| > 2 × |세로|`면 넘긴다. iOS 실기에서 확인.
- 문어가 다른 장소에 있으면 숨긴다 (`.st-elsewhere`).
- WebGL이 끊겨 2D로 넘어가도 같은 장소·같은 공사 단계에서 이어진다.

### 5.10 자동 점검 (`tools/test-expand.js`, Playwright)

- **화면**: 360 × 740에서 옆방이 캔버스 안, 사방 ≥ 8 CSS px. 두 장소의 픽셀 밀도가 같다. 옆방 드로우콜 ≤ 60. 두 번째 왕복 뒤 셰이더 수가 그대로. 마개를 켠 다락 = 지금 다락 (픽셀 차이 0).
- **조건**: 등불 8칸 된 그날 꽉 참 → 제안 없음. 다음 노는 날 칸 없는 귀가 → 1번. 같은 날 또 → 없음. 등불 7 + 꽉 참 → 제안 없이 보이는 바꿔 걸기.
- **넘침**: 바꿔 걸기 때 다른 칸 위치가 그대로다. 사람 칸은 1,000번 시뮬에서 0번 움직인다. 앨범 포스터 수는 줄지 않는다. `hang:false` 포스터는 걸리지 않는다.
- **공사**: 오후 2시 시작 → 그날은 공사 중, 다음 날 5:01 → 다 됨. 새벽 1시 시작 → 그날 5:01 → 다 됨. 공사 관련 화면 글자에 '숫자 + 시간/분/초'가 0건.
- **공개**: 대화 상자 톡 한 번에 끝 상태. 모션 감소면 걷기·먼지·폴짝이 0. 끝까지 안 보고 새로고침 → 처음부터.
- **장소**: 옆방 칸에 거는 귀가는 옆방에서 끝나고 `octopus.place = 'side'`. 다시 열면 옆방. ◀ ▶는 `<button>` + `aria-label`. 장소가 바뀌면 장면 설명이 바뀐다.
- **`by`**: 제안 `demo-rules`, 대답 `user`, 짬·공개 `playback`.
- **모델 틀** (가짜 chooser): `stop` → 화면 변화 0, 방 보기 줄 없음. 8초 넘김 → 제안 화면 0, `fallback`. 24자 넘는 `line` → 원문 보관, 화면 '…'. 상황 payload에 허용 키만, 네 대답 0건, ≤ 1,200바이트.
- **옛 저장**: §5.6 고치기 4가지. 등불 8 옛 저장 → 다음 칸 없는 귀가에서 제안.
- **시드**: 새 코드 `Math.random` grep 0건. 같은 날짜·같은 차례면 같은 짬.
- **2D**: 같은 칸 수, 가로 밀기로 넘김, 모션 감소.

## 8. 주인이 정할 것 (3)

1. **첫 제안은 언제?**
   - (가) 다락 등불 8칸이 다 켜진 **다음 날부터** + 벽 꽉 참. 빨라도 9번째로 노는 날. **추천.** 다락이 날마다 바뀌는 동안 공간이 또 자라면 두 순간이 다 흐려져. 8/8 뒤의 빈자리도 딱 메워.
   - (나) 보드가 생긴 다음 날부터(6번째로 노는 날) + 벽 꽉 참. 더 빨리 보지만 등불 7·8칸(선반·커튼)과 겹쳐.
2. **옆방도 날마다 조금씩 자랄까?**
   - (가) 옆방 천장에 전구 줄. 노는 날마다 한 알씩 켜지고, 물건은 안 생겨. 꾸밀 자리는 네 몫(포스터·가구·네 선반)으로 남아. **추천.** 가볍고, "내일 또"가 생겨.
   - (나) 다락처럼 하루에 한 가지씩 물건이 생겨 (8일 이야기). 더 풍성하지만 소품·그림 8개가 더 필요하고, 가게 가구·선물 목록과 겹치지 않게 새로 골라야 해.
   - (다) 없음. 열리는 날 다 된 방.
3. **몇 번까지 넓힐까?**
   - (가) 이번엔 옆방 하나만 만들고, 놀아 본 뒤 다음을 정해. **추천.** 다음 후보는 위층 다락(사다리, 누워서 보는 천장 포스터)과 지붕 테라스(빨랫줄에 포스터 널기). 매번 두드리는 곳·공사 몸짓·거는 방식이 다른 '새 동사'로 만든다.
   - (나) 처음부터 세 번(옆방·위층·테라스)과 끝을 정해 두고 만들어. 끝이 있는 이야기라 정성껏 만들 수 있지만, 지금 일이 세 배가 돼.

(정해 둔 것: 옆방은 다락 왼쪽 벽 너머 · 공사는 '시작 뒤 첫 새벽 5시'에 끝 · 천은 둘이 같이 걷기 · 거절해도 조르지 않고 방 보기 줄만 남김 · 넓히기는 가게에서 안 팜. 다르게 하고 싶으면 말해 줘.)
