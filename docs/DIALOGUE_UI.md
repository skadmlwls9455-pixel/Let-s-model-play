## 1. 한 줄 요약

쌓이는 「오늘의 산책」 목록을 없애고, 장면 아래에 **한 번에 한 줄만 보이는 사각 대사창**을 둔다. 대사창은 눌러서 넘긴다. 지난 대사는 작은 📜 버튼으로 여는 **「대사 다시 보기」** 창에 글 위주로 전부 남는다.

---

## 2. 왜

- 주인이 폰으로 해 보고 말했다. "기존 내역들이 쭉 아래로 슬라이딩해서 쌓이는 형식인데, 내가 생각한 그 터치해서 대사 넘어가는 사각형 UI 랑 안 맞아."
- 지금은 줄이 올 때마다 목록이 아래로 밀린다. 눈이 따라가야 하고, 무엇이 방금 온 줄인지 헷갈린다.
- 게임에서 흔히 쓰는 모양(초상 + 한 줄 + ▼)은 "지금 한 마디"에 눈을 모아 준다. 문어와 마주 앉아 있는 느낌에 더 가깝다.
- 대신 지난 기록은 하나도 잃으면 안 된다. 특히 **읽음 / 못 읽음** 같은 정직 표시는 그대로 보여야 한다. 그래서 기록은 따로 「대사 다시 보기」로 옮긴다.
- 같은 피드백에서 나온 두 가지도 여기서 같이 푼다.
  - "2프레임이라 깜빡이는 느낌이고 눈이 피곤해." → 대사창의 ▼ 와 기다림 표시부터 고친다 (§5.9).
  - 문어가 "안녕, 나는 ○○이야" 하고 인사한다. 이 인사는 대사창으로 나온다 (§4.4).

## 3. 흐름

### 3.1 누가 말하나: 목소리 셋

대사창 한 장에 세 목소리가 지나간다. 판 색은 바꾸지 않는다. 판 색이 3초마다 밝음과 어두움으로 뒤집히면 그 자체가 깜빡임이 되기 때문이다. 대신 **얼굴, 이름표, 아이콘, 글자 밝기**로 구분한다.

| 목소리 | 언제 | 대사창 모양 | 기록의 `by` |
|---|---|---|---|
| **문어** | 문어(데모 규칙 또는 모델)가 **지금 막** 한 말. 첫 인사, 기억 한 줄, 마무리 반응, "오늘은 집에 있을래" | 왼쪽에 초상(그 줄의 표정). 위 테두리에 이름표 `뚜루 · 데모 규칙`. 밝은 글자 | `demo-rules` · `model` · `human`(개발 패널 조작) |
| **집** | 게임이 아는 사실과 안내. 출발, 기웃 결과, 귀가, 포스터, 요약, 등불 소품, 날 인사, 지난 메모 인용 | 초상·이름표 없음. 왼쪽에 사건 아이콘. 조금 흐린 글자 | 없음 (게임 자신의 글이지 누군가의 행동이 아니다) |
| **나** | 사용자가 한 일. 직접 건 포스터, 나중에 같이 가기에서 주운 것·만든 요리 | 집 줄과 같은 모양, 아이콘 자리에 손 | `user` |

### 3.2 화면 모양 (360px 폰)

```
┌──────────────────────────────┐
│        (3D 다락방 장면)        │
├──────────────────────────────┤
│ 뚜루            등불 ■■■□  🔈 │  상태 줄 (지금 그대로)
└──────────────────────────────┘
┌╴뚜루 · 데모 규칙╶─────────╴📜╶┐  이름표와 📜 가 테두리에 걸침
│ ┌──────┐ 안녕, 나는 뚜루야.    │
│ │ 초상 │                       │  대사창 (높이 고정)
│ └──────┘                    ▼ │
└──────────────────────────────┘
  힌트 (선택)
  [주제나 링크를 슬쩍 건네줘     ]
  [🌧 뽈뽈 다녀와]   [방 보기]
```

순서는 **장면 → 상태 줄 → 대사창 → 초대 바(힌트·버튼) → 앨범**이다. 대사창 높이는 고정이라, 줄이 바뀌어도 아래 버튼이 움직이지 않는다.

### 3.3 단계별 흐름

| 단계 | 화면에 보이는 것 | 사용자가 할 수 있는 것 | 문어가 하는 것 | 집 쪽지 (버튼 안내) |
|---|---|---|---|---|
| 1. 처음 만남 (이름 지은 직후) | 집: "여기는 비 오는 다락방이야." ▼ | 대사창 누르기 | 창가에서 사용자 쪽을 본다 | 대사창을 비추며 "누르면 다음 말로 넘어가." |
| 2. 첫 인사 | 문어: 초상 + `뚜루 · 데모 규칙` "안녕, 나는 뚜루야." ▼ | 누르기 | 폴짝 + 팔 하나 흔들기 | — |
| 3. 집 소개 | 집: "뚜루는 여기 살아. 가끔 산책을 나가." 그 뒤 대사창은 조용 | 누르기 | 제자리에서 숨쉬기 | 힌트 칸 → 뽈뽈 다녀와 (튜토리얼 문서) |
| 4. 평소 (쉬는 중) | 마지막 줄이 그대로 있다. ▼ 없음 | 문어 톡·쓰다듬기, 📜 다시 보기 | 몸짓과 기호 말풍선(? ! ♪ …)만. **대사창은 바뀌지 않는다** | 쓸모가 생길 때 하나씩 |
| 5. 다음 날 다시 열기 | 집: "좋은 아침. 뚜루는 아직 자고 있어." ▼ → 집: "어제 뚜루가 남긴 메모: “…” (데모 규칙)" | 누르기 | "…응?" 하고 눈 뜨기 (결정 #11) | — |
| 6. 뽈뽈 다녀와 | 집: "뚜루가 나갔어 · 힌트: 모자" | 건너뛰기, 📜 | 문으로 걸어가 나간다. 먹물 퐁 | 처음 누를 때 건너뛰기 안내 |
| 7. 기웃 (여러 번) | 집: "🎩 모자의 방 · ✓ 읽음 · 6초 · 처음 온 곳" → 다음 쪽 “모자 속에 역사가 있었어”. 줄은 **저절로** 넘어간다. 다음 줄을 기다리는 동안 ▼ 자리에 멈춘 `…` | 누르면 빨라진다. 안 눌러도 놓치지 않는다 | 마당 모퉁이에서 고개를 내밀고 기호 말풍선 | — |
| 8. 귀가 | 집: "뚜루가 돌아왔어 · 가져온 것: 🪶 깃털" → 문어: 기억 한 줄 → 집: "벽에 포스터가 붙었어 · 비 오는 모자" → 문어: 마무리 반응 → 집: 요약 → 집: "창턱에 이끼 화분이 놓였어" | 누르면 빨라짐 | 포스터를 들고 와 붙이고, 담요에서 잠 | 첫 산책이 끝나면 📜 를 비추며 "지나간 말은 여기서 다시 볼 수 있어." |
| 8′. 집에 있는 날 · 빈 차례 | 문어: "오늘은 집에 있을래" → 집: "오늘은 집 · 등불 +1" / 빈 차례는 문어: "…" | 누르기 | 창가·낮잠 같은 집 활동 | — |
| 9. 건너뛰기 누름 | 지금 줄이 바로 끝나고, **마무리 두 줄**만 이어서 나온다: 문어의 마지막 말 ▼ 집의 요약 | 누르기. 나머지 줄은 다시 보기에 전부 있다 | 바로 판·담요 자리로 | — |
| 10. 대사 다시 보기 | 아래에서 올라오는 창. 날짜별, 글 위주, 읽음/못 읽음 단어 그대로 | 스크롤, 지난 날 펼치기, 닫기 (Esc·바깥·닫기) | 장면은 계속 움직인다 (산책도 계속) | — |
| 11. (나중) 같이 가기 | 헤엄 화면의 구간 사이에 기웃 줄이 한 줄씩. 나: "🐚 내가 주운 것: 조개껍데기" | 헤엄·줍기 | 자기 산책을 그대로 한다 | 같이 가기 안내 (튜토리얼 문서) |

## 4. 지킬 원칙 (MODEL_VOICE 와 잇기)

### 4.1 원칙표

| 원칙 | 대사창에서 이렇게 지킨다 | 근거 |
|---|---|---|
| 말을 바꾸지 않는다 | 긴 말은 **쪽으로 나눌 뿐 자르지 않는다**. 쪽을 다시 이어 붙이면 원문과 같아야 한다. 다시 보기에는 원문 전체가 있다 | MODEL_VOICE §3 |
| 누가 말했는지 보인다 | 문어 줄에는 늘 이름표 + 출처 (`데모 규칙` / `모델` / `사람이 조작`). 다시 보기 줄 아래에도 `데모 규칙 · 15:13` | MODEL_VOICE §5, 중요 1 |
| 문어 입에 남의 말을 넣지 않는다 | 문어 목소리는 "지금 막 한 말"에만 쓴다. 지난 메모는 **집이 따옴표로 인용**한다. 안내는 집의 몫이다. 문어 목소리 문구에 "눌러", "해 봐", "골라 봐", "적어 줘" 가 0건이어야 한다 (grep 검사) | 결정 #10~#12 |
| 말하기를 강요하지 않는다 | 첫 인사는 선택이다. 모델이 안 쓰면 손만 흔든다. 시간이 넘으면 아무 말도 없고, 그걸 문어의 선택처럼 꾸미지 않는다 (`by:'fallback'`) | MODEL_VOICE "말하기를 강요하지 않기", §2 |
| 읽은 척하지 않는다 | 기웃 줄에는 대사창에도 다시 보기에도 **글리프 + 단어**(✓ 읽음 · 📖 책장 메모 · ◌ 모의 방문 · ✕ 못 읽음 · ◌ 앉아만 있었음). 색만으로 구분하지 않는다. 빨강 없음 | 스킬 §2 |
| 코드는 사실만 | 등불 소품 줄을 "놓였어" 같은 사실 문장으로 바꾼다. "이제 진짜 내 다락이야" 같은 감정 주장은 뺀다 | CURIOSITY 원칙 1 |
| 압박이 없다 | "기다리고 있었어" 를 뺀다. 📜 버튼에 '안 읽은 줄 N' 배지나 점을 두지 않는다. 건너뛰어도 잃는 게 없다 | 중요 2 |
| 산책 박자를 붙잡지 않는다 | 게임은 대사창을 **기다리지 않는다**. 대사창은 받은 줄을 보여 주기만 한다. 모델에게 "누가 읽고 있어" 같은 신호를 보내지 않는다 | PROTOCOL §3 |
| 혼잣말은 말풍선으로만 | 톡·쓰다듬기 반응(`…♡`, `?`)은 장면의 기호 말풍선으로만 보인다. 대사창과 다시 보기에 넣지 않는다 | 결정 #10 |

### 4.2 기웃 메모는 누구의 말인가

기웃 줄에 붙는 한 줄 메모(`ev.note`)는 세 곳에서 온다: 그 방의 기억 조각(세계 데이터), 실제로 읽은 글의 요약, 방의 실마리 (`brain.js roomNote`). 읽은 글의 요약은 위키 문장이지 문어의 말이 아니다.

- 그래서 데모에서는 이 메모를 **집이 따옴표로** 보여 준다: `“모자 속에 역사가 있었어”`. 초상을 붙이지 않는다.
- 진짜 모델이 기웃 메모를 직접 쓰면 그때만 문어 목소리(`모델`)로 보여 준다.

### 4.3 지금 문구에서 옮길 것

| 지금 (어디) | 지금 목소리 | 새 목소리와 문구 |
|---|---|---|
| 첫 인사 "안녕, {이름}. 비 오는 다락방에 온 걸 환영해…" (이름 지은 직후) | 문어. 문어가 자기 이름을 부르는 꼴이다 | 집 "여기는 비 오는 다락방이야." → 문어 "안녕, 나는 뚜루야." → 집 "뚜루는 여기 살아. 가끔 산책을 나가." |
| 날 인사 "{좋은 아침}. 뚜루 기다리고 있었어." (`setDayGreeting`) | 문어 | 집 "좋은 아침. 뚜루는 창가에 있어." / "…아직 자고 있어." "기다리고 있었어"는 뺀다. 감정을 덧칠하고 "왜 늦게 왔어"로 읽힌다 |
| 어제 메모 / 지난 메모 행 | 문어 | 집이 인용: "어제 뚜루가 남긴 메모: “…” (데모 규칙)" |
| 등불 소품 `ITEM_LINE` 8개 (app.js:52) | 문어 1인칭 | 집, 사실 문장: ① 창턱에 이끼 화분이 놓였어 ② 낡은 나무 상자가 책상이 됐어 ③ 구석에 양초가 켜졌어 ④ 담요 한 장이 깔렸어 ⑤ 벽에 포스터 판이 걸렸어 ⑥ 비가 잦아들었어 ⑦ 선반이 생겼어. 창밖에 별이 보여 ⑧ 커튼이 걸렸어 |
| 귀가 "돌아왔어. {이유}" | 문어 | 집 "뚜루가 돌아왔어 · 가져온 것: 🪶 깃털". 돌아온 이유는 다시 보기에만 |
| 포스터 "벽에 붙였어 · {제목}" | 기록 | 집 "벽에 포스터가 붙었어 · {제목}". 사람이 직접 붙였으면 나 "내가 벽에 붙였어 · {제목}" (`by:'user'`) |
| 복구 "네가 없는 동안 다녀왔어" (`resumeRunning`) | 문어 | 집 "네가 없는 동안 뚜루가 다녀왔어." / "…집에 있었어." |
| 혼잣말 행 (말풍선마다 기록) | 기록 | 없앤다. 장면 말풍선만 남는다 |
| 첫 토스트 "힌트는 비워 둬도 돼…" | 토스트 | 힌트 칸 버튼 안내 쪽지로 옮긴다 (튜토리얼 문서). 토스트는 "복사됨", "저장 실패" 같은 시스템 알림에만 쓴다 |

- 받침에 따라 조사를 고르는 작은 도움 함수 `josa(name, '이야/야' | '은/는' | '이/가')` 를 둔다.
  - 한글 마지막 글자: `(글자코드 − 0xAC00) % 28 ≠ 0` 이면 받침이 있다 → "하늘**이야**", "뚜루**야**".
  - 숫자: 0·1·3·6·7·8 은 받침 있음으로 친다.
  - 그 밖(영문 등)은 "(이)야"처럼 둘 다 적는다.

### 4.4 문어의 첫 인사 "안녕, 나는 ○○이야"

| 모드 | 하는 일 | 기록 |
|---|---|---|
| 데모 | 이름을 지은 직후, 문어 목소리 "안녕, 나는 {이름}{야/이야}." + 폴짝 + 팔 하나 흔들기. 이름표 `뚜루 · 데모 규칙`. 규칙은 이름(사용자가 준 사실)에 인사말만 붙인다. "반가워", "잘 부탁해" 같은 감정 말을 지어내지 않는다 | `{kind:'intro', who:'octopus', by:'demo-rules', text}` |
| 모델 연결 | 처음 만날 때 **결정 지점 1번** (선택). 아래 상황을 보낸다 | 돌려받은 말 원문 그대로, `by:'model'`, `model` |
| 모델이 `wave` | 말 없이 팔만 흔든다. 대사창에는 집 "뚜루가 팔 하나를 흔들었어." | `{by:'model', action:'wave', text:null}` |
| 모델이 `watch` / `stop` | 아무 말 없이 다음 집 줄로 넘어간다 | `{by:'model', action}` |
| 8초 넘김 · 오류 | 인사를 하지 않는다. 행동한 것처럼 꾸미지 않는다 | `{by:'fallback', text:null}` |

모델에게 보내는 상황 (작게):

```js
{ point: 'meet', facts: { name: '뚜루', firstMeeting: true, timeOfDay: '아침' },
  menu: ['say', 'wave', 'watch', 'stop'] }   // line 은 선택 (권장 24자 이하, 넘어도 자르지 않음)
```

- 넣지 않는 말: "자기소개해 줘", "사용자가 기다려", "반갑게".
- 모델이 "나는 Claude 야"라고 써도 그대로 보여 준다.
- 인사는 **처음 만날 때 한 번**이다. 매일의 인사는 집 목소리 날 인사다 (결정 #11). 주인이 바꿀 수 있다 (§8-3).
- 튜토리얼을 "처음부터 다시 보기"로 돌릴 때는 새로 말하게 하지 않는다. 집이 인용한다: "처음 만난 날 뚜루가 한 말: “안녕, 나는 뚜루야.”"

## 5. 만드는 방법

### 5.1 자리와 크기

- 대사창은 지금 있는 `#log-sec` 안에 JS 가 만든다. 그 섹션을 `#invite`(초대 바) 앞으로 옮긴다. 이렇게 하면 입장 연출(`css/intro.css`)이 `#log-sec` 을 숨겼다 보여 주는 규칙을 고치지 않아도 된다.
- 테두리는 지금 쓰는 `frame_dialog` 9-slice 다. (9-slice: 모서리 그림은 그대로 두고 가운데만 늘리는 테두리 그림.)
- 초상은 **정수 배**로 그린다: 64px + 테 → 72px 칸. 지금 로그의 96px 은 1.5배라 픽셀이 고르지 않다.
- 이름표: 왼쪽 위 테두리에 8px 걸친 작은 나무 판. 이름이 길면 이름만 `…` 로 줄이고, 출처(`데모 규칙`)는 줄이지 않는다.
- 📜 다시 보기 버튼: 오른쪽 위 테두리. 보이는 크기 28px, 누르는 곳 44×44. 넘기기 영역보다 위층이라 눌러도 대사가 넘어가지 않는다.

| 화면 | 글자 | 한 쪽 줄 수 | 대사창 높이 | 한 줄 글자 수 (문어 / 집) |
|---|---|---|---|---|
| 기본 (픽셀 글꼴) | Galmuri9 20px, 줄높이 30 | 3줄 | 130px | 약 10자 / 12자 |
| 화면 높이 ≤ 680px | 같음 | 2줄 | 100px | 같음 |
| 화면 폭 ≤ 340px | Galmuri7 16px, 줄높이 24 | 3줄 (높이 ≤680 이면 2줄) | 112px (88px) | 약 12자 / 15자 |
| 시스템 글꼴 | 16px, 줄높이 24 | 3줄 | 약 100px | 약 13자 / 16자 |

- 계산 (360×740): 장면 325 + 상태 44 + 대사창 130 + 여백 16 + 초대 바 약 176 = 691 → 첫 화면에 다 들어간다.
- 360×640 에서 3줄이면 8px 넘친다. 그래서 높이 680px 아래에서는 2줄로 줄인다 (618).
- 가로 스크롤 0. 보통 글은 `keep-all` + `overflow-wrap:anywhere`, URL 은 `break-all`.
- 글자 폭은 어림이다. 프로토타입에서 실제로 잰다.

### 5.2 한 줄 → 쪽

- 한 쪽은 위 표의 줄 수만큼이다. 넘치면 **어절(띄어쓰기 단위)** 경계에서 다음 쪽으로 넘긴다. 한 어절이 한 줄보다 길면(URL) 그 어절만 쪼갠다.
- 대사창 안의 모든 줄 높이를 같게 둔다. 그래야 "다음 쪽"이 글을 한 칸 올리기만 하면 되고, 줄이 반쯤 잘리지 않는다.
- 대사창에는 그 사건의 **첫 문장**(+ 기웃이면 상태와 "처음 온 곳", 메모 인용)만 나온다. 곁가지(aside, bridge, 지난번 메모·날씨, 돌아온 이유, 힌트 처리 메모, 집 활동 설명)는 다시 보기에만 있다. 산책 한 번이 대사창 줄 10개 안팎이 되게 하려는 것이다.

### 5.3 타자기 (글자가 한 자씩 나오는 효과)

| 항목 | 값 |
|---|---|
| 쓰는 줄 | 문장 줄(문어·집·나). 상태 칩이 붙은 **기록 줄**(출발·기웃·포스터·요약)은 한 번에 나타난다 (2px 올라오는 정도) |
| 속도 | 글자당 45ms (초당 약 22자). 테스트용 `?speed=` 배수를 따른다 |
| 쉼 | `. ? !` 뒤 +180ms, `,` 뒤 +90ms, `…` 뒤 +240ms. 줄 끝에는 쉼 없음 |
| 단위 | 글자 묶음 단위 (`Intl.Segmenter`, 없으면 `Array.from`). 이모지를 쪼개지 않는다 |
| 줄바꿈이 튀지 않게 | 쪽 전체를 먼저 깔고, 아직 안 나온 부분만 `visibility:hidden` 으로 둔다. 줄바꿈 자리가 처음부터 정해진다 |
| 박자 | `requestAnimationFrame` 에 누적 시간으로 센다. 탭이 숨겨지면 그 줄을 바로 끝낸다 |
| 커서 | 깜빡이는 커서는 두지 않는다 |

### 5.4 누르면 무슨 일이

| 대사창 상태 | 누르면 |
|---|---|
| 글자가 나오는 중 | 그 쪽을 바로 다 보여 준다 |
| 다 나왔고 다음 쪽이 있음 (▼) | 다음 쪽 |
| 다 나왔고 기다리는 줄이 있음 (▼) | 다음 줄 |
| 기다리는 줄이 없음 | 아무 일 없음. 대사창이 2px 눌리기만 한다. 마지막 줄은 그대로 남는다 |

- 쪽이 바뀐 뒤 120ms 안에 들어온 탭은 무시한다 (두 번 눌림 방지).
- 판정은 `click` 으로 한다. 스크롤하다 손가락이 닿은 것은 탭으로 치지 않는다.

### 5.5 저절로 넘김과 대기열

대기열은 차례를 기다리는 줄 목록이다.

| 줄 종류 | 언제 | 넘어가는 법 |
|---|---|---|
| 흐르는 줄 | 산책 중에 온 줄 (출발~요약, 소품 줄) | 뒤에 기다리는 줄이 있으면 **읽는 시간**이 지난 뒤 저절로 넘어간다. 마지막 줄은 남는다 |
| 기다리는 줄 | 첫 만남 3줄, 날 인사, 메모 인용, 복구 줄 | 눌러야 넘어간다. ▼ 는 3번 통통 튄 뒤 멈춘다 |

- **읽는 시간** = 1.5초 + 글자당 65ms, 최소 2.5초, 최대 6초. 줄이 시작된 때부터 잰다. 단, 글이 다 나온 뒤 최소 1.2초는 머문다. 문어 줄은 ×1.25 (최대 6초). 20자 줄이면 약 2.8초다.
- 지금 산책 줄 간격(2.2~4.5초)과 거의 같은 박자다. 그래서 **그냥 보고만 있어도 다 읽히고**, 누르면 빨라질 뿐이다.
- '동작 줄이기'를 켜도 읽는 시간은 그대로다. 읽는 시간은 움직임이 아니다.

| 상황 | 대사창이 하는 일 |
|---|---|
| 기다리는 줄 3개 이상 | 읽는 시간 ×0.6, 타자 2배 빠르게 |
| 5개 이상 | 타자 없이 바로 |
| 6개 초과 | 가장 오래된 **집 줄**부터 대사창을 건너뛰고 다시 보기에만 남긴다. **문어 줄은 건너뛰지 않는다** |
| 건너뛰기 누름 | 지금 줄을 바로 끝낸다. 남은 줄은 다시 보기로만 보낸다. 산책이 끝나면 **마무리 두 줄**만 보여 준다: 그 산책 문어의 마지막 말(마무리 반응 → 없으면 기억 한 줄 → 없으면 "오늘은 집에 있을래") ▼ 집의 요약 |
| 뽈뽈 다녀와 누름 | 기다리던 줄을 비운다 (다시 보기에는 있다) |
| 자리 비움: 탭을 10초 넘게 숨겼다 돌아옴, 또는 다른 창(포스터·방 보기·달리기·다시 보기·미니게임)이 덮었다 닫힘 | 덮인 동안 타자와 시계를 멈춘다. 산책은 그대로 진행된다. 돌아왔을 때 기다리는 줄이 2개를 넘으면, 마지막 문어 줄 1개와 마지막 집 줄 1개만 남기고 나머지는 다시 보기로 보낸다. 이 일이 처음 생길 때 한 번만 집 줄 "지나간 말은 다시 보기에 있어." 를 덧붙인다 |
| 버튼 안내 쪽지가 떠 있음 | 타자와 저절로 넘김을 멈춘다 (`DLG.hold`) |
| 목록을 통째로 다시 그림 (새로고침·다른 탭 저장·불러오기) | 대기열에 쌓지 않는다. 가장 새 줄을 타자 없이 조용히 보여 준다 |
| 앱을 처음 열 때 | 날 인사 → (메모 인용) → (복구 줄)을 기다리는 줄로 넣는다. **입장 연출이 끝난 뒤**(`INTRO.onDone`) 시작한다 |

### 5.6 ▼ 와 `…`

- **▼ = "누르면 다음이 있어."** 다음 쪽이나 기다리는 줄이 있을 때만 보인다. 눌러도 아무 일 없는 ▼ 는 거짓말이라 마지막 줄에서는 안 보인다.
- **`…` = "곧 더 와."** 산책 중에 기다리는 줄이 없고, 마지막 줄을 다 보여 주고 1.5초가 지나면 ▼ 자리에 작게 나온다. **움직이지 않는다.** 산책 중이라는 표시는 「다녀오는 중…」 버튼이 이미 하고 있다.
- 지금 로그에서 `…` 줄이 끝없이 숨쉬던 것(`.lrow.typing`)은 대사창에서는 없다.

### 5.7 화면 낭독기

라이브 영역은 화면 낭독기가 새로 바뀐 글을 저절로 읽어 주는 칸이다. inert 는 창이 열린 동안 그 바깥을 누를 수도 읽을 수도 없게 막는 상태다.

| 요소 | 마크업 | 읽히는 것 |
|---|---|---|
| 대사창 묶음 | `#dbox` (`role="group"`, `aria-label="대사"`) | |
| 타자로 나오는 글 | `aria-hidden="true"` | 읽지 않는다 (반쪽 글자를 읽지 않게) |
| 줄 알림 | 숨긴 `<p aria-live="polite" aria-atomic="true">` | 줄이 시작될 때 **한 번만**, 모든 쪽을 합친 전체 글. 예: "뚜루, 데모 규칙: 안녕, 나는 뚜루야." "모자의 방, 읽음, 6초, 처음 온 곳." 장식 이모지는 빼고 읽는다 |
| 넘기기 | 대사창 전체를 덮는 `<button>` | "다음 대사" / 글이 나오는 중이면 "대사 끝까지 보기" / 다음이 없으면 `aria-disabled` + "다음 대사 없음". Enter·Space 로 누른다 |
| 📜 버튼 | `<button aria-haspopup="dialog">` | "대사 다시 보기" |
| 다시 보기 창 | `<dialog>` 안의 기록 목록 (`role="log"`) | 열려 있을 때만 새 줄을 읽는다 |

- 라이브 영역은 **늘 하나만** 살아 있다. 창이 닫혀 있으면 기록 목록은 그려지지 않아 조용하고, 대사창이 읽어 준다. 창이 열리면 바깥이 inert 가 되어 대사창은 조용해진다. 그래서 같은 줄을 두 번 읽지 않는다.
- 대사창은 포커스를 저절로 가져가지 않는다. 힌트를 쓰는 도중에 포커스를 빼앗지 않기 위해서다.
- 실제 폰(TalkBack 또는 VoiceOver)에서 한 번은 직접 확인한다. 자동 테스트로는 확인할 수 없다.

### 5.9 움직임: 대사창과 UI 아트 카드 12

공통 규칙 (주인 피드백 4):

1. 그림 두 장을 번갈아 보이거나, 보였다 사라졌다 하는 것을 **끝없이 돌리지 않는다**. 움직임은 1~2 아트px 이동이나 눌림으로 만든다.
2. 한 동작은 **4~6프레임**, 프레임당 120~250ms.
3. 반복 표시는 **3바퀴 뒤 멈춘다**. 다시 필요해질 때만 다시 돈다.
4. 대사창 둘레에서 동시에 도는 반복은 1개, 한 화면 전체로는 2개 이하. 장면의 숨쉬기와 날씨는 따로 친다.
5. 정수 px, `steps()`. 동작 줄이기면 멈춘 한 프레임.
6. 그림과 코드(프레임 수, `background-size`)는 **한 커밋에** 바꾼다. 그림만 바뀌면 반쪽 그림이 보인다.

| 모양 | 좁은 화면은 아래에서 올라오는 `<dialog id="backlog" class="sheet">`, 600px 이상은 가운데 창. 제목 "대사 다시 보기" |

### 5.11 다른 기능과 잇는 곳 (대사창이 내놓는 손잡이)

훅(hook)은 다른 코드가 끼어들 수 있게 한 줄 불러 주는 자리다.

| 손잡이 | 쓰는 곳 | 약속 |
|---|---|---|
| `DLG.say({voice, text, by, expr, pace, model})` | 첫 인사, 집 줄, 나 줄 | 문어 목소리는 `by` 가 꼭 있어야 한다. 없으면 집 줄로 떨어진다 |
| `DLG.hold(true/false)` | 버튼 안내 쪽지 | 쪽지가 떠 있는 동안 타자·저절로 넘김을 멈춘다. 닫힌 쪽지 글은 다시 보기에 📌 집 줄로 남는다 |
| `DLG.subscribe(fn)` | 같이 가기 헤엄 화면 등 겹창 | 겹창이 산책 줄을 자기 화면에 띄우고 싶을 때. 대사창은 산책의 결정에 아무 통로도 만들지 않는다 |
| `DLG.open()` | 방 보기의 "대사 다시 보기" | |
| 테스트용 `current()`, `pending()` | 스모크 테스트 | 읽기 전용. `{voice, text, by, page, pages}`, 기다리는 줄 수 |

버튼 안내가 비출 대사창 쪽 대상 두 개 (글은 집 목소리):

- 대사창: "누르면 다음 말로 넘어가." (처음 ▼ 가 나올 때)
- 📜: "지나간 말은 여기서 다시 볼 수 있어." (첫 산책의 마지막 줄이 끝났을 때)

### 5.12 저장

| 단계 | 저장 |
|---|---|
| v0, v1 | **바뀌지 않는다.** `ppolppol_v2` 형식 그대로. 대사창이 이미 보여 준 줄인지는 메모리에만 둔다. 저장 안 되는 세션 줄(날 인사·소품 줄·복구 줄)이 새로고침 뒤 빠지는 것은 **지금 로그와 같다** |
| v2 | 산책 밖의 줄을 `S.talk` 에 저장한다. 산책 줄은 지금처럼 `trips[].events` 에서 다시 그린다 (두 번 저장하지 않는다) |

v2 의 `S.talk` 모양:

```js
S.talk = [{
  id: 'tk_…', at: ISO, day: 'YYYY-MM-DD',
  who: 'octopus' | 'house' | 'user',
  kind: 'intro' | 'greet' | 'memo' | 'item' | 'tip' | 'resume',

  tripId: '…'                                           // 있으면

S.settings.textSpeed = 'normal'   // 'slow'(70ms) | 'normal'(45ms) | 'instant'
```

- 불러올 때 `normalize` 에서 배열인지 보고 엉터리 항목을 거른다. `v` 는 2 그대로 (덧붙이기만 하는 변경).
- 개수 상한 500. 넘치면 오래된 날 인사·쪽지부터 지운다. `intro` 와 모델이 쓴 줄은 지우지 않는다.
- 기록 내보내기에 넣는다 (문어의 말은 기록이다). 다른 탭과 합칠 때는 `id` 로 합친다.
- 버튼 안내를 봤는지는 여기 두지 않는다 (튜토리얼 문서의 `ppolppol_ui`).

### 5.13 2D 대체 장면

- 대사창과 다시 보기는 장면 밖의 화면 요소라 2D 와 3D 에서 똑같이 돈다.
- 초상은 `APP.portraitFor(expr)` 를 쓴다. 2D 에서는 SVG 얼굴 초상이 나온다.
- WebGL 이 끊겨 도중에 2D 로 바뀌거나 문어 색이 바뀌면 대사창 초상도 다시 그린다. 그래서 `refreshPortraits` 가 찾는 범위를 `#log canvas.lport-cv` 에서 `canvas.lport-cv` 로 넓힌다.
- 2D 에서는 기웃 말풍선이 다락 머리 위에만 뜬다. 문장은 대사창이 같은 방식으로 맡으니 잃는 것이 없다.

### 5.14 다른 작업과 덜 부딪히게

- 새 파일 `js/dialogue.js` (전역 `DLG`)와 `css/dialogue.css` 가 거의 전부를 맡는다.
- 대사창 스크립트는 시작할 때 `#log` 를 다시 보기 창 안으로 **옮긴다**. 스크립트가 없거나 시작하다 실패하면 지금 화면(「오늘의 산책」)이 그대로 남는다.
- 주소에 `?dlg=0` 을 붙이면 옛 화면으로 볼 수 있다 (비교·문제 찾기용).
- 대사창은 `#log` 의 화면 요소(DOM 행)를 붙잡지 않고 **복사본**을 들고 있다. `renderLog` 가 목록을 통째로 다시 그려도 깨지지 않는다.
- 참고: 지금 `renderLog` 는 진행 중인 산책을 그리지 않는다. 산책 중에 목록을 다시 그리면 이미 나온 산책 줄이 목록에서 사라진다 (지금도 같다). 대사창은 복사본이라 괜찮다. v2 에서 "보여 준 줄까지" 그리게 고친다.

## 7. 플레이테스트에서 볼 것

폰으로, 처음 하는 사람 한 명 + 주인. 말로 묻지 말고 먼저 지켜본다.

| 볼 것 | 어떻게 | 좋은 신호 |
|---|---|---|
| 대사창을 누를 줄 아나 | 첫 화면에서 아무 말 없이 건넨다 | 쪽지가 뜬 뒤 5초 안에 대사창을 누른다 |
| 산책을 보기만 해도 다 읽히나 | 산책 한 번을 손대지 않고 본다. 끝나고 "어디 다녀왔어?" | 들른 곳 하나 이상과 가져온 것을 말한다 |
| 글과 장면이 어긋나나 | 문어가 마당에 나타날 때 대사창 글을 본다 | "글이 늦다/빠르다" 는 말이 없다 |
| 타자 속도 | 45ms 와 70ms 를 프로토타입 토글로 비교 | 답답하다는 말이 없다. 누르면 바로 끝나는 게 자연스럽다 |
| 한 쪽 3줄이 맞나 | 넘김 횟수를 센다 | 한 줄에 쪽 넘김이 거의 없다 |
| 누가 말했는지 보이나 | 끝나고 "방금 '창턱에 이끼 화분이 놓였어'는 누가 한 말이야?" | "집(게임)" 이라고 답한다. 문어 줄은 문어라고 답한다 |
| 다시 보기를 찾나 | 산책 뒤 "아까 그 말 다시 보고 싶으면?" | 📜 를 스스로 찾는다. "못 읽음" 표시 뜻을 안다 |
| 눈이 피곤한가 | 5분 켜 둔다. 동시에 움직이는 것 수를 센다 | 거슬린다는 말이 없다. 대사창 둘레에서 움직이는 것이 1개 이하 |
| 버튼이 밀려 불편한가 | 붙이기 / 걸치기 토글 비교 | 한쪽을 분명히 고른다 (§8-1) |
| 건너뛰기 뒤 두 줄이 충분한가 | 건너뛰기를 누르게 한다 | "뭐가 있었는지 모르겠다"는 말이 없다 |
| 화면 낭독기 | TalkBack 으로 산책 한 번 | 같은 줄을 두 번 읽지 않는다. 반쪽 글자를 읽지 않는다 |

자동으로 볼 숫자 (사람에게는 보이지 않는 테스트에서만): `?speed=4` 로 산책 10번을 흘려 **대사창을 건너뛴 문어 줄 0**, 산책 한 번에 대사창 줄 수 10개 안팎.
