# 미용실 · 몸 색 잠금 — 최종 스펙 (2026-11-08 밤)

설계안(`scratchpad/salon/DESIGN.md`)에 비평 셋(복지·정직 / 플레이어 경험 / 기술 가능성)을 합친 판이다. 아직 코드는 0줄이다. 이 문서가 만드는 사람의 계약서다. 저장소에 넣을 때는 `docs/SALON.md` 로 옮긴다.

주인 말 (11-08 밤, 그대로): "글고 지금 생각해봤는데 물론 게임이긴 하지만 문어 외관을 내 멋대로 슥슥 염색시키는 게 좀 다소... 어색하고 우리 복지 방향이랑 안 맞게 느껴져서 그런데 처음에 선택한 이후로는 사용자가 못 바꾸게 픽스하는 건 별로일까? 흠...... 대신 이 색으로 염색해볼까? 이런 식으로 미용실 컨텐츠 추가하는 거야."

한 줄: **몸 색은 사람이 처음 한 번만 고른다. 그 뒤로는 미용실에서 사람이 색을 내밀고 묻고, 바꿀지는 문어가 정한다.**

지키는 선:
- MODEL_VOICE 두 약속. 고르기 전에 끌지 않는다. 고른 것(행동·말·표정)을 바꾸지 않는다.
- 모든 물음에 '그대로'(`keep`)가 첫째로 있다. 이유를 묻지 않는다. 받은 답을 다시 묻지 않는다.
- '그대로'는 담담하게 보여 준다. 시무룩·죄책 대사·마음 바꾸기 연출이 없다.
- 코드가 짓는 글은 사실만 쓴다('좋아해' 같은 말 0건). 데모 규칙의 말은 늘 보이는 '데모' 꼬리표 아래에서만 나온다.
- 결정은 시드로 한다. `Math.random` 0건이고, 답은 [물어보기]를 누른 순간 계산해 저장한다.
- 주인 규칙: 고를 것과 글은 적게. 화면에 이모지·꾸밈 기호가 없다. 방은 문으로 잇는다(미용실은 방이 아니라 다락 한 구석이다).
- 미용실은 아무것도 주지 않는다. 조개·등불·배지·'함께한 날'이 0이고, 대답은 취향 점수가 되지 않는다.

## 1. 몸 색 잠금

### 1.1 첫 실행 창 (`#name-dialog`)

순서 (위 → 아래):

1. 제목 `h2#name-h` "문어 이름을 지어 줘" — `class="dlg-top"` `tabindex="-1"`
2. 한 줄 "오늘 처음 보내는 문어야." (둘째 문장 "이름은 천천히 불러 줘도 괜찮아." 는 뺀다)
3. 초상 캔버스 64×64 (CSS 64 px, 픽셀 테마 정수 배율). 지금의 `img[data-asset="oct.happy"]` 는 초상을 못 그릴 때(컨텍스트 잃음)만 남는 대체 그림이다
4. 색 6칸: `div.presets.name-colors[role=group][aria-label="몸 색"]` 안에 `button.preset[type=button][aria-pressed][aria-label="빨강"…]`
5. 이름 칸 `#name-in`
6. [이름 저장] `type=submit`
7. 정직 줄 "지금은 미리 만든 규칙으로 움직이는 체험판이야." (그대로)

규칙:
- **색 6개만** (슬라이더 없음). 순서와 값은 빨강 `#e8463c` · 주황 `#f08a3c` · 보라 `#9a5cc8` · 파랑 `#4a86d8` · 초록 `#4fa868` · 분홍 `#f07aa8` 이다. 처음엔 빨강이 눌린 채다.
- 칸을 누르면 **창 안 초상만** 그 색으로 다시 찍는다: `scene.portrait('happy', { bg: 'transparent', color: hex })`. 표정은 바뀌지 않고 폴짝도 없다. 장면 문어는 [이름 저장] 때 한 번 `setOctColor` 로 바뀐다 (그 전에 톡톡 갈아 보는 모습이 주인이 말한 '슥슥'이다).
- 색 단추는 꼭 `type="button"` 이다. 아니면 폼이 제출되어 이름 필수 검사가 뜬다 (기술 MUST 10).
- **포커스**: 손가락 기기에선 제목에 준다(자판이 색 줄을 가리지 않는다). `(pointer: fine)` 이면 지금처럼 이름 칸에 준다. `#name-h:focus { outline: none }` 을 둔다(테두리가 생기면 입력 칸처럼 보인다). 키보드로 Tab 하면 색 칸 → 이름 칸 → 저장 순이다.
- **크기**: `.preset` 보이는 칸 36 px, 누르는 곳 `::before` 로 44 px, 간격 6 px (6×36 + 5×6 = 246 px). 320 px 폰에서 창 안쪽이 246 px 보다 좁으면(실측 픽셀 230 · 시스템 237) `#name-dialog { max-width: calc(100vw - 24px) }` 로 넓히고, 그래도 모자라면 간격을 4 px 로 줄인다. **한 줄, 줄바꿈 없음**이 합격선이다.
- **높이 합격선**: 320×568 에서 두 글꼴 모두 창이 스크롤되지 않고 정직 줄이 보인다 (경험 비평 실측: 픽셀 460 px · 시스템 395 px). 320×460 에서 [이름 저장]이 화면 안에 있다. 360 · 412 px 은 창 폭이 `min(92vw, 340px)` = 331 · 340 px 라 색 줄이 넉넉히 한 줄이다. 어두운 테마는 칸 테두리 `var(--line)`, 눌린 칸은 지금 `.preset.on` 모양 그대로다.
- 글에 "색은 못 바꿔" 같은 말을 넣지 않는다. 겁주는 말은 고르기를 무겁게 만든다. 규칙은 장면과 미용실이 보여 준다.
- 색을 안 누르고 저장하면 빨강이고 `by: 'default'` 다. 누르면 `by: 'player'`.
- 저장: `S.octopus.color = hex`, `S.octopus.colors = [{ at, date: todayKey(), color: hex, how: 'first', by }]`, `S.settings.octColor = hex` (사본).
- 전체 초기화를 하면 같은 창이 다시 뜬다(색도 다시 고른다).
- 첫인사 줄에 색을 넣지 않는다. 어디서도 '문어가 고른 색'·'원래 색'이라고 말하지 않는다.

### 1.2 설정

| 누가 | 보이는 것 |
|---|---|
| 플레이어, 거울 전 (등불 0–1칸) | '문어 색' 칸 자체가 없다 |
| 플레이어, 거울 뒤 (등불 2칸 이상) | 맨 위 `h3` "문어 색" + 한 줄 "거울 앞에서 {이름}에게 물어볼 수 있어." (누르는 것 없음) |
| `?dev=1` 을 직접 붙인 탭 | 위 줄 아래 "개발용 · 바로 바꾸기" + 옛 슬라이더 + 프리셋 6 |

- **개발용 판정은 새 플래그 `DEV_EXPLICIT`** 이다: 주소에 `dev=1` 이 있거나, 같은 탭 sessionStorage 에 `ppolppol_dev = '1'` 이 있을 때(그리고 `dev=0` 이 아닐 때). file:// · localhost 의 자동 `DEV` 로는 안 켜진다. README 가 file:// 와 `dist/ppolppol.html` 을 노는 방법으로 안내하기 때문이다 (복지 MUST 6). 기존 `#demo` 패널·힌트 칸은 지금 규칙(`DEV`) 그대로다. 이 스펙이 더하는 개발용 칸 둘(바로 바꾸기 · 다음 미용실 대답)만 `DEV_EXPLICIT` 을 본다.
- 개발용 슬라이더: `input` 이벤트에선 장면만 미리 보인다(`scene.setColor(hex, { still: true })`, 저장 없음). `change` 에서 한 번 `setOctColor(hex, { how: 'dev', by: 'dev' })` 를 부른다. 한 번 끌면 기록이 한 줄 생긴다 (기술 MUST 6).
- `WHO_LINE` 을 "지금은 모델이 아니라 미리 만든 규칙이 골라. 고른 이는 포스터와 쪽지 뒷면, 미용실 줄에 적혀." 로 바꾼다.
- 칸 순서는 지금처럼 '문어 색'이 맨 위다. 익숙해지면 아래로 내리거나 뺀다 (나중).

### 1.3 바꾸는 길은 하나

```js
setOctColor(hex, meta)   // meta = { how: 'first'|'salon'|'dev', by, ask?, at? } — 없으면 { how: 'dev', by: 'dev' }
// → S.octopus.color = hex; S.settings.octColor = hex; colors.push({ at, date: todayKey(), color: hex, how, by, ask }); save();
//   salonActive 가 아니면 applyLook({ still: how !== 'salon' })
applyLook(opts)          // 장면 색 ≠ S.octopus.color 이면 scene.setColor(color, opts) + refreshPortraits(). salonActive 동안은 미룬다
```

- `applyLook()` 은 `renderScene()` 끝, 이름 저장 뒤, `adoptRemote` 뒤, `importJSON`·`resetAll` 뒤, `sceneLost` 2D 다시 그리기 뒤에 부른다 (기술 MUST 4: 지금은 이 길들에서 장면 색이 안 따라온다).
- `sceneOpts().color` 는 `S.octopus.color` 를 읽는다.
- `scene.setColor(hex, { still: true })` 는 흔들기(`oct.wiggle`)를 하지 않는다. 미용실 연출만 흔든다.
- `APP.setOctColor` 는 시험용으로 그대로 공개한다. 인자 하나로 부르면 개발용 기록(`how: 'dev'`)이 된다 (smoke 1705 행이 그대로 돈다).
- `js/runner.js` 250 행은 `octopus.color` 를 먼저, `settings.octColor` 를 다음으로 읽는다 (한 줄).

### 1.4 옛 저장

- 이미 놀던 기록(이름이나 trips 가 있음)은 **지금 색 그대로** 간다. `colors` 가 비어 있으면 `{ how: 'first', by: 'migrated', color: 지금 색, at: born || null, date: null }` 을 넣는다. 첫 실행 창은 다시 뜨지 않는다.
- `by: 'migrated'` 의 뜻은 "미용실 전에 사람이 설정에서 고른 색(또는 기본값)"이다. 문어가 고른 색으로 풀어 쓰지 않는다.
- v1 → v2 옮기기 결과도 `normalize()` 를 거친다. 지금은 `load()` 가 `migrateV1` 결과를 normalize 하지 않는다 (기술 SHOULD 10).

## 2. 자리 — 다락 뒷벽 왼쪽 거울 코너

다른 자리 둘과 비교했다(설계안 §1). 시트만 두면 '설정 바꾸기'처럼 읽힌다. 미용실 방을 따로 지으면 문어를 다락 밖으로 데려가야 하고, 일이 크다(L). 그래서 다락 안 한 구석이다. 나중에 옷방이 열리면 같은 규칙(`SALON`)과 프로토콜 그대로 자리만 옮길 수 있다.

### 2.1 3D 기하 (`js/scene3d.js`)

주변 사실: 방 5×5 m (x, z ∈ [−2.5, 2.5]), 뒷벽은 z −2.5 쪽. 뒷벽 샛기둥은 x −1.9 · −0.9 · 1.12(폭 0.14)라 코너 빈 폭은 **x −1.83 … −0.97** 이다. 등불은 (−1.6, 1.95, −0.9)로, 거울이 아니라 문어 자리 위에 있다. 도르래 밧줄은 x −1.6, z −1.9 … −2.01, y 1.9 위다. 등불 7칸 선반은 y 1.70, x −2.3 … −0.8 이고 받침이 x −2.15 · −0.95 (y 1.37 … 1.67)에 있다. 거미줄은 왼쪽 위 모서리에 있다.

| 부품 | 모양 | 재질 · 메시 | 자리 |
|---|---|---|---|
| 거울 틀 | 바깥 0.56 × 0.82, 위는 반지름 0.28 아치, 두께 0.05 | `lambert` 어두운 나무 `W[1]` · **메시 A** | 가운데 x −1.40, 아래 y 0.62, **위 y ≤ 1.44** (선반·기념품과 띄움, 기술 SHOULD 1). 뒷면이 벽 널에 닿게 (설계안 z ≈ −2.44, 스크린샷으로 맞춤) |
| 유리 | 안쪽 0.44 × 0.70 아치 + 1px 사선 빛줄기 2개 | `basicV` 청회색 2톤 (밤엔 한 칸 어둡게, `setTime` 에서 recolor) · **메시 B** | 틀 안쪽, 틀 앞면보다 0.01 뒤 |

- 레이어 0 만 쓴다. 초상(레이어 2)에 안 찍힌다.

**드로우콜** (기술 비평 실측: 등불 2칸 기준 62/65 낮/밤, 메시 하나가 패스마다 따로 그려진다):

| 가만히 (A + B + 보일 때 C) | +6 ~ +8 | 기준 + 8 이하 |
| '바꾸기' 연출 중 (+ D, E, F, G) | +14 ~ +16 | 기준 + 16 이하 |

**색이 제대로 읽히는가** (경험 MUST 2): 물을 `lambert` 로 그리면 낮엔 여섯 색이 다 흰색에 가까워지고, 밤엔 주황·분홍이 갈색으로 바뀐다(증거 `critic/shots/tub-colours.png`). 그래서 병·물·유리는 `basicV` 로 그린다. 합격선: 6색 × 낮·밤 스크린샷에서 병 가운데 아트픽셀과 물 픽셀의 색상(hue)이 원래 색과 ±25° 안이다. 못 미치는 색만 `buildPalette(octHex, source, extra)` 의 `extra` 로 그 프리셋 한 칸을 팔레트에 더한다. 고유 색 수(`look-metrics`)가 팔레트 + 5 를 넘지 않는지 같이 본다.

**누르는 곳**:
- `#btn-salon` 은 진짜 `<button class="scene-spot">` 이다. `aria-label="미용실"`, `aria-haspopup="dialog"`, `aria-controls="salon-sheet"`, `aria-describedby="scene-desc"` 를 달고, index.html 의 `#btn-machine` 뒤에 둔다.
- `SPOT_KEYS` 와 app.js `ROOM_SPOT` 에 `salon` 을 더한다. `spotInfo('salon')`: 다락이 보이고 · 방 이동·문 작업·전환·입장 연출이 없고 · `props.salon.visible` 이고 · 앱이 `scene.setSalonOpen(true)` 로 허락했을 때만 'over' 다. 상자 = 메시 A·B 의 투영 상자(거울 + 병 선반), 44×44 이상.
- 톡은 캔버스 `pick` 이 받는다. 우선순위는 레이캐스트 가장 가까운 것 → 문어 히트 구 → 창 → 근처 기념품·포스터 → 미용실 단추 칸 순이다. 문어가 거울 옆에 서 있으면 문어를 누른 게 먼저다. 등불 8칸 기념품이 겹쳐도 기념품이 먼저다.

**v2 (나중, 스크린샷 확인 뒤)**: 대야 속 잠수. 기술 비평이 찾은 맞는 값: 대야 r 0.48–0.5 · 테 0.20–0.22, 안에 있는 동안 몸 x/z 0.9 배 · 팔 접기 · 0.05–0.08 m 가라앉기, 폴짝 꼭대기 0.65 r 이상. 0.14 m 가라앉으면 눈이 안 보인다(`tech/shots/tubfit2-*.png`).

### 2.2 2D 대체 장면 (`js/scene2d.js`)

- `item.salon` 층: 거울 + 병 줄을 왼쪽 벽 창 오른쪽에 둔다. 무대 x 114–138 근처이고, 왼쪽 벽과 같은 `skewY(26.565deg)` 다. 오른쪽 벽 x 166 쪽은 놀이방 문 자리라 피한다.
- 대야·물·물보라 층은 '바꾸기' 동안만 바닥에 보인다. 물 `fill` 은 내민 색이다.
- `SPOT_BOX.salon`, 2D `ANCHORS.salon` 을 둔다. 정확한 자리는 스크린샷으로 잰다.
- 2D 단추 찾기에 지금 items 검사가 없다. 등불 2칸 전엔 `#btn-salon` 을 숨긴다 (기술 SHOULD 7).
- 2D 에서도 문어 쪽 동작이 하나는 있어야 한다(걸어가서 폴짝). 몸만 저절로 바뀌면 설정을 바꾼 것처럼 보인다 (복지 SHOULD 1).

### 2.3 앵커는 네 곳에 (기술 MUST 7)

`ANCHORS.salon` 을 scene3d · scene2d · app.js `ANCHORS`(없으면 `anchorName()` 이 'center' 로 바꿔 버린다) · `SPOT_DESC` (`salon: '거울 옆'`) 에 넣는다. `anchorName('salon')` 은 거울이 없으면(등불 < 2) 'center' 다. `allowedIdleAnchors()` 에 거울이 있을 때 'salon' 을 더한다. 문어가 가끔 거울 옆을 지나가고, 그때 거울 속 문어가 보인다. 거울을 찾게 하는 장치이고, 꾸밈이지 결정이 아니다(기록 없음).

### 3.3 묻기 — 고르는 과정이 보이게

[물어보기]를 누르면:

1. **다시 읽고 확인**: 저장소에서 기록을 다시 읽어 합친다(§7.5). `SALON.canAsk(state, todayKey(), octState)` 가 거짓이면 시트를 닫고 그 토스트를 띄운다. 두 탭 · 자정 넘김을 막는다.
2. **답을 정하고 바로 저장**: 데모면 `SALON.demoAnswer(...)` (§4), 개발용 '다음 대답'이 걸려 있으면 그 답(`by: 'human'`)이다. 물음 한 줄과 ('바꾸기'면) 색 기록 한 줄, `octopus.color` 를 **`save()` 한 번에** 쓴다. 장면만 연출이 끝날 때까지 옛 색이다(`salonActive` 동안 `applyLook` 을 미룸). 모델 길(나중)은 여기서 `status: 'waiting'` 으로 먼저 저장하고 요청을 보낸다. 새로고침으로 물음을 무를 수 없다.
3. 시트가 닫히고(250 ms) `salonActive = true` 가 된다. 돌아다니기·생각 말풍선·쓰다듬기·톡 반응·창문 걷기를 멈춘다. `oct.busy` 는 `setBusy` 가 덮어쓰므로 쓰지 않는다 (기술 SHOULD 2).
4. 행 1 (집 목소리, 라벨 '미용실'): "파란색 어때? 하고 물어봤어."
5. 문어가 걷는 중이면 도착을 기다린다(최대 4 s, 넘으면 그 자리로 건너뜀). 쓰다듬기 중이면 끝낸다.
6. 눈이 내민 병으로 간다(이미 가 있음). **숨 고르기 1.0 s + 움츠림 0.5 s**. 움츠림은 새 장면 상태 `ponder`(`scaleY .92 / scaleX 1.05`, 얼굴 idle)다. 출발용 `anticipate` 를 쓰지 않는다(반눈 calm 얼굴과 출발 먹물이 따라온다). 두 답 모두 같다. 모델 길이면 이 박자가 요청 대기를 덮는다.
7. 대답을 보인다 (§3.4).

마음 바꾸기는 꾸며 내지 않는다. '그대로' 앞에 다가가기·기울기가 없다.

### 3.4 대답 연출

공통 (대답을 보이는 순간):
- 장면 얼굴 = 고른 이가 준 `expr` 이다. 데모는 '바꾸기' happy · '그대로' idle 이다. 모델이 안 줬거나 사람(개발용)이 정했으면 idle 이다. `scene.setExpression(expr)` 를 직접 부른다(말이 없어 행 2 가 없어도).
- 말이 있으면 말풍선(앞 24자 + '…') + 행 2 (라벨 '대답', 문어 목소리 행, 초상 = 같은 `expr`, 모델 말은 `data-raw="model"` 로 원문 전부). **말이 없으면 행 2 도 말풍선도 없다**(데모 문구로 채우지 않는다).
- `happy` 면 장면의 기본 폴짝 2번이 같이 나온다. 다른 표정은 폴짝이 없다.
- 소리 `AUDIO.on('salon', { act: 'answer', action, by, joy })`.

**'바꾸기' (`dye`) — v1** (보통 속도, `?slow=` 를 따른다):

| 박자 | 보통 | 모션 줄이기 |
|---|---|---|
| 말풍선 0.4 s 뒤 거울 옆(`salon`)으로 걷기. 이미 거기면 말풍선 1.6 s 를 기다린다 | 0 – 3.3 s | 바로 그 자리 |
| 대야가 놓인다 (2칸 @12 fps, 쿵) · 병이 선반에서 대야 테로 폴짝 (호 0.3 s) | 0.3 s | 1칸 |
| 멈춤 0.3–0.6 s (`hashSeed(ask.id)` 로) | 0.45 s | 0.2 s |
| 병이 기울고 (3칸) 물이 내민 색으로 물든다 (3칸) | 0.5 s | 1칸 |
| 대야 쪽으로 몸을 돌림(카메라 ±40° 안) · 예비 120 ms · 제자리 폴짝 (꼭대기 0.3 r, 대야 쪽으로 ≤ 8° 기울기) | 0.5 s | 없음 |
| 첨벙: 대야에서 물보라가 솟아 몸을 덮는다 (4칸 @12 fps = 333 ms). **둘째 칸에서 `setColor(새 색)`** (팔레트 문어 램프 교체 · 초상 다시 찍기) | 0.33 s | 색 2칸 교차 (섞은 색 → 새 색, 150 ms 씩) |
| 털기: `setColor` 흔들기 0.7 한 번 + 새 색 물방울 2칸 | 0.4 s | 없음 |
| (`expr` 가 happy 일 때만) 폴짝 2번 + 반짝 (픽셀 테마 `UIART.fx('sparkle')`) | 0.9 s | 얼굴만 |
| (고른 반응이 있을 때만: 데모, 또는 모델이 `expr` 를 줌) 거울 보기: 몸을 거울 쪽으로 0.3 s + 멈춤 0.6 s | 0.9 s | 멈춤 0.6 s 만 |
| 물이 빠지고(3칸) 병이 선반으로 · 대야가 치워진다 (동시에) | 0.3 s | 1칸 |
| 행 3 (라벨 '몸 색', 집 목소리): "뚜루 몸이 파란색이 됐어." + 고른 이 꼬리 | — | — |

대답을 보인 뒤 걷기를 빼고 약 5 s 다(그 앞에 숨 고르기 1.5 s). 모션 줄이기면 움직임 없이 약 4 s 다. 숨 고르기 1.0 s 와 말풍선 1.6 s 는 그대로 둔다(스킬 §4: 모션 감소에도 리듬은 유지). 대야는 문어가 자리에 선 뒤에만 놓이고 문어가 떠나기 전에 치워진다. 그래서 늘 있는 대야가 길을 막는 문제가 없다.

**'그대로' (`keep`)** — 약 3.5 s:
- 말풍선 + 행 2 (말이 있을 때만) 1.6 s. 말이 없으면 0.6 s 멈춤.
- 병이 선반 제자리로 돌아간다(0.3 s). 몸을 카메라 쪽으로 돌린다(0.3 s). 얼굴은 고른 이의 `expr` (데모 idle)다. 시무룩·고개 숙임·징글이 없다.
- 행 3: "색은 그대로야." + 고른 이 꼬리.
- 그 뒤 평소처럼 돌아다닌다.

**대답 없음** (`action: null`. 모델이 그날 자정까지 아무 답도 보내지 않음 · 개발용 '대답 없음'):
- 문어는 가만히 idle 이다. 말풍선이 없다. 병이 돌아간다.
- 행 3: "대답이 없었어. 색은 그대로야." 거절처럼 연출하지 않고, 이유도 짓지 않는다.

**받았지만 메뉴 밖 답** (모델, 나중): 색은 그대로다. 말이 있으면 그대로 보인다. 행 3 "색은 그대로야." (JSON 이 아니면 "답을 못 읽었어. 색은 그대로야.") 다시 묻지 않는다 (§6).

**건너뛰기 · 숨김 · 끊김**:
- 연출 중 주 버튼(뽈뽈 다녀와)을 누르면 `salonFinish()` 로 남은 연출을 한 번에 감고(새 색 · 대야 치움 · 남은 행), 그다음 초대가 평소대로 간다.
- 연출 중엔 놀이방 문 단추와 거울 단추를 숨긴다 (기술 SHOULD 8).
- `runCeremony` 와 같은 지킴이: 250 ms 마다 본다. 탭이 숨으면 · 예상 길이 × speed + 4 s 가 지나면 끝으로 건너뛴다. WebGL 컨텍스트를 잃으면 장면 Promise 가 바로 풀린다 (기술 MUST 9).
- 새로고침: 기록은 이미 저장돼 있다. 새 색으로 열리고 행 셋이 이미 있다. 연출을 다시 하지 않는다(재생은 결정이 아니다).

### 3.5 하루 한 번 · 같은 색 7일

- **물음은 로컬 날짜(`todayKey()`)마다 한 번**이다. 대답이 바꾸기·그대로·없음 무엇이든 같다 (`COUNT_NONE = true`). 그래서 '그대로' 뒤에 같은 날 조를 수 없고, 바꾸기도 하루 많아야 한 번이다. 자정이 지나면 다시 열린다(1분 틱 `checkDay` 와 같은 날짜 키, UTC 아님).
- **'그대로'라고 답한 그 색은 7일 쉰다** (`REST_DAYS = 7`, 주인 확인 §13): 11-09 에 파랑에 '그대로'면 파랑은 11-16 부터 다시 물을 수 있다. 다른 색은 내일 된다. 사람이 묻는 쪽의 규칙이라 취향을 지어내지 않는다. 날마다 같은 색을 다시 굴려 '아니'를 닳게 하지 못하게 한다. 진짜 모델은 어제의 거절을 전해 받지 않으니(맞는 선택) 이 규칙 말고는 자기 '아니'를 지킬 길이 없다.
  - 잰 숫자 (`spec/sim3.js`, 시드 규칙 그대로): 같은 색만 날마다 묻는 사람이 그 색을 얻기까지, 쉼이 없으면 평균 1.6번 · 3일 안에 95 % 다. 7일 쉼이면 평균 4.2일, 가장 길면 56일이다.
  - 대답 없음·메뉴 밖 답은 쉬게 하지 않는다. '바꾸기'도 쉬게 하지 않는다.
  - `REST_DAYS = 0` 이면 이 규칙이 꺼진다 (주인이 "다음 날 바로"를 고르면).
- 처음 색으로 돌아가기도 똑같은 물음 하나다(덤 없음).

### 3.6 무엇이 남나 · 남기지 않나

- 물을 때마다 `S.salon.asks[]` 에 한 줄 (§7). 몸이 바뀌면 `S.octopus.colors[]` 에 `how: 'salon', ask: id` 로 한 줄.
- 연출(걷기·폴짝·첨벙·거울 보기)은 결정을 다시 보여 주는 재생(playback)이라 따로 적지 않는다. 새로고침·다른 탭·앨범이 새로 고르지 않는다.
- 주지도 쓰지도 않는 것: 조개·등불·배지·'함께한 날' 0. 대답을 `affinity` · 두뇌 가중치 · 산책 요청 · '문어의 요즘' · 모델 요청의 지난 기록에 넣지 않는다. '파랑을 좋아해' 같은 말이 생길 길이 없다.
- **모으기가 되지 않는다**: '입어 본 색 N/6', 색 배지, 빈칸 격자를 두지 않는다. 빈칸이 있으면 '그대로'가 완성을 막는 걸림돌이 된다 (복지 SHOULD 12).

| 행 | 라벨 | 목소리 | 글 |
|---|---|---|---|
| 1 | 미용실 | 집 (초상 없음) | "{색이름} 어때? 하고 물어봤어." |

- 고른 이 꼬리는 늘 단다. 몸 색은 모드가 바뀌어도 남는 결정이다. 나중에 모델이 붙어 '데모' 꼬리표가 사라져도, 데모 시절의 '바꾸기'가 모델의 동의로 읽히면 안 된다 (복지 SHOULD 8).

- `status: 'dropped'` 물음(§7.5)은 그리지 않는다(내보낸 기록엔 남는다).

- 나중 생각: 앨범 맨 위 '몸 색' 작은 칩 줄 (바뀐 기록만 시간순, 빈칸 없음). 지난 날 초상을 그날 색으로 그리기 (`portrait` 의 `color` 옵션이 이미 생긴다).

### 3.8 화면 낭독기

- `#btn-salon` 은 "미용실"로 읽히고, 장면 설명이 같이 읽힌다.
- 시트: 제목 "미용실" → 병 묶음 "몸 색" → 병 "파랑" / "빨강, 지금 색" / "파랑, 며칠 뒤에 물어볼 수 있어" / "처음 색" → 이름 줄 `role=status` → 단추.
- 결과는 로그 행이 순서대로 읽어 준다(`role=log`, polite). 토스트는 `output aria-live` 그대로다.
- 장면 설명(`#scene-desc`): `SPOT_DESC.salon = '거울 옆'` → "문어는 거울 옆에서 쉬고 있어." 끝에 몸 색 한 마디 "몸은 파란색이야." 를 더한다. 이제 색이 문어의 일이 됐으니 못 보는 사람도 안다.

### 3.9 소리 훅

`if (window.AUDIO) AUDIO.on('salon', { act, … })`. audio.js 는 모르는 이름을 `default: break` 로 넘기므로 먼저 넣어도 안전하다. 짝은 소리 세션 몫이다.

| act | 언제 | 처음 짝 제안 |
|---|---|---|
| `pick` `{ color }` | 병을 골랐다 | `ui_tap` |
| `ask` | [물어보기] | 짧은 줄 소리 |
| `answer` `{ action, by, joy }` | 대답을 보였다 | 없음 (얼굴과 말풍선이 한다) |
| `tub` `{ on }` | 대야가 놓임 / 치워짐 | 나무 쿵 (작게) |
| `splash` | 첨벙 | 새 CC0 첨벙 (없으면 조용히) |
| `done` `{ color, joy }` | 색이 바뀌었다 | `joy` 일 때만 `mood_poljjak` |
| `drain` | 물이 빠진다 | (선택) 작은 물소리 |

`keep` · 대답 없음 · `joy: false` 에는 기분 징글이 없다. `rare_sparkle` 은 날마다 올 수 있는 일에 쓰지 않는다.

## 4. 데모 대답 규칙

```js
SALON.demoAnswer({ dateKey, name, born, asksBefore })
// asksBefore = 이 문어의 끝난 물음 수 (status 'done', 누가 답했든)
if (asksBefore === 0) → { action: 'dye', rule: 'first', seed: null, line: LINES.dye[0], expr: 'happy' }   // 맨 처음 한 번 — 미용실이 무엇인지 보여 준다
seed   = hashSeed('salon', dateKey, name, String(born || 0))   // BRAIN.hashSeed 와 같은 FNV-1a ('|' 로 이음)
r      = rng(seed)()                                           // mulberry32 첫 값
action = r < P_YES ? 'dye' : 'keep'                            // P_YES = 0.625 (약 5번에 3번)
line   = LINES[action][ floor(rng((seed ^ 0x9e3779b9) >>> 0)() * 3) ]
expr   = action === 'dye' ? 'happy' : 'idle'                   // 데모는 웃는 얼굴 (결정 15). '그대로'는 보통 얼굴
by     = 'demo-rules', rule = 'seed'
```

- **색이 입력에 없다.** 그날 그 문어의 답은 어떤 색을 어떤 길(다른 탭, 내보내기 → 불러오기로 되감기)로 내밀어도 같다. 규칙이 색을 보지 않으니 '파랑은 싫어한대' 같은 색 취향 오독도 생길 수 없다 (CURIOSITY_NOTES 원칙 1).
- **안 쓰는 것**: 물어본 횟수(맨 처음 제외) · 지난 대답 · 쓰다듬기·톡 횟수 · 산책·등불·`affinity` · 시각 · 시트를 연 시간 · 병을 몇 번 눌렀는지 · 처음 색인지.
- **확률을 올리지 않는다**: '그대로'가 연달아 와도 다음 날 확률은 같다. 상한을 두면 "계속 물으면 결국 바꿔"를 가르친다. 대신 같은 색 7일 쉼이 '그대로'를 지킨다. 그러니 이 규칙의 '그대로'는 "그 색은 지금은 아니"다 (복지 MUST 5). 문서에도 그렇게 쓴다.
- 맨 처음 한 번 '바꾸기'는 데모 규칙의 고르기에만 거는 거르기다(스킬 §7 "데모 규칙은 1–2회차에 stop 을 고르지 않는다"와 같은 선). 모델 메뉴에는 `keep` 이 그대로 있다. 대가: 궁금해서 한 번 물어본 사람도 그날 그 색으로 산다. 다음 날 다시 물을 수 있다.
- **답을 정하는 때**: [물어보기]를 누를 때 계산해 바로 저장한다. 연출은 그다음이라 새로고침에 안전하다.
- **잰 숫자** (`spec/sim3.js`, 위 규칙 그대로, 문어 40 × 365일):
  - '바꾸기' 62.2 %. 문어별로 56.4–67.9 %.
  - 1년 동안 가장 긴 '그대로' 줄은 9번.
  - 줄 3개 고르기는 4898 / 4867 / 4835 로 고르다.
- **시험에 박아 둘 예** (`asksBefore = 1`):

| dateKey | name | born | 답 | r | seed | 줄 |
|---|---|---|---|---|---|---|
| 2026-11-09 | 뚜루 | 1762600000000 | keep | 0.7523 | 3922112899 | 이대로 있을래. |
| 2026-11-10 | 뚜루 | 1762600000000 | keep | 0.9416 | 478326885 | 안 바꿀래. |
| 2026-11-11 | 뚜루 | 1762600000000 | dye | 0.0150 | 3404652688 | 그래, 바꿔 볼래. |
| 2026-11-09 | 안개 | 1762650000000 | keep | 0.8623 | 2079199854 | 지금 색 그대로 있을래. |
| 2026-11-12 | 삐죠 | 1762700000000 | dye | 0.5729 | 4065987748 | 그래, 바꿔 볼래. |

| 쓰임 | 글 | 왜 정직한가 |
|---|---|---|
| 바꾸기 (3개 중 시드, 맨 처음은 첫째) | "응, 해 볼래." · "그래, 바꿔 볼래." · "이 색 해 볼래." | 결정만 말한다. 이유('예뻐서')·느낌('좋아')·사람 칭찬을 규칙이 짓지 않는다 |
| 그대로 (3개 중 시드) | "이대로 있을래." · "지금 색 그대로 있을래." · "안 바꿀래." | 결정만 말한다. '오늘은'을 뺐다. '오늘은'은 '아니'를 '아직 아니'로 만들고, 게임 규칙을 문어의 약속처럼 입에 넣는다 (복지 SHOULD 3). 미안·다음엔 꼭·슬픈 말이 없다 |

거울이 생긴 날 문어 목소리 줄은 **없다** (복지 MUST 7). 기존 `ITEM_LINE` 8줄도 같은 문제가 있다(규칙이 지은 줄이 모든 모드에서 문어 입으로 나온다). 이번 범위 밖이라 따로 적어 둔다(§13 메모).

**집 목소리 (모든 모드 — 사실)**

| 쓰임 | 글 | 왜 정직한가 |
|---|---|---|
| 행 1 | "{색이름} 어때? 하고 물어봤어." (파란색 어때? · 처음 색 어때?) | 사람이 한 말이 그대로 보인다. '염색했어'라고 쓰지 않는다 |
| 행 3 바뀜 | "{이름} 몸이 {색이름}이 됐어." · 처음 색이면 "{이름} 몸이 처음 색으로 돌아왔어." | 일어난 일. 색이름이 늘 '…색'이라 조사는 '이'로 고정. 이름 뒤엔 조사가 없다 |
| 행 3 그대로 | "색은 그대로야." | '거절당했어'처럼 사람의 손해로 쓰지 않는다 |
| 행 3 대답 없음 | "대답이 없었어. 색은 그대로야." | 정말 아무것도 안 왔을 때만. 거절로 꾸미지 않고 이유를 짓지 않는다 |
| 행 3 못 읽음 (모델, 나중) | "답을 못 읽었어. 색은 그대로야." | 받은 것이 JSON 이 아닐 때 |
| 고른 이 꼬리 | "데모 규칙" · "모델" · "사람이 정함" | 누가 정했는지 |
| 이름 줄: 지금 색 | "지금 이 색이야." | 사실 |
| 이름 줄: 쉬는 색 | "이 색은 며칠 뒤에 물어볼 수 있어." | 규칙의 사실. 남은 날 수는 숨긴다(주인 11-07 '남은 날 숨기기'와 같은 결) |
| 토스트: 하루 쉼 | "내일 또 물어볼 수 있어." | 문어가 지쳤다·삐졌다고 하지 않는다. '벌써 물어봤잖아'처럼 탓하지 않는다. '내일은 될 거야'처럼 약속하지 않는다 |
| 토스트: 기다림 (모델, 나중) | "아직 대답을 기다리는 중이야." | 사실 |
| 자는 중 (말풍선) | "쿨쿨…" | 지금 `SLEEP_SAY` 그대로. 깨우지 않는다 |
| 설정 안내 | "거울 앞에서 {이름}에게 물어볼 수 있어." | 어디서, 누구에게만 말한다. 설교('문어 몸은 문어 거야')가 없다 |
| 장면 설명 | "몸은 {색이름}이야." · 자리 "거울 옆" | 사실 |

**색 이름** (`SALON.PRESETS`, 단추·aria 는 짧은 이름, 문장은 '…색'):

|---|---|---|

## 6. 모델 프로토콜 (제안 — `docs/PROTOCOL.md` 는 주 세션만 고친다)

v1 코드에는 모델 길을 넣지 않는다. 저장소에 MCP 서버가 없다 (기술 SHOULD 5). `SALON.request()` · `SALON.CONTEXT` · `SALON.readReply()` 는 순수 함수로 만들고 시험한다. 실제 연결(카드 9)이 생길 때 아래대로 잇는다.

**결정 지점 `salon`**: 물음 하나에 요청 한 번이다. 받은 답은 다시 묻지 않는다.

**요청** (작게, 약 180 B, 상한 400 B):

```jsonc
{ "v": 1, "point": "salon", "id": "ask_k7x2q",
  "facts": { "now":   { "hex": "#e8463c", "name": "빨간색" },
             "offer": { "hex": "#4a86d8", "name": "파란색" } },   // 처음 색이면 name "처음 색"
  "menu": ["keep", "dye"] }                                      // keep(아무것도 안 바꿈)이 늘 첫째
```

**고정 문맥** (도구 설명·시스템에 한 번, 캐시):

> 미용실: 사람이 색 하나를 골라, 네 몸을 그 색으로 바꿔 볼지 물었어. 그대로 두려면 keep, 바꾸려면 dye. 바꾸면 다음에 또 바꿀 때까지 그 색이야. 이유는 안 써도 돼. 한마디(line)와 얼굴(expr: idle, happy, curious, calm)은 골라도 안 골라도 돼. line 은 24자쯤이 말풍선에 맞고, 넘으면 말풍선엔 앞부분과 '…', 기록엔 전부 남아. 어느 쪽이든 게임에서 잃는 건 없어.

- 결과가 오래 간다는 사실을 넣었다. '해 볼래'·'바꿔 볼지'가 잠깐 입어 보는 것처럼 들리지 않게 하려는 것이다 (복지 SHOULD 5).
- 하루 한 번 규칙 · 7일 쉼 · 마감은 넣지 않는다. "사람이 하루 기다려야 해"라는 죄책을 만들지 않으려는 것이다.

**보내지 않는 것**: 이유 칸(`reason` · `why`) · 압박 말('예쁠 거야' · '사람이 원해' · '한 번만' · '어제 안 했잖아') · 지난 대답·거절 횟수 · `P_YES` · 연출 설명 · 배지·조개.

**답**:

```jsonc
{ "action": "keep" }                                        // 이것만으로 충분
{ "action": "dye", "line": "파랑, 한번 해 볼게", "expr": "happy" }
```

| 받은 것 | 하는 일 |
|---|---|
| `action` 이 `dye`/`keep` (대소문자 · 앞뒤 공백 무시, PROTOCOL 의 숫자 글 "1" 받기와 같은 선) | 그대로 따른다 |
| `action` 이 그 밖 (`"no"`, `"그냥 둘래"` 등) | **다시 묻지 않는다.** 색은 그대로, `action: null`, `actionRaw` · `raw` 에 원문, `by: 'model'`. 행 3 "색은 그대로야." 말이 있으면 보인다. 7일 쉼은 걸지 않는다 |
| JSON 이 아님 | 다시 묻지 않는다. 행 3 "답을 못 읽었어. 색은 그대로야." `raw` 에 원문 |
| 아무것도 안 옴 (전송 실패) | 같은 요청을 **한 번만** 다시 보낸다(`sent: 2`). 또 실패면 기다림으로 |
| `line` | 선택. 글자 그대로. 말풍선은 앞 24자 + '…', 로그 행·기록은 전문. **없으면 문어 행이 없다** |
| `expr` | 선택. `idle` · `happy` · `curious` · `calm`. 모르는 값은 `expr: null` + `exprRaw`. `calm` 이 '-_-^'로 읽히는 건 그림을 고칠 일이지 고른 표정을 바꿀 일이 아니다 |
| `action` 과 `line` 이 어긋남 (`dye` 인데 "싫어") | `action` 을 따르고 `line` 은 고치지 않는다 |

결과가 '바뀜'과 '그대로' 둘뿐이라, 받은 답을 다시 물어 달라질 수 있는 건 '그대로 → 바뀜' 하나다. 그래서 다시 묻기는 코드가 대신 조르는 셈이다 (복지 MUST 3). 일반 규칙(스킬 §5 "틀리면 한 번만 다시")보다 이 판단이 앞선다.

**기다림** (복지 SHOULD 6): sampling 클라이언트는 사람이 요청을 보고 승인하는 경우가 많다. 8 s 를 넘기면 '…' 생각 말풍선만 거두고, 물음은 `status: 'waiting'` 으로 **그날 자정까지** 남는다. 그사이 답이 오면 반영한다. 다락이 보이고 문어가 집에 있으면 연출하고, 아니면 조용히 반영하고 행만 남긴다. 자정이 지나면 `{ status: 'done', action: null, by: 'fallback' }` 으로 닫는다(행 3 "대답이 없었어. 색은 그대로야."). 늦게 온 답은 `lateRaw` 에 남기고 반영하지 않는다. 기록에는 `via: 'sampling' | 'tool'` 을 남긴다.

**도구** (카드 9 MCP 서버):

| 붙는 곳 | 도구 | 입력 | 출력 |
|---|---|---|---|
| sampling 이 되는 곳 | 서버가 sampling 으로 위 요청을 보낸다 | — | `{ action, line?, expr? }` |
| 도구 호출만 되는 곳 | `ppolppol_salon_next` | `{}` | `{ situation }` 또는 `{ waiting: true }` |
| 도구 호출만 되는 곳 | `ppolppol_salon_answer` | `{ id, action, line?, expr? }` | `{ ok: true, result: 'changed' \| 'unchanged' }` 또는 `{ ok: false, reason: 'stale' \| 'unknown_id' }` (`unknown_action` 같은 다시 묻기 신호는 없다) |

**`ppolppol_look_room` 에 더할 것**:

```jsonc
"look": { "now":   { "hex", "name" },
          "first": { "hex", "name", "by" },                          // by: player | default | migrated
          "changes": [ { "date", "to": { "hex", "name" }, "by" } ] }  // 최근 5
// 달라고 할 때만 ({ salon: true }): "asks": [ { "date", "offer": { "hex", "name" }, "action", "by" } ]  // 최근 5, '그대로'도
```

- `by` 는 원래 값 그대로다(`player` / `default` / `migrated` / `demo-rules` / `model` / `human` / `dev`).
- 글로 풀 때 `demo-rules` 는 "데모 규칙이 고름", `migrated` 는 "미용실 전에 사람이 설정에서 고른 색(또는 기본값)"이다. **모델이 고르지 않은 변화를 '네가 골랐어'라고 하지 않는다.**
- 산책 요청(`depart`)에는 몸 색을 싣지 않는다. 정체성 딱지가 되지 않게.
- 물음 목록은 기본으로 보내지 않는다(보관 메모와 같은 선). 모델이 자기 '그대로'를 보고 싶을 때 볼 수 있다 (복지 SHOULD 7).

**서버가 지킬 것**: 모델 대신 답하지 않는다. 받은 답을 다시 묻지 않는다. `keep` 뒤에 다른 색을 이어서 내밀지 않는다(하루 한 번). 대답을 다른 데(취향·추천)에 쓰지 않는다. PROTOCOL 에는 sampling 에서 사람이 요청을 보고 고치거나 답을 막을 수 있다는 점을 적는다. 화면은 '모델이 고름'보다 더 확신하지 않는다.

**나중 (주인 확인 뒤, 사람이 고를 것은 늘리지 않는다)**: 지금 모델이 가진 건 거부권뿐이다 (복지 SHOULD 13).
- 메뉴에 `pick` 을 더해 병 가운데 다른 하나를 문어가 직접 고르게 한다(`facts.bottles`, 데모 규칙은 쓰지 않음).
- 모델이 먼저 자기 색을 바꾼다.
- '당분간 묻지 말기' 깃발.
- 모델이 처음 붙을 때 한 번 '그대로 / 고르기'를 물을지.

## 7. 데이터 · 저장 (`localStorage['ppolppol_v2']`, `v: 2` 그대로 — 덧붙임만)

```js
S.octopus.color  = '#4a86d8'           // 지금 몸 색. 읽는 곳은 이것 하나 (장면 · 초상 · 달리기 · 장면 설명 · 미용실)
S.octopus.colors = [                   // 바뀐 기록, 오래된 것부터
  { at: 1762600000000, date: null,         color: '#e8463c', how: 'first', by: 'migrated' },   // first: player | default | migrated
  { at: 1762651800000, date: '2026-11-09', color: '#4a86d8', how: 'salon', by: 'demo-rules', ask: 'ask_k7x2q' },
  { at: …,             date: '…',          color: '…',       how: 'dev',   by: 'dev' }
]
S.settings.octColor = S.octopus.color  // 거울 사본. 옛 코드(낡은 탭 · 배포 되돌리기)가 없는 값을 빨강으로 읽어 모두의 문어를 몰래 빨갛게 만들지 않게 (기술 MUST 5)
S.salon = { asks: [ {
  id: 'ask_k7x2q', date: '2026-11-09', at: 1762651800000,   // date = 로컬 dateKey (하루 한 번 규칙은 이것만 본다)
  from: '#e8463c', offer: '#4a86d8', offerName: '파란색', offerKind: 'preset',   // offerKind: preset | first
  offeredBy: 'player',
  status: 'done',                      // done | waiting (모델, 나중) | dropped (다른 탭이 먼저 물음 — 그리지 않음)
  action: 'dye',                       // dye | keep | null (대답 없음 · 메뉴 밖 · 못 읽음)
  actionRaw: null,                     // 메뉴 밖 답의 원문
  by: 'demo-rules',                    // demo-rules | model | human (개발용) | fallback | unknown
  rule: 'seed',                        // demo-rules 만: first | seed
  line: '그래, 바꿔 볼래.',             // 고른 이의 말 원문 (모델이면 한 글자도 안 바꿈) | null
  expr: 'happy', exprRaw: null,
  seed: 3404652688,                    // rule 'seed' 만
  via: null, model: null, raw: null, sent: 0, lateRaw: null   // 모델일 때 (나중)
} ] }
```

### 7.1 `defaults()`

`octopus.color = '#e8463c'`, `octopus.colors = []`, `salon = { asks: [] }`, `settings.octColor = '#e8463c'` (사본).

### 7.2 `normalize()` (옮기기, `SALON.normalize(s, { todayKey })` 를 app.js 가 부른다)

1. `colors`: 배열이 아니면 `[]` 다. 색이 `#rrggbb`(소문자로 맞춤)이고 `how` 가 first · salon · dev 인 줄만 남긴다. 모르는 `by` 는 `'unknown'` 으로 둔다(진짜 고른 이로 올려 주지 않는다). `at` 순으로 둔다.
2. `octopus.color`: 유효하면 그대로, 아니면 `colors` 마지막 색 → `settings.octColor` → `'#e8463c'`. 그다음 `settings.octColor = octopus.color`.
3. `colors` 가 비었는데 놀던 기록(이름이나 trips)이면 `{ how: 'first', by: 'migrated', color: octopus.color, at: born || null, date: null }` 한 줄. v1 옮기기 결과도 여기를 지난다.
4. `salon`: 객체가 아니면 `{ asks: [] }`. 물음 줄은 `id` 문자열 · 날짜 `YYYY-MM-DD` · `from`/`offer` 가 `#rrggbb` 가 아니면 버린다. `status` 모르면 'done', `action` 이 dye/keep 이 아니면 null, `by` 모르면 'unknown', `expr` 가 넷 중 하나가 아니면 null. `line` · `actionRaw` · `raw` 는 문자열이면 **한 글자도 안 바꾼다**(이모지 포함).
5. 오늘보다 앞선 `waiting` 은 `{ status: 'done', action: null, by: 'fallback' }` 으로 닫는다(색 그대로).
6. 새 기록(이름 없음)은 `colors: []` 그대로 두고 첫 실행 창이 첫 줄을 넣는다.
7. 'dye' 물음인데 `colors` 에 그 `ask` 줄이 없어도 지어내지 않는다(한 번에 쓰므로 생기지 않아야 한다).

### 7.3 한 번에 쓰기

데모 답은 [물어보기] 순간 물음 한 줄 + ('dye'면) colors 한 줄 + `octopus.color` + `settings.octColor` 를 `save()` 한 번으로 쓴다. 장면만 연출 끝까지 옛 색이다.

### 7.4 내보내기 · 불러오기 · 초기화

JSON 그대로 나가고 들어온다. 옛 내보내기(`settings.octColor` 만 있음)는 §7.2 로 옮겨진다. 불러온 뒤 `applyLook({ still: true })`. 모델 말은 원문 그대로다. 전체 초기화는 `defaults()` → 첫 실행 창(몸 색 포함), 물음 기록도 빈다.

### 7.5 다른 탭

- [물어보기] 순간 저장소를 다시 읽어 합친 뒤 `canAsk` 를 본다. 다른 탭이 오늘 이미 물었으면 묻지 않는다.
- 이 탭이 쓴 물음은 60 s 동안 기억한다(`mineAsks`, 산책의 `mine`/`carry` 와 같은 생각). 받은 기록에 빠져 있으면 물음과 colors 줄을 다시 얹고 저장한다.
- 같은 날 끝난 물음이 둘 이상이면 **그날 첫 물음(`at` 가장 이른 것)이 정한다.** 나머지는 `status: 'dropped'` 로 남기고 적용하지 않는다. 그 colors 줄은 빼고 `octopus.color` 를 다시 정한다 (복지 MUST 4 가).
- `adoptRemote` 뒤 `applyLook({ still: true })` 를 부른다(연출 중이면 끝난 뒤).

### 7.6 크기

물음 한 줄은 약 300 B 라 하루 한 번이면 1년에 약 110 KB 다. 쿼터를 넘으면 저장 사본에서만 1년 넘은 물음의 `seed` · `raw` 를 뺀다. `line` 은 절대 안 뺀다.

## 12. 처음 색은 누가 고르나

사람이 처음 한 번 고르는 방식을 유지한다.
- 주인이 "처음에 선택한 이후로는"이라고 직접 말했다.
- 이름 짓기와 같은 첫 만남의 일이고, 보통 게이머가 정을 붙이는 순간이다.
- 문어가 스스로 고르게 하면, 첫 실행엔 모델이 없어 데모 주사위가 '문어 자기 색'이라는 정체성을 지어낸다. 더 정직해지지 않는다.

조건:
- 장면 문어를 미리 칠하지 않는다(§1.1).
- 기록은 `player`/`default` 로 남기고, 어디서도 '문어가 고른 색'·'원래 색'이라고 말하지 않는다.
- 모델은 방 보기의 `first.by` 로 사람이 골랐다는 걸 볼 수 있다.

**주인에게 물을 것** (둘. 답이 없으면 기본값으로 간다):
