## 찾은 것

### V2-1 should — 부엌을 손가락으로 닫으면 조리대에 노란 포커스 테두리가 남는다

- **재현**
  1. `REC(5)` 로 360x740 터치 화면을 연다. `APP.goRoom('play')` 로 놀이방에 간다.
  2. 조리대(`#btn-cook`)를 손가락으로 톡한다. 부엌이 열린다.
  3. 부엌 안 '닫기'를 손가락으로 톡한다.
- **본 것**: 놀이방으로 돌아오면 조리대 둘레에 노란 2px 테두리와 남색 안쪽 띠가 남는다. 다른 곳을 누를 때까지 그대로다.
  - `ring.js`: `btn-cook {"focused":true,"focusVisible":true,"ringOff":false,"outline":"solid"}`
  - 같은 길의 오락기(달리기 닫기)와 재봉틀은 `focusVisible:false` 다. 테두리가 없다.
- **증거**: `V2/cook-360-back.png` (오른쪽 조리대의 노란 상자), `V2/ring.js` 출력.
- **기준**: 손가락 · 마우스로 연 단추는 '포커스는 두되 링은 없이' (`css/style.css:1125` 주석, `focusRoomBtn`). 키보드(Esc)로 닫을 때 링이 보이는 것은 맞다.
- **자리 (추정)**
  - `openCook` 이 `focusRoomBtn(opener, false)` 로 `ring-off` 를 붙인다.
  - 그런데 포커스가 iframe 으로 넘어갈 때 `on()` 의 `blur` 리스너가 `ring-off` 를 지운다.
  - 덮개가 닫히면 브라우저가 포커스를 조리대로 돌려주는데, 이때는 `ring-off` 가 없어서 `:focus-visible` 링이 그려진다.
  - 덮개 `close` 에서 손가락으로 닫았으면 `ring-off` 를 다시 붙이면 될 듯.

### V2-2 should — 320 폭 폰에서 게임 안 부엌 무대가 한 단 작다

- **재현**
  1. `REC(5)` 로 320x568, dpr 2, 터치 화면을 연다. 놀이방에서 조리대를 톡한다.
  2. 부엌 무대(`.ck-cv`) 크기를 잰다 (`cook-embed-size.js 320 568 2`).
  3. 같은 크기에서 `cook.html` 을 따로 열어 잰다 (`cook-size.js 2`).
- **본 것**
  - 게임 안 덮개는 216x240 이다 (dpr 1 이면 144x160).
  - 따로 연 부엌은 288x320 이다.
  - 360 · 412 폭에서는 둘이 같다 (288 · 360).
  - 덮개의 계산된 스타일: `border: 2px solid`, `box-shadow` 세 겹. 그래서 iframe 안쪽이 316 px 이고, 정수 배 무대가 한 단 내려간다.
  - `:root[data-font="pixel"] dialog[open]:where(:not(.rn-dlg))` 의 떠오르는 움직임도 덮개에 붙는다. 갈래 E 보고는 '테두리 · 여는 움직임 없음' 이라고 했다.
- **증거**: `V2/cook-embed-320-dpr2.png` 와 `V2/cook-standalone-320.png`. `V2/cook-360-open.png` 에도 둘레의 갈색 2px 테두리가 보인다.
- **기준**: 지시문 "놀이방 조리대: 톡하면 요리(COOK)가 바로 열리게". 주인 폰보다 작은 폰에서 손으로 다룰 무대가 4분의 3 로 줄어든다.
- **자리 (추정)**: `css/style.css:1640` 의 `dialog.cook-overlay { border: 0 … }` 가 `:root[data-font="pixel"] dialog` (`css/style.css:688`) 보다 약하다. 픽셀 글꼴 판에서도 이기게 선택자를 세게 하면 될 듯.

### V2-3 should — 2D 폴백에서는 부엌에 갈 길이 없다

- **재현**
  1. `REC(5)` 로 `?scene=2d` 를 360x740 터치로 연다.
  2. 다락의 문(`#btn-door`)을 톡해 놀이방으로 간다.
- **본 것**
  - 2D 놀이방 그림 오른쪽에 조리대(서랍 · 선반)가 그려져 있다. 그런데 보이는 단추는 `btn-settings`, `btn-play-door`, `btn-machine` 뿐이다.
  - `#btn-cook` 은 `hidden` 이다. 2D 에서는 부엌으로 가는 다른 길도 없다.
  - 오락기 → 달리기는 2D 에서도 열리고 닫힌다.
- **증거**: `V2/2d-play.png`, `V2/fallback2d.js` 출력 (`cook btn {"hidden":true}`).
- **기준**: V2 지시문 "the 2D fallback (`?scene=2d`) still playable for all of the above that exists in 2D". 조리대는 2D 그림에 있다.
- **자리 (추정)**: `js/scene2d.js:170` `SPOT_BOX` 에 `machine` 처럼 `counter: [x, y, w, h, 'play']` 한 줄이 없다. 앱 쪽 `ROOM_SPOT.counter` 는 이미 있다.

### V2-4 should — 짧은 로딩에서는 로딩 문어가 반쯤 잘린 채로만 보인다

- **재현**
  1. 저장소 뿌리를 `python3 -m http.server 8765 --bind 127.0.0.1` 로 띄운다.
  2. `boot.js 1000` 을 돌린다. three · scene3d · app 스크립트를 1초씩 늦춘다.
- **본 것**
  - 로딩 문어(112 px 폭)는 `translateX(-112px)` 화면 밖에서 출발해, 5.6 s 에 한 번 건넌다.
  - 화면에 몸이 다 들어오는 것은 출발 뒤 약 1.33 s 다 (112 / 472 × 5.6).
  - 1초 늦춘 로드에서는 걷히기 직전 마지막 틀이 x = -50 이었다. 112 px 중 62 px 만 보였다 (`V2/boot-1s-load-edge.png`: 왼쪽 가장자리에 문어 반쪽).
  - 늦추지 않은 로컬 로드에서는 `#boot` 가 4프레임만 보이고, 문어는 화면 밖(-112)에 있었다. 그때 플레이어는 빈 남색 화면만 본다.
  - 다시 찾는 사람(캐시)은 대개 이 경우다. 2.5 s 늦춘 로드에서는 가운데를 잘 건넌다 (`V2/boot-2.png`).
- **좋은 것**
  - 빨간 벡터 문어(`#oct-svg`)는 늦춘 로드 · `?intro=1` · 동작 줄이기 모두에서 걷히기 전 0프레임이었다.
  - 게임이 그리면 바로 걷힌다 (`html.booted`).
  - 동작 줄이기에서는 가운데 멈춘 한 칸이다 (`V2/boot-reduce-2.png`).
- **기준**: 주인 11-15 "게임 속 픽셀 문어가 왼쪽에서 오른쪽으로 뽈뽈 기어가는 반복 그림". 짧은 로딩에서는 기어가는 문어가 아니라 가장자리의 잘린 조각이 깜빡 보인다.
- **자리 (추정)**: `index.html` 머리 `<style>` 의 `#boot .boot-oct` `boot-cross`. 예를 들어 음수 `animation-delay` 로 가운데 근처에서 시작하거나, 첫 바퀴만 화면 안 왼쪽 끝(0)에서 출발하게 하면 될 듯.

## 문제없던 것 (확인한 그대로)

  - 시트 높이: 360x740 은 0.46, 412x915 는 0.38, 320x568 은 0.61 (글자 길이는 H 몫이라 뺀다).
  - 세트 도감은 '세트 도감 0/9' 한 줄로 접혀 있고, 누르면 펼친다. 콘솔 에러 0.
