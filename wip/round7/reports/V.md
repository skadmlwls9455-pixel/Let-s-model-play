# 갈래 V 보고 — 마을에 서 있는 것 (`lane/7-v`, 11-21)

## 결론

마을 길과 광장에 **옷가게 · 잡화점 · 카페 덱 · 빈 집 · 광장 (게시판 · 무대 · 우물)** 과 길 소품이 서 있고, 단추 열 개와 NPC 문어 API · 카페 자리가 계약 C6 대로 들어갔다.
갈래 W 의 브랜치 (6c873fd) 와 **시험용으로만** 내 컴퓨터에서 합쳐 (푸시하지 않음) 진짜 땅 · 진짜 배관 위에서 브라우저 시험 109 개가 다 통과했다. 내 브랜치만으로는 장면의 시험 스텁 위에서 89 개 통과.
새 셰이더 프로그램 0 · 점광 0 · 마을 것만의 드로우콜 6 ~ 29 (예산 40) · 바깥 전체 41 ~ 70 (예산 150).

가장 큰 판단 하나: **폰 화면은 가로 6.7 m 뿐이라 계약의 길 (±3 m) 이 화면을 다 채운다.** 터 (|t| 3.5 ~ 10) 에 얌전히 지으면 길 한가운데를 걸을 때 가게가 하나도 안 보였다.
그래서 건물을 길에 바짝 붙이고 판매대와 가게 문어를 길 가장자리로 내놓았다 (아래 '주인이 확인할 결정' 1).

## 내보낸 API (`APP.scene`, 정확히)

- `npcSpots()` → `[{ id, x, y, z, face }]` (일곱)
- `npcSet([{ id, color, hat, pose }])` → 그린 수. 목록에 없는 문어는 지운다. 모르는 id 는 버리고, 모르는 모자 · 자세 · 색은 기본값 (`none` · `stand` · `#d9694f`). 마당을 짓기 전에 불러도 기억한다
- `npcMark(id, on)` → 켜졌나 (그려지지 않은 문어면 false)
- `cafeSit(true)` → `Promise<앉았나>` · `cafeSit(false)` → `Promise<일어났나>` · `cafeCup(on)` → 보이나 (앉아 있을 때만) · `cafeSeated()`
- `villageGo(단추 id | key)` → `Promise<가까이 섰나>` · `villageNear(단추 id | key)` → boolean
- `document` 이벤트 `ppol:cafe-seat` (`detail: { on }`)
- 시험용: `villageInfo()` · `debugVillageStub()` · `debugVillageFrame(dt)` · `debugVillageHide(on)`

## 주인이 확인할 결정

1. **건물을 길에 붙였다.** 폰 (360 px) 은 바깥에서 가로 6.7 m 만 보인다. 계약대로 터 안쪽에 지으면 길 가운데에서 가게가 안 보여, 길 쪽 모서리를 |t| 3.2 로 당기고 판매대 · 가게 문어를 길 가장자리 (|t| 2.2 ~ 3.3) 에 내놓았다. 더 좋은 길: 마을 구간의 걷는 폭을 ±2.2 로 좁히거나 (갈래 W), 바깥에서 한 단계 멀리 보기.
2. **건물은 등각 (x · z 축).** 마당 집과 같은 꼴이다. 가게 앞면이 길 쪽 · 아래쪽을 비스듬히 본다.
3. **카페 덱에 지붕이 없다.** 기둥 넷과 가는 들보 · 전구 줄뿐이라 어느 각에서 봐도 안이 보인다. 비 · 눈은 덱에도 그대로 내린다 (가릴 지붕이 없으니 덱 안에 떠 있는 입자도 없다).
4. **카페 자리는 식탁 옆.** 식탁 뒤에 앉히면 기본 각에서 식탁이 몸을 가려, 길 쪽 걸상에 식탁을 옆에 두고 앉는다 (옆모습).
5. **NPC 문어의 몸 색은 받은 색보다 한 톤 어둡게** 그린다 (한낮 햇빛에 하얗게 떠서). 재질은 건물과 같은 것이라 다락 문어와 음영이 조금 다르다.
6. **NPC 표시** (`npcMark`) 는 작은 노란 마름모 하나. 차양 밑에서도 보이게 다른 것 위에 그린다.
7. 가게 문어는 **발판 위**에 선다 (판매대가 얼굴을 가려서).
