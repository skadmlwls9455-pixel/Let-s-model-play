# 갈래 S · 다섯째 바퀴 설계 — 계산대 목록 (11-24)

주인 (그대로): "상점이 실제 물건을 반영하기보다는 누르면 세부사항으로 간편하게 살 수 있도록 되어있는데 차라리 npc 상점 직원을 두고 계산대로 가면 리스트업된 게 쭈르르 떠서 그걸 담는 걸로 하자. … 조개 얼마 남았는지도 띄워주고."
주인 결정: 잡화점 · 옷가게 둘 다 · 사는 건 계산대 목록에서만 · 마네킹 톡 → 입어 보기는 그대로.
흐름만 가져온다 (목록 → 담기 → 한 번에 계산). 생김새는 우리 카드 규칙 (종이 · 2px 테 · 4px 그림자 · 16px 바닥).

## 박자

1. 가게 안에서 계산대 (`#btn-room-counter`) 나 직원 문어 (`#btn-npc-clothes` · `#btn-npc-goods`) 를 톡 → 캐릭터가 계산대 앞까지 걸어간다 (건물 갈래의 걸어가기) → 목록 카드가 계산대 위에 뜬다.
2. 목록: 오늘 그 가게가 파는 것 전부 (옷가게 넷 · 잡화점 씨앗 + 그날 염료 셋). 줄마다 작은 그림 · 이름 · 값 꼬리표, 가진 것 · 다 판 것은 도장 (담기 안 됨).
3. 줄 톡 = 담기. 옷은 한 벌에 하나 (다시 톡하면 빼기). 잡화점은 `−` `+` 로 개수 (씨앗은 그날 남은 수까지, 염료는 9 까지).
4. 맨 위에 늘 `조개 N`, 담으면 그 옆에 `담으면 M 남아` (화면 낭독기에는 aria-live). 담으면 조개가 모자라는 줄은 안 담기고 값이 흔들리며 한 줄: `조개가 N 개 모자라`.
5. 아래 `닫기` / `사기 (합계)`. `사기` 한 번에 계산 (값 · 가진 조개 · 가짐을 그 자리에서 다시 본다 — SHOP.buy 를 한 개씩, 옷장에 못 넣은 옷은 값을 안 낸다).
6. 계산 뒤 같은 카드가 영수증으로 1.5 s (`산 것 · 조개 N 냈어`, 묻는 말 · 단추 없음) → 닫힘 · 직원 대본 한 줄 (`shop.pay`). 입어 보던 옷을 샀으면 입은 채로.
7. `닫기` · Esc · 카드 밖 톡 · 방을 나감 → 담은 것은 버린다 (조개는 안 나간다).

마네킹 톡 = 입어 보기 · 벗기만 (꼬리표 카드의 `살래` 는 없앤다, `계산대에서 살 수 있어` 한 줄). 선반 톡 = 그 물건 이름 + `계산대에서 살 수 있어`.
2D 폴백 (방이 없음) = 같은 목록 부품이 예전 시트 안에 뜬다 (시트에서도 사는 건 목록에서만).

## 그림 (360x740, 옷가게 계산대 앞)

```
┌──────────────────────────────────┐ 상태 줄
│  (방 · 마네킹 · 계산대 · 시침)        │
│ ┌──────────────────────────────┐ │
│ │ 시침의 계산대     조개 30       │ │ ← 늘 보임 · 담으면 '담으면 10 남아'
│ │ ┌──┐ 세일러         ⟨24⟩  [ ]  │ │ ← 줄 = 단추 (aria-pressed)
│ │ │그│ 작은 가방      ⟨16⟩  [✓]  │ │
│ │ └──┘ 정장           ⟨36⟩  흐림  │ │ ← 모자라면 흔들림 + 한 줄
│ │      야구모자        ⟨ 4⟩ [팔림] │ │ ← 가진 것 · 판 것: 도장
│ │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │ │
│ │ 담은 것: 작은 가방               │ │
│ │ [ 닫기 ]          [ 사기 16 ]   │ │
│ └──────────────────────────────┘ │
│  (캐릭터는 카드 밖에 보인다)          │
└──────────────────────────────────┘ 큰 단추
```

## 부품 (미용실도 쓴다)

`listOpen(opts)` 하나: `{ id, title, host (장면 안 카드 | 시트 몸통), anchor, items() → [{ key, name, pic(), price, max, mark: 'owned' | 'sold' | 'trying' | null }], wallet() → 조개, buy(cart) → { bought: [{ item, n }], paid, why }, say(key), onClose }`.
가게는 이 위에 옷가게 · 잡화점 두 벌을 얹는다. 미용실은 V · P 가 준비되면 같은 부품에 머리 모양 · 색 목록을 넘긴다.

## 지키는 것

- 담기는 아무것도 쓰지 않는다. 계산은 `사기` 를 누른 뒤에만, 한 번 (0.6 s 두 번 톡 막이). 두 탭 · 불러오기 규칙 (값과 산 것이 함께 · 영수증 기록) 그대로.
- 16px 바닥 (두 글꼴), 320 폭 · 가로 · 큰 글자에서 목록은 접히지 않고 카드 안에서 굴러간다. 움직임 줄이기면 흔들림 · 영수증 반짝임 없음.
- 화면 낭독기: 목록은 단추 줄 (옷 = aria-pressed, 잡화 = `−` `+` 에 이름), 조개 · 합계는 aria-live.
- 글은 사실만 (`담으면 10 남아` · `조개가 6 개 모자라` · `계산대에서 살 수 있어` · `냈어`). 직원 말은 NPC 갈래의 대본 (`shop.enter` · `shop.pay` …).

## 확인할 것 (다른 갈래)

- 잡화점 선반 그림은 여섯 색 · 씨앗이 늘 같다 (V 의 고정 그림) — 그날 염료 셋과 맞지 않는다. 맞추려면 V 쪽에 `scene.goodsShelf(list)` 같은 것이 필요 (리드에게 알림).
- 직원 문어 단추를 누르면 N 의 `talk` 줄과 내 목록이 함께 뜬다 (대사창은 카드를 피한다 — `data-npc-avoid`).
