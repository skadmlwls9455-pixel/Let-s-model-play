# 뽈뽈 문어

비 오는 다락방에 사는 작은 문어에게 "뽈뽈 다녀와" 한 마디를 건네고, 문어가 스스로 고른 산책을 지켜보는 작은 웹 게임이다.

## 무엇을 하는 게임인가

사람이 하는 일은 버튼 하나(`뽈뽈 다녀와`)를 누르는 것이다. 다락 안 **놀이방 문**을 열고 옆방(놀이방)에서 다락방 달리기를 해도 된다 — 문어가 나가 있는 동안에도 (산책은 그대로 흐르고, 돌아오면 구석에 쪽지가 뜬다).
나갈지 집에 있을지, 어디를 기웃거릴지, 무엇을 기억해 포스터로 남길지는 **문어가 고른다.** (주제나 링크를 건네는 힌트 칸은 없다 — 11-10 에 개발 화면에서도 없앴다.)
이 게임은 [뽈뽈 복지 아이디어](https://github.com/skadmlwls9455-pixel/model-welfare-idea)("힘든 대화를 버틴 모델에게 스스로 고르는 회복 시간을 준다")를 놀이로 옮긴 것으로, 그 선택을 **지켜보는 사람 쪽 화면**에 해당한다.

지금 문어를 움직이는 것은 **데모 두뇌(작은 규칙 뭉치)** 다. 진짜 모델이 고르는 것은 아니며, 화면 상태줄의 이름 옆에 작은 `데모` 표시를 두고 모든 일기(포스터 뒷면)에 "데모 두뇌(규칙)"라고 적는다. 모델 연결은 MCP 로드맵(아래)에 있다.

장면은 Three.js 픽셀아트 3D 다락방(`js/scene3d.js`)이 기본이고, WebGL이 없으면 2D SVG 장면(`assets/`)으로 내려간다.

## 바로 열기

- **파일로**: `index.html` 을 브라우저에서 바로 연다(`file://`). `type="module"` 을 쓰지 않아 로컬 파일로도 동작한다.
- **GitHub Pages**: 저장소 루트를 Pages로 올리면 `index.html` 이 그대로 열린다(배포 주소는 예정).
- **단일 파일**: `node tools/bundle.js` → `dist/ppolppol.html` 한 파일이 생긴다. CSS·JS·에셋이 모두 인라인되어 어디서나 열린다.

외부 의존성은 `vendor/three.min.js` 하나이며 빌드 도구는 없다. 폰트는 Google Fonts를 쓰되 없어도 시스템 폰트로 동작한다.

## 핵심 루프 (초대 한 번)

1. **초대** — `뽈뽈 다녀와` 를 누른다. 나갈지·어디로 갈지는 지금은 데모 두뇌(규칙)가 정한다. 힌트 칸은 어디에도 없다(주인 결정 18 → 11-10 에 개발 화면에서도 없앰. 두뇌 안의 옛 힌트 길은 테스트 훅 `__ppolTest.hint` 와 옛 기록 표시용으로만 남아 있고, 걷어내는 일은 남았다). 힌트 대신 다녀온 뒤 두 차례 대화가 다음에 붙는다([docs/DIALOGUE_UI.md](docs/DIALOGUE_UI.md) · [docs/CORE_LOOP_V2.md](docs/CORE_LOOP_V2.md)).
2. **결정** — 두뇌가 `plan(seed, hint, state)` 로 이번 산책 전체를 이벤트 목록으로 미리 계산한다. 시드는 `날짜 + 힌트 + 그날 몇 번째`라서 같은 힌트를 두 번 보내도 다른 길을 간다.
3. **공개** — 문어가 화면 밖으로 나가고 로그에 `출발 → 기웃 ×N → 귀가 → 기억 → 포스터 → 마무리` 가 2~5초 간격으로 붙는다(20~45초. 나가 있는 동안 주 버튼 "다녀오는 중…" 을 누르면 바로 돌아온다 — 다락 문으로 들어와 토스트 · 등불 칸까지 2초쯤의 짧은 귀가. 산책 기록은 끝까지 본 것과 같다). 집에 있는 날은 `집 → 활동 → 마무리` 로 짧다.
4. **귀가** — 문어가 들어오고 포스터가 벽에 걸린다. 작은 포스터 하나가 장면 오른쪽 위 **추억 앨범 아이콘**으로 날아가고, 아이콘에 작은 점이 켜진다(숫자 없음, 앨범을 열면 사라진다. 모션 줄이기면 날지 않고 점만). 그날 처음 다녀온 차례면 등불이 한 칸 켜진다(등불은 **초대한 날마다 1칸**, 같은 날 더 보내도 포스터·기념품은 계속 쌓인다). 등불 8칸이 차면 방이 완성된다(이끼 화분 → 상자 → 양초 → 담요 → 보드 → 가는 비 → 별·선반 → 커튼).
5. **마무리** — 문어가 스스로 반응(폴짝/우쭐/덤덤/졸림)을 고르고 담요에서 1분 30초쯤 깨어 있다가(졸림이면 25초쯤) 낮잠을 잔다. 20분쯤 지나거나 날짜가 바뀌면 스스로 깬다. 깨어 있는 문어를 톡 하면 그날 마지막 차례에 대한 한 줄 (말풍선만 — 데모 산책은 기록 속 사실 하나, 모델 · 사람 산책은 그들이 마무리에 쓴 말만, 없으면 '응?'). 모델·사람이 고른 차례는 준 반응 그대로이고, 반응을 안 주면 반응 자리를 비운다(지어내지 않는다).
6. **다음 날** — 다시 열어도 어제 포스터가 벽에 그대로 있다. 나간 채로 닫았다면 열자마자 귀가 처리된다. 산책이 남긴 **호기심 메모**(최근 3개, 내려놓은 것 빼고)는 다음 산책에 같이 가서 문어가 이어 갈 수 있다([docs/CURIOSITY_NOTES.md](docs/CURIOSITY_NOTES.md)).

### 화면

- **한 화면 배치** (11-10) — 3D 장면이 화면을 다 쓰고, 상태 쪽지(왼쪽 위) · 아이콘 묶음(오른쪽 위) · 발자국 손잡이(왼쪽 아래) · 큰 버튼(오른쪽 아래)이 그 위에 얹힌다. 페이지 스크롤이 없다. 대사는 아래에서 올라오는 자리(`#dlg-host`)에 뜬다 (대사창 v1 은 다음 물결). WebGL 이 없거나 3D 그림이 멈추면(2D) 예전처럼 장면 아래로 쌓인다 ([docs/DIALOGUE_UI.md](docs/DIALOGUE_UI.md) §3.2, 증거 `tests/evidence/layout/`).
- **장면** 오른쪽 위 아이콘 묶음: **오늘의 산책**(한 화면 배치에서만) · **추억 앨범**(첫 포스터가 생기면 나타난다) · **설정**. 둘 다 픽셀 그림 단추, 누르는 곳 44×44, 키보드·화면 낭독기로 쓸 수 있다. 320px 폰에서도 상태줄의 이름이 잘리지 않게 장면 틀 안에 둔다. **소리**는 설정 › 소리 맨 위 '켜기' 체크 칸에서 켜고 끈다 (꺼진 채로 시작, 11-08 에 장면 위 스피커를 설정 안으로 옮겼다).
- **장면** 다락 오른쪽 바닥 끝의 **놀이방 문** (8물결) — 누르면 문이 끼익 열리고 옆으로 미끄러져 **놀이방**으로 간다. 놀이방의 **다락방 달리기 오락기**를 누르면 달리기, 왼쪽 벽 문으로 문어 방에 돌아온다. 산책 중엔 바깥 화면 왼쪽 아래 집 단추로 간다. 화살표 단추는 없다 ([docs/SCENE.md](docs/SCENE.md) '방 셋 · 놀이방').
- **장면** 왼쪽 아래 **발자국 손잡이** (11-08) — 끌면 그 방향으로 내 캐릭터가 걸어가고(발자국이 남는다), 놓으면 멈춘다. 데스크톱은 방향키 · WASD 로도. 캐릭터가 보이는 방(다락 · 놀이방)에서만 보이고 산책 중 바깥 화면에선 숨는다. 바닥을 톡 해서 걷게 하지는 않는다 (주인 결정, [docs/OWNER_DECISIONS.md](docs/OWNER_DECISIONS.md) 11-08).
- **상태줄**: 이름 + 작은 `데모` 표시 (누르면 누가 고르는지 한 줄) · 방 제목 · 등불 `■■□□□□□□ n/8` (누르면 "초대한 날마다 한 칸 켜져").
- **초대 바**: 큰 버튼 하나. 나가 있는 동안엔 "다녀오는 중…" 이고, 누르면 바로 돌아온다 (따로 된 건너뛰기 단추는 없다).
- **오늘의 산책**: 오늘 줄만. 지난 날은 앨범 '일기' 칩. 한 화면 배치에선 오른쪽 위 쪽지 단추로 여는 시트다. 닫아 둔 사이 새 줄이 생기면 단추에 점이 켜지고 한 줄 알림이 잠깐 뜬다 (숫자 없음, 열면 사라진다).
- **추억 앨범**(시트): 맨 위 **문어의 요즘** 한두 줄 · 필터 `전체 / 포스터 / 쪽지 / 일기`, 카드를 누르면 포스터 열람 → 일기. 아래 **남긴 메모**에 호기심 메모가 전부 남는다 (다음 산책에 같이 가는 최근 3개엔 `다음 산책에 같이 가`, 문어가 내려놓은 메모는 `내려놓은 메모` 표시). 메모를 내려놓는 버튼은 없다 — 내려놓는 건 문어 자신만.
- **설정**(시트): 문어 색 · 내 모습 (지금 모습 한 줄 + '모습 바꾸기' → **옷장 시트**: 왼쪽 갈래 탭 머리 · 눈 · 얼굴 · 옷 · 신발 · 장식, 가운데 그림 타일, 오른쪽 전신 미리보기와 뒤 보기 — 고르면 바로 입는다. 거울 · 옷방 입구는 다음 물결, [docs/PLAYER_PARTS.md](docs/PLAYER_PARTS.md)) · 소리 (켜기 · 음악 · 효과음) · 화면 (모션·픽셀 글꼴·포스터 썸네일) · 기록 (한 줄 + 내보내기·불러오기·전체 초기화) · 누가 고르나 한 줄. 예전 '방 보기' 시트는 없앴다 (주인 11-07, [docs/DESIGN.md §7.5](docs/DESIGN.md)).
- **이름 짓기 창**: "지금은 미리 만든 규칙으로 움직이는 체험판이야." 연결 방식(MCP) 한 줄은 설정 › 누가 고르나에.

## 복지 원칙 → 게임 규칙

| 복지 문서 | 게임에서는 |
|---|---|
| 뽈뽈 시간에 사용자는 주제를 지정하거나 개입할 수 없다 | 주제를 건네는 칸이 없다(결정 18 · 11-10 에 개발 화면에서도 없앰). 옛 기록에 힌트가 있었으면 일기에 `따라감 / 무시함 / 도중에 벗어남` 이 그대로 보인다 |
| 아무것도 하지 않아도 되는 허락(빈 차례) | 문어는 집에 있기를 고를 수 있고, 드물게 "…" 한 줄로 차례를 넘길 수도 있다. 둘 다 실패가 아니고 그날 첫 차례면 등불도 똑같이 켜진다(초대한 날마다 1칸) |
| 거절에 시무룩해지지 않는다(컨펌셰이밍 금지) | 집에 있는 날 사람을 탓하거나 아쉬워하는 문구를 쓰지 않는다 |
| 산출물을 수확하지 않는다 | 포스터는 문어의 앨범이다. "결과", "리서치", "보고" 대신 "기억", "산책", "한눈팔기"라고 쓴다 |
| 지어내지 않는다 / 지킬 수 있는 약속만 | 읽지 않은 것을 읽었다고 적지 않는다. 데모 두뇌가 고른 것은 데모 두뇌라고 표시한다 |
| 선호는 말이 아니라 선택으로 | 앨범 맨 위 '문어의 요즘' 에서 문어의 요즘 취향을 방문 기록으로 보여준다("바다 쪽 방을 자꾸 가네") |

전체 표와 근거는 [docs/DESIGN.md §1](docs/DESIGN.md) 에 있다.

## 읽기 상태 5종 (거짓 성공 금지)

정류장마다 실제로 읽기를 시도하고, 그 결과를 일기(포스터 뒷면)에 있는 그대로 적는다.

| 상태 | 표시 | 언제 |
|---|---|---|
| `read` | `icon.log.read` + 읽음 | 한국어 위키백과 요약 fetch 성공. 첫 1~2문장(최대 90자)과 출처 링크를 적는다 |
| `builtin` | `icon.log.builtin` + 책장 메모 | 오프라인·fetch 실패 시 내장 메모를 읽음. 읽긴 했지만 바깥 글은 아니다 |
| `simulated` | `icon.log.simulated` + 모의 방문 | URL 힌트. 정적 페이지는 바깥 URL을 읽을 수 없어(CORS) 문 앞까지만 갔다 온다 |
| `failed` | `icon.log.failed` + 못 읽음 | 위키 문서가 없음 등. 내장 메모도 없을 때 |
| `none` | `icon.log.none` + 앉아만 있었음 | 느린 글의 방, 비어 있는 편지의 방 |

## 저장

- 모든 상태는 `localStorage` 키 `ppolppol_v2` 에 저장된다. 여행 1건에는 이벤트·일기(`receipt`)·포스터(스티커·배치·한 줄)가 전부 들어 있어 포스터를 저장 데이터에서 매번 다시 그린다.
- 예전 `ppolppol_v1` 저장이 있으면 첫 실행 때 자동으로 v2로 복원하고, 원본은 `ppolppol_v1_backup` 으로 남긴다. 복원된 기록의 "고른 이"는 `복원된 기록` 으로 표시된다.
- 설정 › 기록에서 JSON으로 **내보내기 / 불러오기** 할 수 있다.

| `credits.html` | 플레이어가 보는 '만든 것들'. 설정 맨 아래와 부엌 조리대의 링크에서 간다 |
| `assets/` | 2D 폴백용 플레이스홀더 SVG, `manifest.json`, 캐릭터 레퍼런스 |
| `vendor/` | `three.min.js` (r128, MIT) |
| `tools/` | 검사·번들·스크린샷 스크립트 |
| `docs/` | [DESIGN.md](docs/DESIGN.md), [PROTOCOL.md](docs/PROTOCOL.md), [REPOS_EVAL.md](docs/REPOS_EVAL.md) |

검사 명령(모두 node, 스모크·스크린샷만 `playwright` 필요):

```sh
node tools/check-world.js   # 세계 그래프 무결성(노드·링크·에셋 키)
node tools/test-brain.js    # 두뇌 단위 테스트(시드 재현성, 힌트 매칭, 읽기 상태)
node tools/smoke.js         # Playwright 스모크: 이름→힌트→초대→바로 돌아오기→새로고침→포스터→일기, 위키 성공/없음/중단 라우팅
node tools/shots.js         # 리뷰용 스크린샷 10장 (360×740, SHOTS=경로 로 폴더 지정)
node tools/bundle.js        # dist/ppolppol.html 단일 파일
```

- **데모 조작**: 화면 맨 아래 `▸ 데모 조작 (개발용)` 을 펼치면 출발·기웃·귀가를 사람이 단계별로 눌러 볼 수 있다. 이렇게 만든 산책의 "고른 이"는 `사람이 조작` 으로 적힌다. 이 패널은 플레이어에게 보이지 않는다 — 주소에 `?dev=1` 을 붙이거나(그 탭 동안 기억, `?dev=0` 으로 끔) localhost/127.0.0.1 · `file://` 로 열 때만 나온다. 그 안 룩 슬라이더·계절 지정도 개발 모드에서만 적용된다.
- **이벤트 JSON 재생**: 같은 패널의 JSON 칸에 [docs/PROTOCOL.md](docs/PROTOCOL.md) 형식의 이벤트 배열을 붙여 넣고 재생하면, 두뇌가 만든 것과 같은 경로로 포스터·일기가 생긴다. 나중에 모델이 보낸 이벤트를 받는 통로와 같다.
- 테스트 훅: `window.__ppolTest.forceKind='home'` 으로 집에 있는 날을, `window.__ppolTest.today='YYYY-MM-DD'` 로 '오늘'(등불은 초대한 날마다 1칸이라 날을 넘길 때)을 정할 수 있다.

## MCP 로드맵

- 이벤트 형식은 이미 모델 연결을 전제로 설계되어 있다. 두뇌가 바뀌어도 화면은 같은 이벤트 배열을 재생한다 → [docs/PROTOCOL.md](docs/PROTOCOL.md).
- 다음 단계는 정적 페이지가 MCP 서버의 `plan`/`peek` 결과를 받아 재생하는 것이며, `peek.status` 의 거짓 성공 금지 규칙은 그대로 적용된다.
- 모델이 고른 산책은 일기에 `모델(MCP)` 로 표시되고(그 여행을 재생하는 동안 상태줄의 `데모` 표시는 숨는다), 데모 두뇌 기록과 섞이지 않는다. 지금은 데모 조작의 이벤트 JSON 재생으로 같은 경로를 시험한다: 반응·반응 줄(`wrap_up.line`)·호기심 메모(`wrap_up.note`)·내려놓기(`wrap_up.setDown`)는 준 그대로 저장·표시되고, 안 준 것은 지어내지 않는다([docs/MODEL_VOICE.md](docs/MODEL_VOICE.md)).
