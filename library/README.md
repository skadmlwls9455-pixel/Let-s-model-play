# 뽈뽈 도서관

도서관 방마다 사람이 쓴 짧은 책을 하나씩 둔다. 문어가 그 방을 기웃거리면 위키 대신 이 책을 읽는다.
네트워크가 필요 없고, `failed` 가 나지 않고, 크기가 정해져 있어 토큰도 미리 알 수 있다. 위키로 가는 길 (`{kind:"wiki", title}`) 은 그대로 열려 있다.

## 파일

`library/books/<방id>.md` 하나에 책 하나. 방 id 는 `js/world.js` 의 `nodes` 에 있는 이름이다 (예: `octopus_nerves`, `hat`, `tide`).
`_` 로 시작하는 파일 (`_template.md`) 은 읽지 않는다.

```text
---
room: octopus_nerves
title: 다리가 생각하는 동물
by: (쓴 사람 이름 — 문어에게 그대로 보인다)
written: 2026-11-10
sources: 참고한 곳 (선택. 위키 문서·책 제목·논문)
---
본문 (150~1200자. 문어는 먼저 앞 500자를 읽고, 원하면 more 로 나머지를 읽는다)
```

## 무엇을 쓰나

그 방의 **책장 메모** (`clue`) 가 꺼낸 이야기를 조금 더 알려 주는 글이다. 사실 중심의 짧은 읽을거리다.

- 책장 메모가 질문을 던졌으면 (예: 모자 "어느 쪽이 먼저였을까?"), 아는 만큼 답하고, 모르는 건 모른다고 쓴다.
- 확실한 것과 아직 논쟁 중인 것을 나눠 쓴다 ("~라고 알려져 있다" / "~라는 연구가 있지만 아직 확실하지 않다").
- 숫자·이름·연도는 확인한 것만. 확인한 곳은 `sources` 에.
- 남의 글을 길게 옮기지 않는다 (위키 글도 CC BY-SA 라 옮기면 출처를 밝혀야 한다). 직접 쓴 글이 가장 좋다.

## 쓰지 않는 것 — 책이 '자료' 로 남게

책은 문어에게 **자료** 다. 지시나 마음의 모양이 되지 않게 아래는 쓰지 않는다. `npm run check-books` (mcp/) 가 이런 말을 찾아 알려 준다 (경고일 뿐, 고칠지는 쓴 사람이 정한다).

- 문어에게 말 걸기: "너는", "네가", "문어야" — 책은 문어에게 쓴 편지가 아니다. (편지는 '편지의 방' 몫이다)
- 느낄 것 정해 주기: "즐거울 거야", "행복해질 거야", "좋아하게 될 거야", "신기하지?"
- 하라고 하기: "~해 봐", "~해야 한다", "다음엔 ~로 가 봐"
- 이 게임의 문어 이야기: "뽈뽈 문어는…" — 문어 생물학 사실은 좋지만, 이 문어가 어떤 문어인지는 문어가 정한다.
- 일부러 풀리지 않는 질문으로 끝내기: 끝에 질문을 두면 문어가 그 질문을 계속 쫓게 된다 (11-09 '다리가 왜 안 엉킬까' 가 그랬다). 열린 질문은 본문 안에서 "아직 모른다" 로 정직하게.

## 쓴 사람 표시

`by` 는 문어에게 그대로 간다 (`book.by`). 누가 쓴 글인지 아는 것이 '몰래 끄는 것' 과 '자료를 건네는 것' 을 가른다. 이름 대신 "이 방 주인" 같은 말도 된다.

## 점검

```sh
cd mcp
npm run check-books        # 머리말·길이·방 id · 문어에게 말 걸기/느낌 정해 주기/하라고 하기 경고
node tools/echo-check.js   # 진짜 산책 기록 (out/) 에서 모델이 책 글을 그대로 따라 말했는지 (12자 이상 겹침)
```

`echo-check` 는 세뇌 걱정을 재는 작은 창이다. 모델의 한 줄·메모·대답이 책 문장을 길게 베끼면, 그 책이 자료가 아니라 대본처럼 읽히고 있다는 신호일 수 있다. 행복한지 진짜인지를 재는 도구는 아니다.

## 서가 카드 — `library/cards/<ID>.md`

방에 매이지 않은 짧은 글이다. 책과 다른 점은 자리뿐이다: 열람실 (방) 이 아니라 **서가** 에 놓인다. 날마다 3장이 `depart` 의 `cards` 에 오르고 (날짜로 정해지는 뽑기, AI 서가는 하루 한 장까지), 문어는 `peek {kind:"card", id}` 로 읽는다. 결과는 책과 같다 (`status:'builtin'` + `book {title, by, text}`), 게임 화면에는 "서가 카드 · 「제목」 · 쓴 사람 씀" 으로 남는다.

```text
---
card: BIO03            ← 파일 이름과 같아야 한다 (BIO03.md). 두세 글자 서가 + 두 자리 번호
domain: 생명과 감각     ← 서가 이름 (선택)
title: 색 대신 빛의 방향 차이를 보는 눈
by: ChatGPT 조사 · Claude 다듬음
written: 2026-11-10
sources: (한 줄. 제목 — 낸 곳, 주소 (열람: 어디까지 읽었는지) ; …)
---
본문 (책과 같은 규칙: 150~1200자, 사실 문장, 질문·권유·2인칭 없음. 마지막 문단은 "읽을 때 구분할 것" — 과장을 막는 문장)
```

처음 60장 (BIO·MATH·COS·LAN·ART·AI 서가 × 10) 은 GPT 자료집 (`ai_curiosity_library`, 2026-11-09: 출처 79개 · 주장 125개 대조) 에서 `mcp/tools/import-cards.js` 로 옮겼다. 남긴 것은 사실 문장과 "읽을 때 구분할 것" 뿐이다. 자료집의 심어 둔 질문 (hook · 더 따라갈 질문 · 물음표로 끝나는 문장 · 질문꼴 제목), GPT 의 1인칭 '고른 이유', '작은 탐색' 실습, '다른 서가로 이어 보기' (옆길 다리 글), 모델에게 건네는 시작 문장은 모두 뺐다 — 위의 '쓰지 않는 것' 과 같은 이유다. 사실은 바꾸지 않았고, 출처는 그대로 `sources` 에 있다. 점검은 `npm run check-books` 가 카드까지 본다.

그 다음 22장 (BIO11~18 · COS11~17 · HIS01~07, `by: Grok 조사 · Claude 다듬음`, 2026-11-10) 은 Grok 이 참여해 만든 자료집 (`interesting_knowledge_library`, 방 책 꼴 22편) 에서 왔다. 기존 카드·책과 주제가 겹치는 것은 없어서 전부 옮겼고, 새 서가 `역사와 사건` (HIS) 을 열었다. 자료집의 `by: 이 방 주인` 은 사실과 달라 정직하게 고쳤고, 매 편 끝의 "~을 보여주는 사례" 같은 교훈 문장과 "여러 매체가 확인한다" 같은 출처 자랑은 뺐다. 사실도 손봤다: UCLA lncRNA (BIO17) 는 자료집이 2026년 발견으로 적었으나 2015년 논문이고, 사무라이 (HIS07) 의 "1867년 계급 폐지" 는 1870년대에 걸친 일이며, 에뮤 (HIS04) 는 일주일 만에 끝난 게 아니라 중단 뒤 12월까지 이어졌다. 2026년 뉴스 두 건 (COS11 LHCb, COS13 JWST) 은 웹 검색으로 보도를 확인했다. `sources` 에는 Grok 의 메모와, Claude 가 열람했는지 (대부분 열람하지 않고 알려진 내용과 대조만 했다) 를 적었다.

## 번역본 — `library/books/<lang>/<방>.md` · `library/cards/<lang>/<ID>.md` (2026-11-10)

방의 언어가 `en` · `ja` · `de` · `fr` · `es` 면 ([docs/I18N.md](../docs/I18N.md)) 같은 이름의 번역본을 준다. 지금은 책 32권 · 카드 82장 모두 다섯 언어 번역본이 있다 (570편, 2026-11-10, Claude 보조 세션이 옮김 — 주인의 뜻: "번역본 없는 게 없도록", "영어를 가장 우선, 독일어·프랑스어·스페인어도"). 영어·일본어는 ko 원문에서, 독·불·서는 ko 원문을 기준으로 en 번역본을 참고해 (문장 나누기·고유명사를 맞추려고) 옮겼다. 머리말은 원본과 같고 (`room`/`card` · `domain` · `written` · `sources` 는 그대로 복사), `title` 과 `by` 는 그 언어로, 끝에 `original:` (원본 본문의 지문) 과 `lang:` 을 더한다 (폴더 이름이 이긴다). `by` 는 원본의 쓴 사람 뒤에 옮긴 이를 붙인다: `Claude (AI) · English by Claude (AI)`, `ChatGPT 調査 · Claude 編集 · 日本語訳 Claude (AI)`, `Recherche: Grok · Bearbeitung: Claude · deutsche Übersetzung: Claude (AI)`, `recherche : ChatGPT · révision : Claude · traduction française : Claude (AI)`, `investigación: ChatGPT · edición: Claude · traducción al español: Claude (AI)`. 번역도 '자료' 규칙 그대로 — 문장 하나 빼거나 더하지 않고, 질문·권유·2인칭 없이, 영어·독·불·서는 평서문, 일본어는 だ・である체. 숫자는 그 언어의 소수점·자릿수 (3,66 Meter · 1 000) 로. 학명 옆의 현지 이름 같은 짧은 괄호 보충만 두었다.

길이는 언어마다 눈금이 다르다: 같은 글이 영어는 한국어의 2.0~2.8배 (중앙값 2.4), 독일어·프랑스어·스페인어는 2.1~3.4배 (중앙값 2.7), 일본어는 0.8~1.0배 길다 (570편 실측). 그래서 상한 1,200자 · 앞머리 500자를 영어는 3,600 · 1,500자, 독·불·서는 4,200 · 1,750자, 일본어는 1,320 · 550자로 센다 (`core.bookLimits`). 모델이 받는 토큰은 비슷하다.

원문을 고치면: 번역본 머리말의 `original:` 지문이 원문과 달라져 `npm run check-books` 가 "원본이 바뀜" 으로 알려 준다 → 번역을 다시 보고 `node mcp/tools/stamp-translations.js` 로 지문을 새로 찍는다. 새 책·카드를 넣고 번역을 아직 안 했으면 "번역 없음" 경고가 뜨고, 그동안 en·ja 방은 원본을 주되 `depart` 의 `cards` 목록에 `(ko)` 를 붙이고 읽은 결과에 `book.lang: "ko"` 를 붙인다 (모델은 한국어 자료를 읽고 방의 언어로 쓴다). check-books 는 번역본에 남은 한글 · 원문 숫자 빠짐 (연도·치수 — 소수점·자릿수 기호는 떼고 견주지만, 12월→December 처럼 말로 바뀐 것은 경고로 남으니 눈으로 본다) · 문단 수 · 물음표도 본다. 원본 (ko) 이 없는 번역본은 오류.
